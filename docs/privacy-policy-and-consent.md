# SPACEKIJUN 개인정보처리방침과 동의 이력

## 목적

SPACEKIJUN에서 처리하는 계정정보와 학생 교육정보의 범위, 보유기간, 권리행사,
처리위탁 및 보호조치를 공개한다. 특히 생활기록부, 성적, 상담·위기지원 기록은
별도의 특별 보호 원칙을 적용한다.

웹 방침의 현재 버전은 `2026-07-24`이며
`src/components/privacy/PrivacyPolicyContent.tsx`에서 관리한다.

## 사용자 흐름

1. 로그인 전에도 `/privacy`에서 방침 전문을 볼 수 있다.
2. 로그인한 사용자는 `RequireAuth`에서 현재 버전 동의 여부를 확인한다.
3. 동의 이력이 없으면 기존 사용자와 신규 사용자 모두 보호 라우트 대신 동의
   화면을 본다.
4. 사용자는 다음 세 항목을 각각 확인해야 한다.
   - 계정·권한 관리와 사이트 제공에 필요한 개인정보 처리
   - 생활기록부·성적·상담기록 특별 보호 수칙
   - 만 14세 이상 또는 학교가 별도로 확인한 법정대리인 동의
5. 동의하지 않으면 로그아웃할 수 있으며 보호된 기능은 이용할 수 없다.

## 데이터베이스

마이그레이션:
`supabase/migrations/20260724082333_privacy_policy_consent.sql`,
`supabase/migrations/20260724082459_index_privacy_consent_policy_version.sql`

### `privacy_policy_versions`

공개된 방침의 버전, 제목, 시행일과 현재 활성 여부를 저장한다. 한 번에 한
버전만 활성화할 수 있다. 익명·인증 사용자는 활성 버전 메타데이터만 읽을 수
있고 클라이언트에서 변경할 수 없다.

### `user_privacy_consents`

인증 사용자 ID, 방침 버전, 서버가 기록한 동의 시각과 세 필수 확인 결과만
저장한다. IP 주소, 브라우저 정보, 사용자 에이전트, 전화번호는 동의 증명을
위해 추가 수집하지 않는다.

- 사용자는 RLS를 통해 자신의 동의 이력만 읽을 수 있다.
- 인증된 사용자는 현재 활성 방침에 대한 자신의 동의만 추가할 수 있다.
- 세 확인값은 모두 `true`여야 하며 동의 이력은 클라이언트에서 수정·삭제할
  수 없는 불변 기록이다.
- 인증 사용자가 삭제되면 해당 동의 이력도 함께 삭제된다.

## 새 방침을 게시하는 방법

1. 개인정보 보호책임자의 검토와 승인을 받는다.
2. `PrivacyPolicyContent.tsx`의 전문, 버전과 시행일을 갱신한다.
3. 기존 활성 버전을 비활성화하고 새 버전을 활성화하는 새 SQL 마이그레이션을
   만든다.
4. 처리 목적, 수탁자, 처리 국가, 항목 또는 보유기간 변경 여부를 확인한다.
5. 프론트엔드와 DB 마이그레이션을 같은 배포 단위로 반영한다.
6. 새 버전이 활성화되면 모든 사용자는 다시 동의해야 한다.

## 수탁자 계약 이력

실제로 체결·수락한 처리 약관을 여기에 기록한다. 방침 본문(6장)의 수탁자 표와는
별개이며, 표에서 어떤 사업자를 빼더라도 **실제 데이터 흐름과 계약 사실은 여기 남는다**.

### Google (Google Workspace for Education)

- 약관: [Cloud 데이터 처리 추가 조항(CDPA)](https://admin.google.com/terms/apps/8/2/en/dpa_terms.html)
- 수락일: 2026-07-27 / 수락 계정: `user597@example.com`
- 함께 수락: Google Workspace for Education 서비스 데이터 관련 추가 조항 (2026-07-27, 같은 계정)
- 수락하지 않음: EU/영국/스위스 GDPR 표준계약조항 적용 옵션, Google Workspace/Cloud ID
  HIPAA 비즈니스 제휴 개정안 — 둘 다 본교 적용 대상이 아니라는 판단
- 확인 경로: Google 관리 콘솔 → 보안 및 개인정보 보호에 대한 추가 약관
- 증빙: 관리 콘솔 화면 캡처를 `docs/privacy/evidence/`에 보관한다(파일은 저장소에
  커밋하지 않고 학교 문서고에 두어도 된다 — 이 문서의 기록이 색인 역할을 한다).

### 그 밖의 수탁자

- Supabase: 서비스 계약(별도 기록 필요)
- OpenAI / Upstage: API 이용 계약과 데이터 보존 설정 확인 필요(미기록)

## 운영 전·정기 점검

- 학교 개인정보 보호책임자가 방침의 담당자, 연락처, 개인정보파일별 실제
  보유기간을 확인한다.
- Supabase, Google, OpenAI, Upstage의 실제 계약 주체, 처리 국가, 재위탁,
  API 데이터 보존 설정과 국외 이전 고지 요건을 확인한다.
  (Google은 2026-07-27 CDPA·Education 추가 조항 수락 — 위 "수탁자 계약 이력" 참조)
- 식별 가능한 생활기록부 전체, 상담 원문, 건강·징계·위기정보가 AI API에
  입력되지 않도록 기능별 데이터 최소화와 권한을 점검한다.
- AI 결과만으로 성적, 상담, 징계 또는 진학 결정을 하지 않도록 교직원 교육과
  사람의 검토 절차를 유지한다.
- 퇴직·전출·졸업 시 접근권한 회수와 졸업생 익명화가 작동하는지 확인한다.
- 학생·교사의 개인 전화번호가 새 필드나 자유 형식 메타데이터에 다시 저장되지
  않는지 점검한다.
- 개인정보 열람·정정·삭제·처리정지·동의 철회 요구의 접수 및 처리 기록을
  관리한다.

수탁·국외 이전 계약 내용은 학교 개인정보 보호책임자가 배포 전에 최종
확인한다.
