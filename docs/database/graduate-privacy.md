# 졸업생 개인정보 익명화

## 익명명 규칙

졸업생은 실제 입학 코호트를 기준으로 입학연도를 정한다. 일반 학생은
`resource.meta.id`의 앞 두 자리와 입학연도가 같지만, 전입생은 ID 발급
시점 때문에 다를 수 있으므로 매핑 CSV에서 실제 입학연도를 별도로 확인한다.
같은 입학연도 안에서 실명을 가나다순으로 정렬하고, 동명이인은 학생코드순으로
정렬한다.

익명명 형식은 `YYYY입학NNN`이다. 예: `2023입학001`.

## 처리 범위

- `resource.name`과 학생 이름이 복제된 학생 기본정보·진로 제출·방과후·문서 발급 데이터
- `student_basic_info` 내부 JSON에 포함된 실명
- `student_detailed_activities.content`, `data`, `analysis`에 포함된 실명
- 학생코드로 연결되는 Auth 사용자/Identity/Profile 및 YouTube 프로필
- Auth 감사 로그에 남은 해당 계정의 실명
- 졸업생 Auth 계정 차단과 세션·리프레시 토큰 폐기
- `resource.meta.grade`, `resource.meta.picture`, `resource.meta.birthday` 삭제
- `student_basic_info.grade`, `class_num`, `number` 초기화

과거 교육 활동을 설명하는 학년 값은 이력의 의미가 있으므로 삭제하지 않는다.

## 매핑 CSV

DB 변경 전에 `입학연도, 순번, 학생코드, 실명, 익명명, 리소스ID` 열을 가진
CSV를 생성한다. 파일은 `.tmp/`에 저장하여 Git 추적 대상에서 제외한다.
이 파일은 재식별이 가능한 개인정보이므로 관리자만 접근할 수 있는 별도
보관소로 옮겨야 한다.

학생 관리 탭의 입학연도별 졸업 처리도 같은 열의 UTF-8 CSV 다운로드를 먼저
시작한다. 화면의 미리보기에는 실명과 변경될 익명명을 함께 표시한다. 이미
같은 입학연도의 익명명이 있으면 사용 중인 마지막 번호 다음부터 배정한다.
전입생 ID가 실제 입학연도와 다른 경우에는 졸업 처리 전에 관리자 데이터의
학생 ID를 실제 코호트와 일치시키고 미리보기 포함 여부를 확인한다.

## 재발 방지

`resource_graduated_student_privacy` 제약은 졸업생 리소스가 익명명 형식을
사용하고 학년·사진·생년월일 메타데이터를 보유하지 않도록 강제한다. 관리자
화면의 졸업 처리는 입학연도별 일괄 메뉴를 사용하며, 개별 상태 변경으로는
신규 졸업 처리를 할 수 없다.

`process_graduated_student_cohort` RPC는 로그인한 관리자만 실행할 수 있다.
화면에서 내려받은 미리보기의 리소스 ID·익명명과 서버가 다시 계산한 값을
비교한 뒤, 일치할 때만 관련 테이블 익명화, 현재 학적·사진·생년월일 삭제,
Auth 계정 차단, 세션 폐기, `resource.status = 'graduated'` 변경을 하나의
트랜잭션으로 실행한다. 미리보기가 오래되었거나 중복 이름 때문에 문서의
자유 텍스트에서 한 학생을 특정할 수 없으면 해당 실명을 연결 가능한 익명명
목록으로 교체한다. 서버 검증과 실제 데이터가 일치하지 않으면 어떤 데이터도
변경하지 않고 실패한다.

`anonymize_detailed_activities_on_graduation` 트리거는 학생 리소스 이름이
졸업 익명명으로 변경될 때 학생코드로 연결된 상세 활동의 텍스트와 JSON도
같은 트랜잭션에서 익명화한다. 처리 뒤 실명이 남아 있으면 트랜잭션을
실패시킨다.
