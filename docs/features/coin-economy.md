보유 현황 표는 **쪽으로 나눈다**(50·100·200명씩, 2026-10-21 사용자 요청 — 재학생만 600여 명). 머리 체크박스 = 이 쪽만, 다른 쪽까지는 «결과 N명 모두 고르기»(고른 사람은 쪽을 넘겨도 남고 «다른 쪽 N명 포함»으로 보인다). 거르기·정렬이 바뀌면 첫 쪽으로. 계산 = `paginate`·`pageButtons`.

판정 한 곳 = `economy_private.spend_rows` — 표의 합과 「기록」 창이 같은 줄을 센다(드라이런: 상위 5명 표 합 = 기록 창 합).
**수익화 — 의뢰 작품 수익**(2026-10-26, `20261026160000_tama_gacha_royalty.sql`): 다마고찌 의뢰로 만든 가챠 물건(`tama_item.creator` = 의뢰자)을 **다른 사람이 코인을 내고** 뽑으면 의뢰자에게 `least(값 × tama.royalty.percent ÷ 100 내림, tama.royalty.max)`(기본 50% · 최대 30)를 통합 원장 `tama_royalty`(source_id `gacha:<뽑기 기록 id>` — 멱등)로 준다. 관리자 무료 뽑기·자기 물건 뽑기는 0, 겹쳐서 환급받은 뽑기도 값 기준으로 준다. ⚠️ 의뢰 작품을 가챠에 새로 넣을 때 `creator` 를 적을 것(안 적으면 수익이 조용히 0). 뽑기 함수는 운영 정의에서 세 자리를 치환했다(운영 본문이 CRLF 라 LF 로 맞춘 뒤).
**경제 통계** 탭(같은 날, RPC `admin_coin_economy_stats`): 발행(지갑 시작 지급 + 얻은 코인) · 시중(지갑 합) · 사용 · 벌어들인 코인 · 수익화 · 회수, 얻은 곳·쓴 곳별 합, 최근 14일, 의뢰 작품별 수익. 기대 잔액(발행 − 사용 − 회수)과 시중의 차이를 «기록 밖 차이»로 그대로 보인다(첫 측정 +1,400 — 원장 이전 지급 등). 계산 `summarizeEconomy`.
**최근 획득 · 사유** 열과 «최근 획득 순» 정렬(2026-10-26, `20261026150000_coin_wallets_last_earned.sql`) — 판정 한 곳 = `economy_private.earn_rows`(「기록」 창의 들어온 줄과 같은 출처: 통합 원장 +줄 · 다마고찌 돌봄 보상(집중의 숲 제외) · 이야기 장 · 자습 보상 받기 · 공방 수수료. 환급·환불은 얻은 코인이 아니다). 사유 = 이름표 + 메모(`moveReason` — 메모가 이름표를 되풀이하면 메모만), 최근 사용 열도 같은 모양. «최근 변동 순»(`updated_at`)은 쓴 것까지 포함한다.
- 사용 = **스스로 쓴 것**, 낸 값 − 돌려받은 값: 통합 원장 차감(퍼즐·이세계 동전) · 가챠(값 − 겹침 환급) · 캐릭터·꾸미기·공방 의뢰 · 남의 공방 작품 구매(그때 값).

## 2. 구조

- **정본 = `public.coin_economy_setting`**(키 54개 · 값 · 기본값 · 최소·최대 · 앱 · 얻기/쓰기/횟수). 로그인 사용자 모두 읽고(값은 화면에 그대로 보인다), 쓰기는 `admin_coin_economy_set` RPC 만.
- 서버 함수는 `economy_private.num(키)` 로 읽는다 — **모르는 키는 0 이 아니라 예외**(보상이 몰래 0 이 되거나 값이 무료가 되지 않게).
- **규칙 함수 7개는 이름·모양 그대로**(`credit_rule` · `gacha_machine` · `slot_price` · `achievement_rule` · `star_coin_rule` · `isekai3d_play_rule` · `puzzle_coin_cost`) 본문만 표를 읽게 바꿨다(`IMMUTABLE → STABLE`, 의존 색인·제약 0 확인). 호출부 20여 곳은 손대지 않았다.
- **숫자가 본문에 박힌 함수 9개**(출석 자동 지급·회수, 자습 청구, 피드백, 장 완료, 플래너, 공방 의뢰, 상점 구매 수수료, 캐릭터·꾸미기 의뢰)는 운영 정의를 읽어 그 숫자만 치환했다 — 생성기가 «정확히 1회 일치»를 단언(본문 일부가 CRLF 라 줄바꿈도 원본에 맞춤).
- 화면: `src/lib/coinEconomy.ts` 의 `useCoinEconomy()`(게임 루트 셋 — TamagotchiPage · AcademyPage · StarTowerPage)가 표를 읽고, 기능마다 `economySync.ts` 가 **자기 상수를 그 자리에서 갱신**한다(`CREDIT_RULES` · `GACHA_MACHINES` · `DECOR_PRICES` · `SLOT_PRICES` · `ACHIEVEMENTS` · `CHARACTER_PRICE` · `workshopEconomy` · `STUDY_*` · `STAR_COIN` …). 상수를 읽는 3D 장면 같은 React 밖 코드까지 따라온다. 설정을 못 읽으면 아무것도 안 바꾼다(코드 기본값 = 시드 기본값).

## 3. 사용자 결정 · 내가 정한 것

- 회수(음수 부여)도 넣었다 — 요청은 «부여»였지만 잘못 준 것을 되돌릴 길이 필요하다. **0 아래로 내려가지 않는다**(clamp). 부여만 받는 사람에게 알림(`coin_grant`, 끌 수 있음).
- 부여는 사유 필수(학생 알림·원장 `note`에 남는다), 묶음 기록 `coin_admin_grant`(누가·얼마·몇 명·실제 합).
- 지갑이 없는 사람에게 부여하면 지갑이 100 으로 만들어진 뒤 더해진다(기존 `apply` 동작).
- **새 지갑 시작 코인(100)은 설정에 넣지 않았다** — 읽기 함수 7곳이 «지갑 없음 = 100» 을 따로 가정해, 기본값만 바꾸면 화면과 실제가 어긋난다.
- 탑 재화(물고기·별 조각 자체)·업적 목표·이세계 동전 1개의 시간(24분)처럼 **코인이 아닌 값**은 다루지 않았다.

## 4. 조용히 틀리는 자리

1. **가챠 겹침 환급 > 한 번 값이면 뽑을수록 코인이 는다**(무한 증식) — 설정 RPC 가 저장 뒤 다섯 기계를 다시 보고 거부한다(화면도 같은 검사).
2. **숫자를 못 박은 표 제약 10개**(`charged_coins ∈ {0,100}` · `sale_price = 35` · 수수료 `= 10` · 자습 영수증 `= 5` · 장 보상 `= 50` · 펫 원장 `1~5` · 공방 진열 `= 35`)를 범위로 풀었다 — 그대로 두면 값을 바꾸는 순간 그 기능이 오류로 멈춘다.
3. **출석 취소 회수는 «지금 값»이 아니라 영수증에 적힌 값** — 지급 뒤 값을 바꿔도 준 만큼만 되돌린다(드라이런: 6 지급 → 9 로 바꿈 → −6). 같은 이유로 자습 영수증·장 보상·수수료는 실제 지급액을 행에 적는다.
4. **의뢰는 «확인한 값»을 서버가 대조한다**(`confirm_cost`) — 옛 화면이 «100» 으로 확인하면 값이 120 일 때 거부(드라이런 확인). 환불은 낼 때 적은 `charged_coins` 라 값이 바뀌어도 어긋나지 않는다.
5. 화면 상수는 **루트가 `useCoinEconomy()` 를 부르고 `economySync` 를 불러와야** 갱신된다. 새 게임 화면이 코인 숫자를 보이면 같은 배선을 할 것(회귀가 세 루트를 검사).
6. 공방 작품 진열 가격은 **새로 배송되는 작품부터**(이미 진열된 작품의 값은 그 행에 있다).
7. 「기록」 창은 **기록이 남는 경로만** — 아카데미 상점 구매·플래너 «오늘 완료»는 행 기록이 없다(구매는 `academy_user_items` 에 값이 없다).
8. 집중의 숲 보상은 하루 횟수 공유 때문에 펫 원장(`forest:` 출처)과 통합 원장 둘 다에 적힌다 — 기록 합칠 때 펫 쪽 `forest:` 줄은 뺀다.
9. 공모전판(contest 스키마)은 복제본이라 이 설정을 따르지 않는다.
10. seaton 저장소의 화면 문구(예: «2P = 1코인»)는 이 저장소 밖이다 — 서버 견적(`seaton_puzzle_quote`)은 설정을 따른다.

## 6. 2026-10-21 — 가챠 값 수정 버그 · 얻기 넓히기
