# 요즘 세상 — 세상 관측 일지

학생이 뉴스에서 질문을 발견하고 탐구로 이어 가는 `/world-today` 화면. 교사·학생 메뉴와 관리자 메뉴 관리에 등록했다.

## 하나로 이어지는 컨셉

리아는 변화를 발견하고 질문을 여는 관찰자, 루온은 근거와 확인 방법을 찾는 탐구 동료다. ‘탐구 아카데미의 관측소’라는 하나의 공간에서 뉴스는 도착한 관측 이야기, 네 컷은 이야기의 입구, 개인 메모는 학생이 이어 쓰는 관측 일지가 된다. 분야가 바뀌어도 같은 캐릭터와 발견 → 이해 → 질문 → 탐구 순서를 유지한다.

- 첫 화면: 최신 관측 이야기 한 편을 크게 소개하고, 이후 이야기를 읽을 수 있는 매거진 목록을 제공한다.
- 읽기: 기사별 만화의 1~3컷은 기사 내용, 4컷은 탐구 질문이다. 말풍선이 들어간 원본 전체를 표시하고 확대 링크·대사 텍스트를 제공한다. 만화가 없는 기사는 수집된 핵심·해설·발췌와 질문을 텍스트로 제공한다.
- 기사 이동: 다이얼로그의 이전/다음 버튼 또는 좌우 방향키로 전체 공개 소식을 최신순으로 읽는다. 목록 필터·페이지와 독립적이며 목록 상태는 유지한다. 입력란의 방향키는 글 편집에 사용한다. 첫/마지막 기사는 해당 방향을 비활성화한다.
- 생각하기: **수집 단계에서 기사 내용으로 만든 탐구 질문 3개**(`ai_news.inquiry_questions`)를 먼저 제안한다. 본문에 답이 그대로 있는 확인 질문은 만들지 않고, 원리·조건 변경·사회적 의미처럼 결이 다른 세 갈래로 낸다. 질문이 없는 과거 기사는 종전대로 로컬 규칙 씨앗으로 돌아가며, 그 씨앗은 기사 사실을 생성하지 않는 일반 안내문이다. 화면이 둘을 구분해 말한다(「이 기사에서 뽑은 질문」/「리아의 질문 씨앗」).
- 이어 쓰기: 질문 / 예상과 이유 / 확인할 방법 / 발견과 새 질문을 본인 계정에 저장한다. 빈 일지로 소식만 담아 두는 것도 가능하다.
- 연결: 출처 포함 복사와 ‘탐구 설계로 이어가기’를 제공한다. 저장된 본인 일지를 DB에서 다시 읽어 탐구 설계의 요구사항에 반영한다. 교사는 학생을 선택한 뒤 씨앗을 가져오며, 자동 분석이나 AI 호출은 실행하지 않는다.

## 데이터와 권한

확인한 연결 프로젝트: `your-project-ref`. 구현 당시 `ai_news` 24건, `keep=true` 24건이었다. 국내 로봇 연구, 해외 로봇 활용, 경제 전망, 에너지 전환, 수학 연구 등이 포함되어 있다. 수집 파이프라인은 변경하지 않는다. 현재 AI·과학기술 중심이라는 안내를 제공하며 원문 매체의 국가를 사건 발생 국가로 추정하지 않는다.

- 기사는 `keep=true`이면서 `profiles.role`이 student/teacher/admin인 로그인 사용자에게만 SELECT를 허용한다. anon 접근과 클라이언트의 기사 쓰기 권한은 부여하지 않는다.
- `ai_news.summary`: 2026-09-12부터 **기사 전문을 읽고 만든 요약**이 들어온다(그 전 행은 RSS 발췌일 수 있다). 수집기가 채택 기사만 본문을 받아 요약하므로 탈락 기사에는 적용되지 않는다.
- `ai_news.inquiry_questions`: `text[]`, 기본값 `'{}'`. 수집기가 3개를 넣고 상한은 5개다. 개수를 강제하지 않아 과거 행(빈 배열)도 유효하게 남는다. 컬럼 추가만이라 기존 `ai_news` RLS 정책과 `authenticated` grant 를 그대로 따른다.
- `ai_news.keywords`: `text[]`, 기본값 `'{}'`, CHECK 상한 8개(수집기는 5개), GIN 인덱스 `ai_news_keywords_idx`. **`subjects` 와 다른 축이다** — 교과는 닫힌 8종의 **필터 축**(화면의 `모든 교과` 드롭다운 → `.contains('subjects', [값])`)이고, 핵심어는 기사마다 다른 **열린 어휘**다(`기계 관류`, `decoherent histories`, `OP3DSG`). 소급 생성하지 않아 **2026-09-18 실측 86건 중 16건만** 값을 갖는다.
- `world_news_inquiries`: `(user_id, news_id)` 기본키, 질문·예상·확인 방법·발견, 생성·수정일. 외래키는 `auth.users`와 `ai_news`, 삭제 시 cascade.
- 일지는 본인만 SELECT/INSERT/UPDATE/DELETE할 수 있다. 교사·관리자도 다른 사용자의 일지를 열람하지 못한다. 소유자 변경 및 비공개 기사에 대한 새 일지 작성은 차단한다.
- 관리자 미리보기에서는 개인 일지 조회·저장을 생략해 실제 관리자 계정의 메모가 학생 것처럼 보이지 않도록 한다.
- 기존 자동 생성 클라이언트와 거대한 공용 타입 파일은 수정하지 않았다. 실제 SQL과 대조한 기능 한정 `WorldDatabase` 타입으로 같은 클라이언트의 타입을 보강한다.
- 마이그레이션: `20260911233935_world_today_news_and_inquiries.sql`, 연결 프로젝트 반영 완료. 기존 `create_ai_news`·`profiles`·`auth.users` 이후 적용한다.
- 마이그레이션: `20260912030000_ai_news_comic_columns.sql`(`comic_path`·`comic_panels`, 공개 버킷 `world-today-comics`).
- 마이그레이션: `20260918120000_ai_news_keywords.sql`(`keywords`). 컬럼·CHECK·GIN 인덱스는 **이미 연결 프로젝트에 있고**(2026-09-18 카탈로그 대조) 파일은 그 기록이다. `inquiry_questions` 와 같은 이유로 **화면보다 먼저 적용돼야 한다** — 목록 쿼리가 이 열을 조회한다.
- 마이그레이션: `20260912021500_ai_news_summary_and_inquiry_questions.sql`. **이 마이그레이션을 먼저 적용한 뒤 배포할 것** — 목록 쿼리가 `inquiry_questions` 를 조회하므로 컬럼이 없으면 요즘 세상 화면이 통째로 실패한다(한 열이 빠진 게 아니라 쿼리 자체가 거부된다).

## 성능·실패 처리

- 기사 전체를 먼저 내려받지 않는다. 서버 필터(제목 검색·분류·교과)와 12편 단위 range, 발행일 DESC NULLS LAST → ID DESC 순서를 사용한다.
- 목록에는 필요한 열만 요청하고, 상세와 개인 일지는 열 때 조회한다. 요청 취소 신호와 5분 캐시, 새 소식 확인 버튼을 사용한다. 수집 데이터는 다음 조회에 반영된다.
- 목록·캐릭터에 전체 레이아웃 이동이나 무한 반복 애니메이션을 사용하지 않는다. 기사 이동 시 본문 확대 애니메이션을 제거했다. 인접 기사 ID만 각 방향 1건씩 조회하므로 모든 기사를 내려받지 않는다. 발행일 동률·NULL도 목록과 같은 순서로 처리한다.
- 네트워크 오류와 빈 결과를 구분한다. 저장 오류 시 초안을 유지하고, 저장되지 않은 일지를 닫거나 다른 기사로 이동하거나 페이지를 새로고침할 때 확인한다. 저장 중에는 기사 이동을 막는다. 기존 일지 조회가 실패하면 빈 폼으로 덮어쓰지 않는다.
- 원문 링크는 HTTP(S)만 허용하고 `noopener noreferrer`로 연다. 기사 텍스트를 HTML로 실행하지 않는다.

## 교과와 핵심어 (2026-09-18)

`ai_news.keywords` 를 교과와 **함께, 그러나 같은 모양이 아니게** 보여 준다.

- **둘은 다른 것을 말한다.** 교과는 목록을 거르는 닫힌 8종의 축이고, 핵심어는 이 기사가 실제로
  다루는 말이다(기사마다 다르고 미리 알 수 없다). 그래서 **칠한 칩은 계속 '교과' 하나만 뜻하고**,
  핵심어는 테두리 칩으로 그린다 — 같은 옷을 입히면 이 화면에서 색이 가진 유일한 약속이 사라지고,
  학생은 눌러서 걸러지길 기대하는데 아무 일도 일어나지 않는다.
- **구분은 재질로 주되 가독성은 양쪽 다 지킨다.** 표면 대비를 낮춰 부차적으로 보이게 만들지
  않았다(핵심어 칩 5.8:1, 라벨 4.7:1 — 기존 보조 텍스트가 3.1~3.6:1 인 화면이라 오히려 더 읽힌다).
- **카드는 3개, 다이얼로그는 전부.** 카드는 훑는 자리이고 핵심어는 최장 21자라, 3개를 `·` 로 잇고
  `line-clamp-2` 로 카드 높이 증가를 묶는다(`#` 접두가 붙은 교과 줄과 자연히 갈린다).
  이야기를 펼치면 `핵심어` 라벨과 함께 전부 보여 준다.
- **70/86 은 빈 배열이다.** 값이 없으면 라벨을 포함해 **줄 자체를 그리지 않는다** — 빈 라벨만
  남는 것이 이 변경에서 가장 쉽게 나는 사고다. 판정은 `articleKeywords()` 단일 출처이고
  `inquiry_questions` 와 같은 관습(`?? []` → trim → 빈 값 제거)을 따른다. 화면에서
  `article.keywords.map(...)` 을 직접 쓰지 말 것 — 열을 빼고 조회하는 경로가 생기면 거기서만
  조용히 죽는다.
- **아직 핵심어로 목록을 거르지는 않는다.** GIN 인덱스가 있어 `.contains('keywords', [값])` 나
  `overlaps` 로 넓히는 것은 가능하지만, 검색창은 지금 `title` 만 `ilike` 로 본다(배열 원소의
  부분 일치는 GIN 이 타지 않는다). 넓힐 때 이 차이를 먼저 볼 것.

## 관심 분야 맞춤 (2026-10-11)

«의학에 관심 있는 학생에게 의학 기사를» — 학생의 관심 분야에 걸린 새 소식을 먼저 안내한다. 사용자 결정 3가지:
