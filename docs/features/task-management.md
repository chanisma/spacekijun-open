**Manager vs Assignee Behavior** (2026-07-23 개편):
- **화면 이름 = «책임자»** (2026-10-05 사용자 결정) — 코드·데이터 이름(`manager`·`meta.managers`·이 문서의 «매니저»)은 그대로다. «관리자»는 시스템 관리자(admin) 전용. 같은 날 정한 이름표: Action = **작업**(«실행»은 작업을 한 번 돌린 것 — 이력·검수에만) · 미완료 = **진행 중** · 업무 진행 모달 = **단계별 진행** · 캔버스 = **업무 흐름**. 서버 예외문 27곳도 맞췄다(`20261005130000`). 회귀 `npx tsx scripts/task-naming-test/run.mts` — 옛 이름이 화면 문구에 되살아나도 빌드는 통과한다
- 담당자 저장 = `task.meta.assignees` JSONB 배열, 상태 `pending|completed|cancelled`
- Manager detection: **`event.meta.managers`** 배열(`{id, name}`) 기준 — `event.manager_id`는 레거시 호환으로 함께 검사
- 담당자: 본인 상태만 변경(`update_assignee_status_meta`)
- 매니저: **모든 담당자 상태 변경 가능** — `useToggleAssigneeStatusJsonb`가 `assigneeId` 유무로 분기, 매니저 경로는 `set_task_assignee_status` RPC(서버가 매니저 권한 재검증)
- 담당자 표시 = `TaskAssigneeSummary` — **`canEditAll`(=매니저) 여부로 UI가 완전히 갈린다**(2026-08-11 사용자 결정). 매니저: 완료 N/M 칩 + 아바타 스택 + 팝오버 전체 명단(누구든 완료/미완료 토글). **비매니저: 명단을 일절 노출하지 않는다** — 아바타 스택·셰브론·팝오버 없이 `N/M 완료` + `내 상태 완료/대기` 배지만 두고 **칩 클릭 = 내 상태 토글**(`SelfAssigneeSummary`). 아바타 스택도 담당자 이니셜을 드러내므로 팝오버만 막으면 반쪽이다. **예외 = 다중 마감**: 회차별 완료(`meta.deadlineProgress`)라 한 번 클릭으로 표현 불가 → 이때만 팝오버를 쓰되 **내 회차만** 담는다

**과제 단위 업무 (2026-08-12)**: 담당자를 인물이 아니라 **과제 명칭 단위**(과목별 서류 등)로 배분 — `task.meta.units`(`[{key,label}]`) + `meta.unitProgress`(`{unitKey:{assigneeId:{status}}}`, **항목 존재=배정/자기 선택**) + 기존 `meta.assignees`=**담당자 범주(pool)**. 범주 담당자는 카드 팝오버에서 담당자 없는 단위를 직접 선택(claim)해 수행하고, 파생 규칙은 **사람 기준과 다르다**: 개인=내 단위 전부 완료, task=모든 단위 완료(범주에만 있는 사람은 완료를 안 막음). 상태 변경은 `set_task_unit_status` RPC만(동시 선택 lost-update 방지 — 클라 직접 UPDATE 금지), 단일 출처=`src/lib/taskUnits.ts`, 편집 UI=`TaskEditDialog` "과제 단위별" 모드+`TaskUnitEditor`(프리셋 과목별=`teacher_timetable` 현행 학기·학급별=담임 태그 — **스냅샷 복사**, 라이브 참조 아님; 엑셀 2열 붙여넣기). **다중 마감과 상호 배타**, 제출과는 **두 방식 모두 조합 가능**(제출 시 단위 선택 → 그 단위 완료, `task_submission.unit_key`). 비매니저 카드 팝오버는 **내 단위+미선택 단위만**(남이 맡은 단위는 개수만 — 명단 비노출 결정 유지). **상세 모달(`TaskDetailDialog`)도 단위 지원**: 헤더 "과제 단위 N개" 칩, 내 작업 패널이 단위 토글(완료/선택 취소/내가 하기)·제출 진입으로 전환, "과제 단위 현황" 섹션(단위↔담당 매핑 — 이 다이얼로그는 담당자 명단을 원래 노출하므로 같은 수준). 회귀 `npx tsx scripts/task-units-test/run.mts`, 스키마 상세 `docs/database/core.md` §8-2

**제출 받기 = 작업 세 개 (2026-10-01 개편 — 아래 «방식 2종»은 옛 방식)**: `submit.file`(파일) · `submit.document`(양식 문서) · `submit.physical`(실물 — 매니저 [받음]). 요청·명단은 **입력 받기와 같은 표**(`collect_request.kind`·`collect_target`), 제출물 = `action_submission`. 대상 = 입력 받기와 같은 **대상 규칙**, 기본 = 새 조건 **«이 할 일의 담당자»**(`task_assignees` — **id 를 담지 않는다**, 서버가 풀 때마다 지금 담당자로 바꾸고 담당자가 바뀌면 명단이 따라간다). 요청은 **[요청 보내기]를 눌러야만** 열린다(2026-10-01 — 연결·저장만으로 알림이 가지 않는다. 입력 받기와 같다. 그래서 보내기 전에는 완료 가드도 없다). **완료 = 그 담당자가 대상인 열린 제출 요청을 전부 채움** — 가드는 `task` BEFORE UPDATE 트리거 하나(`guard_submission_completion`, 상태·단위 RPC·직접 쓰기 모두)라 과제 단위 할 일의 «제출 없이 완료» 구멍도 막혔다. **과제 단위 할 일**은 축 `unit` — 단위를 골라 내면 그 단위를 맡고, 그 단위에 남은 제출이 없으면 완료. 내 할 일·할 일 상세는 내야 할 것이 남으면 [완료하기] 대신 [제출하기]. ⚠️ 요청이 열리면 이미 완료였던 담당자·단위가 대기로 돌아간다(의도). 실물 양식을 목록에서 빼면 **드라이브에서도 지운다** — 단 연간 가져오기·흐름 복사로 **같은 파일을 공유하는 다른 작업이 있으면 남긴다**(`deleteUnusedFormFiles`, 설정 저장 뒤). 옛 `task.meta.submission` 의 화면 코드는 2026-10-05 에 걷어 냈다(아래). **요청은 한 자리에만 보인다 (2026-10-05)** — 제출 요청이고 그 할 일이 내 할 일 목록에 행으로 있으면 **행**(«파일 제출 남음» + [제출하기])이 맡고 「요청」 구획·계획표에서는 뺀다. 입력 요청과 행이 없는 제출 요청(담당이 아닌데 대상)만 구획에. 판정 단일 출처 = `collectInput.placeInboxRequests`(내 할 일·계획표·홈 「나의 업무」 카드가 같이 쓴다 — 구획은 그래서 페이지가 아니라 `MyTaskInbox` 가 그린다). 다 낸 요청은 구획 아래 «다 낸 요청 N건»으로 접는다. 메뉴 배지는 그대로 전부 센다. 회귀 `scripts/inbox-request-placement-test/run.mts`. 상세 = `docs/features/submit-action.md`, 회귀 = `npx tsx --tsconfig tsconfig.app.json scripts/submit-action-test/run.mts`(50건).
