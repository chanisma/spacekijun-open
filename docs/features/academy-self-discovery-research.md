# 별빛 아카데미: 자기 발견 기능과 튜토리얼 퀘스트 연구

2026-09-13 · 학생 시점의 제품 설계안. 교육 자료와 현재 저장소 구현을 함께 검토했다. 아래 신규 기능과 튜토리얼 확장은 제안이며 구현·배포 완료를 뜻하지 않는다. 앞서 착수한 연속 퀘스트와 NPC 기억 작업에 연결할 요구사항을 정리한다.

후속 구현: 같은 날 1차 범위인 튜토리얼 안내, 연속 의뢰, 두 근거에 연결되는 마음의 별자리, NPC 기억 조회를 구현했다. 상세한 실제 범위와 검증·배포 상태는 [아카데미 구현 현황](academy.md#2026-09-13--튜토리얼-연속-의뢰-마음의-별자리)을 참고한다. 이하의 폭넓은 기능안과 실제 구현 범위는 구분한다.

## 1. 제안하는 경험

**리아가 책과 세상을 만나고, 직접 작은 일을 해 보고, NPC와 그 경험을 돌아보면서 자신에 대한 설명을 조금씩 고쳐 쓰는 게임**으로 만든다.

핵심 반복은 `발견 → 선택한 이유 이야기 → 작은 시도 → 경험 돌아보기 → 나에 대한 문장 확인 → 다음 만남에서 다시 살펴보기`다. 보상으로 남는 것은 인장·방의 장식·새 대화와 함께, 학생이 직접 확인한 자기 이해의 기록이다.

알아갈 대상은 여섯 가지다.

| 대상 | 학생이 답해 볼 질문 | 확인할 자료 |
| --- | --- | --- |
| 흥미 | 나는 무엇을 할 때 더 알아보고 싶은가? | 직접 고른 주제와 그 이유, 활동 후의 관심 |
| 가치관 | 여러 좋은 선택이 충돌하면 무엇을 중요하게 생각하는가? | 기사에 대한 판단, 조건에 따른 선택과 이유 |
| 강점 | 어떤 상황에서 어떤 행동이 실제 도움이 되었는가? | 본인 활동의 구체적인 행동과 결과, 도움받은 내용 |
| 학습 방법 | 막혔을 때 어떤 방법이 도움이 되었는가? | 예상·시도·수정·회고 |
| 원하는 미래 | 어떤 문제를 다루고 어떤 일상을 살고 싶은가? | 여러 가능성에 대한 기대, 망설임, 확인해 볼 행동 |
| 변화 | 예전 생각이 지금도 맞는가? 무엇을 더 알게 되었는가? | 날짜가 다른 본인의 발언과 현재 해석 |

흥미와 강점은 별도로 표현한다. 잘해도 흥미가 적을 수 있고, 좋아하지만 아직 어려울 수도 있다. 활동 수나 클릭 횟수는 능력이나 진로 적합도의 점수로 바꾸지 않는다. 기록이 적다는 사실은 탐색 기회가 적었다는 뜻일 수도 있다.

## 2. 연구 근거와 적용 범위

EEF는 메타인지와 자기조절학습에서 계획·점검·평가를 명시적으로 가르치고, 이를 실제 교과와 과제 안에 넣는 접근을 설명한다. 이 게임에는 탐구 전 예상, 실행 중 방법 수정, 실행 후 회고를 연결하는 원리로 적용한다. EEF의 교육 효과를 이 게임의 효과 수치로 옮겨 쓰지는 않는다. [EEF 지침, 2025년 2판](https://educationendowmentfoundation.org.uk/education-evidence/guidance-reports/metacognition)

자기결정성이론의 교육 적용은 자율성·유능감·관계성을 지원하는 상호작용을 강조한다. 학생이 주제와 다음 행동을 고르고, NPC가 구체적인 노력에 반응하며, 건너뛰거나 생각을 바꿀 수 있도록 설계하는 근거다. 특정 답변을 해야 NPC의 호감을 얻는 구조는 채택하지 않는다. [SDT 교육 적용](https://selfdeterminationtheory.org/topics/application-education/)

O*NET Interest Profiler는 활동과 직업에 대한 흥미를 탐색하는 도구이며 RIASEC 여섯 흥미 영역을 사용한다. 관심을 여러 방향으로 넓혀 보는 참고 틀로 유용하다. 다만 게임의 AI 대화를 임의로 점수화해 공식 검사 결과로 표시할 수는 없다. 공식 도구를 실제 도입한다면 별도로 이용 조건과 한국어·학생 대상 적용 근거를 확인해야 한다. 이번 제안에는 검사 문항을 복제하지 않는다. [O*NET 공식 설명](https://www.onetcenter.org/IP.html), [기술 매뉴얼 소개](https://www.onetcenter.org/reports/IP_Manual.html)

OECD는 진로 탐색, 실제 경험, 미래에 대한 생각을 진로 준비의 중요한 축으로 다룬다. 여러 가능성을 경험해 보는 의뢰를 제안하는 근거로 삼는다. AI 역할극은 실제 직업인과의 만남이나 현장 경험을 대신했다고 기록하지 않는다. 관련 종단 연구의 연관성을 이 제품의 인과적 효과로 주장하지 않는다. [OECD 진로 지도](https://www.oecd.org/en/topics/career-guidance.html), [2025 청소년 진로 준비 보고서](https://www.oecd.org/en/publications/the-state-of-global-teenage-career-preparation_d5f8e3f2-en.html)

이하의 장소·게임 규칙·우선순위는 위 근거를 현재 서비스에 적용한 제품 설계 판단이다. 해당 기관들이 이 기능 자체를 검증한 것은 아니다.

## 3. 기능 제안

### A. 마음의 별자리 — 나에 대한 발견을 모으기

- **장소:** 연구시설의 망원경 옆, 별빛 거울. 기존 지식 별자리와 연결된 별도 관측 모드다.
- **플레이:** 최근 활동이나 대화에서 단서 하나를 선택한다. 카시안과 대화한 뒤 학생이 자기 설명을 직접 쓰거나 AI 초안을 수정·확인한다. 확인한 문장이 작은 별로 켜진다.
- **예시:** “나는 환경 문제 전체보다, 직접 수치를 모아 원인을 비교하는 과정에 더 끌린다.”
- **별을 누르면:** 자기 설명, 근거가 된 내 기록과 날짜, 아직 확인하지 못한 점, 다음에 시도할 행동이 나온다.
- **AI 역할:** 같은 주제 안에서도 어떤 행동에 끌렸는지 구체화한다. 근거 하나로 학생 전체의 성격을 단정하지 않는다.
- **변화:** 새 경험 후 학생이 문장을 고치면 이전 별에서 현재 별로 빛이 이어진다. 이전 문장은 과거 시점의 생각으로 남는다.
- **중요한 구분:** 기존 지식 그래프는 학습 내용과 연결을 보여 준다. 마음의 별자리는 그 경험을 학생이 어떻게 해석했는지를 보여 준다. AI 추정을 확정된 KG 역량·성과로 자동 삽입하지 않는다.

### B. 가치의 저울 — 내가 중요하게 여기는 것 알아보기

- **장소:** 전서구 우편국, 노엘의 기사 책상.
- **플레이:** 실제 기사에서 이해관계가 다른 입장을 읽고, 근거 카드를 저울 양쪽에 놓는다. 카드를 끌기 어려운 학생은 버튼으로 놓을 수 있다.
- **예시:** 도시 녹지에 관한 기사를 읽었다면 “공간이 한정되어 있을 때 무엇을 먼저 확인하고 결정하고 싶어?”라고 묻는다. 기사에 없는 조건을 추가할 때는 가정 상황이라고 표시한다.
- **후속 대화:** 선택의 이유, 추가로 필요한 정보, 선택을 바꿀 조건을 한 번에 하나씩 묻는다. 제3의 방안이나 판단 보류도 가능하다.
- **자기 발견:** “나는 이 상황에서 편리함보다 사람들이 쉬어 갈 공간을 우선했다. 다만 이동이 어려운 사람들의 접근성도 확인하고 싶다.”
- **보상:** 학생이 확인한 문장이 담긴 편지 봉인. 어느 입장을 골랐는지는 보상 크기에 영향을 주지 않는다.

### C. 강점의 공방 — 내가 실제로 한 행동 찾기

- **장소:** 연구시설의 작업대, 카시안과의 활동 회고.
- **플레이:** 본인 활동 하나를 가져오면 상황·내 행동·결과가 기록 조각으로 펼쳐진다. 학생은 빠진 내용을 보완하고, 다른 사람의 행동과 자신의 행동을 구분한다.
- **질문 예시:** “측정 방법이 달라 결과를 비교하기 어려웠다고 적었구나. 그때 네가 직접 바꾼 것은 무엇이었니?”
- **자기 발견:** “나는 자료가 뒤섞였을 때 기준을 정리하는 방식으로 팀에 기여했다.” 강점 이름만 붙이는 대신 작동한 상황과 행동을 남긴다.
- **다음 의뢰:** 그 행동을 다른 작은 상황에서 다시 시도하고, 잘 맞는 조건과 어려운 조건을 비교한다.
- **교수 면담과의 관계:** 질문은 실제 내용에서 생성한다. 면접 연습을 선택한 경우에만 일반형 S1–S4 또는 경험형 STAR+F로 답변 구성을 평가한다. 자기 발견 대화의 모든 답변에 면접 점수를 매기지 않는다. 학생 대상 S4는 앞으로의 학업·탐구·진로 활용으로 표현한다.

### D. 나만의 탐구 실험 — 나에게 맞는 방법 알아보기

- **장소:** 연구대와 학생의 실제 생활.
- **플레이:** “나는 설명을 읽을 때보다 직접 비교해 볼 때 질문이 잘 떠오르는 것 같다”처럼 확인하고 싶은 가설을 만든다. 작고 실행 가능한 활동을 선택한다.
- **전후 비교:** 하기 전 예상 → 실제로 한 일 → 도움이 된 방법·어려웠던 점 → 다음 수정.
- **분기:** 재미있었다면 한 단계 확장하고, 맞지 않았다면 다른 방법이나 주제로 이동한다. 흥미가 없다는 발견도 정상적인 완료다.
- **기록 원칙:** 계획, 학생이 보고한 실행, 기존 활동 기록과의 연결을 구분한다. AI가 계획서를 만들었다는 이유로 실행 완료 처리하지 않는다.
- **게임 변화:** 시도 전에는 작업대에 도구가 놓이고, 학생이 결과를 기록하면 해당 도구 옆에 발견 메모가 꽂힌다.

### E. 미래에서 온 편지 — 여러 삶의 가능성 살펴보기

- **장소:** 우편국의 특별 우편함. 안내자 루온과 노엘이 이어 준다.
- **플레이:** 학생이 관심 있는 문제와 해 보고 싶은 일을 선택하면, 서로 다른 두세 가지 미래의 하루를 가상 편지로 펼친다. 직업 이름 외에 하는 일·협업·어려움·배우는 과정을 다룬다.
- **AI 역할:** 학생의 현재 관심을 참고한 상상 시나리오를 생성한다. 미래 예측이나 진로 적합 판정으로 표시하지 않는다. 사실적인 직업 정보는 별도 검증 자료가 있을 때만 근거와 함께 제공한다.
- **학생 행동:** 마음에 드는 장면, 망설여지는 장면을 고르고 그 이유를 말한다. 선택한 가능성을 알아볼 현실의 작은 탐색 행동으로 연결한다.
- **자기 발견:** “나는 연구 결과 자체만큼 다른 사람에게 이해하기 쉽게 설명하는 일을 경험해 보고 싶다.”

### F. 회상의 회랑 — 예전의 나와 지금의 나 만나기

- **장소:** 도서관의 개인 서가. 엘리안이 날짜가 다른 두 기록을 펼친다.
- **플레이:** 책갈피를 넘기면 당시의 학생 발언이 나타나고, 지금의 생각을 새 여백에 적는다. 다른 생각을 나란히 놓아 비교한다.
- **질문 예시:** “그때는 결과가 맞는지 알고 싶다고 썼는데, 이번에는 조건을 어떻게 비교할지 적었군요. 본인은 어떤 점이 달라졌다고 느끼나요?”
- **학생 선택:** 달라짐 / 그대로임 / 상황이 달랐음 / 아직 모르겠음. AI가 다른 문장을 발견했더라도 변화의 해석은 학생이 확인한다.
- **완료 결과:** 학생이 제목을 붙인 한 장의 회고. 해당 NPC가 다음 만남에서 이 기록을 근거로 후속 질문을 한다.
- **발생 시점:** 새로운 활동이나 충분히 다른 시점의 기록이 생겼을 때 제안한다. 매일 억지로 변화했다고 답하게 하지 않는다.

## 4. NPC가 기억하는 방식

학생 원문, 저장된 활동의 사실, AI 해석, 학생이 확인한 자기 설명을 구별한다. NPC는 기록의 근거와 시점을 말할 수 있어야 한다.

| NPC | 주로 이어 갈 이야기 | 다음 만남의 대사 예시 |
| --- | --- | --- |
| 루온 | 시작하기 어려웠던 점, 직접 선택한 다음 행동 | “지난번엔 주제를 고르기 어렵다고 했지. 오늘은 어느 이야기부터 살펴볼까?” |
| 엘리안 | 책에서 붙잡은 질문, 자기 설명의 과거·현재 | “그 책을 읽고 남긴 질문이 여기 있어요. 지금도 같은 점이 궁금한가요?” |
| 카시안 | 선택 이유, 탐구 방법, 실제 활동과 회고 | “이번 회고에는 비교 기준을 정리했다고 썼구나. 그 방법은 어떤 때 도움이 됐니?” |
| 노엘 | 기사에 대한 관점, 판단 기준, 미래에 대한 바람 | “그 기사에서는 접근성을 먼저 살펴보고 싶다고 했지. 이번 소식에서도 그 점이 궁금해?” |

예시 대사는 해당 내용이 실제 저장되어 있을 때만 사용한다. ‘지난번’은 해당 NPC의 실제 대화 이력이 있을 때만 쓴다. 다른 장소에서 남긴 기록은 ‘네 수첩에서 보았어’처럼 출처를 밝힌다. NPC가 다정하게 반응하는 조건을 사적인 고백이나 특정 가치관에 동의하는 것으로 만들지 않는다.

학생은 ‘기억한 내용 보기’에서 근거를 펼치고, 해석을 수정하거나 더 이상 대화에 사용하지 않도록 할 수 있다. ‘기억에서 제외’와 원문 삭제는 서로 다른 동작으로 설명하고, 파생 요약·검색에서도 제외가 적용되도록 설계한다.

### 질문 생성 흐름

1. 학생이 대화·기억·의뢰를 선택한다.
2. 서버가 본인 권한으로 원문과 학생이 확인한 기억을 조회한다.
3. NPC의 짧은 기다림 대사가 나오고, 동시에 질문을 생성한다. 기다림 대사에 확인되지 않은 경험을 넣지 않는다.
4. 현재 맥락에 필요한 질문 하나를 표시한다. 흥미·가치관·강점은 내부 탐색 목적이며 학생에게 질문 유형을 먼저 선택시키지 않는다.
5. 대화 후 자기 발견 문장이 필요하면 초안을 제안한다. 학생이 수정·확인해야 자기 설명으로 채택한다.
6. 다음에 확인해 볼 작은 행동을 학생이 선택한다.

일일 질문은 기존 ‘하루 한 번, 선택할 때 생성’ 규칙을 유지한다. 튜토리얼 재생이나 기억 조회가 일일 질문을 추가로 생성하지 않게 한다. 기존 질문이 있다면 해당 대화를 이어 간다. AI 실패 시 작성한 답변을 보존하고 재시도 또는 나중에 이어 하기를 제공한다.

## 5. 튜토리얼 퀘스트: 리아의 첫 하루

처음부터 긴 설명서를 펼치지 않는다. 실제 장면에서 행동 하나를 해 보고, NPC의 짧은 반응을 받은 다음 행동으로 넘어간다. 첫 진입은 루온과 선택적으로 시작하며, 건너뛴 뒤 수첩에서 재개할 수 있다. 예상 분량은 기본 안내 3–5분, 확장 안내를 포함하면 8–12분으로 잡고 사용성 테스트로 조정한다.

| 장 | NPC·장소 | 배우는 실제 행동 | 완료 근거 | 연출·결과 |
| --- | --- | --- | --- | --- |
| 1. 낯선 아카데미 | 루온·광장 | 말 걸기, 선택지 고르기, 도서관으로 이동 | 목적지 장면에 도착 | 루온이 문을 가리키고 이동 경로가 잠깐 빛남 |
| 2. 잠든 책의 첫 장 | 엘리안·도서관 | 책 꺼내기 → 목차 선택 → 활동 읽기 | 실제 자료의 마지막 장까지 열람 | 책 표지·페이지 넘김, 해당 책에 책갈피 |
| 3. 나의 첫 물음 | 엘리안·도서관 | 궁금한 점과 이유를 직접 남기기 | 기존 첫 발견 퀘스트의 질문 저장 성공 | 수첩에 글씨가 나타나고 첫 발견 인장 수령 |
| 4. 세상이 보낸 편지 | 노엘·우편국 | 실제 기사 펼치기, 내 생각을 관측 일지에 남기기 | 본인의 기사 관측 일지 저장 성공 | 전서구 도착·봉인 해제·기록 보관 |
| 5. 나의 하늘 | 카시안·연구시설 | 망원경 열기, 별의 근거 확인, 연구대에 질문 가져오기 | 본인 별의 근거를 열람하고 질문 전달 확인 | 초점이 맞고 별에서 근거 기록이 펼쳐짐 |
| 6. 첫 번째 나의 문장 | 카시안 또는 루온 | 앞서 고른 내용에서 내가 끌린 점을 직접 확인 | 학생이 확인한 자기 발견 문장 저장 성공 | 마음의 별자리의 첫 별과 다음 의뢰가 열림 |

4장에서는 노엘과 AI로 기사 이야기를 나눌 수 있다. 대화는 선택 사항이며 AI의 응답 성공 자체를 튜토리얼 통과 조건으로 삼지 않는다. 5장도 긴 AI 분석·탐구 확정·실제 활동 제출까지 요구하지 않는다. 그 과정은 이후 연속 퀘스트가 맡는다.

### 기록이 없거나 진행을 건너뛴 학생

- **기존 KG 없음:** ‘아직 기록된 별이 없어요’ 장면에서 내 첫 질문을 연구대에 놓는다. 설명용 별을 사용한다면 연습용임을 명시하고 본인의 활동으로 저장하지 않는다.
- **개인 활동 없음:** 흥미와 질문에서 시작한다. 강점의 공방과 실행 회고는 나중에 실제 경험을 선택할 때 열 수 있다.
- **열람할 책·기사 없음:** 자료 불러오기 재시도와 해당 안내를 나중에 하기를 제공한다. 동작 안내는 명확한 연습 자료로 가능하지만 실제 독서·기사 기록의 완료로 위장하지 않는다.
- **이미 첫 발견을 마침:** 기존 진행을 인식하고 이동·읽기를 반복시키지 않는다. 이후 안내만 제안한다.
- **오늘의 질문을 이미 받음:** 새 질문 생성 없이 기존 대화로 안내한다.
- **건너뜀·중단:** 안내 상태는 완료와 구분한다. 기본 장소·도구를 잠그지 않으며, 다음 방문에는 마지막 저장 지점에서 이어 간다.
- **모션·입력 접근성:** 동작 줄이기, 대사 즉시 표시, 키보드·터치 조작, 끌기 대신 버튼 선택을 제공한다.

### 안내 진행과 실제 성취는 별도로 기록

‘망원경 사용법을 배움’과 ‘학생의 탐구 활동을 수행함’은 다른 사건이다. 튜토리얼 안내 상태는 단계를 보았는지·건너뛰었는지·직접 해 보았는지를 저장하고, 실제 기록이 필요한 단계는 원래 서비스의 저장 성공을 확인한다. DOM 클릭만으로 실제 기록 저장·퀘스트 보상을 처리하지 않는다. 재생은 가능하지만 인장과 첫 발견 기록을 중복 생성하지 않는다.

## 6. 연속 퀘스트와 연결하는 예시

다음은 실제 학생 기록이 아닌 설명용 시나리오다. 시간표나 연속 접속을 강제하지 않고 학생의 진행에 따라 이어진다.

1. **튜토리얼:** 리아가 도서관에서 측정 활동을 읽고 “조건을 바꾸어 비교해 보고 싶다”는 질문을 남긴다.
2. **흥미 발견:** 카시안이 기록의 어떤 부분에 끌렸는지 묻는다. 리아는 “설명만 읽기보다 직접 비교하는 과정이 궁금하다”는 문장을 확인한다.
3. **연속 의뢰:** 그 질문을 실제 탐구로 설계하고, 실행 후 자신의 활동을 연결한다.
4. **강점·방법 발견:** 예상과 결과가 달랐던 순간에 어떻게 대응했는지 함께 돌아본다. 학생은 “비교 조건을 정리하니 이해하기 쉬워졌다”는 근거를 남긴다.
5. **NPC의 기억:** 다음 방문에서 카시안이 해당 회고를 펼치며 같은 방법을 다시 써 보고 싶은지 묻는다.
6. **생각의 변화:** 엘리안과 처음 질문·현재 회고를 나란히 읽는다. 리아는 달라진 점이나 아직 같은 점을 자신의 말로 정리한다.
7. **다음 분기:** 비교하는 일을 더 해 보기, 설명하는 역할을 해 보기, 다른 주제 살펴보기 중 학생이 선택한다.

진행 중인 연속 의뢰의 회고에는 ‘무엇을 발견했는가’와 ‘이번 경험으로 나에 대해 알게 된 것은 무엇인가’를 자연스럽게 연결한다. 모든 경험에서 새로운 자기 설명을 만들도록 강제하지는 않는다.

## 7. 현재 코드와 연결할 지점

현재 확인한 구현은 다음과 같다. DB 전체 감사나 새 기능의 동작 검증을 수행한 것은 아니다.

| 코드·기록 | 현재 확인한 역할 | 확장 방향 |
| --- | --- | --- |
| `src/features/academy/game/AcademyGame.tsx` | 장소 이동, NPC, 첫 발견 퀘스트, 시설 패널 | 튜토리얼 안내 흐름, 실제 사건에 따른 후속 의뢰 |
| `GameBook.tsx`, `progress.ts` | 책과 첫 발견 단계 | 기존 완료 기록을 활용해 첫 안내 반복 방지 |
| `GameObservatory.tsx` | 본인 KG, 탐구 선택 이유·실행 활동 연결·회고 | 마음의 별자리, 강점 회고, 작은 실험 |
| `GamePost.tsx` | 기사 열람, 본인 질문·예측·계획·회고 저장 | 가치의 저울, 미래 편지 |
| `DailyEncounter.tsx`, `dailyService.ts` | 날짜별 일일 NPC 대화 저장·조회 | 과거 학생 발언에 대한 후속 질문과 회상 |
| `NpcChat.tsx` | 현재 창의 자유 대화, 최근 대화 전달 | 현재는 창을 닫으면 자유 대화가 사라짐. 지속 기억을 약속하려면 저장·조회·제외 흐름 추가 필요 |
| `supabase/functions/_shared/academyJourney.ts`, `supabase/migrations/20260913063958_academy_journey_discovery_tutorial.sql` | 연속 의뢰 계약과 확정된 스키마 | 최초 연구 시점의 초안을 후속 구현에서 검증·연결함. 현재 상태는 아카데미 구현 현황 참고 |

기존 활동·기사·탐구 원문은 동일한 DB의 원래 기록을 사용한다. 게임용으로 학생의 수행 이력을 복제하거나 교사의 제안을 본인 확정 활동으로 바꾸지 않는다. 아카이브의 선배 활동은 참고 자료이지 리아가 수행한 활동이 아니다.

추가 저장이 필요한 것은 튜토리얼 안내 상태, 본인이 확인한 자기 발견 문장과 버전, 그 문장의 근거 참조, NPC 대화 세션·기억 사용 설정이다. 이것은 설계 항목이며 이번 문서 작성에서 테이블을 만들지는 않았다.

자기 발견 항목에는 최소한 본인 소유자, 학생 확인 문장, 주제 영역, 시점, 이전 버전, 확인 여부, 근거 기록의 ID·작성자·종류, 다음 실험을 연결한다. AI 초안은 확정된 자기 설명과 구별한다. 원문이 삭제되거나 접근할 수 없게 되면 후속 대화가 옛 원문을 계속 사실 근거로 사용하지 않게 한다.

개인 성찰과 대화는 본인 열람을 기본으로 설계한다. 기존 교사 조회 화면에 자동 노출하지 않고, 공유가 필요한 경우 학생이 선택한 기록을 별도 흐름으로 다룬다. 다른 학생 시점의 미리보기에서는 AI 생성·기억 저장·퀘스트 변경을 허용하지 않는다.

## 8. 구현 우선순위와 검증

**1차:** 튜토리얼 확장 + 연속 퀘스트 회고 + 마음의 별자리 한 문장 + NPC의 근거 있는 재방문 대사. 학생이 처음 들어와 무엇을 할지 알고, 한 경험을 끝내고, 다음 방문에서 그 경험을 되짚을 수 있는 한 줄의 플레이를 완성한다.

**2차:** 회상의 회랑 + 가치의 저울 + 강점의 공방. 기존에 쌓인 대화·기사·활동을 사용하므로 학생마다 다른 내용을 제공하기 좋다.

**3차:** 미래 편지와 여러 탐색 경로. 기존 관심에 갇히지 않도록 다른 주제·역할도 학생이 선택할 수 있게 한다.

1차는 현재의 리아·남성 NPC 투명 PNG와 세 시설 배경을 재사용할 수 있다. 별빛 거울, 책갈피, 저울, 봉인, 회고 카드에는 SVG/CSS/게임 오브젝트와 간단한 애니메이션을 사용한다. 신규 대형 일러스트 없이 핵심 상호작용을 먼저 검증한다. 새 이미지가 필요해지면 실제 알파 채널, 모바일 대비, 캐릭터 일관성을 확인한다.

확인할 제품 동작:

- 새 학생이 안내를 건너뛰고 재접속해도 정확한 안내 상태에서 다시 시작할 수 있는가?
- 저장 실패·AI 실패·자료 없음 상황에서도 학생의 입력을 잃지 않는가?
- 기존 첫 발견 완료자와 일일 대화 참여자가 중복 생성·보상을 받지 않는가?
- NPC가 인용한 원문·학생·시점이 실제와 일치하는가? 다른 NPC에게 말한 것을 자신의 만남으로 바꾸지 않는가?
- 학생이 AI 해석에 동의하지 않거나 기억 사용을 중단했을 때 이후 대화에 반영되는가?
- 확정되지 않은 탐구·선배 활동·연습용 자료가 본인 성과로 처리되지 않는가?
- 역할과 계정이 바뀌면 개인 대화·자기 발견 캐시도 분리되는가?

교육적 가치는 접속 시간이나 긍정 답변 비율만으로 판단하지 않는다. 탐색 전후에 학생이 자신에 대해 말할 때 구체적인 근거를 드는지, 상황에 따른 차이를 설명하는지, 다음에 확인할 행동을 스스로 고르는지를 소규모 사용성 검토에서 살펴본다. 변화하지 않았다는 답도 허용한다. 이 지표들은 제품 개선용이며 성적·성격·입시 적합도 점수가 아니다.
