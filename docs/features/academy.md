## 게임과 학생 시점

네 장소 모두 Phaser 장면에서 걷기·시설 이동·인물 대화를 제공한다. React/Radix로 책과 편지, 연구대, 대화창을 장면 위에 펼친다. 타이핑 대사, 책 펼치기·넘김, 망원경 진입, 전서구 도착, 장소 전환, 빛 입자와 선택형 효과음을 적용했다. OS 및 게임의 동작 줄이기를 지원한다. 캐릭터 이동은 단일 원화의 트윈이며 방향별 걷기 시트/리깅은 아니다.

학생 ID는 본인 인증 이메일의 학생 코드로 결정한다. 교사 계정에는 학생 명단이나 작성 기능을 제공하지 않는다. 관리자가 기존 기능에서 명시적으로 선택한 학생 시점은 읽기 전용이다. 서버의 AI 3종도 학생 역할을 확인한다. 실제 데이터 접근은 기존 RLS/RPC를 유지한다.

| 장소 | 게임 안에서 하는 일 | 공유 데이터 |
| --- | --- | --- |
| 중앙 광장 | 루온과 의뢰 대화, 지도, 오늘의 NPC 만나기 | 인증, 개인 게임 진행 |
| 왕립 도서관 | 분야 책 꺼내기 → 표지 → 목차 → 목적·과정·결과, 새 이야기 제안 | activity, activity_proposal |
| 별의 연구시설 | 망원경으로 실제 지식 별·관계/버전 관측, 연구대의 탐구 설계, 전체 별자리 조언, 교수 면담, 연구 수첩 | student_kg_*, 기존 탐구 설계·종합 분석 서비스 |
| 전서구 우편국 | 편지 검색/분류, 봉인 열기, 기사/만화 읽기, 노엘과 기사 AI 대화, 개인 관측 일지 | ai_news, world_news_inquiries |

도서관의 목차 선택은 기존 단건 조회로 전문을 읽는다. 원래 활동 화면으로 나가는 링크는 없다. 새 이야기 제안은 기존 검토 흐름으로 저장한다. 첫 의뢰는 루온에게 수락 → 활동 세 장 읽기 → 질문과 이유 20자 이상 기록 → 엘리안에게 인장 받기다. 인장은 학업 점수나 랭킹과 무관하다.

연구대는 본인 수업·활동과 선택한 KG 노드로 기존 AI 탐구 서비스를 호출한다. 학생의 선택 이유와 함께 **status=saved**로 확정한다. 선생님 제안은 자신의 수락 이유로 받아들이며, 수첩에서 성찰과 실제 활동 연결을 기록한다. 별자리 전체 조언의 방향·연결 과목을 선택한 뒤 제안을 연구대에서 이어 만든다.

## 오늘의 만남

- 한국 시간 자정 기준으로 계정마다 남성 NPC 한 명이 정해진다. 동일 계정/날짜는 같은 NPC다.
- 게임 입장, 일일 상태 조회, 대화 수첩 열기는 **읽기만** 수행한다. NPC에게 오늘의 이야기를 듣겠다고 선택한 순간 AI가 질문을 생성한다. 미리 준비한 질문 은행·정기 생성 작업은 없다.
- AI는 학생 본인의 최신 KG에서 관심사·탐구·활동 자료를 읽는다. 탐구/진로 관련 질문 또는 일상 상식의 관찰·추론 질문 하나를 만든다. 자료가 없으면 경험을 지어내지 않고 누구나 생각해 볼 질문을 한다.
- 준비 중에는 NPC별 대사가 먼저 표시되고 저장된다. 질문, 학생 답변, 기다리는 대사, AI 후속 반응을 DB에 보관한다. 답변은 AI 호출 **전에** 기록하여 생성 실패/창 닫기에도 잃지 않는다.
- 질문 이후에는 같은 주제에서 생각을 넓히는 대화를 이어간다. 학생 답변은 1~2,000자. 날짜별 수첩에서 최근 60일의 저장된 대화를 열람한다. 그 이전 기록도 DB에서 삭제하지 않는다.
- `academy_daily_conversations`의 (user_id, day) 기본키, 행 잠금, revision, 75초 작업 임대로 중복 창/동시 요청을 직렬화한다. AI 호출 자체는 45초 제한이다. 실패하거나 임대가 만료되면 저장된 요청을 재시도한다. 늦은 이전 작업은 새 작업 결과를 덮어쓰지 못한다.
- 한 날짜에 **저장되는 첫 질문은 하나**다. 생성 실패/임대 만료 후 재시도는 AI를 다시 호출할 수 있으나 이미 저장된 질문을 다시 뽑지 않는다. 네트워크 외부 작업의 정확히 1회 실행을 주장하지 않는다.
- 클라이언트는 본인 행 SELECT만 가능하다. INSERT/UPDATE/DELETE와 작업 RPC는 허용하지 않는다. JWT 검증 Edge Function이 확인한 사용자 ID로만 서버 쓰기 클라이언트를 사용한다. 학생 기록 조회에는 호출자 JWT 클라이언트를 별도로 사용한다.
- 일일 대화는 연습/성찰 대화이며 학교 평가·입시 점수·보상 판정을 수행하지 않는다.

## 기사 AI 대화

편지를 읽고 **노엘과 이 기사에 대해 이야기하기**를 누르면 선택 기사 ID가 전달된다. 서버가 현재 공개된 기사를 다시 읽고 본인 관측 일지를 함께 제공한다. 모델의 출처 ID나 URL을 신뢰하지 않으며 서버가 읽은 기사 제목/ID로 게임 내 참고 버튼을 만든다. 기사 사실과 해석/학생 의견을 구분하고, 제공하지 않은 원문·통계·최신 사실을 지어내지 않도록 지시한다.

학생의 마지막 생각을 관측 일지로 가져와 수정·저장할 수 있다. 작성 중인 다른 일지 필드는 AI 대화를 여닫아도 유지한다. 일지의 질문을 들고 연구시설로 이동하면 게임의 연구대에 전달한다. 원문 링크는 실제 기사 출처 확인 용도로만 새 탭에서 열린다.

일반 NPC 자유 대화는 최근 4회 대화를 맥락으로 사용하며 창을 닫으면 대화 자체는 사라진다. **DB에 자동 보관하는 것은 오늘의 만남 대화**다. 기사 관측 일지는 학생이 보관 버튼으로 저장한다.

## 교수 면담

1. Interest/Thread/Activity를 선택하고 직접 연결된 실제 활동을 최대 12개 고른다.
2. 교수는 **선택한 내용에서 자연스러운 질문을 생성**한다. 일반형/경험형 선택 UI 또는 사전 질문 유형은 없다.
3. 학생은 20~6,000자로 답하고 조언을 받는다. 평가 시 질문·답변 내용에서 적용 구조를 판단한다.
4. 일반적인 개념·동기·판단은 S1 결론, S2 이유, S3 실제 근거/사례, S4 전공·진로 연결을 평가한다. 경험·행동·문제 해결 내용이면 STAR+F도 함께 적용한다.
5. 4문장은 의미 구조이며 문장 개수로 감점하지 않는다. S4는 대학 학습/진로 연결로 해석한다. Feeling은 생각·해석·성찰을 포함한다.
6. 항목별 근거, 보완 조언, 내용에 따른 후속 질문을 제공한다. 실제 입시 점수/합격 확률이 아니다.

서버에서 학생/버전/노드/관계를 다시 검증하고 무관한 활동을 차단한다. 클라이언트의 경험 설명은 신뢰하지 않는다. 면담 답변/평가는 현재 면담 화면의 메모리에서만 유지되며 면담을 떠나면 초기화한다. 오늘의 만남 저장 정책과 구분한다.

## 동작 줄이기(별 버튼)의 기본값 (2026-09-14)

HUD 오른쪽 위 별(Sparkles) 버튼은 **애니메이션을 줄이는** 스위치이고 눌린 상태(`aria-pressed`)가 "줄임"이다. **기본은 애니메이션 켬**(사용자 결정). 종전엔 초기값을 OS `prefers-reduced-motion` 에서 읽어 그 설정이 켜진 기기(Windows "애니메이션 효과" 끔 등)에서는 처음부터 눌린 채였고, 게다가 academy CSS 다섯 파일에 같은 미디어 쿼리가 따로 있어 **버튼을 꺼도 애니메이션이 살아나지 않았다**(버튼이 거짓말을 했다). 지금은 ①초기값 = 저장된 선택(`academy-reduced-motion:v1`, `safeLocalStorage`) 없으면 켬 ②`data-reduced` 속성이 **유일한** 스위치(미디어 쿼리 블록은 전부 `[data-reduced=true]` 선택자로 바꾸거나, 이미 같은 규칙이 있으면 삭제) ③OS 설정 변경 리스너 제거. OS 접근성 설정을 자동으로 따르지 않게 된 것은 의도이며, 동작에 민감한 학생은 버튼 한 번으로 끄고 그 선택이 기억된다.

## 2026-09-13 · 튜토리얼, 연속 의뢰, 마음의 별자리

게임 수첩에 ‘리아의 첫 하루’를 추가했다. 루온의 의뢰 수락, 책 읽기, 질문 기록과 첫 인장, 기사 관측 일지, 망원경 안내, 자기 발견 문장으로 이어진다. 기존 기록으로 완료한 장은 인식하며 안내 일시 중단·재개를 DB에 보관한다. 망원경 안내는 도구를 살펴본 뒤 학생이 확인하는 사용 안내이며 실제 활동 수행을 뜻하지 않는다. 기존 별자리가 없는 학생도 안내를 확인하고 질문에서 시작할 수 있다. 안내가 기본 시설을 잠그지 않으며, AI 생성 성공을 통과 조건으로 사용하지 않는다.

‘질문이 별이 되는 여정’은 첫 발견의 질문 → 본인 이유로 확정한 탐구 선택 → 실제 본인 활동 연결 확인 → 회고의 네 단계다. 장소 이동 버튼은 게임 안 연구대·연구 수첩을 열며 질문을 전달한다. 서버는 현재 학생 소유자·탐구 상태·활동 연결을 검증한다. 마지막 회고는 기존 탐구의 reflection에도 저장되므로 기존 성찰을 펼쳐 보고 가져와 이어 쓸 수 있다. 완료하면 관측실에 회고의 별이 표시되고 인장 수가 늘어난다. 재방문·중복 요청은 추가 보상을 만들지 않는다.

‘마음의 별자리’의 첫 구현은 첫 질문과 완료한 의뢰 회고에 각각 연결되는 두 별이다. 학생은 근거를 읽고 10~1,000자 자기 설명을 작성한 뒤 확인 체크를 해야 별을 밝힐 수 있다. 서버가 원문을 직접 조회하고 클라이언트가 보낸 출처 본문을 신뢰하지 않는다. 수정 시 바로 이전 문장과 현재 문장을 함께 보관한다. 같은 버전의 동시 수정은 덮어쓰지 않고 재조회하도록 안내한다. NPC 기억 사용을 끄고 다시 켤 수 있으며, 이 설정은 자기 설명의 후속 조회에 적용된다. 기존 일일 대화의 원문은 삭제되지 않는다.

교수의 재방문 대사와 AI 자유 대화는 학생이 확인하고 기억 사용을 허용한 문장을 참고한다. NPC AI와 일일 질문 생성은 같은 NPC의 최근 두 일일 대화에서 학생이 한 말을 추가로 조회한다. 일일 질문 생성에는 오늘 이전의 기록만 포함한다. AI 답변을 학생 사실로 요약하지 않으며, 수첩에서 읽은 내용과 직접 나눈 대화를 구분하도록 지시했다. AI 자유 대화 화면에는 실제 서버가 참고한 기억을 펼칠 수 있다. 자유 대화 자체는 여전히 창을 닫으면 사라지고, 일일 대화 및 확인한 자기 설명이 장기 기록이다.

추가 테이블 세 개는 owner SELECT RLS이며 클라이언트 직접 쓰기 권한이 없다. 서버 전용 invoker 함수 세 개는 검증한 인증 사용자 ID로만 호출한다. `20260913063958_academy_journey_discovery_tutorial.sql`을 연결 DB에 적용했고 `academy-journey` v1, `academy-npc` v3, `academy-daily` v2를 JWT 검증 활성 상태로 배포했다. 세 엔드포인트의 익명 요청은 401이며 신규 객체 관련 Security Advisor 지적은 없었다. 다른 기능의 공유 Edge Function 변경은 배포하지 않았다.

검증: 단위·서비스 테스트 18개, `supabase/tests/academy_growth.sql`의 실제 DB 롤백 검사, 아카데미 범위 ESLint·서비스 TypeScript 검사 통과. 전체 앱 TypeScript에는 기존 다른 기능 오류가 남아 있으나 이번 검사에서 아카데미 오류는 없었다. 프로덕션 빌드 통과; 기존 큰 청크 경고 유지. 브라우저 검사는 서비스·AI 경계를 fixture로 대체하고 실제 React/Phaser UI를 사용한다. 상세 시나리오는 `scripts/academy-test/growth-browser-checks.mjs`에 있다. 프런트엔드 호스팅 배포는 별도이며 현재 로컬 구현과 빌드 상태다.

후속 기능인 가치의 저울, 강점의 공방, 미래 편지와 다중 자기 발견 기록은 [자기 발견 연구안](academy-self-discovery-research.md)의 다음 단계다. 이번 구현이 연구안 전체를 구현한 것은 아니다.

최종 브라우저 검증 통과: 튜토리얼 중단·재개, 망원경 안내 확인, 자기 설명 확인 체크·저장 실패 시 입력 보존·수정 전후·기억 제외·재방문 복원, 질문의 연구대 전달, 활동 미연결 거절, 연구 수첩에서 실제 활동 연결 후 회고 완료 및 회고의 별 복원. 390px에서 가로 넘침이 없으며 신규 버튼에 잘못 적용되던 모바일 grid 위치를 수정했다. 기존 첫 발견 게임 시나리오와 시설·일일 대화·기사·면담 회귀 검사도 통과했다. UI와 AI 경계는 fixture이고 DB 전이는 별도 실 DB 롤백 검사라는 검증 범위를 유지한다.

개발 서버의 HMR 포트가 8080으로 고정되어 있어 다른 포트의 검증 서버가 기존 서버의 새로고침 신호를 받을 수 있다. 다른 포트에서 브라우저 검증할 때는 해당 검증 서버의 HMR을 끄고 실행한다. 최종 검증은 HMR을 끈 독립 Vite 서버에서 수행했다.

## 2026-09-13 · 게임 장면 중심 UI

게임은 브라우저 높이를 채우는 하나의 장면이다. 위치·설정·인장 HUD, 장소 상호작용, ‘여정과 소지품’ 메뉴를 장면 안에 배치하고 바깥쪽 중복 버튼 줄과 푸터를 제거했다. 책·편지·여정·대화의 포털도 게임 장면 내부로 연결한다. 소지품에서 기능을 열거나 이동하면 메뉴를 닫는다. 도서관 제안은 엘리안 앞에서 제안서를 작성하는 전용 화면이며 기존 활동 제안 훅과 학생 식별자를 사용한다.

대화에는 장면 높이 대부분을 사용하는 투명 NPC 원화와 대사/선택지 영역을 표시한다. 자유 AI 대화, 일일 만남, 교수 조언·면담도 같은 구성을 사용한다. 대화 중에는 탐험용 작은 캐릭터와 장소 버튼을 숨긴다. 탐험 원화의 높이·발 위치는 방별 가구 원근에 맞춰 따로 조정하며 이동 시 깊이에 따라 리아의 크기가 달라진다. 모바일 대화에서는 인물 위쪽과 아래쪽 대사창을 배치하고 긴 대화는 창 안에서 스크롤한다.

연구시설의 공통 기능 탭 모달을 제거했다. 망원경은 게임 전체를 별자리 관측 장면으로 바꾸며, 기존 `InquiryGraphCanvas`를 직접 사용한다. 기존 Cytoscape 배치, 관계, 검색, 확대/축소, 필터, 노드 간격, KG 버전, 범례를 유지하고 별자리 테마를 적용한다. 새 탐구나 면담 시작 버튼은 이 화면에 없다. 별의 근거 기록은 관측 장면에서 펼친다.

연구대는 같은 KG 지도를 책상 위에 두고 그 위에 탐구 설계지를 겹친다. 종이를 접어 지도를 조작하고 다시 펼쳐 질문·선택 이유를 기록한다. 선택한 실제 노드와 학생 본인의 수업·활동으로 기존 탐구 서비스를 호출한다. 별자리 조언과 교수 면담은 카시안과 대화할 때 선택하며, 연구 수첩은 연구시설의 독립 상호작용 버튼으로 연다. 학생 소유권, 기존 저장 상태와 DB 구조는 유지한다.

검증 시나리오는 `scripts/academy-test/scene-browser-checks.mjs`에 있다. 실제 React/Phaser/Cytoscape 화면에서 포털 위치, 중복 버튼 제거, 큰 초상화, 관측 화면의 전체 폭, KG 조작, 지도·설계지 접기, 학생 탐구 확정 저장, 교수 조언·면담, 기사 AI와 일지 내용 유지, 제안서 저장, 일일 질문 선택 시 생성·기다림·대화 재열람, 튜토리얼 및 390px 모바일 배치를 검사한다. 데이터·AI 경계는 fixture로 대체하며 실 AI 품질 검증을 의미하지 않는다. 이번 UI 변경에는 DB/Edge 배포가 없고 프런트엔드는 로컬 구현이다.

이번 변경의 검증 결과: 위 브라우저 시나리오, 단위·서비스 테스트 18개, 아카데미 범위 ESLint, `npm run build` 통과. 전체 앱 TypeScript 검사는 다른 기능의 기존 오류 230개로 실패하며 아카데미 파일의 오류는 없었다. 빌드의 큰 청크 경고는 남아 있다. 개발 서버를 최신 코드로 다시 실행하고 `/academy` 응답을 확인했다.

도서관에서 펼친 책은 높이를 화면 안에 고정하고 목차 목록과 본문을 독립적으로 스크롤한다. 두 영역의 스크롤바는 숨기며 휠·터치·키보드 스크롤은 유지한다. 책 제목과 책장 복귀 버튼은 목차 위에 유지하고, 다른 활동이나 장을 선택하면 본문 위치만 초기화한다. 긴 목차·본문 fixture로 데스크톱과 390px 모바일에서 독립 휠 스크롤, 숨김 스타일, 본문 위치 초기화 및 책 전체의 스크롤 방지를 확인했다.

## 2026-09-13 · NPC와 함께하는 전환, 연구대, 관리자 미리보기

망원경을 선택하면 리아가 관측하고 카시안이 옆에서 조절을 도와주는 동작 일러스트를 표시한 뒤 기존 KG를 연다. 책 표지를 선택하면 리아가 직접 책을 펼치고 엘리안이 안내하는 일러스트 다음에 목차/본문을 연다. 이미지 로드 후 일반 모드 3.6초, 동작 줄이기 1.4초 뒤 전환하며 즉시 건너뛰거나 Escape로 취소할 수 있다. 이미지 오류나 지연은 인물 원화와 안내로 대체하며 진행을 막지 않는다. 관련 장소에서 이미지를 미리 요청한다.

연구시설의 바닥에는 ‘연구대 보기’ 하나만 표시한다. 이를 선택하면 별자리 지도 위의 실제 종이와 수첩 그림이 있는 책상 근접 장면이 열린다. 왼쪽 종이는 새 별 찾기, 오른쪽 수첩은 기존 탐구 기록으로 연결된다. 해당 화면에서 뒤로 가면 연구대로, 연구대에서 돌아가면 시설로 이동한다. 그림을 완전히 불러온 뒤 오브젝트를 활성화한다. 기존 퀘스트나 기사에서 탐구 질문을 전달하는 직접 진입 흐름은 유지한다.

탐험 장면의 리아는 남성 NPC보다 작게 표시한다. 방별 리아/NPC 높이 비율은 약 78~79%이고 원근에 따른 이동 크기 조절을 유지한다. 네 NPC의 대화 버튼은 얼굴 위에서 발치 아래로 이동했다.

관리자는 게임 안 ‘여정과 소지품 → 관리자 · 학생 시점 미리보기’에서 이름/학번으로 학생을 검색·선택할 수 있다. 기존 AuthProvider의 `viewAsStudentId`와 학생 미리보기 상태를 사용하므로 다른 화면에서 선택한 학생도 이어진다. 검색은 기존 인증 클라이언트로 `student_basic_info`를 읽고 RLS를 유지한다. 학생·교사에게 이 컨트롤이나 명단을 표시하지 않는다. 선택한 학생의 KG·연구 수첩은 읽기 전용이며, 실제 역할은 관리자 그대로라 AI 요청·학생 기록 쓰기는 차단된다. 미리보기 변경/해제도 게임 안에서 가능하다. 학생은 미리보기 ID가 있더라도 본인 이메일의 학생 코드만 사용한다.

에셋과 전체 생성 프롬프트는 [게임 에셋 문서](academy-game-assets.md)에 있다. 이번 변경에는 DB 스키마나 Edge Function 배포가 없다. 새 브라우저 검증은 실제 React/Phaser/Cytoscape와 생성 PNG를 사용하며, 학생 조회·저장·AI 경계만 fixture로 대체한다. 관리자 학생 선택과 해당 KG 조회, 저장/AI 비활성화와 미리보기 해제, 보조 NPC가 있는 두 전환 화면, 연구대 오브젝트 선택 및 모바일 배치를 검사한다.

최종 검증: 위 브라우저 시나리오와 기존 책 독립 스크롤 검사 통과. 단위·서비스 테스트 19개 및 아카데미 ESLint 통과. 전체 앱 타입 검사에는 기존 다른 기능 오류 230개가 남고 아카데미 오류는 없다. 프로덕션 빌드 통과; 프런트엔드는 로컬 구현 상태이며 호스팅 배포는 하지 않았다.

## 교수와 대화로 새 별 찾기 · 나가기 확인

연구대의 새 별 찾기 설계지에서 **교수와 대화하며 설계하기**를 선택하면 게임 안에서 카시안의 큰 초상과 대화 화면이 열린다. 기존 `requestInquiryConversation`을 재사용하며 학생 본인의 수업·선택한 KG 자료·직접 쓴 질문을 첫 대화에 전달한다. 교수 답변 2회부터 설계도를 만들 수 있고 최대 10회까지 이어 간다. 전송 실패 시 입력과 기존 대화를 유지하며, 설계지로 잠깐 돌아갔다 다시 열어도 같은 맥락이면 대화를 이어 간다. 수업·자료·질문이 바뀌면 새 대화로 시작한다. 관리자 학생 미리보기는 AI 및 저장을 허용하지 않는다.

대화 완료 시 기존 탐구 분석 → 임시 초안 → 학생 본인의 선택 이유 → 확정 저장 흐름을 사용한다. 서버의 2,000자 지침 제한에 맞춘 최근 대화 요약과 함께 전체 대화·원래 질문을 `manual` 출처로 전달한다. `student_inquiry_designs.selected_source_snapshot`과 확정 설계의 출처에 저장하며, 이미 실행한 활동의 증거로 취급하지 않도록 명시한다. 연구 수첩에서 설계 대화를 다시 펼칠 수 있다. 새 DB 테이블이나 AI 엔드포인트는 만들지 않았다. 설계도 생성 전 대화는 화면 상태이며 새로고침하면 사라진다.

타이틀 및 게임 HUD의 나가기는 게임 영역 안의 확인 창을 연다. **확인하고 나가기**만 메인 화면으로 이동하며, **계속 머무르기** 및 Escape는 현재 화면과 입력을 유지한다. 저장되지 않은 내용은 나가면 사라질 수 있다는 설명을 표시한다.

검증: 대화 API는 메모리 fixture로 대체한 실제 React/Phaser 브라우저 흐름에서 맥락 전달·실패 재시도·대화 재개·설계 입력·초안/확정 대화 보관·수첩 표시·관리자 제한을 확인한다. `design-conversation.test.ts`는 긴 대화/수동 조건 보존 및 이전 기록 호환성을 검사한다. 실제 모델 응답 품질을 측정하는 실계정 AI 호출과는 구분한다.

최종 검증(2026-09-13): 프로덕션 빌드, 대상 ESLint, 자동 테스트 28개, 데스크톱·모바일 브라우저 시나리오 통과. 전체 앱 타입 검사는 기존 영역의 오류 230개로 실패하며 아카데미 변경 파일의 오류는 없다. 루온 카탈로그 마이그레이션은 연결 DB 적용 완료, 프런트엔드 호스팅 배포는 하지 않았다.

## 망원경 배경 별이 배포 사이트에서만 멈춰 보이던 문제 (2026-10-04)
