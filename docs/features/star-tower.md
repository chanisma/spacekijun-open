# 별까지 쌓기 (`/star-tower`)

집중하는 동안 낚시를 하고, 낚은 것으로 물에 잠긴 세계 위의 탑을 하늘까지 쌓는 **방치형 타이머 게임**(2026-10-10).
참고 = Steam «CELESTAY Craft&Slowlife»(바탕화면 한쪽에 띄워 두는 작업 동반자) — **구조만** 가져왔고 그림·세계·이야기는 우리 것이다
(꼭대기 관측 돔 · 별자리 8 · 병 편지 12 · «별빛» 세계관).

- 대상 = 학생·교사·관리자(직원 제외). 메뉴 기본값 = **공개**(신설 당일 관리자만으로 다듬은 뒤 같은 날 공개 — 사용자 «이제 기능 LIVE로»)
- 진행 동력 = **집중 타이머**(사용자 결정 — 순수 방치형이 아니다). 통합 지갑(아카데미 코인)과 **잇지 않는다**

## 1. 루프

1. 집중 15 · 25 · 45 · 60분 → 낚시꾼이 낚싯대를 드리운다
2. **5분 칸이 찰 때마다 한 번** 걸린다. 끝까지 채우면 **한 번 더 + 별 조각(15분마다 하나 — 15분 1 · 25분 2 · 45분 3 · 60분 4, 2026-11-06 사용자 «집중 시간에 비례», `20261106100000`)**. 중간에 그만두면 **다 찬 칸만**
3. 물물교환 뗏목: 물고기 3 → 나무 1, 물고기 5 → 고철 1
4. 층 16종 중 아무거나 골라 **돔 바로 아래**에 올린다. 비용 = `ceil(바탕 × (1 + 0.3 × 쌓은 수))`, 별 조각 = `쌓은 수 / 4`
5. 2층마다 별자리 하나 — 세계 높이에 놓여 있어 탑이 올라가면 «말 그대로» 그 하늘이 보인다
6. 병 편지(5%)를 주울 때마다 이야기 한 통

페이스(기댓값): 25분 한 번 ≈ 물고기 6 · 나무 2.6 · 고철 0.7 · 별 조각 1.2. 16층 전부 ≈ 집중 55번(약 23시간) — 한 학기에 걸쳐 쌓는 속도.

## 1-1. 높이마다 다른 하늘 (2026-10-10 2차 — 사용자 요청 «높이 올라갈수록 다양한 경험, 비공정이 날아다니는 것 같은»)

탑이 닿은 높이에 따라 하늘에 사는 것이 바뀐다. **쉬는 동안 카메라가 꼭대기를 보므로**(집중 중엔 낚시터) 층을 올리면 그 높이의 하늘이 저절로 눈앞에 온다.

| 높이 띠 | 세계 높이 | 열리는 층 | 방문자 · 장면 |
|---|---|---|---|
| 바다 | 0~110 | 0~1 | 갈매기(날갯짓 2프레임, 3층부터 V자 무리) · 바다 고래 꼬리(물에서 솟아 반사까지) |
| 구름 아래 | 110~260 | 2~3 | 연 · 열기구 · 비 갠 낮의 무지개 |
| 구름층 | 260~460 | 5~9 | 작은 비공정 · 떠 있는 섬 · 하늘 고래 · **비공정 상인 정박(7층)** |
| 높은 하늘 | 460~700 | 10~13 | 오로라(10층, 맑은 밤) · 하늘 해파리(밤) · 유성우(12층, 나흘에 하루쯤) · 옛 인공위성 |
| 우주의 문턱 | 700~ | 15 | 별의 정령(밤) — 하늘이 우주색에 가까워진다 |

- **방문자는 눌러서 인사한다** — 튀어 오르고 도트 말풍선(♪·♥·!·✦·zzz)과 반짝이, 화면 위에 한 줄. **보상은 없다**(사용자 결정 — 경제·서버 검증 불필요). 처음 누른 방문자는 도감 «방문자» 탭(서버 `tower_meet`)
- **비공정 상인**: 구름층(7층)에 닿으면 돔 아래층 옆에 정박(밤엔 등불). 누르면 상인 교환 — 물고기 4 → 고철 1(뗏목은 5), 별 조각 1 → 나무 4 + 고철 2. 후반 병목이 고철·나무이고 별 조각은 남으므로(기댓값 66 vs 필요 24) 남는 별을 재료로 돌린다
- 방문자는 «탑이 닿은 높이» **와** «카메라가 보는 높이» 둘 다 맞을 때만 생긴다 — 화면 밖에서 태어나 아무도 못 보는 방문자를 만들지 않는다. 비 오는 날엔 갈매기·고래만
- 정의 단일 출처 = `model/visitors.ts`(띠·문턱·속도·빈도·반응), 그리기 = `scene/skyLife.ts`. 무지개·유성우 판정 = `model/sky.ts`(`rainbowAt` · `meteorShowerAt` — 한국 날짜 해시라 누구에게나 같은 밤)
- 시험용 `?summon=sky-whale,airship` · `?weather=rainbow` · `?meteor=1`

## 1-2. 관리자 = 재화 무한 (테스트용, 2026-10-10 3차 — 사용자 요청)

`20261010120000_star_tower_admin.sql` — 다마고찌의 «관리자는 확인용으로 전부 열림»과 같은 방식.
- **저장값은 건드리지 않는다**: 상태 JSON 이 물고기·나무·고철·별 조각을 9999 로 **보여 주고**, 짓기·교환에서 **빼지 않는다**. 관리자에서 내려와도 9999 가 데이터에 남지 않는다(실측: 무한으로 지은 뒤에도 저장값 = 물고기 5 · 고철 2 · 별 1 그대로)
- 병 편지는 이야기 진도라 실제 값 그대로(무한이면 편지 12통이 한꺼번에 열린다)
- 화면은 «∞» + «관리자 · 재화 무한» 띠 — 진짜 계정과 헷갈리지 않게
- 판정 = 서버의 **진짜 role**(`tower_private.is_admin`, 직접 호출 막음). 헤더의 역할 미리보기(학생 시점)는 서버에 닿지 않으므로 미리보기 중에도 무한이다
- 집중 시간은 그대로 서버 시각 — «재화»만 무한이다
- 하네스 `?admin=1`

## 1-3. 살아 있는 탑 · 낚시 도감 · 소리 · 그다음 (2026-10-10 4차 — 사용자 선택 «B»)

**살아 있는 탑** — 층마다 «가만히 있을 때의 움직임» 하나와 «누르면 일어나는 일» 하나(`model/floorLife.ts` · `scene/floorFx.ts`).
- 부엌·훈제실 굴뚝 연기 · 찻방·목욕탕 김 · 수조 물방울 · 무전기 빨간 불 깜빡임 · 밤엔 불 켜진 창을 사람 그림자가 지나간다
- 자리는 **그림에서 찾는다**(`assets.ts` anchors — 가장 위 화소 = 굴뚝 끝, 파란 덩어리 = 수조, 빨간 화소 = 무전기, 불빛 범위 = 창) — 그림을 다시 그려도 좌표를 고치지 않는다
- 층을 누르면 도트 말풍선 + 한 줄 + 소리(종탑 «댕—», 축음기 음표, 수조 물방울 …). 맨 아래 갑판은 낚시꾼까지 누를 수 있다

**낚시 도감(희귀 물고기 8)** — 굴림의 «그 순간»(5분 칸이 차는 시각)의 한국 시각·날씨·달로 자격을 보고 8% 로 희귀 물고기(물고기 3).
달빛 은어(밤 8시~4시) · 노을 잉어(5~8시) · 새벽 송어(5~8시) · 비 장어(비) · 벚꽃 송사리(봄) · 여름 날치 · 단풍 쏘가리(가을) · 얼음 빙어(겨울).
- 서버 `tower_private.rare_*` · `rain_at` — `20261010140000_star_tower_fish.sql`(처음엔 130000 이었는데 다른 세션의 다마고찌 마이그레이션과 번호가 겹쳐 옮겼다). 도감 = `tower_state.caught`(지난 기록에서 채움)
- ⚠️ **날씨 해시가 화면과 같아야 한다** — 서버가 화면의 FNV-1a 를 그대로 다시 구현했다. 2,000개 시각 실측 **불일치 0**(`scripts/star-tower-test/weather-parity.mts` → SQL 로 대조, 마이그레이션을 고치면 다시 돌릴 것)
- 실측(2만 번): 희귀 비율 8.13% · 가을밤 단풍 쏘가리 816 / 달빛 은어 810(반반) · 60분 집중 한 번에 실제로 달빛 은어가 걸렸다

**소리** — 파일 없이 WebAudio 합성(`audio/ambience.ts`): 배경 = 파도(물이 보이는 만큼) · 비 · 바람(높을수록) / 효과 = 종 · 갈매기 · 고래 노래 · 축음기 · 물방울 · 뱃고동 …
- 첫 손짓에서 길을 연다(자동 재생 정책) · 탭이 안 보이면 멈춘다 · [소리] 단추가 전부 끈다
- ⚠️ 헤드리스 브라우저에서는 들을 수 없다 — 오류 없이 도는 것까지만 확인했다(실제 소리는 사람이 들어 볼 것)

**그다음(16층 뒤)**
- **층 순서 바꾸기**(짓기 판 아래, 재료 없음 — `tower_reorder`, 같은 층들의 다른 순서만)
- **계절**(한국 달력): 봄 꽃잎(2×2 — 1줄짜리는 낮 하늘에서 안 보였다) · 여름 밤 반딧불 · 가을 낙엽 · 겨울 눈 — **겨울의 비는 눈이 된다**(비·눈 모두 별·해를 가린다)
- **완성(16층)** — 맑은 밤이면 관측 돔 망원경에서 별을 향해 빛줄기(빛깔 = 나의 별, §10). 그 순간 등성이 오르고, [짓기]에서 새 탑을 쌓을 수 있다
- 시험용 `?season=spring|summer|autumn|winter`

## 2. 서버 (`supabase/migrations/20261010100000_star_tower.sql`)

| 표 | 내용 |
|---|---|
| `tower_state` | 사람마다 한 줄 — 자원 5종 · `floors text[]`(아래→위) · `visitors text[]`(처음 만난 방문자, 2차) · 누적 집중 초 · 완주 수 · `towers`(완성한 탑 = 등성 랭크) · `past_towers jsonb`(지난 탑, §10) |
| `tower_focus` | 집중 기록 — 시작·끝 = **서버 시각**, `catches jsonb`(걸린 것 key), 사람마다 열린 집중 하나(부분 유일 인덱스) |

RPC(전부 SECURITY DEFINER, anon·PUBLIC 회수): `tower_read` · `tower_focus_start(분)` · `tower_focus_finish(id, 그만두기)` · `tower_trade(종류, 횟수)` · `tower_build(층)` · `tower_meet(방문자)`(2차 — `20261010110000_star_tower_sky.sql`, `tower_trade` 를 상인 교환까지 다시 정의, 상인은 7층 문턱).
내부 `tower_private`: `actor()`(신원 + 첫 방문 행 만들기) · `catch_table()` · `floor_base()` · `scaled()` · `roll(seed)` · `close_focus()` · `state_json()`.

- **걸린 것은 서버가 굴린다** — `md5(세션 id || ':' || 순번)` 앞 28비트 % 100 을 누적 확률에 대 본다. 재현되고 조작할 수 없다(2만 번 실측: 정어리 30.2% · 나무 21.9% · 고등어 18.4% · 톱니 11.6% · 가자미 10.1% · 병 4.8% · 별빛 물고기 3.0%)
- **시간이 안 찼으면 `running` + 남은 초**만 준다(기기 시계를 믿지 않는다). 시간이 지난 뒤 늦게 와도 완주(만료 없음 — 느린 삶 톤). 새 집중을 열면 열린 집중을 먼저 닫는다(시간이 찼으면 완주로)
- 쓰기는 RPC 전용(직접 UPDATE = `permission denied` 실측), 읽기는 본인 행만

## 3. 화면

- 전체 화면 앱(다마고찌·아카데미처럼 `Layout` 없이). 장면 = 캔버스 2D, **내부 해상도 = 컨테이너 ÷ 정수 배율**(내부 높이 340 안팎) — 넓은 데스크톱·세로 휴대폰·작은 창 모두 같은 코드
- 그리는 순서·좌표 = `scene/TowerScene.ts` 머리 주석. 하늘은 **한국 시각**을 따르고(노을·밤·별·별똥별), 날씨는 한국 날짜 + 3시간 칸 해시(비 12%)
- **카메라**: 탑이 다 들어가면 다 보여 주고, 안 들어가면 **낚시터(아래)**에 붙는다(집중하는 동안의 주인공은 낚시꾼). 층을 지으면 7초 동안 꼭대기, 끌면 12초 동안 따라가지 않는다
- 집중 카드 = 넓은 화면은 왼쪽 아래, 휴대폰은 가운데 아래 + 장면이 카드 높이만큼 낚시터를 올린다(`bottomInset`)
- **작은 창**: Document Picture-in-Picture(늘 위) → 안 되면 `/star-tower?mini=1` 팝업
- 시간이 다 차면 저절로 건져 올리고 결과 판을 연다. 탭이 안 보이면 브라우저 알림(권한은 첫 집중 때 한 번 묻는다), 종소리는 WebAudio(파일 없음)
- 시험용 `?hour=18.5&weather=rain` — 하늘 고정
- **첫 로딩 화면 (2026-10-11)**: 탑 기록(서버) · 그림 58장 · 갈무리 글꼴이 다 될 때까지 덮고 «무엇을 기다리는지 · N/58 · %»를 말한다(`components/LoadingScreen.tsx`, 진행률 = 순수 함수 `model/loading.ts`). 종전엔 서버만 기다려서 **그림이 오기 전에 HUD 가 먼저** 떴다. 그림 진행은 `scene/assets.ts` 의 모듈 전역 카운터(`subscribeAssetProgress`) — 캔버스와 **같은 캐시 promise** 라 두 번 받지 않는다. ⚠️ 그림은 받은 뒤 «재기(measure)»까지 끝나야 done 이라 받은 수가 58/58 이어도 100% 가 아니다 · 글꼴은 4초 상한(`FONT_WAIT_MS`) · 서버 실패는 같은 자리에서 [다시 시도] · 한 번 걷히면 다시 덮지 않는다(탭 복귀 때의 다시 읽기는 조용히). 작은 창(`?mini=1`)에는 두지 않았다

## 5. 조용히 틀리는 자리

1. **값이 두 벌**(SQL `tower_private.*` ↔ `model/catalog.ts`) — 한쪽만 고치면 화면이 짓기 버튼을 켜 두고 서버가 거절하거나 그 반대. 회귀가 대조한다
2. **비용은 정수로만** — `Math.ceil(base * (1 + 0.3 * n))` 은 12.000…2 를 13 으로 올려 서버(정수식)와 어긋난다 → `scaledCost` 의 `(base*(10+3n)+9)/10`
3. **`actor()` 는 volatile** — 행을 만드는 함수를 stable 로 두면 첫 호출이 `0A000 INSERT is not allowed in a non-volatile function`(2026-10-10 흐름 시험에서 실제로 났다)
4. **처음 받을 때 0 → N 은 «지었다»가 아니다** — `SceneView.ready` 전엔 층 변화를 보지 않는다. 안 그러면 첫 화면부터 짓기 연출 + 7초 꼭대기 보기(실측)
5. **층은 스프라이트 높이로 쌓지 않는다** — `deck`(위에서 처음으로 폭 60% 이상 찬 줄)에 앉힌다. 높이로 쌓으면 굴뚝 끝에 다음 층이 얹혀 뜬다
6. **밤 불빛 = 따뜻한 화소의 «뭉치»** — 하나씩 보면 금빛 장식까지 켜져 탑 전체가 꼬마전구가 된다(둘레 8칸 중 5칸)

## 10. 등성 랭크 · 새 탑 (2026-10-15 — 사용자 요청 «탑을 완성할 때마다 랭크», 결정 «(가) 새 탑을 1층부터»)

랭크 = 별의 **등성**(겉보기 등급 — 숫자가 작을수록 밝다). 완성한 탑이 없으면 **7등성**(맨눈에 안 보이는 별), 탑 하나 완성할 때마다 한 등성씩 밝아진다:
6 → 5 → … → 1등성 → 0등성 → −1등성(시리우스) …, **끝이 없다**. 각 등성엔 실제 하늘에서 견줄 것(북극성 2 · 스피카 1 · 베가 0 · 시리우스 −1 · 금성 · 보름달 · 해)을 붙였다.

- **서버 정본 = «완성한 탑 수» 하나**(`tower_state.towers`). 등성 = `7 − towers` 는 화면 순수 함수 `model/rank.ts` 한 곳 — 숫자를 두 벌 두지 않는다
- **16층째를 지은 순간 오른다**(`tower_build` 안) — 새 탑을 쌓을 때가 아니다. 다 지은 층 수 = `floor_base()` 줄 수(`tower_private.full_floors()`)
- **새 탑** `tower_new_tower()` — 다 지은 탑에서만. 층만 비우고 지금 탑은 `past_towers`(층 순서 + 완성 시각)로 물러난다. 재료·도감·병 편지·집중 기록·등성은 그대로. 화면은 `window.confirm` 으로 묻는다(되돌릴 수 없다)
- 마이그레이션 `20261015100000_star_tower_rank.sql`(운영 적용 — 적용 시점 16층 0명이라 옮길 기록 없음). 학생 흐름 실측: 15층에서 새 탑 거절 → 16층째 = towers 1 → 새 탑 = 층 0 · 지난 탑 1 · 재료 그대로 → 다시 새 탑 거절 · 익명 실행 권한 없음

**화면**
- 오른쪽 단추 줄 맨 위 = **나의 별**(등성 빛깔의 별 + «6등성») → 랭크 판(지금 등성 · 견줄 별 · 다음 등성까지 지금 탑 N/16 · 등성 사다리 · 지난 탑 목록). 장면의 별을 눌러도 열린다
- 장면: **돔 바로 위에 나의 별** — 탑이 늘수록 십자 팔·번짐이 커지고(상한 있음) 빛깔이 붉은 별(M) → 푸른 별(O)로. 완성 순간엔 고리가 퍼진다. 완성 빛줄기도 같은 빛깔
- **지난 탑 = 수평선의 1/6 실루엣** — 그 탑의 실제 층 순서로 쌓아 탑마다 모양이 다르고, 꼭대기엔 그 탑이 남긴 별. 최근 탑일수록 가운데 가까이 좌우로 번갈아, 화면 폭에 안 들어가는 오래된 탑은 그리지 않는다(랭크 판이 개수를 말한다). 물 반사는 저절로
- 빛깔(분광형)은 **게임의 표현**이다 — 실제 별의 밝기와 색은 무관하다고 랭크 판이 말한다
- 관리자 통계: 등성 분포(`towers_hist`, 마지막 칸 = 7개 이상) · 참여자 목록 «등성» 열

**조용히 틀리는 자리**
1. **새 탑이면 도감이 다시 잠겨 보인다** — 별자리·방문자 «높이»는 지금 탑이 아니라 «가 본 높이»(완성한 적이 있으면 16)로 판정한다. 관리자 통계의 별자리도 `reach_hist`
2. **첫 로딩의 0 → N 은 «등성이 올랐다»가 아니다** — 층과 같은 `ready` 규칙(`lastTowers`)
3. **나의 별이 있으면 카메라 위 여백을 늘린다** — 안 그러면 휴대폰에서 별이 위 자원 줄 뒤로 숨는다(실측)
4. **밝은 낮 하늘에선 덧칠(lighter)이 사라진다** — 별의 팔은 그냥 칠하고 번짐만 덧칠
5. 새 탑이면 **비공정 상인도 떠난다**(7층 규칙 그대로) — 별 조각 → 코인도 새 탑이 7층에 닿을 때까지 닫힌다. 짓기 판이 미리 말한다

- 하네스 `?floors=4&towers=3`(지난 탑 2 + 지금) · `?floors=15&admin=1`(완성 → 새 탑 흐름). 스크린샷 `output/star-tower/rank-*.png`(데스크톱·휴대폰·낮·완성 직후·새 탑 직후·−2등성)

## 11. 휴대폰 글자·단추 크기 (2026-10-15 — 사용자 제보 «모바일에서 버튼이 너무 작게 표시»)

- **원인**: 화면 글자가 갈무리11 의 «점이 맞는 크기» 12px 하나로 고정이었고 단추 높이가 36px 였다. 데스크톱에서는 맞지만 휴대폰에서는 장면에 비해 깨알이고 손가락 규약(44px)보다 작았다.
- **글자 = `--st-fs`**(기본 12px). 손가락 기기(`pointer: coarse`)는 `model/pixelFont.ts` 의 `pixelFontSize(dpr)` 가 «15px 이상이면서 글꼴 한 칸 = 기기 화소 정수 개»인 가장 작은 크기를 고른다(dpr 3 → 16 · dpr 2 → 18 · 2.625 → 18.29). 그래서 점이 번지지 않는다. **CSS 에 글자 크기를 숫자로 적지 말 것** — `var(--st-fs)` 와 그 2배만(회귀가 검사).
- **누르는 것 44px**(`@media (pointer: coarse)`): 단추·집중 길이·탭. 오른쪽 단추 줄은 64px, 글자에 맞춰 넓어진다.
- **오른쪽 단추 줄은 위 자원 막대와 아래 집중 카드 «사이»에** 놓는다 — 두 높이를 ResizeObserver 로 재 `--st-top-h`·`--st-card-h` 에 넣는다(글자가 커지면 둘 다 커지므로 «가운데 정렬»은 키 작은 휴대폰에서 카드와 겹쳤다). 자리가 모자라면 단추가 48px 까지 줄어든다.
- 좁은 휴대폰(≤420px)은 나가기를 화살표만(자원 다섯 칸이 한 줄에), 키 작은 휴대폰(≤740px)은 집중 카드 설명 한 줄을 접는다.
- 확인 = 390×844 · 375×667(쉬는 중·집중 중) · 1280×800 스크린샷(데스크톱은 종전과 같다).
