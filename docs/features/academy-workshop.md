# 공방 맞춤 주문과 배송

2026-09-13. 학생은 기숙사 공방의 **맞춤 제작 · 배송함**에서 리아 의상·헤어, 루온 의상·헤어, 기숙사 방 중 하나를 골라 주문 이름과 프롬프트를 제출한다. 기존 진열 상품의 구매 기능도 유지한다.

## 학생과 관리자의 흐름

1. 학생이 이름 2~100자와 디자인 설명 20~2,000자를 작성해 제출한다. 제작비·작품 공개 조건을 확인하고 의뢰하면 100코인을 차감한다. 제작 대기 주문은 최대 3개이며 클라이언트 토큰으로 동일 요청의 재시도를 합친다.
2. 실제 관리자 프로필에 연결된 `user_resource.resource_id`로 기존 `notification_events` 알림을 생성한다. 알림의 ‘공방 주문 확인’은 `/admin?tab=academy-workshop&order=<id>`를 연다. 관리자 사이드바에서도 주문 목록을 열 수 있다.
3. 관리자는 제작 시작을 표시하고, 학생 설명에 캐릭터 외형·그림 규격을 더한 제작용 프롬프트와 기준 원화를 받는다. **이번 구현의 제작 방식은 외부 이미지 도구로 제작한 뒤 완성 PNG를 업로드하는 방식**이다. 앱 내부의 유료 이미지 생성 API를 자동 호출하지 않는다.
4. 관리자 화면은 PNG 파일 시그니처, 10MB 제한, 256~4,096픽셀, 이미지 비율을 검사한다. 의상은 세로 2:3이며 네 모서리와 투명 픽셀을 확인하여 불투명 배경을 거부한다. 방은 가로 3:2다. 얼굴·체형·포즈·손발 여백 또는 방 배치는 관리자가 기준 원화와 비교한다. 의상과 헤어스타일(머리 길이·앞머리·묶기·땋기)은 학생 요청에 따라 변경할 수 있으며, 요청하지 않은 부분은 기준 원화를 유지한다. 학생 안내, 제작용 프롬프트, 관리자 배송 확인에 같은 기준을 적용한다. 자동 얼굴 동일성 판별은 아니다.
5. 완성본 미리보기와 배송 편지를 확인한 뒤 **배송 준비 → 학생에게 배송 확정**으로 전송한다. 업로드 후 RPC가 실패하면 같은 업로드를 재사용한다. 제작할 수 없을 때에는 이유를 담은 답장을 보낼 수 있다.
6. 학생에게 배송 알림을 보내고 `/academy/dorm?workshop=orders&order=<id>`에 연결한다. 학생이 선물 상자를 열면 의뢰자에게 추가 비용 없이 소장품을 한 번 지급한다. 옷장에서 선택해 기존 의상·방과 동일하게 적용·해제한다. 루온의 맞춤 의상은 대화 초상화에도 적용한다.

`submitted → crafting → delivered → received`, 접수 중 취소는 `cancelled`, 제작 불가 답장은 `declined`다. 관리자만 제작·배송·반려하고, 학생 본인만 접수·취소·수령한다. 관리자 학생 미리보기는 읽기 전용이다. 학생 계정을 선택하지 않은 미리보기에 관리자 전체 주문을 표시하지 않는다.

## 데이터와 접근 제어

- `academy_workshop_orders`: 학생, 고유 요청 토큰, 슬롯, 제목·프롬프트, 상태, 배송 편지·이미지 경로·작품 ID·처리자·시각. 학생 본인 또는 실제 관리자만 SELECT할 수 있으며 직접 쓰기는 허용하지 않는다.
- public invoker RPC `academy_workshop_read`, `academy_workshop_write`가 기존 `academy_private`의 고정 `search_path` 함수에 위임한다. 내부에서 `auth.uid()`와 `profiles.role`을 검사한다. 요청의 학생 ID·상품 가격을 신뢰하지 않는다.
- 주문별 행 잠금과 학생별 advisory lock으로 동시 배송·수령·장착을 처리한다. 배송·수령을 재시도해도 작품과 알림, 소장품을 중복 생성하지 않는다. 실제 상태를 다시 읽어 이미 취소/배송된 주문의 후속 변경을 거부한다.
- 배송 작품은 `academy_shop_items.academy_owner`로 의뢰자를 기록하고, 의뢰자가 고른 20~50코인(기본 35코인)에 판매한다. 의뢰자는 배송함에서 무료 수령하며 본인 작품 구매는 서버에서도 차단한다. 카탈로그와 완성 이미지는 인증된 사용자에게 공개하되, 주문 프롬프트와 관리자 편지는 주문 접근 권한 안에 유지한다. 공개 상품 설명에는 배송 편지를 복사하지 않는다.
- private Storage 버킷 `academy-workshop`의 `<order UUID>/<file UUID>.png` 경로를 사용한다. 관리자만 제작 중인 주문에 업로드하며 덮어쓰기는 허용하지 않는다. 배송된 원본을 삭제할 수 없고, 사용하지 않은 미리보기만 정리할 수 있다.
- 학생은 자신의 배송 완료 이미지에만 접근한다. 1시간 signed URL을 발급하고 게임 기숙사 쿼리는 30분마다 갱신한다. Phaser는 추가 작품을 필요할 때 읽으며 정적 원화와 같은 표시 규격을 사용한다.

Storage 접근 방식은 [Supabase private bucket 문서](https://supabase.com/docs/guides/storage/buckets/fundamentals)에 맞춰 signed URL과 RLS로 구현했다.

## 적용과 검증

`20260913143155_academy_workshop_orders.sql`을 연결 프로젝트에 적용했다. CLI로 파일을 만든 뒤 연결 DB의 실제 적용 이력 버전 20260913143155에 로컬 파일명을 맞췄다. 새 테이블 및 버킷과 RPC·정책을 추가하며 기존 주문/소장품 데이터를 이동하거나 삭제하지 않는다.

`supabase/tests/academy_workshop.sql`은 실제 DB 트랜잭션에서 관리자 알림, 위조 학생 ID 거부, 다른 학생의 주문 비공개, 진열 상품·완성 이미지 공개, 재제출·배송·수령 멱등성, 기존 장착 RPC와의 연결, 익명 권한을 검사하고 롤백한다. 이미지 객체 메타데이터는 이 테스트 트랜잭션 안에서만 만든다.

`scripts/academy-test/workshop.test.ts`는 프롬프트 범위, 루온 원형 안내, 개인 작품의 signed URL 적용, 알림 목적지를 검사한다. 브라우저 fixture는 실제 React/Phaser 화면과 PNG 검증기를 사용해 제출 실패 시 초안 보존, 관리자 제작·잘못된 이미지 차단·배송 확정, 재시도 업로드 재사용, 수령·맞춤 의상 적용을 검증한다. 실사용 계정으로 파일을 업로드하고 알림을 발송한 종단 검사는 아니다.


## 제작비·진열 판매·커미션 (2026-09-13)

- 주문 100코인, 완성 작품 판매 기본 35코인(의뢰자가 정수 20~50코인 중 선택), 다른 학생의 최초 구매마다 의뢰자에게 10코인. 서버가 주문 소유권·가격 범위를 검증하고 실제 진열 금액으로 결제한다. 브라우저에서 임의로 지정한 결제 금액이나 커미션 수령인은 사용하지 않는다.
- 제출은 `confirm_cost:100`, `publish_design:true`를 요구한다. 과거 UI가 비용 안내 없이 새 주문을 만드는 것은 거부하고, 이미 저장된 동일 토큰 재시도는 재결제하지 않는다.
- 제출·잔액 차감·알림은 한 트랜잭션이다. 잔액 부족이나 문항 유효성 오류 시 주문과 결제 모두 롤백한다. 취소 가능한 접수 상태에서 취소하거나 관리자가 제작을 거절하면 실제 결제액을 한 번만 전액 환불한다. 과거 무료 주문은 소급 결제하거나 100코인을 환불하지 않는다.
- `academy_workshop_commissions`는 `(order_id,buyer_id)`를 기본 키로 사용한다. 기존 소장자는 재구매하지 않으며 중복 클릭·재시도에서 소장품과 정산을 중복 지급하지 않는다. 구매자와 의뢰자의 지갑 잠금은 UUID 순서로 획득하여 서로의 작품을 동시에 구매하는 경우의 잠금 순환을 피한다. 단일 SQL 테스트는 재시도를 검증하며 별도 연결의 부하 검증은 포함하지 않는다.
- 완성 이미지와 이름을 공유하며 사적인 주문 프롬프트·배송 편지는 공유하지 않는다. 공개 작품을 구매한 학생은 판매 중단 후에도 소장품 이미지에 접근할 수 있다. Storage 버킷 자체는 비공개로 유지하고 서명 URL로 표시한다.
- 배송함에서 작품별 판매 횟수와 지급된 커미션 합계를 표시한다. 기숙사 지갑은 30초마다 다시 읽는다. 코인 거래는 결제 시스템과 연결되지 않은 기존 게임 재화다.

적용 마이그레이션: `20260913170928_academy_workshop_marketplace.sql`, `20260913171029_academy_workshop_image_read_fix.sql` 순서. 후자는 상품의 `name`과 Storage 객체의 `name`을 구분해 이미지 조회 정책을 수정한다. 두 파일 모두 적용 완료. 실제 역할의 `supabase/tests/academy_workshop.sql`은 결제·취소/반려 환불·진열 공개/주문 비공개·35/10 정산·본인 구매 거부·중복 방지를 검증하고 롤백했다.

가격 설정 추가: `20260913171541_academy_workshop_sale_price.sql` 적용 완료. `sale_price` 기본값 35와 20~50 CHECK를 추가하고, 의뢰 학생만 `set_price`로 접수·제작·배송·수령한 주문의 가격을 변경한다. 배송 후 변경은 진열 상품에도 반영하며 이전 정산 원장의 구매 가격은 보존한다. 구매 확인 시 `expected_price`를 보내고, 확인 후 진열 가격이 달라지면 차감 없이 다시 확인하도록 한다. 커미션은 판매 가격과 관계없이 10코인이다. DB 테스트에서 범위·소수 거부, 다른 학생 변경 거부, 실제 35/50 결제, 오래된 가격 거부, 10코인 정산을 검증했다.

검증 결과: 관련 자동 테스트 35개와 대상 ESLint, 프로덕션 빌드 통과. 전체 앱 타입 검사는 기존 다른 영역 오류 230개가 남아 있으며 이번 아카데미 변경 파일 오류는 없다. DB 역할 검사는 롤백했고, 새 기능 관련 보안·성능 Advisor 지적은 없었다. 프런트엔드 호스팅 배포는 하지 않았다.
