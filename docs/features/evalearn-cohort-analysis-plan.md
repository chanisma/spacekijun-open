# 시험 결과 분석 — 학년·학급 단위 분석 계획

> 상태: 계획 (2026-09-03). 구현 전 합의용 문서.
> 대상: `/evalearn` (구 '모의고사 분석' → '시험 결과 분석')

## 왜 이 문서가 있나

지금 evalearn 은 **학생 1명**만 본다. 왼쪽 패널에서 학생을 고르면 그 학생의 마킹표·취약점이 나온다.
학년 버튼이 이미 있지만 그건 **관리자가 업로드한 HTML 리포트**(`evalearn_grade_analysis`)를 여는 것이라
데이터에서 계산된 분석이 아니고, 새 회차가 올 때마다 사람이 만들어 올려야 한다.

여기서는 **학년·학급을 고르면 그 집단의 분석이 계산되어 나오는** 기능을 설계한다.

## 1. 실제로 가진 데이터 (2026-09-03 실측)

| 데이터 | 위치 | 상태 |
|---|---|---|
| 문항별 정오 | `student_basic_info.mock_marking[].subjects[].correct` | 3학년 9월 172명. **주관식 포함 전 문항 채점됨**(`mockGrading` fallback) |
| 학생 답안 | 같은 곳 `.answers` | 오답 시 무엇을 골랐는지까지 있음 |
| 공식 성적 | `.mock_result[].subjects[]` = 등급·원점수·백분위·표준점수 | **2026-09 는 아직 없음**(발표 전). 7월까지 있음 |
| 문항 메타 | `mock_problems` | 대분류/소분류(**2026-09-03 체계 통일 완료**), 전국 정답률, 정답, 선택률, 배점 |
| 학급 소속 | `resource`(type=student, status=active) `meta.grade/class/number` | 3학년 9개 반 × 24~25명, 전원 마킹 보유 |
| 학교 지필평가 | `school_exam_result`, `school_exam_question` | 별도 탭에 이미 있음 |

**핵심**: 우리는 여섯 숫자 요약(최솟값·Q1·중앙값·Q3·최댓값·평균)보다 훨씬 많은 걸 갖고 있다.
**원점수 배열 + 문항별 정오 + 학생이 고른 오답 + 전국 정답률**이 다 있다.
그래서 참고로 주신 통계 설명의 "알 수 없는 것" 세 가지가 **우리에겐 전부 답할 수 있는 것**이 된다:

| 그 글이 "알 수 없다"고 한 것 | 우리 상황 |
|---|---|
| 봉우리 개수(이봉분포 여부) | 원점수 배열이 있으니 **히스토그램으로 직접 보인다** |
| 어떤 문항이 문제였는지 | 문항별 교내 정답률이 있으니 **원인 문항을 지목할 수 있다** |
| 표본 크기 | 알고 있다 — 그리고 이게 **가장 중요한 제약**이다(§4) |

## 2. 원점수 문제 (선결 과제)

집단 분석의 대부분이 **원점수 분포**에서 나오는데, 2026-09 는 공식 성적이 아직 없다.
마킹 + 배점으로 계산해야 한다.

- 방법 검증됨: 2026-03 에서 `Σ(맞은 문항 배점)` == 공식 원점수가 **영어 589/589, 한국사 588/588, 국어 399/399** 정확히 일치.
- 배점은 리로스쿨 CSV 에 없어서 2026-07/09 가 전부 `point=2` 로 들어가 있다 → **EBS 문제지 PDF 에서 추출**(§ EBS 등급컷 작업과 공유).

즉 **배점 적재가 학년·학급 분석의 선행 조건**이다. 배점 없이는 분포 자체를 못 그린다.

## 3. 분석 항목

### 3-1. 분포의 모양 (1순위)

- **히스토그램** — 원점수 5점 구간. 여섯 숫자 요약으로는 못 보는 **이봉분포(중위권 공동화)**를 여기서 본다.
- **박스플롯** — 반별로 나란히. 이미 `SchoolExamBoxPlot.tsx` 부품이 있으니 재사용.
- **평균 vs 중앙값** — 차이가 5점 이상이면 "평균 N점짜리 시험"이라는 표현이 오해를 만든다는 경고를 함께 띄운다.
- **Bowley 왜도** `(Q1 + Q3 − 2·중앙값) / (Q3 − Q1)`, |값| > 0.2 면 비대칭 표시.

### 3-2. 변별력 (1순위)

- **IQR** — 100점 만점 기준 15점 미만이면 "중위권이 뭉쳐 석차가 한두 문제로 뒤집힘" 경고.
- **(중앙값 − Q1) vs (Q3 − 중앙값) 비대칭** — 위쪽이 좁으면 상위권 변별 실패.
- **천장/바닥 효과** — Q3 가 90점대 후반이거나 Q1 이 바닥이면 표시.
- ★ **원인 문항 지목** — 변별력이 낮다는 진단에서 끝내지 않고, **교내 정답률이 극단(≥90% 또는 ≤10%)인 문항**을 같이 보여준다. 이건 문항별 데이터가 있어야 가능하고, 우리는 있다.

### 3-3. 문항 분석 (우리만 할 수 있는 것, 1순위)

- **교내 정답률 ↔ 전국 정답률 산점도**. 대각선에서 크게 벗어난 문항이 곧 우리 학교의 강·약점이다.
  (2026-09 실측 교내-전국 평균 격차 ~24%p 이므로 **격차 자체가 아니라 격차의 편차**를 봐야 한다.)
- **오답 선택지 쏠림** — `answers` 로 학생들이 어떤 오답에 몰렸는지 집계. 특정 오답에 40% 이상 몰리면
  그건 찍은 게 아니라 **공통 오개념**이다. 수업에서 바로 쓸 수 있는 가장 실질적인 산출물.
- **단원별 정답률** — `major_category`/`sub_category` 기준. 체계 통일이 끝나 회차를 가로질러 비교 가능.

### 3-4. 집단 비교 (2순위)

- 반별 · 회차별(추이) · 과목별 비교. 과목 간 비교는 상담에서 "너만 이 과목을 못한 게 아니다"의 근거가 된다.
- **회차 추이**가 반별 비교보다 안전하다(§4). 같은 반의 3월→6월→9월 변화는 표본이 같아 비교 가능.

### 3-5. 개별 학생 위치 (2순위)

- 학년/반 내 사분위 위치. "상위 25% 안"이 "78점"보다 잘 전달된다.
- 등급 추정은 **EBS 등급컷(원점수 기준)을 쓴다**. IQR ÷ 1.349 로 표준편차를 근사해 z 점수를 내는 방법은
  분포가 비대칭이면 오차가 커지는데, 우리는 실제 등급컷이 있으므로 근사할 이유가 없다.

## 4. 통계적 주의 — 반 24명 (설계에 반드시 반영)

**반별 평균 비교는 대부분 노이즈다.** 한 반이 24명이고 원점수 표준편차가 20점 안팎이면
반평균의 표준오차 ≈ 20/√24 ≈ **4.1점**, 두 반 차이의 표준오차 ≈ **5.8점**.
즉 **반 평균이 12점쯤 차이나야** 통계적으로 의미가 있고, 5점 차이는 그냥 흔들림이다.

이걸 화면에 넣지 않으면 담임 간 오해를 만든다. 그래서:

- 반별 막대에 **오차막대(±2 표준오차)를 반드시 함께** 그린다.
- 오차 범위가 겹치는 반끼리는 "차이 있음"으로 **표시하지 않는다**.
- 반 순위표(1등 반 … 9등 반)는 **만들지 않는다**. 순위는 차이가 없어도 항상 생기고, 그 자체가 오해다.
- 표본이 작을수록 **회차 추이**(같은 집단의 변화)가 반별 비교보다 신뢰할 수 있다는 안내를 붙인다.

## 5. UI 계획

### 진입
왼쪽 패널(`StudentList.tsx`)은 이미 학년 → 반 → 학생 트리다. 여기서
**학년 행을 클릭하면 학년 분석, 반 행을 클릭하면 학급 분석**으로 들어가게 한다
(학생 클릭 = 지금처럼 개인 분석). 별도 메뉴를 만들지 않는다 — 선택 대상이 곧 분석 범위라는 것이
트리에서 바로 읽힌다.

기존 "학년 분석" 버튼(관리자 업로드 HTML)은 **탭 하나로 남겨** 과거 리포트 열람을 유지한다.

### 화면 구성 (`CohortAnalysisPanel`)
1. 회차 선택 (개인 분석과 같은 방식)
2. 요약 카드 — 응시 인원 · 평균 · 중앙값 · IQR · 왜도, 각 카드에 자동 진단 문구
3. 분포 — 히스토그램 + 박스플롯(학년이면 반별, 학급이면 학년 대비)
4. 문항 분석 — 교내↔전국 산점도 + 오답 쏠림 표
5. 단원별 정답률 히트맵
6. 추이 — 회차별 중앙값·IQR 변화

### 재사용할 부품
- `SchoolExamBoxPlot.tsx` (상자그림), `dataviz` 원칙 + `lib/chartAnimation.ts` `drawLineProps`
- 난이도 밴드 = `utils/difficulty.ts`(모의고사 컷 40/70 — 학교시험 컷과 다름에 주의)
- 정오 판정 = `utils/mockGrading.ts` (개인 분석과 반드시 같은 출처)

### 권한
교사·admin 전용. 학생은 자기 개인 분석만(현행 `useStudentSelfMockData` 유지).
학급 분석은 **담임이 아니어도 교사면 열람 가능**하게 할지 결정 필요 — 현재 evalearn 은 교사 전체 열람이다.

## 7. 학생 대시보드에서 옮겨올 것 (2026-09-03 추가)

`/student-dashboard` 의 분석 패널(`components/analysis/AnalysisPanel.tsx`)에 이미 탭 9개가 있고,
**그중 5개가 성적 분석**이다. 즉 이 기능은 "새로 만드는 것"이 아니라 **흩어진 성적 분석을
시험 결과 분석으로 모으는 것**이다. 특히 `학급별 비교`는 §3-4 와 정면으로 겹치므로
그걸 모르고 새로 만들면 같은 분석이 앱에 두 벌 생긴다.

| 탭 | 컴포넌트 | 판단 |
|---|---|---|
| 성취도 추이 | `GradeTrendAnalysis` | **이동** — 성적이 주체 |
| 학급별 비교 | `ClassComparisonAnalysis` | **이동** — §3-4 와 중복. 이걸 옮겨 확장하는 게 맞다 |
| 내신-모의고사 | `MockVsSchoolAnalysis` | **이동** — 두 시험의 비교 |
| AI 성적예측 | `GradePredictionAnalysis` | **이동** |
| 6·9월 모평 분석 | `PyeonggawonShiftAnalysis` | **이동** — 명백히 모의고사 |
| 출신 중학교별 | `MiddleSchoolAnalysis` | 잔류 — 학생 배경이 주체 |
| 출결-성적 | `AttendanceGradeCorrelation` | 잔류 — 출결이 주체 |
| 교과 선택 | `SubjectSelectionAnalysis` | 잔류 — 과목 선택이 주체 |
| 종합 활동 | `ComprehensiveActivityAnalysis` | 잔류 — 비교과 |

**가르는 기준**: "시험 결과가 주체인가, 학생의 다른 면이 주체인가."
출결-성적 상관은 출결을 이해하려는 것이므로 대시보드에 남고, 학급별 성적 비교는 시험을
이해하려는 것이므로 옮긴다.

**주의**: 옮길 때 `data={analysisData}` 로 `useAnalysisData` 훅에 묶여 있으므로 데이터 계층을
같이 봐야 한다. 컴포넌트만 복사하면 대시보드와 evalearn 이 서로 다른 경로로 같은 수치를
계산하게 되어 두 화면 숫자가 어긋난다. 이동 단계는 §6 의 3~5 **이후**에 두어,
새로 만든 `useCohortData` 로 통일해 갈아끼운다.

## 8. 열린 결정

1. **학급 분석 열람 권한** — 교사 전체 vs 담임+관리자
2. **2026-09 처럼 공식 성적이 없는 회차**에서 등급을 EBS 참고컷으로 보여줄 때, 집단 통계(등급 분포)까지
   참고컷으로 낼 것인가. 개인 화면은 "참고" 표시로 충분하지만 집단 통계는 숫자가 혼자 돌아다니기 쉽다.
3. **탐구 과목 등급컷** — EBS 풀서비스는 로그인 사용자의 응시과목만 보여줘 비로그인으로는 못 얻는다.
