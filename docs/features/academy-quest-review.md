# 아카데미 퀘스트·추가 기능 검토

2026-09-13. 현재 로컬 구현의 코드와 데이터 흐름을 검토한 결과다. 이번 검토에서는 제품 코드·DB·배포를 변경하지 않았다. 아래 제안은 미구현 사항이며, 기존 테스트의 통과를 새 시나리오의 검증으로 간주하지 않는다.

## 결론

장소 이동, 책·편지 열람, 지식 별자리, 학생 탐구 설계, 기사 AI 대화와 일일 만남의 기반은 마련됐다. 다음 개발의 중심은 **읽고 생각한 내용이 다음 사건으로 이어지고, 그 결과를 NPC와 세계가 기억하는 구조**여야 한다.

현재 완료 판정과 보상이 있는 퀘스트는 첫 발견 의뢰 하나다. 인장 수는 완료 여부에 따라 0 또는 1이다. 일일 대화는 날짜별로 보관하지만 별도의 완수·회고·후속 탐구 연결이 없다. 연구·기사·면담 기능도 퀘스트 진행과 연결되지 않는다.

## 우선 보완할 실제 동작

### P1 · 저장된 탐구 초안을 재방문 후 확정할 수 없음

- 재현 조건: 연구대에서 AI 설계 생성 → 자동 초안 저장 → 확정 전에 새로고침 → 연구 수첩의 초안 열기.
- 현재 초안은 조회되지만 연구 수첩에는 성찰 기록만 있고, 초안을 연구대로 복원하여 선택 이유와 함께 확정하는 동작이 없다. 종합 분석도 방향만 준비하고 재방문하면 그 준비 결과에서 다음 생성을 이어가는 경로가 없다.
- 영향: 저장한 AI 결과가 있어도 다시 분석해야 하는 상황이 생긴다. 장기 퀘스트의 중간 저장으로 사용하기 어렵다.
- 보완: 원래 대상·KG 버전·선택 자료 스냅샷·AI 결과·초안 ID를 복원하는 '이어서 연구하기'. 종합 분석은 준비된 추천 ID와 방향/과목을 복원한다.
- 근거: [GameObservatory.tsx](../../src/features/academy/game/GameObservatory.tsx) 23~24, 96, 106~115행, [inquiryDesignService.ts](../../src/features/inquiry-design/services/inquiryDesignService.ts) createDraftInquiryDesign/saveInquiryDesign.

### P2 · 첫 의뢰의 질문이 연구시설에 전달되지 않음

- 재현 조건: 첫 발견 의뢰 완료 → 보상창의 '별의 연구시설로 가기' → 연구대 열기.
- 현재 버튼은 장소만 이동한다. `progress.question`을 연구대의 `researchSeed`로 넘기지 않는다. 우편국의 연구 이동은 이 전달을 구현했다.
- 영향: '내가 발견한 질문으로 새 별을 찾는다'는 이야기의 연결이 끊긴다.
- 보완: 질문과 참고 활동의 출처를 전달하고, 교수의 인사·연구대 초안·후속 퀘스트가 같은 자료를 참조하도록 한다.
- 근거: [AcademyGame.tsx](../../src/features/academy/game/AcademyGame.tsx) 249~251행.

### P2 · 여행 수첩으로 가져온 생각을 첫 의뢰 이후에는 기록할 수 없음

- 재현 조건: 첫 의뢰를 끝낸 뒤 사서/루온과 자유 대화 → '내 마지막 생각을 여행 수첩으로 가져가기'.
- 현재 새 생각을 `question` 상태에 넣지만 수첩 입력폼은 `step === 'read'`일 때만 보인다. 완료 상태에서는 예전에 저장한 첫 의뢰 질문만 표시한다.
- 영향: 가져오기 버튼을 눌러도 새 생각을 편집·보관할 수 없다. 첫 의뢰 후 추가로 읽은 책에서도 질문 기록 버튼이 사라진다.
- 보완: 첫 의뢰 제출과 별개로 여러 개의 질문을 보관하는 개인 발견 수첩을 만들고, 퀘스트는 그 기록 ID를 참조한다.
- 근거: [AcademyGame.tsx](../../src/features/academy/game/AcademyGame.tsx) 238, 241~245행, [GameBook.tsx](../../src/features/academy/game/GameBook.tsx) 44행.

### P2 · 자정을 넘긴 일일 대화의 실패 복구 경로가 없음

- 재현 조건: 자정 전에 답변을 전송했으나 AI 후속 응답 실패 → 다음 날 날짜별 기록에서 이전 대화 열기.
- 답변은 저장되지만 `past`가 선택되면 보내기/재시도 동작을 모두 막는다. 따라서 실패한 후속 응답을 게임 화면에서 다시 받을 수 없다.
- 보완: 지난 날짜의 새 질문 생성은 금지하면서, 이미 저장된 답변의 미완료 응답만 재시도하도록 구분한다. 최초 질문도 생성되지 못한 지난 기록은 상태와 종료 이유를 명시한다.
- 근거: [DailyEncounter.tsx](../../src/features/academy/game/DailyEncounter.tsx) 27~31, 52~53행, academy_daily_claim의 날짜/질문 조건.

## 게임으로서 부족한 부분

| 항목 | 현재 | 필요한 변화 |
| --- | --- | --- |
| 이야기 진행 | 첫 의뢰 완료 후 자유 탐색 | 기존 활동 결과를 참조하는 다음 장/연속 의뢰 |
| 선택의 영향 | 주로 화면 이동·분야 선택 | 같은 소재라도 비교 대상·관점·행동에 따라 후속 대사와 의뢰 변화 |
| NPC의 기억 | 자유 대화는 닫으면 초기화, 일일 AI에는 해당 날짜 대화만 전달 | 확인 가능한 이전 기록과 학생이 보관한 생각을 근거로 회상 |
| 기다리는 대화 | NPC별 고정 준비 대사, 후속 답변 때도 반복 | 질문 준비/답변 생각/재시도를 구별한 대사와 짧은 행동 연출 |
| 성장 표현 | 첫 인장 하나 | 발견 수첩, 책갈피·전서구 우표·별자리 장식, NPC의 기억 장면 |
| 면담의 누적 | 면담을 떠나면 답변·평가 초기화 | 같은 질문의 답변 수정 이력과 내용별 조언을 다시 볼 수 있는 기록 |
| 일일 질문 다양성 | KG의 ID순 최대 35개, 지난 날짜 질문은 미참조 | 최근 관심·활동 및 이전 질문의 중복을 고려해 요청 시 생성 |

NPC가 기억하는 내용은 실제 저장 기록과 출처에 연결해야 한다. AI가 만든 추정·요약을 학생의 실제 경험이나 KG의 확정 사실로 자동 등록하지 않는다.

## 추천 퀘스트 구성

### 1. 첫 발견의 연속 의뢰 — 가장 먼저 개발

**엘리안의 책 → 리아의 질문 → 카시안의 연구대 → 실제 실행 기록 → 교수의 회고**

| 단계 | 플레이 | 완료 근거 | 세계의 반응 |
| --- | --- | --- | --- |
| 기록에서 씨앗 찾기 | 책에서 궁금한 점과 이유 남기기 | 개인 질문 기록 + 참고 활동 ID | 사서가 그 책을 기억함 |
| 별의 설계도 | 질문·선택 자료를 교수와 검토하고 자신의 이유로 탐구 확정 | 본인 status=saved 설계 ID | 연구대에 해당 설계도 표시 |
| 별을 따라 걷기 | 실제 탐구를 수행하고 본인 활동 기록 연결 | 실행 활동 ID + 학생 확인 | 관측 진행 상태 변화 |
| 나의 발견 설명하기 | 실제 내용 기반 질문에 답하고 성찰 남기기 | 면담/성찰 기록 ID | 교수의 회고 장면과 기념 장식 |

설계만 만든 것을 실제 활동 완료나 KG의 새 지식으로 표시하지 않는다. '계획한 별'과 '실행 기록이 있는 별'의 시각 표현을 구분한다. 실제 활동에 시간이 필요하므로 날짜가 바뀌어도 진행을 유지한다.

### 2. 노엘의 특파원 의뢰

편지 선택 → 기사에서 확인된 사실과 자신의 해석 구분 → 노엘과 관점 대화 → 확인할 방법을 관측 일지에 저장 → 필요하면 연구대에서 탐구로 연결한다.

단순 기사 열람 횟수보다 학생이 남긴 질문·근거·확인 계획을 진행의 기준으로 삼는다. 완료 후 해당 기사 날짜·제목이 붙은 우표를 개인 우편첩에 남긴다. 새로운 기사 사실은 확인 가능한 원문/수집 자료를 사용한다.

### 3. 엘리안의 비교 독서 의뢰

관심 분야의 활동 두 개를 고르고 접근 방식·공통점·차이를 비교 → 자신이 해 보고 싶은 방향을 설명 → 개인 책갈피에 두 출처와 생각을 보관한다.

공식 아카이브 수정은 기존 제안·검토 흐름을 따른다. 개인 책갈피나 AI 대화가 공개 기록을 자동 수정하지 않는다.

### 4. 오늘의 만남에서 다음 모험으로

요청한 **하루 한 명의 NPC·하루 한 첫 질문·선택 시 생성** 원칙을 유지한다. 답변 뒤 '오늘 남길 생각'을 학생이 선택해 수첩에 보관하고, 원하는 경우 연구/독서 의뢰로 이어간다. 다른 NPC의 일일 질문을 추가해 하루 제한을 우회하지 않는다.

출석을 놓쳤다고 진행을 삭제하거나 친밀도를 깎지 않는다. 핵심 탐구·열람 기능은 보상 획득과 관계없이 사용할 수 있다.

## 추가 기능 우선순위

1. **공통 발견 수첩과 재개**: 책·기사·일일 대화·면담의 출처, 내 생각, 이어할 일을 한곳에서 관리.
2. **연속 퀘스트 진행 관리**: 수락·진행·보고 가능·완료 상태, 다음 행동 안내, 여러 창/재시도에서도 한 번만 완료 처리.
3. **근거가 있는 NPC 기억**: '지난번 네가 궁금해한 하천 이야기'처럼 이전 기록을 실제로 참조. 이름만 바꾼 공통 대사보다 장소별 역할을 강화.
4. **수집과 공간 변화**: 내 책갈피, 기사 우표, 설계도, 관측실 장식. 반복 클릭이나 AI 점수만으로 무한 보상을 얻지 않도록 한다.
5. **단계별 연출 에셋**: 책을 건네는 손, 교수의 기록 읽기, 전서구 착지, 설계도 놓기·별 점등. 기능 진입과 실제 완료 순간에 맞춰 제작한다.

질문 내용은 계속 요청 시 AI로 만든다. 퀘스트 단계·완료 조건·보상 규칙은 코드/메타데이터로 명확히 관리하고 AI의 '완료했다'는 대사로 상태를 변경하지 않는다. 핵심 학습 데이터는 기존 DB를 사용하고 게임 메타데이터는 원본 기록 ID를 참조한다.

## 다음 구현의 수용 기준

- 첫 의뢰 질문과 출처를 복사·재입력 없이 연구대에서 이어갈 수 있다.
- 저장된 초안과 종합 분석 준비 결과를 새로고침 뒤에도 이어서 확정할 수 있다.
- 첫 의뢰 완료 후에도 다른 책과 대화에서 발견한 질문을 계속 보관할 수 있다.
- 새 일일 질문을 생성하지 않고 지난 답변의 실패 응답을 복구할 수 있다.
- 퀘스트 완료는 실제 본인 기록의 저장 성공 이후에만 반영되고 중복 보고 시 보상이 중복되지 않는다.
- 교수 질문은 실제 자료에 따라 생성하며, 일반형/경험형 구분은 평가에 적용한다.
- 한 연속 의뢰를 끝내면 내 수첩·NPC 반응·장소의 소품 중 적어도 하나에 다시 확인할 수 있는 변화가 남는다.

권장 구현 순서는 **기록 재개·전달 보완 → 첫 발견 연속 의뢰 → NPC 기억 → 특파원/비교 독서 → 수집·연출 확장**이다.
