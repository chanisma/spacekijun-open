# 문서 분석과 공지 AI 도우미

- 문서 분석은 파일 첨부와 텍스트 입력을 지원한다. 텍스트는 선택 제목과 함께 기존 TXT 파서·분석·이력 저장 경로를 사용한다. 파일 업로드 없이 입력하고 바로 분석할 수 있다.
- 모달은 분리된 헤더, 스크롤 본문, 고정 푸터를 사용한다. 후보를 검토하고 선택한 업무 초안을 기존 이벤트 작성 흐름으로 넘긴다.
- 공지사항 오른쪽 하단 AI 도우미에 원문을 입력하면 제목·본문·확인 사항을 생성한다. 제목과 본문을 수정하고 공지 작성 폼으로 넘긴 뒤 부서·게시 기간 등을 정해 등록한다. AI 생성 자체는 공지를 게시하지 않는다.
- 공지 생성은 기존 aiChat/Solar 인증 프록시를 재사용한다. 원문은 최대 30,000자이며 응답 형식을 검사한다. 작성자·부서·게시 기간 등 메타데이터는 AI 응답에서 받지 않는다. 닫기/취소 후 도착한 응답은 무시한다.
- 새로운 스키마나 Edge Function 배포는 필요 없다. 기존 AI 프록시 설정과 문서 분석 이력 테이블을 사용한다.

## 학교 문서 분석의 504 — 원인 둘과 대처 (2026-09-23)

사용자 보고: `solar-proxy` 가 **504 Gateway Timeout**. 매번은 아니고 가끔. 파고 보니
**서로 독립인 결함이 둘**이었고, 둘 다 빌드·타입 검사를 통과하며 화면에도 신호를 남기지
않았다. 하나는 "가끔 실패", 다른 하나는 "성공했는데 결과가 빈다"로 나타난다.

### ① 추출 과제에 추론이 켜진 채 나가고 있었다 — 504의 직접 원인

엣지 게이트웨이는 약 150초(`Request idle timeout limit (150s)`)에 요청을 끊는다.
`solar-proxy` 의 `reasoningEffort` 기본값은 `'low'` 인데 **`aiChat` 에는 이 값을 넘길
통로가 아예 없었다** — 그래서 이 앱에서 가장 큰 단일 프롬프트(최대 45,000자)가
추론을 켠 채로 나갔다.

**같은 문서·같은 모델(`solar-pro4`) A/B 실측** (`scripts/ai-chat-live-test`, 합성 가정통신문 ≈9,000자):

| `reasoning_effort` | 결과 | 벽시간 | 추론 토큰 | 후보 |
|---|---|---|---|---|
| `'low'` (고치기 전 실사용값) | **실패** | **> 180초** (하네스 상한 안에도 미완료) | — | — |
| `'none'` (지금) | 성공 | **33.1초** | **0** (0%) | 16건 |

즉 `'low'` 는 **구조적으로 150초를 넘는** 설정이었다. "매번은 아니다"는 문서 길이가
그 선을 넘나들었기 때문이지 운이 아니다.

- 값은 **모델에서 유도한다** — `documentAnalysisService.DOCUMENT_ANALYSIS_REASONING_EFFORT_BY_MODEL`
  은 `specFillService.PLAN_REASONING_EFFORT_BY_MODEL` 과 같은 규약으로 **측정된 모델만**
  담는다(현재 pro4 하나). 표에 없으면 **아무것도 보내지 않고** 엣지 기본값 `'low'` 가
  적용된다 — 미전송과 미적용은 다르다. **모델을 바꾸면 여기부터 재측정할 것.**
- `aiChat` 에 `reasoningEffort` 가 생겼다. 세 값이 서로 다른 요청이다 —
  `undefined`(미전송 → 엣지 기본 `'low'`) · `null`(키 자체를 뺀 요청 → 모델 기본값) ·
  `'none'`(끄라고 명시). **solar 경로에만 실린다**(openai-proxy 는 이 키를 모른다).

### ② 근거 blockId 가 정확 일치만 인정돼 후보가 전부 버려졌다 — "후보 0건"의 정체

프롬프트는 블록을 `[block:p1 p.1]` 로 직렬화하는데(`chunkDocument.serializeBlock`),
모델은 **대괄호 안을 통째로** `evidence.blockId` 에 옮겨 적는다. 실측에서 정확히 추출한
후보 3건의 blockId 가 전부 `"block:p1 p.1"` 이었고, 검증기가 `validBlockIds.has(...)` 로
정확 일치만 봤으므로 **세 건 모두 버려져 후보가 0건**이 됐다. 화면에는 "근거가 확인된
실행 후보가 없습니다" 만 뜬다 — 오류가 아니라 **정상적인 빈 결과로 위장**한다.
페이지 번호가 붙는 **PDF** 가 정확히 이 형태다.

- 수정 = `validateAnalysis.resolveBlockId` — `block:` 접두사·대괄호·쪽 표시를 걷어내고
  **실재하는 id 에 맞춰 본다**. **환각 방지는 그대로다**: 없는 블록은 계속 버리고 경고에
  남긴다(장식을 걷어낼 뿐 블록을 만들어 내지 않는다).
- 프롬프트에도 표기 규칙을 명시하고 버전을 `school-document-analysis/0.3.0` 으로 올렸다.
  **프롬프트만으로는 보장되지 않으므로** 읽는 쪽 정규화가 본 방어선이다.
- 실측: 같은 문서에서 후보 **0건 → 16건**.

### 시간 초과가 났을 때의 대처

1. **오류를 값으로 판정한다.** supabase-js 는 504를 `FunctionsHttpError("Edge Function
   returned a non-2xx status code")` 로 감싸는데 **그 문장에는 숫자가 없다**. 그래서
   기존 `isRetryableError` 의 `/5\d\d/` 가 **한 번도 맞지 않았고**, 청크 경로의
   `retryOnce` 는 504에 단 한 번도 발동한 적이 없다. 지금은 `throwEdgeFunctionError` 가
   **`EdgeFunctionError`(`status`·`timedOut`)** 를 던지고 판정은 `aiChat` 의
   `isAiChatRetryableError` / `isAiChatTimeoutError` 단일 출처가 맡는다.
   → **새 기능에서 정규식으로 오류를 분류하지 말 것.**
2. **호출부가 게이트웨이보다 먼저 포기한다.** `aiChat({ timeoutMs })` — 단일 호출 100초,
   청크 70초. 150초를 그대로 버리면 대안을 시작할 때 이미 2분 반이 지난 뒤다.
   ⚠️ **요청이 취소되는 것은 아니다**(supabase-js v2 의 `invoke` 에는 `signal` 이 없다).
   "우리가 기다리기를 그만뒀다"는 뜻이므로 **같은 요청을 되쏘면 안 된다**.
3. **되쏘지 않고 더 작은 요청으로 바꾼다.** 단일 호출이 시간 초과면 **분할 분석으로
   전환**한다(청크 프롬프트 · 동시 2). 문서 생성에서 Solar fallback 을 걷어낸 것과 같은
   교훈이다 — 같은 크기로 다시 걸면 "느리게 실패하는 경로"만 하나 더 붙는다.
   **시간 초과일 때만** 내려간다(401·파싱 오류는 쪼개도 똑같이 실패한다).
4. **회로 차단.** 청크가 **연속 2회** 시간 초과면 남은 청크를 포기하고 모은 것만 병합한다.
   없으면 AI 가 느려진 날 40청크 × (70초 + 재시도 70초) 로 **40분 넘게** 돌다 전부 실패한다.
   결과에는 `AI 응답 지연으로 …` 경고를 붙여 **부분 결과임을 밝힌다**.
5. **취소가 실제로 듣는다.** 종전엔 `aiChat` 이 호출 **전후로만** `aborted` 를 봐서
   [분석 취소]가 화면만 바꾸고 사용자는 응답이 올 때까지 계속 기다렸다. 지금은 signal 을
   경주에 넣어 즉시 손을 뗀다.
6. **진행률이 되돌아가는 이유를 말한다.** 분할로 전환하면 `1/1` → `0/4` 가 되는데 아무
   설명이 없으면 고장처럼 보인다 → `DocumentAnalysisProgress.note`.

### 회귀

## 추출 결과를 사람이 고친다 — 카드별 수정 모달 (2026-09-23)

AI 가 뽑은 것을 **그대로** 업무로 만들지 않는다. 후보 카드마다 [수정] 을 눌러 별도 모달에서
다듬은 뒤 초안을 만든다. 고칠 수 있는 것은 **제목·설명·유형·기한** 넷이다(사용자 결정).

### 원본을 덮어쓰지 않고 «변경분»을 얹는다

저장 위치는 `analysis_result` JSONB 안의 **`candidateEdits`**(`localId` → 바뀐 항목만).
`candidates` 는 AI 원본 그대로 남는다. **마이그레이션이 없다** — 기존 컬럼 안이다.

그렇게 한 이유 둘 —
- `analysis_result` 는 `model`·`prompt_version` 과 짝을 이루는 **재현 기록**이다. 덮어쓰면
  "그 모델이 무엇을 뽑았는가"라는 그 행의 의미가 사라진다.
- 변경분만 담으면 «원본으로 되돌리기» 가 항목 삭제 한 줄이고, «수정됨 · 제목·기한» 배지도
  추측이 아니라 **데이터**가 된다. 원래 값으로 되돌려 놓으면 항목이 저절로 사라진다.

**기한은 `dates[]` 에 끼워 넣지 않는다.** 그 배열은 AI 가 **원문에서 읽은 표현**(근거)이지
결정이 아니다 — 섞으면 근거와 결정을 구분할 수 없다. 사람이 정한 기한은 `edit.dueDate` 로
따로 두고, 화면은 «업무 기한» 한 줄과 «문서 표현» 목록을 나눠 보여 준다(종전에는 원문 표현만
있어서 **여러 날짜 중 무엇이 초안에 들어가는지 알 수 없었다**).

`dueDate` 는 **3상태**다: `undefined`(안 고침 → AI 유도값) · `null`(기한 없음으로 명시) · 날짜.

### 조용히 틀리는 자리

- **⚠️ 화면·초안·유사 업무 매칭은 전부 `resolveCandidate()` 를 거칠 것.** 한 곳이라도 원본
  후보를 그대로 읽으면 «화면에는 고쳐졌는데 만들어진 업무는 원본» 이 된다 — 오류도 경고도
  없고 사용자는 자기가 저장을 안 눌렀다고 생각한다. 단일 출처 = `analysis/candidateEdits.ts`.
- **유형 수정은 «할 일이 되는가» 를 바꾼다.** `event·task·submission·approval` 만 초안의 할
  일이 되고 `constraint` 는 업무 설명의 관련 제약으로, `information` 은 아무것도 되지 않는다.
  그래서 편집 모달이 유형 아래에 그 결과를 **미리 말해 준다**.
- **이력에서 읽은 수정분을 믿지 않는다.** `analysis_result` 는 자유 JSONB 이고 재분석하면
  `localId` 가 바뀐다 → `normalizeCandidateEdits` 가 없는 후보의 «유령 수정», 알 수 없는 유형
  문자열, 형식이 틀린 날짜를 버린다.
- **근거(evidence)·신뢰도는 고치지 않는다.** «AI 가 원문의 어디를 보고 이렇게 판단했는가» 의
  기록이라, 사람이 손대면 카드가 원문을 가리키지 못한다. 편집 모달 아래에 읽기 전용으로
  보여 줘서 무엇을 근거로 고치는지 옆에 두고 판단하게 한다.
- **저장 실패해도 화면의 수정을 되돌리지 않는다.** 되돌리면 방금 친 글이 사라진다. 대신
  «이번 화면에서만 유효하다» 는 경고를 남긴다(업무 초안에는 반영된다).
- **이미 업무에 반영한 분석은 읽기 전용**이다(감사 기록) — [수정] 버튼이 뜨지 않는다.
- 저장은 `analysis_result` 통째 덮어쓰기라 **마지막 쓰기가 이긴다**. 이 표는 RLS 가
  `created_by` 본인으로 묶여 있고 편집 지점이 이 모달 하나뿐이라 지금은 충돌할 자리가 없다.
  다른 화면에서도 같은 행을 고치게 되면 `jsonb_set` RPC 로 옮길 것.

### 중첩 모달

카드 편집 모달은 문서 분석 모달 **위에 겹쳐** 뜬다(바깥을 닫지 않는다). `container` 를 넘기지
않으므로 body 로 포털돼 화면 가운데에 뜬다 — 넘기면 바깥 모달 가운데에 뜬다.
안쪽 `Select` 는 `DialogContent` 가 알아서 자기 안으로 포털한다. 규약 = `docs/nested-modal-pitfalls.md`.

### 회귀

- `npx tsx --tsconfig tsconfig.app.json scripts/document-analysis-test/edits.mts` (41건)
  — 변경분 최소화·3상태 기한·**원본 불변**·되돌리기·초안 반영·이력 값 검사.
- `scripts/document-analysis-test/ui/` — 브라우저 fixture. `npm run dev` 후
  `/scripts/document-analysis-test/ui/index.html` 을 열면 실제 편집 모달이 뜨고, 저장하면
  «AI 원본 / 변경분 / 초안» 셋이 각각 화면에 찍힌다. **중첩 Dialog 안의 Select** 는 이
  저장소에서 반복적으로 오류 없이 깨진 자리라 눌러 보는 것 말고 확인할 방법이 없다.

## 검증

공지 응답 파싱 단위 검사와 실제 컴포넌트/모의 서비스 기반 브라우저 검사에서 텍스트 분석 → 업무 초안, 공지 AI 생성 → 수정 → 작성 폼 → 등록 후 즉시 목록 반영, 모바일 모달 푸터를 검증한다. 실제 모델 응답 품질은 자동 검사 범위에 포함하지 않는다.
