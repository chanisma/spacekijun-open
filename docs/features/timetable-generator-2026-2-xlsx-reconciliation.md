# 2026학년도 2학기 수강 원본 대조와 정정

> 후속 결과(2026-09-23): 동일 원본 629명·804수업의 기본 공강·교사 하드 제약을 모두 만족하는 배치를 찾고 검증했다. [가능성 검증 완료 보고서](./timetable-generator-2026-2-feasibility.md). 아래 탐색 미완성은 정정 당일의 기록이다.

2026-09-22. 사용자가 제공한 Downloads 폴더의 `학생편성현황(2026학년도  2학기  1).xlsx`, `… 2).xlsx`, `… 3).xlsx`를 기준으로 DB 수강 명단을 대조하고 정정했다. 운영 중인 학생 시간표의 과목 명단으로 보정하지 않았다.

## 원본 대조 결과

| 학년 | 원본 행 | DB에만 있던 행 | 원본에만 있던 행 |
| --- | ---: | ---: | ---: |
| 1 | 2,240 | 20 | 20 |
| 2 | 1,927 | 47 | 58 |
| 3 | 2,130 | 1 | 8 |
| 합계 | 6,297 | 68 | 86 |

학년·반·번호·이름·과목·분반으로 대조했다. `미재학` 이름 표기도 원본 정보라 포함한다. 따라서 68행 제외·86행 추가 모두가 실제 수강 변경이라는 뜻은 아니다. 1학년의 20행은 두 학생의 미재학 표기 차이다. 기존과 매칭된 행의 학점 차이는 0건이었다.

`주제 탐구 독서`는 DB 40명에서 원본 43명으로 정정됐다. 학생 집합 기준으로 원본에 없는 21명 제외·원본에 있는 24명 추가다. 이전에는 운영 시간표만으로 이 정정을 확정할 수 없었으나 이번에는 **사용자가 제공한 수강 원본**으로 확인했다. 기존 과부하 20명도 모두 해소됐다.

## 반영과 검증

- 변경 전 6,279행 전체 백업, 변경 계획과 복구 SQL을 로컬 Git 제외 폴더 `reports/private/`에 저장했다.
- 기존 변경 대상의 전체 행이 백업과 동일한지 검사하고, DB 트랜잭션에서 68행 제외·86행 추가를 실행했다. 먼저 ROLLBACK 시험 실행을 통과한 뒤 COMMIT했다. 스키마 변경은 없다.
- 반영 후 DB를 다시 조회하여 세 원본과 대조했다. 누락·추가·학점 차이 및 등록의 학생/강좌 연결 차이 0건, 전체 6,297행을 확인했다.
- 공동 교사 강좌는 기존 수강 명단이 연결된 강좌 ID를 사용했다. 학생은 학년·반·번호·이름을 모두 확인했다. 미재학 1명은 학생 리소스가 없어 연결을 null로 보존했으며 임의로 다른 학생에 연결하지 않았다.
- 원본의 미재학 6명(1학년 2, 2학년 4)은 기록을 보존하고 생성 입력의 과목·진로활동 명단에서 제외한다. 생성 대상은 629명(222/190/217), 수업 804개다. 미재학도 포함한 원본 전체에서도 시수 초과는 없다.
- 기본 공강은 그대로 유지했다. 2학년 생성 대상 190명은 모두 31교시이며 과부하 사전 검사를 통과한다. 통과는 배치 가능성의 충분조건이 아니다.
- 반영 후 DB 행에 실제 서비스와 동일하게 학생 리소스의 학년·반 보정을 적용한 입력도 629명·804수업, 사전 검사 경고 0건을 확인했다. 이전 과부하 20명을 이름·학년·반·번호로 각각 다시 대조해 모두 34→31교시로 해소된 것을 별도 CSV에 기록했다.

## 배치 탐색 결과

원본 기반 픽스처 `grades123-2026-2-xlsx.json`을 사용했다. 시간표 원본은 수강 과목의 근거로 사용하지 않는다.

| 모드 | 시드 | 시간 | 결과 |
| --- | ---: | ---: | --- |
| 표준 | 7 | 90.5초 | 교사 동시수업 1건, 일일 상한 16건, 연속 수업 49건, 마지막 교시 상한 13건 |
| 정밀 | 11 | 240.4초 | 교사 동시수업 1건, 일일 상한 18건, 연속 수업 58건, 마지막 교시 상한 9건 |
| 기존 교사 위치로 초기화한 정밀 | 7 | 240.4초 | 교사 동시수업 1건, 일일 상한 15건, 연속 수업 33건, 마지막 교시 상한 7건 |

위 실행은 완전한 해를 찾지 못했다. 세 번째 실험은 수강 명단과 시수를 그대로 유지하고 교사 시간표의 위치만 초기화에 사용했다. 804수업 중 779개의 위치를 연결할 수 있었으며 나머지는 이전 탐색 위치를 사용했다. 이는 입력 과부하와 구분되는 탐색 미완성이며 배치 불가능의 증명이 아니다. 다른 자료를 입력으로 사용했던 이전 성공 결과를 이 원본 명단의 성공으로 대체하지 않는다.

회귀 테스트 42개, 기능 범위 ESLint, 프로덕션 빌드가 통과했다. 생성 후보를 운영 시간표에 확정하지 않았다.

## 재현과 상세 자료

`scripts/timetable-generator-test/audit-enrollment-xlsx.mts`는 로컬 DB 조회 백업과 원본 세 파일을 대조하고 변경 계획·시험 SQL·복구 SQL·익명 픽스처를 만든다. 이 스크립트 자체는 DB에 쓰지 않는다. `VERIFY_ONLY=1`은 변경 계획을 덮어쓰지 않고 반영 후 일치를 검사한다. SQL은 검토 시점의 변경 대상 행과 건수를 확인하며, 재실행은 백업 이후 변경 검증에서 거부된다.

생성 테스트:

```powershell
$env:FIXTURE='grades123-2026-2-xlsx.json'
$env:MODE='standard'
$env:SEEDS='7'
npx tsx scripts/timetable-generator-test/run-coordinated.mts
```

개인정보 포함 상세는 `reports/private/2026-2-xlsx-enrollment-corrections.csv`(154개 변경 행)와 `2026-2-xlsx-enrollment-comparison.json`에 있다. `2026-2-enrollment-overload-resolved.csv`는 20명의 과부하 해소를 확인한 자료다. 이전 `2026-2-enrollment-overload.csv`는 정정 전 문제 20명의 기록이며 현재 오류 명단이 아니다.

기존 수강 업로드는 키별 추가/갱신 방식이어서 새 원본에서 사라진 등록을 자동 삭제하지 않는다. 파일을 다시 올리는 것만으로 삭제 정정까지 처리되지는 않는다. 이번 정정은 전체 학기 자료를 대조한 명시적 변경 계획으로 수행했다.
