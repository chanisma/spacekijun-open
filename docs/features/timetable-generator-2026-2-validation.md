# 2026학년도 2학기 공강 활동 제외와 생성 검증

2026-09-22. 아래는 **수강 원본 제공 전** 검증 기록이다. 이후 사용자가 제공한 세 엑셀로 수강 명단을 정정해 과부하를 해소했다. 현재 상태와 DB 반영 내역은 [원본 대조·정정 결과](./timetable-generator-2026-2-xlsx-reconciliation.md)를 따른다. 아래 실험 당시에는 DB를 조회만 했다.

## 최종 생성 기준: 수강 신청 명단

최종 사용자 지시에 따라 **새 생성과 공강 진단은 `course_offering + student_enrollment`를 기준으로 한다.** 목표는 현재 운영 중인 시간표를 재현하는 것이 아니라 수강 명단의 학생별 과목·시수를 유지하면서 주어진 격자 안에 배치할 수 있는지 확인하는 것이다. 화면의 편성 기준은 `수강 신청 명단`으로 고정했다. 현재 학생 시간표는 대조 자료이며, 이 자료에 없다는 이유로 수강 과목을 삭제하거나 이 자료에만 있다는 이유로 추가하지 않는다.

원본 수강 명단으로 재검증한 결과 **2학년 20명이 34교시를 수강하지만 가용 칸은 31칸**이다. 기존 공강과 시수를 유지하면 학생 한 명의 수업조차 모두 배치할 수 없으므로, 탐색 시간 부족이 아닌 **입력 데이터 오류**로 사전 검사에서 거부한다. 진단에는 학년·인원·필요 시수·가용 칸·초과 시수를 집계하며, 공강을 줄여 오류를 우회하도록 안내하지 않는다. 표준 모드 seed 7 실행은 사전 검사 4ms 후 `invalid-input`으로 끝났으며 탐색을 시작하지 않았다.

과부하 20명의 전체 등록 과목·시수·분반은 로컬 `reports/private/2026-2-enrollment-overload.csv`에 정리했다. 독서 과목 불일치 45명의 CSV와는 목적이 다르다. 실제로 어떤 등록이나 시수가 잘못되었는지는 원본 자료 확인이 필요하며, 운영 시간표와의 차이만으로 독서 등록을 삭제하지 않는다. 두 원본 자료는 이후 수정 여부가 다를 수 있다.

최종 기준 변경 후 회귀 테스트 40개, 기능 범위 ESLint, 프로덕션 빌드가 통과했다. 과부하 CSV는 20행이며 식별 정보·전체 등록 과목 누락과 시수 불일치가 없음을 검사했고, 개인정보 포함 보고서의 로컬 Git 제외도 확인했다.

오류 메시지 재현 후 추가로 DB의 동일 학생·강좌 중복과 동일 학생·과목 복수 등록을 검사했으며 2학년 배치 대상 교과에서 모두 0건이었다. 과부하 학생은 각각 서로 다른 11과목 33학점에 진로활동 1교시가 더해진다. 저장소의 2026-05-07자 2학기 2학년 교육과정 보고서와 픽스처의 일반 교과 24과목 학점도 일치했다(진로활동은 해당 교과 행이 없어 대조 제외). 최신 수강 신청 원본이나 정정 근거가 필요하다. 결과 화면에서는 사전 검사 실패를 `입력 사전 검사에서 중단되었습니다`로 표시해 탐색 후 후보를 찾지 못한 경우와 구분했다. 표시 수정 후 회귀 40개와 해당 파일 ESLint가 통과했다.

## 이전 학생 시간표 기준 비교 실험과 저장본 호환

이전에 요청받아 구현한 학생 시간표 입력 경로는 비교 테스트와 해당 기준으로 저장된 계획의 복원용으로 남긴다. 새 생성의 기준으로 사용하지 않는다. 저장본은 기록된 `sourceBasis`를 따르고, 기준이 없는 구 저장본은 수강 명단으로 복원한다.

`studentTimetableSource.ts`는 학생 시간표의 실제 과목·주당 시수·교사 분담으로 분반과 명단을 복원한다. 학생 시간표 FK 또는 교사 시간표의 동일 학년·과목·교사·교시를 통해 실제 개설강좌 ID에 연결한다. 두 경로에 연결이 없을 때만 **그 학생이 현재 시간표에서 듣는 과목**의 기존 수강 강좌를 보조로 참조한다. 수강 명단에만 있는 과목은 추가하지 않는다. 연결이 없거나 모호하면 오류를 반환한다. 가상 강좌 ID와 실제 DB 강좌 ID를 분리해 확정 행에 가상 ID가 들어가지 않도록 검사한다.

실제 서비스 어댑터를 통과하는 `grades123-2026-2-source.json` 픽스처로 630명·804수업, 학생별 실제 과목·시수 보존, 전체 강좌 ID 연결을 검증했다. 표준 seed 7은 87.7초에 하드 위반 0, 표준 seed 11은 90.5초 후 연속 수업 위반 2건으로 미완성이었다. 아래 이전 비교 픽스처 결과와 구분해야 한다.

정밀 seed 7의 추가 검증은 79.5초에 하드 위반 0으로 종료했다. 동일 후보를 `prepareTimetableFinalization`에 전달해 학생 행 18,991개, 교사 행 804개가 실제 강좌 ID로 전개되는 것까지 확인했다(DB 쓰기 없음). 회귀 테스트는 최종 40개 통과, 기능 범위 ESLint 통과. 전체 TypeScript 검사에는 기존 다른 영역 오류 202개가 있고 이 기능 경로 오류는 없다. 현재 원본 시간표 좌표 자체에는 같은 과목 하루 중복 6건이 있어, 학생 시간표를 수강 기준으로 삼더라도 그 기존 배치를 무검증으로 확정하지 않는다.

불일치 상세는 로컬 `reports/private/2026-2-reading-enrollment-audit.csv`, 설명은 같은 이름의 `.md`에 있다. 학생 이름·반·번호가 포함되어 로컬 Git 제외 목록에 등록했으며, 원본 수강 명단을 수정한 내역이 아닌 조회 시점 대조 보고서다.

## 공강 칸의 수업은 다시 분배하지 않는다

사용자가 지정한 범위는 학생 시간표에 남아 있어도 생성기가 배치할 필요가 없는 자율·자치활동과 동아리활동이다. 기존 `buildTimetableInput`의 `isActivitySubject` 검사가 이미 이를 제외하고 있었다. 해당 처리를 중복 구현하거나 원본 시간표에서 삭제하지 않고, 화면 안내를 명확히 하고 회귀 테스트를 추가했다. 진로활동은 기존 정책대로 배치한다.

| 학년 | 공강 칸에 실제 존재하는 수업 | 학생 시간표 행 수 |
| --- | --- | ---: |
| 1학년 | 화4 자율·자치, 금4·5 동아리 | 666 |
| 2학년 | 화4 자율·자치, 금4·5 동아리 | 573 |
| 3학년 | 화4 자율, 금4·5 동아리 | 651 |

합계 1,890개 학생별 시간표 행이다. `course_offering`에는 이 활동에 대응하는 강좌 54개가 있으며, 생성 입력에 포함된 해당 활동 Lesson은 **0개**다. 1·3학년 월4·수4 및 2학년 월4는 해당 학기 학생 시간표에 수업이 없으며 그대로 배치 금지 칸으로 유지한다.

## 수강 명단과 현재 학생 시간표는 다르다

화면의 입력 경로는 `course_offering + student_enrollment`이다. 이 원본으로 만든 2학기 입력은 633명·804개 수업이며, 자율·동아리를 제외한 뒤에도 2학년 20명이 주 34교시로 계산된다. 가용 칸은 31개여서 사전 검사가 즉시 실패한다. 이는 공강 활동을 잘못 포함한 결과가 아니다.

대조 결과, 이 20명은 현재 학생 시간표에 없는 **주제 탐구 독서 3교시**가 수강 명단에 있었다. 과목 전체 대조에서는 수강 명단에만 있는 학생 21명, 학생 시간표에만 있는 학생 24명이 확인됐다. 이 불일치 45명 모두가 잘못된 수강 명단이라는 뜻은 아니다. 20명의 총시수 초과는 확인됐지만 잘못 등록된 과목이 독서인지는 확정할 수 없다. 수강 명단을 임의로 수정하거나 특정 학생의 과목을 자동 삭제하지 않았다.

## 비교 테스트 입력

이름·UUID·실제 학번을 제거한 두 픽스처를 별도로 보관한다.

- `scripts/timetable-generator-test/grades123-2026-2.json`: 실제 생성 화면과 동일한 개설강좌·수강 명단 입력. 410개 원본 강좌, 수강 행 6,279개. 용량 초과 실패를 재현한다.
- `scripts/timetable-generator-test/grades123-2026-2-timetable.json`: 현재 `student_timetable`에서 복원한 **비교용 입력**. 학년·과목과 주간 교시/교사 목록이 같은 학생들을 한 분반으로 묶고, 실제 주간 시수 및 교사별 분담 수를 유지했다. 학생 630명(1학년 222, 2학년 191, 3학년 217), 수업 804개(270/267/267). 자율·동아리 분반도 원본 픽스처에는 두되 입력 빌드에서 제외한다.

최초 비교용 강좌는 테스트용 ID이므로 운영 DB 확정용 데이터가 아니다. 이후 추가한 `grades123-2026-2-source.json`은 이름·UUID를 제거한 실제 학생/교사 시간표와 원본 강좌 연결을 함께 보관하여 서비스 어댑터까지 검사한다. 학생 시간표 비교 입력에서의 성공은 원본 수강 명단의 배치 가능성을 입증하지 않는다. 기존 수강 명단 원본은 변경하지 않았다.

## 이전 비교 실험 결과

학생 시간표 기준의 비교 입력은 2학년 191명 전원이 정확히 31교시이며 사전 검사를 통과했다. 시간 칸·수강 과목·시수·교사 제약을 줄이지 않았다.

| 입력 | 모드 / 시드 | 시간 | 결과 |
| --- | --- | ---: | --- |
| 개설강좌·수강 명단 | 표준 / 7 | 사전 검사 4ms | 34교시 > 31칸으로 거부 |
| 현재 학생 시간표 | 표준 / 7 | 43.0초 | 하드 위반 0 |
| 현재 학생 시간표 | 표준 / 11 | 38.8초 | 하드 위반 0 |
| 현재 학생 시간표 | 표준 / 19 | 90.5초 | 교사 연속 수업 위반 1건, 미완성 |

이번 표준 모드 3개 시드 중 2개는 성공했고, 1개는 교사 연속 수업 위반 1건을 남겼다. 성공 후보는 원본 명단에서 재분반을 다시 계산한 뒤 검증했고, 점수 함수와 독립된 카운터로 학생·교사 동시수업, 교사 부하, 공강 칸, 전체 수업 배치를 확인했다. 픽스처 → 입력 변환에서도 학생별 과목·시수가 실제 시간표와 일치하는지 회귀 검사한다. 시간 제한 탐색이므로 다른 실행의 성공률이나 동일 소요 시간을 보장하지 않는다.

최초 비교 실험 시점의 회귀 테스트는 31개였다. 이후 서비스 어댑터·명단 기준·과부하 진단을 포함해 40개로 확대했다. 브라우저 직접 조작과 운영 DB 확정은 수행하지 않았다.

## 재현

```powershell
npx jest --config scripts/timetable-generator-test/jest.config.cjs --runInBand

# 실제 화면의 수강 명단: 사전 검사 실패 재현
$env:FIXTURE='grades123-2026-2.json'
$env:MODE='standard'
$env:SEEDS='7'
npx tsx scripts/timetable-generator-test/run-coordinated.mts

# 현재 학생 시간표 기준 비교 테스트
$env:FIXTURE='grades123-2026-2-timetable.json'
$env:SEEDS='7,11,19'
npx tsx scripts/timetable-generator-test/run-coordinated.mts

# 실제 서비스 어댑터와 DB 쓰기 없는 확정 행 전개까지 검증
$env:FIXTURE='grades123-2026-2-source.json'
$env:SEEDS='7'
npx tsx scripts/timetable-generator-test/run-coordinated.mts
```

`AUDIT_ONLY=1`은 탐색 없이 입력 규모와 사전 검사만 출력한다. 생성 테스트 시에는 해당 환경 변수를 제거한다. 후보가 없거나 잔여 하드 위반이 있으면 실행 스크립트는 종료 코드 1을 반환한다. 원본 수강 명단 사례의 실패는 의도한 검증 결과다.
