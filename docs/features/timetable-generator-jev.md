# 시간표 생성기와 TypeSafe Jev 적용 검토

2026-09-22. Claude용 `typesafe-ai` 스킬 0.5.7 및 공식 라이브 문서를 확인했다. 이 문서는 적용 가능성 검토이며, Jev API 호출·SDK 설치·운영 연동은 수행하지 않았다.

## 판단

**자연어 요구를 기존 설정으로 변환하는 보조 기능에는 적합하다. 배치 솔버와 확정 검증을 대체하는 용도에는 적합하지 않다.**

현재 생성기는 명단·교사·교시라는 구조화된 입력을 받아 충돌 그래프와 탐색 알고리즘으로 시간표를 만든다. 이번에 확인한 공통수업 누락, 편집 내용 미저장, 잘못된 후보 확정은 데이터 연결·검증 결함이다. 이들은 결정적인 코드와 회귀 테스트로 해결해야 한다.

사용자가 지적한 핵심 문제인 **한정된 시간 칸에서 제약을 모두 만족하는 배치를 찾지 못하는 현상**에는 [배치·분반 공동 탐색](./timetable-generator-coordinated.md)을 구현했다. 이는 명단 매칭과 시간 배치를 함께 개선하고 연쇄 이동·MILP로 남은 위반을 수리하는 조합 최적화 문제다. Jev의 타입 제한 출력만으로 이 전역 제약 탐색을 대체할 수는 없다.

공식 스킬은 계산·정확한 조회·실행은 코드에 남기고 의미 이해가 필요한 지점에 모델을 넣도록 안내한다. 타입에 맞는 출력이 판단의 정확성까지 보장하지는 않는다. [공식 스킬](https://github.com/typesafe-ai/skills/blob/main/skills/typesafe-ai/SKILL.md), [Jev 소개](https://typesafe.ai/blog/introducing-system-one-models-and-jev).

| 적용 위치 | 평가 | 구체적인 연결점 |
| --- | --- | --- |
| 자연어 편성 요구 → 설정 제안 | 가장 유망 | `teacherUnavailable`, `blockedCellsByGrade`, 교사 부하 상한의 변경 초안 |
| 비표준 과목명 → 교과 분류 후보 | 제한적 | `categorizeSubject`에서 명확히 매칭되지 않는 이름만 검토 대상으로 분류 |
| 담당자의 선호 설명 → 후보 순위 | 조건부 | 기본 충돌 0인 후보만 대상으로 정성적 선호를 보조 평가; 기존 수치 점수는 유지 |
| 솔버 전략 선택 | 실험 필요 | 입력 규모·실측 성공률로 고른 기준선보다 좋은지 비교해야 함; 현재 도입 근거 없음 |
| 학생·교사 동시수업, 차단칸, 배치 누락 검사 | 부적합 | `evaluateFull`과 `prepareTimetableFinalization`의 정확한 검사를 유지 |
| 전 수업 배치·재분반·불가능성 증명 | 부적합 | 개별 확률적 선택만으로 전체 제약의 동시 충족을 보장할 수 없음 |
| 원본 강좌 ID 복원·저장·확정 | 부적합 | `sourceOfferingIds`와 명시적 검증으로 처리 |

## 권장 첫 실험

“2학년은 금요일 4·5교시를 비워 주세요” 같은 문장을 설정 변경 **초안**으로 바꾼다. 실제 값 목록에서 학년·교사·요일·교시를 선택하고, 금지/선호/기존 설정 유지/해당 없음 등의 의도를 별도로 판단한다. 복수 교시는 칸별 Noul 또는 코드에서 열거한 조합으로 표현하며, 단일 Choice를 복수 선택으로 오용하지 않는다.

흐름: 자연어 + 현재 설정 → 서버의 공용 AI 어댑터 → 제한된 선택지에 대한 판단 → 코드가 ID·범위·상충 여부 검사 → UI에서 변경 초안 검토 → `BuildInputConfig` → 기존 솔버. 모델에 DB 쓰기나 확정 권한을 주는 구조가 아니다.

공식 [function calling 예제](https://docs.typesafe.ai/cookbooks/function_calling)는 자연어를 함수와 닫힌 집합 인자로 연결한다. [Choice 문서](https://docs.typesafe.ai/primitives/choice)는 `instructions`와 옵션 설명을 담은 `criteria`를 요구하며 최대 255개 선택지를 지원한다. 저장소의 2026-09-21 연구 문서에 있는 `options` 예시를 현재 API 구현에 그대로 복사하지 말아야 한다.

검증 데이터는 한국어 합성 요청으로 만든다. 부정문, “가능하면”과 “반드시”, 복수 요일·교시, 동명이인, 존재하지 않는 대상, 기존 설정과 상충하는 요청을 포함한다. 설정 전체 일치율·잘못된 제약 추가율·재확인 비율·응답시간·비용을 측정하고 수동 설정/단순 파서와 비교한다. 질문과 기준은 한 파일에 모으고 API 키는 서버에서만 사용한다. 운영 도입 여부는 이 실험 결과로 판단한다.
