## 1. 모델·측정·기각 기록

- **예측 모델 재생성 (2026-09-04)**: 스냅샷이 2026-07-02 에 멈춰 세 학년 모두 한 학기씩 뒤처져 있었다(1학년은 **아예 없었고** 2학년은 2-1 을, 3학년은 3-1 을 못 봤다). 재생성 = `pip install -r ml/requirements.txt` 후 `python ml/train_grade_predictor.py`. **재생성 전에 `ml/out/snapshots/` 로 백업할 것** — 예측이 실측으로 바뀌면 그 예측을 다시 채점할 수 없다(사후 검증의 유일한 근거). 검증 스크립트는 `--snapshot ml/out/snapshots/...` 로 과거 스냅샷을 채점한다. 결과: 출력 636명(1학년 223 신규 · 2학년 196 · 3학년 217), 학습 표본 913 → **1,770**.
  - **⚠️ 그냥 돌리면 3학년이 통째로 사라졌다**: `predict_student` 는 `SEMESTERS` 의 다음 학기를 예측 대상으로 삼는데 3-1 이 실측이 되면 `remaining = []` 가 되고, 출력부의 `if preds:` 가 **학생 자체를 버렸다**(라이브 206명). 목록에서 빠질 뿐 아니라 `current_grades`·`key_exam_flow` 도 없어져 모의고사 흐름·9월 참고 등급·수능 추정 화면까지 못 연다. 지금은 `if raw_grades:` 로 담고, **화면이 "예측 없음"을 정상 상태로 표현**한다(`hasAnyPrediction`=false 면 표 제목이 '실측'이 되고 예측 차트 2개는 이유를 적은 안내로 대체). 3학년은 "예측할 내신 학기가 없다"가 정상이지 데이터가 없는 것이 아니다.
  - **⚠️ 등급제를 학년으로 판정하면 해마다 한 학년씩 밀린다**: 구 코드 `5 if grade == 2 else 9` 가 이미 틀려 있었다 — 현 1학년(26학번)은 석차등급 1~5(5등급제)인데 9등급제로 정규화돼 전원이 실제보다 좋게 나오고 되돌릴 때 "7.3등급" 같은 값이 나온다. 지금은 `build_grade_system_map` 이 **데이터에서 유도**한다: ①본인 최대 석차등급 > 5 면 9등급제(전입생 확정) ②아니면 같은 (입학연도, 학년) 집단에서 **5를 넘는 학생의 비율 ≥ 10%** 면 9등급제. **집단 최대값을 쓰면 안 된다** — 9등급제 학교에서 전입한 25학번 1명 때문에 2학년 196명이 통째로 9등급제로 뒤집혔다(실제 발생).
  - **⚠️ 학습 표본은 늘리는 것보다 등급제를 통일하는 것이 중요하다**: 24학번의 3-1 을 학습·입력에서 모두 빼고(`HOLDOUT_COHORT=24 HOLDOUT_FROM=3-1`) 같은 코드로 3-1 예측을 채점한 결과 — 졸업생만 913샘플: MAE 0.62·RMSE 0.81·편향 +0.15 / **9등급제 코호트 확장 1,565: MAE 0.62·RMSE 0.78·편향 +0.02** / 전체 확장(5등급제 포함) 1,952: MAE 0.65·RMSE 0.84·편향 +0.26. **표본을 가장 많이 늘린 쪽이 가장 나빴다.** 5등급제는 값이 5개 점에 몰려 한 칸 이동의 크기가 달라 전이 동역학이 다르고, α 가 0.70 → 0.87 로 튄 것이 신호다(α 는 검증셋에서 고르는데 확장 검증셋은 5등급제가 다수라 9등급제 예측에 과했다). 그래서 학습 풀은 **완성 전이가 가장 많은 등급제 하나로 통일**한다(연도를 손으로 고치지 않아도 전환되도록 자동 선택 — 현재 9등급제 1,939 vs 5등급제 387). **2027학년도부터는 9등급제 코호트가 사라지므로 그때 5등급제 표본으로 다시 측정할 것.**
  - **척도마다 모델을 하나씩 만든다 (2026-09-04 사용자 결정)**: 3학년(9등급제)을 예측할 땐 1·2학년 성적을 **9등급으로 환산**해 함께 쓰고, 1·2학년(5등급제)을 예측할 땐 반대로 3학년·졸업생을 **5등급으로 환산**한다. 환산은 수시 지원의 검증된 모듈을 이식한 **`ml/grade_scale.py`**(잠재특성+이산우도 사후평균, 원본 실측 RMSE 0.167·편향 −0.008)를 쓴다 — **midpoint 정규화로 두 척도를 잇지 말 것**. 그건 "등급 → 백분위 중간값" 대응이라 한 과목엔 맞지만 여러 과목의 **평균**엔 틀린다(비선형이라 평균의 변환 ≠ 변환의 평균). 환산에는 **그 평균에 들어간 과목 수**가 필요해서 교과군별로 실제 개수를 센다(기본값 13은 1~3과목짜리 교과군에 과하다). 이식 대조 = `npx tsx scripts/naesin-scale-test/cross-check.mts`(205 격자점, 최대 차이 1e-6등급 — 갈라지면 화면의 9등급 환산값과 모델이 학습한 값이 어긋난다). 역방향(9→5)은 원본에 없어 새로 만들었다.
  - **⚠️ 환산 표본은 "네이티브가 모자랄 때만" 넣는다**: 같은 홀드아웃으로 9등급제 예측을 잰 결과 — 9등급제 네이티브만 1,565샘플 **MAE 0.62·RMSE 0.78·편향 +0.02(최선)** / 전체를 환산해 추가 1,952샘플 MAE 0.64·RMSE 0.81·편향 +0.07 / midpoint 로 혼합 1,952샘플 MAE 0.65·RMSE 0.84·편향 +0.26. **환산은 midpoint 혼합보다 확실히 낫지만 네이티브만 쓰는 것보다는 못하다** — 환산에 잔차 SD 0.17등급이 원리적으로 남아(5등급제가 버린 상위 10% 안의 순위는 되살릴 수 없다) 표본을 늘리는 동시에 잡음을 더하기 때문이다. 반대로 5등급제 공간은 네이티브 완성 전이가 **387건뿐**이라 환산이 유일한 방법이다. 그래서 규칙은 `NATIVE_SAMPLE_FLOOR`(1,000) 미만일 때만 환산 표본으로 채우는 것이고, 이 값은 관측된 두 점(1,565=충분 / 387=부족) 사이의 **판단이지 측정된 임계값이 아니다**. 2027학년도에 9등급제 코호트가 사라지면 판정이 자동으로 뒤집히므로 **그때 재측정할 것**.
  - **1·2학년 예측 성능은 아직 잴 수 없다** — 타깃(2-2·1-2)이 산출되지 않았다. 위 수치는 전부 9등급제(3학년 3-1) 방향의 측정이고, 5등급제 방향에 그대로 옮겨 읽으면 안 된다.
  - **⚠️ 학년 차트는 "비어 보이지 않으면서" 틀릴 수 있다 (2026-09-05 사용자 발견)**: 3학년은 3-1 내신이 산출되는 순간 예측 대상 학기가 사라져 **예측 보유자가 3-1 성적이 없는 11명뿐**이 된다(라이브 217명 중). 그 11명은 무작위가 아니라 "아직 성적이 없는 학생"이라 하위권에 쏠려 있어(예측 평균 6.1등급), 예측 보유자만 세면 **상단 타일은 217명이라 쓰고 차트는 편향된 11명**을 그렸다. 지금은 **예측 보유가 과반이 아니면 최근 실측 모의고사**로 바꿔 그린다(217명 전원 · 평균 4.54등급). 판정·집계 단일 출처 = `analysisUtils.buildMockCohortChart`, 회귀 = `npx tsx scripts/mock-cohort-chart-test/run.mts`(30건). **`some()` 으로 '예측 학년'을 판정하지 말 것** — 11/217 도 true 가 되어 표 제목·차트가 실제 내용과 어긋난다(과반 기준). 무엇으로 그렸는지는 제목(`예측`/`실측`)과 부제의 분모로 화면이 밝힌다.
  - **모달의 예측 ↔ 실측 대조 (2026-09-05)**: 이 모달은 예측 표와 실측 표 **양쪽에서** 열리므로 "그때 뭐라고 했고 실제로 어땠는가"를 같은 자리에서 본다. **실측은 스냅샷이 아니라 DB 원본(`academic_development`)에서 읽어야 한다** — 스냅샷의 `current_grades` 는 그 스냅샷을 만든 시점의 실측이라, 7월 예측을 골라 사후 검증하려 해도 그때 없던 3-1 성적이 거기 있을 리 없다(대조표가 늘 비어 사후 검증이 불가능해진다). 계산 = `analysisUtils.semesterNaesinFromRecords`(파이프라인 `extract_semester_features` 와 같은 규칙 — `category='regular'` + rank 있는 행만, 이수단위 가중, **한국사는 사회로**). 라이브 교차 확인: 7월 스냅샷 기준 3-1 내신평균 MAE **0.625** 로 독립 검증 스크립트의 0.62 와 일치. 회귀 = `npx tsx scripts/naesin-actual-test/run.mts`(15건)
  - **3-2 예상 카드는 백분위가 본체다 (2026-09-05)**: 과목별로 6월·9월 실측을 나란히 두고 수능 예상을 낸다. 국어·수학·탐구는 백분위(괄호에 유도 등급), 영어·한국사는 절대평가라 등급만. 계산 = `evalearn/utils/suneungForecast.buildSuneungForecast`, 회귀 36건
  - **학생 모달은 영역·척도 토글 2개가 지배한다 (2026-09-05 사용자 지시)**: 헤더 **오른쪽 위**에 [내신 / 모의고사·수능]과 [등급 / 백분위]가 있고, **왼쪽(분석)과 오른쪽(실측)이 함께 바뀐다** — 따로 두면 "예측은 내신인데 실측은 모의고사"가 만들어져 나란히 놓은 뜻이 사라진다. 종전엔 척도 토글이 **네 곳**(차트·모의 예상·실측 내신·실측 모의)에 흩어져 각자 자기 구획만 바꿨고, 그래서 "백분위를 눌렀는데 옆 표는 등급"이 정상 상태였다. 조작 지점을 하나로 모으면 상태도 하나라 그 어긋남이 구조적으로 불가능해진다(`modalDomain`·`trendScale`). 이 정리 중에 마크업 결함도 드러났다 — **모의고사 예상·수능 예상이 `학기별 내신 예측`의 `<div>` 안에** 들어 있었다(시각적 문제가 아니라 DOM 상 자식이었다).
- **모의고사 예상은 대부분 이월값이다 — 표가 그 사실을 말해야 한다 (2026-09-05)**: 값 = **직전 실측 회차 × 0.6 + (그 학기 내신 예측을 내신↔모의 회귀에 넣은 값) × 0.4**(`train_grade_predictor.py` 의 `sub_norm`). "AI 가 예측한 모의고사 등급"으로 읽히지만 **6할이 직전 회차**라, 재료를 감추면 "왜 이 숫자인가"에 답이 없다. 표에 `직전 실측 ·0.6` / `내신 예측 ·0.4` 두 열을 나란히 둔다. 직전 실측이 없으면 회귀값만 쓰므로 그 칸은 `없음`으로 밝힌다(빈칸이면 0 으로 읽힌다).
