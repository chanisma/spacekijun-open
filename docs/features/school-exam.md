# school-exam

> CLAUDE.md Component Architecture에서 분리한 학교 지필평가(evalearn '학교 시험' 탭) 상세. 스키마는 docs/database/education-ontology.md.

#### 학교 지필평가 (evalearn '학교 시험' 탭, 2026-08-14 신설)
- **무엇인가**: NEIS 정기고사(1차·2차) 문항 정보와 학생 마킹을 evalearn에 들여, 모의고사 취약점 분석과 같은 자리에서 **내신 문항 분석**을 한다. 진입 = 학생 선택 → `AnalysisPanel`의 네 번째 탭. 스키마·데이터 성질 상세 = `docs/database/education-ontology.md` "School Exam Tables"
- **교사·관리자 전용 (2026-08-14 사용자 결정)**: 내신 점수·석차는 상담 도구로만 쓴다. `/evalearn`은 학생도 들어오므로 탭을 `RoleGate not="student"`로 감싸고, 서버도 `school_exam_*` RLS를 교사/admin으로 제한해 이중으로 막는다(실사용자 컨텍스트 검증: 교사 7,433행·학생 0행). **학생에게 열려면 RLS 정책 추가가 먼저**다 — 화면 분기만 풀면 API로 남의 점수가 그대로 나간다
- **모의고사에 없는 세 가지가 있다**: ①성취기준 코드(라이브 전 문항) ②교사 지정 난이도 ③문항별 배점. 그래서 취약점을 "내용영역"과 "성취기준" 두 축으로 볼 수 있고, **지정 난이도 vs 실제 정답률 괴리**라는 출제 피드백이 나온다
- **학생 매칭 키는 (학년, 반, 번호)**: NEIS 학번(`2026000182`)은 우리 학생코드(`00-00646`)와 이어지지 않는다. **이름으로 매칭하지 말 것** — 학년 내 동명이인이 19쌍이다. 이름은 검증에만 쓰고 자리와 어긋나면 따로 보고한다. `반`이 숫자가 아닌 행은 타교 위탁 수강생이라 제외
- **배열 인덱스가 곧 문항번호다**: `answers[i]`/`correct[i]` = 선택형 `i+1`번. 문항 메타를 찾을 때 **`answer_type='선택형'`을 반드시 함께 걸 것** — 선택형·서답형 문항번호가 각각 1부터라 번호만 보면 서답형 1번이 선택형 1번 자리에 들어온다. NEIS가 뒤쪽 연속 무응답을 잘라 보내는 경우가 있어(라이브 1건) 파서가 무응답으로 복원한다
- **`subject_section`은 학년 간 겹친다 — 조회 키에 `grade`가 반드시 들어간다**: `인공지능 수학(3)` 1차를 2학년 26명·3학년 40명이 **각각 다른 시험으로** 봤다. 학년을 빼면 66명이 한 모집단이 되고 같은 `problem_number`에 서로 다른 두 문항의 정오가 쌓여 정답률·평균·석차가 통째로 오염된다. 그리고 그 학년은 **응시 당시 학년**(결과 행의 `grade`)이지 학생의 현재 학년이 아니다 — 현재 학년을 쓰면 지난 학년도 고사에서 문항을 못 찾는다
- **난이도 컷오프가 모의고사와 다르다**: 학교 시험 평균 정답률이 66.9%라 모의고사 컷(≤40%=상)으로는 '상'이 9%뿐이라 가중치가 죽는다 → **≤55%=상, ≥80%=하**(`SCHOOL_HARD_CUTOFF`/`SCHOOL_EASY_CUTOFF`). 난이도 괴리는 **2단계 어긋남만** 표시한다(1단계는 전체의 47%라 노이즈)
- **화면 두 층 — 전체 과목 개요(기본) → 과목별 문항 분석**: 왼쪽 목록 첫 줄이 `전체 과목`이고 기본 화면이다. 특정 과목으로 바로 떨어뜨리면 왜 그 과목인지 알 수 없다
- **과목별 상자그림 (`SchoolExamBoxPlot.tsx`, 2026-08-14)**: 과목마다 학년 분포(최저–25%–중앙–75%–최고)를 가로 상자로 깔고 그 위에 학생 점수를 점으로 찍는다. 행 클릭 = 그 과목 문항 분석으로 진입. 기본 정렬은 **취약순**(백분위 나쁜 순)
  - **색은 emphasis 1개뿐이다**: 분포는 회색(맥락), 학생만 indigo(요점). 성적에 색으로 우열을 칠하지 않는다 — 상자 안 **위치**가 이미 그 정보이고, 색을 얹으면 같은 사실을 두 번 말하면서 "빨간 과목 = 못하는 과목" 낙인만 남는다. 데이터를 지닌 마크는 전부 표면 대비 3:1 이상으로 검증(윤곽선 7.24:1 · 중앙값 9.85:1 · 강조점 4.23:1)
  - **SVG가 아니라 CSS 절대 위치로 그린다**: x축이 항상 0~100점 고정이라 백분율이 곧 좌표다. `viewBox`를 쓰면 폭에 따라 **글자까지 확대·축소**돼 좁은 화면에서 과목명이 죽는다
  - **렌더 검증에서 나온 두 수정(되돌리지 말 것)**: ①중앙값선을 상자보다 **높게**(h-5) 뽑는다 — 학생 점수가 중앙값과 겹치면 10px 점 + 4px 흰 링이 선을 통째로 덮어, 하필 "딱 중간"이라는 가장 흔한 판독이 불가능해진다 ②트랙 양끝을 `INSET`(6px) 들여 그린다 — `left:0%` + `translateX(-50%)`이면 0점 마크와 눈금 라벨의 절반이 잘린다(라이브에 최저 0점·최고 100점이 실재)
  - **채점 중인 과목은 점선 상자 + `채점 24/99`**: 분포가 채점된 학생만으로 계산돼 편향돼 있다. 실선 상자와 나란히 두면 같은 신뢰도로 읽힌다
  - 표 토글(`Table2`)이 같은 수치를 그대로 읽는 동등 경로다
- **파일 구조**: 파서 `utils/schoolExamCsv.ts`(순수 — 관리 UI와 Node 스크립트가 공유) · 집계 `utils/schoolExamAnalysis.ts`(순수) · 행 변환 `utils/schoolExamRows.ts`(순수 — 서비스는 브라우저 클라이언트를 물어서 Node가 못 부른다) · 서비스 `services/schoolExamService.ts` · 훅 `hooks/useSchoolExamData.ts`. RFC 4180 CSV 리더는 `src/lib/csv.ts`로 공용화(구 `dutyCsv.ts` 구현을 옮기고 re-export)
- **적재 2경로**: 관리 UI(evalearn ⚙ → 학교 시험, admin 전용, 분석 → 확인 → 등록) / 스크립트 `npx tsx scripts/school-exam-import/run.mts <문항.csv> <답안.csv> [--apply]`(`--apply`와 `SUPABASE_SERVICE_ROLE_KEY`가 **둘 다** 있어야 씀)
- 회귀 = `npx tsx scripts/school-exam-test/run.mts`(98건). `SCHOOL_EXAM_DIR=<NEIS 내려받기 폴더>`를 주면 라이브 전체 파일까지 검증한다 — **"전 과목에서 답안 수 == 선택형 문항 수" 같은 성질은 거기서만 잡힌다**(픽스처는 4과목뿐)
