# course-analyze

> CLAUDE.md '주요 패턴'에서 분리한 course-analyze 상세 노트. 성적 표기·예상등급·학급 관리.

- **course-analyze 성적 표기 · 부분 평균 명시 (2026-08-31)**: 성적 숫자는 **소수점 셋째 자리에서 반올림해 두 자리**로 표시한다(`1.23`). 단일 출처 = **`utils/gradeFormat.ts`**(`formatGrade`/`formatGradeDelta`) — 새 화면에서 `toFixed`를 직접 쓰지 말 것. 종전엔 `toFixed(1)`·`toFixed(2)`가 섞여 같은 학생의 같은 성적이 탭마다 `2.1`과 `2.14`로 달리 보였다.
  - **등급 `0`은 "1등급보다 좋다"가 아니라 성적 없음**이다(`getEffectiveGrade`가 미보유 학생에게 0을 준다) → `formatGrade`는 0 이하를 `-`로 낸다. **차이(±)는 0·음수가 정상 값**이라 `formatGradeDelta`가 따로 있다(여기에 "0=없음" 규칙을 쓰면 안 된다).
  - **정수인 단일 과목 석차등급(`record.rank`)·예상등급(`estimatedGradeFromRank`)·구간 경계 라벨(`gradeBands.fmt`)은 대상이 아니다** — 이들은 평균이 아니라 정수 범주라 `3.00등급`으로 찍으면 오히려 틀린 인상을 준다.
  - **부분 평균은 표식을 단다**: 화면의 평균 옆에는 늘 더 큰 모집단(수강 인원·전체 과목 수)이 적혀 있는데 실제 분모는 "성적이 있는" 일부다 → `components/common/PartialAverageMark.tsx`의 `<PartialAverageMark covered total unit missingLabel />`(앰버 `부분` 칩 + 툴팁에 분자·분모·제외 수). **판정은 순수 함수 `isPartialAverage`**(utils)이고 **분모가 온전하면 아무것도 렌더하지 않는다** — 항상 붙는 표식은 곧 배경이 되어 읽히지 않는다. 셀 수 없지만 범위가 좁은 것은 아는 경우(DB 평균 등급 = 석차등급 보통교과만)는 `<PartialScopeMark title=… />`.
  - 적용처 = 등급 분포 카드(성적 보유 vs **수강** 인원 — 카드의 `N명 / 전체N명`도 수강 인원으로 정정) · 분반 카드 · 조합 검색 평균 · 과목 수 탭 `등급 비교`(열 폭 `w-56`로 확대) · 학생 예상등급 표(제외 과목·분석 대상 인원) · DB 성적 상세 모달('전체 평균 등급' → '평균 등급' + 표식).
  - **조합 검색 평균은 표기가 아니라 계산이 틀렸다(수정)**: `sum(등급 || 0) / 전체 인원`이라 성적 없는 학생의 `0`이 **분자에 더해지면서 분모에도 남아** 평균을 실제보다 좋게(작게) 끌어내렸다(실측 형태: 2·3등급 2명 + 미보유 2명 → `1.25`, 정정 후 `2.50`).
  - 회귀 = `npx tsx scripts/course-grade-format-test/run.mts`(31건 — 반올림 경계·값 없음·부분 판정·구 결함 재현)
- **course-analyze 좌측 패널 새로고침 (2026-08-31)**: 사이드바 헤더(`현재 데이터`)의 `RefreshCw` 버튼이 **지금 보고 있는 학년도를 그대로 다시 적재**한다(`useCourseData.refreshData` → `loadFromDatabase`가 내부에서 DB 성적 재조회까지 발사하므로 신청 데이터와 성적이 함께 갱신된다. `databaseAdapter`에 캐시가 없어 항상 서버를 새로 친다).
  - **급소 = `processData`가 학년/차수를 초기화한다**: 원래 로드 후 첫 학년·최신 차수를 자동 선택하므로 그대로 쓰면 2학년 3차를 보다가 새로고침하면 1학년으로 튄다. `ProcessDataOptions.preserveSelection`으로 **새 데이터에 그 학년/차수가 남아 있으면 유지**하고 사라졌을 때만 기본값으로 떨어진다. `setCurrentGrade`가 (stale한) `gradeRoundGroups`로 차수를 덮어쓰므로 **차수 확정은 반드시 그 뒤에서 `parsedGroups` 기준으로** — 순서를 바꾸지 말 것.
  - 헤더는 `SHOW_FILE_LOADING_UI=false`인 지금도 보이고(구 '데이터 관리' 헤더를 흡수), 마지막 반영 시각을 `HH:MM 기준`으로 적는다. **상대 시간("3분 전")을 쓰지 않은 이유**는 타이머 없이는 곧 거짓말이 되기 때문. `isRefreshing`(= `isLoading || isFetchingDbGrades`)이 스피너·비활성을 함께 관장한다.
  - **알려진 깜빡임**: `loadFromDatabase`가 cohort 전환 안전장치로 `databaseGrades`를 즉시 비우므로, 새로고침 중 성적 칸이 잠시 `-`로 보였다가 되채워진다. 같은 학년도 재적재에는 과한 초기화지만 그 가드를 푸는 쪽이 위험해 그대로 뒀다.
- **course-analyze 예상등급 (2026-08-25 전면 수정)**: 학생별/과목별 예상등급은 "과목 신청자를 등급으로 줄 세우고 컷오프(5등급제 10/34/66/90%)를 적용"한다. **순수 로직 단일 출처 = `utils/estimatedGrade.ts`**(`compareByRankingGrade`/`estimatedGradeFromRank`/`getEstimateExcludeReason`) — 예전엔 비교자가 두 탭에 복붙돼 있었고 그 복붙본의 결함이 양쪽에서 똑같이 재현됐다.
  - **순위는 "교과군 등급 우선, 없으면 전체 평균" 폴백이다. 두 블록으로 가르지 말 것** — 구 구현은 `if (!hasCategoryA) return 1`로 교과군 등급 미보유자를 **성적과 무관하게 전원 뒤로** 밀었다. 1학년의 구 '기타' 교과군은 등급이 나오는 과목이 `정보` 하나뿐(222명 중 97명 이수)이라, **전과목 1등급 학생이 정보 미이수라는 이유만으로 전체평균 4.75인 학생보다 뒤에 놓여** 한문·언어생활과 한자·생태와 환경 예상등급이 3등급으로 나왔다(00-00750 실측). 값 조회용 `getStudentGradeForSubject()`는 원래 폴백이었으므로 **"명단에 넣을 때 쓴 등급"과 "줄 세울 때 쓴 등급"이 서로 달랐던 것**이 근본 원인이다.
  - **카테고리 세분(2026-08-25)**: 구 `기타` → `과학기타`·`외국어`·`기술가정정보`·`교양` + 잔여 `기타`. **분류 정본 = 학교 편제표 `school_curriculum.category`(교과군)**이고 생기부 `subject_group` 실측으로 교차 검증했다. 이름과 다른 2건을 되돌리지 말 것 — **`생활과학 탐구`=기술·가정/정보**(과학 아님, 생기부 22건 전부 그 교과군), **`융합과학 탐구`=과학**. 카테고리→DB 등급 키 변환은 `gradeMapping.toDbGradeCategory()` 단일 출처(물리·화학·생명·지구과학·**과학기타**→'과학'; 종전엔 `SCIENCE_CATEGORIES` 배열이 4개 탭에 복붙돼 있었다).
  - **교양은 예상등급을 매기지 않는다**(`NO_RANK_CATEGORIES`): 교양 교과(진로와 직업·생태와 환경·교육의 이해·보건·논술·인간과 철학·삶과 종교)는 2022 개정에서 **이수/미이수(P)**로만 기록된다 — 편제표 `grading_type='이수/미이수'` + 라이브 생기부에서 `rank`가 전 건 NULL. 화면은 'P'/'등급 미산출'로 표시하고 평균에서 제외한다. **미결**: 등급이 안 나오는 과목이 교양만은 아니다(예술·체육 = 성취도 3단계, 2015 잔여 진로선택 일부도 3단계). 그것들은 **카테고리 단위로 갈라지지 않고**(같은 '수학'에 5등급 기하와 3단계 인공지능 수학이 공존) 편제표의 `grading_type`이 2026 입학 코호트 행에 전부 비어 있어 런타임 판정이 불가능하다 — 확실히 입증된 교양만 제외 중.
  - **course-analyze admin의 "과목 설정" 화면은 분석 탭에 반영되지 않는다**: 그 화면은 `AdminContext`의 `subjectConfig`를 **localStorage(`course_analyze_admin_config`)에만** 저장하고, 분석 탭이 쓰는 `subjectConfiguration`은 `databaseAdapter` → **DB `course_selectable_subject.category_code`**에서 온다. 카탈로그에는 세분 코드가 없으므로(전부 `ETC`) 세분은 `databaseAdapter.splitEtcSubjects()`가 `DEFAULT_SUBJECT_CATEGORIES` 이름 매칭으로 수행한다 — DB·수강신청(course-selection) 스키마 무수정. 세분 표에 없는 과목은 잔여 `기타`에 남아 조용히 사라지지 않는다.
  - **등급 분포 구간 기준 2종 토글 (2026-08-25)**: 등급 분포 탭은 소수점 평균 등급을 막대에 담을 때 자르는 위치를 고를 수 있다 — `level`(**정수 등급**, 기본값·종전 동작: 2등급 = 2.0~2.9)과 `rounded`(**반올림 등급**: 1등급 = 1.0~1.5, 2등급 = 1.5~2.5). 순수 로직 = `utils/gradeBands.ts`(`getGradeBands`/`gradeBandIndex`), 선택은 `localStorage` 키 `course-analyze-grade-band-mode-v1`. **두 모드의 막대 개수가 같아서**(=maxGradeLevel) 색상표·범례·클릭 모달 구조가 그대로 재사용된다. **분포 집계와 막대 클릭 필터는 반드시 `gradeBandIndex` 하나를 공유할 것** — 종전엔 집계가 `Math.floor(g)-1`, 클릭 필터가 `Math.floor(g)===grade || (grade===9 && g>=9)`로 따로 적혀 있어(9등급제 전용 특례가 클릭 쪽에만 있었다) 한쪽만 고치면 막대 높이와 모달 인원이 어긋난다. 등급 0(미상)은 집계 대상이 아니므로 클릭 필터에서도 빼야 한다(clamp 때문에 1등급 막대 모달에만 나타난다). **참고: 정수 기준의 마지막 막대는 사실상 죽어 있다** — 5등급제에서 `floor(g)=5`는 정확히 5.00이어야 하는데 라이브 최저 성적이 4.88이라 항상 0명이고, 반올림 기준에서는 같은 모집단의 15명이 그 막대에 들어간다.
  - 회귀 = `npx tsx scripts/course-estimated-grade-test/run.mts`(85건 — 라이브 ETC 카탈로그 26과목 전수 분류·구간 분할 불변식 포함)
- **course-analyze 학급 관리**: 담임(태그 `N학년 M반`)·부장(태그 `부장`)·admin이 현재 차수 학급 학생(미신청자 포함)의 선택과목을 모달로 편집. 권한은 `useClassManagementAccess`(resource 태그 파싱), 저장은 기존 `save_course_selection_group` RPC(`p_actor_role:'teacher'`) 경유 — 새 마이그레이션 없음. 선택 로직은 `useSubjectSelectionDraft`(course-selection)를 StudentApply와 공유.
  - **`p_actor_role`은 권한이 아니라 감사 로그 라벨이다 (2026-08-24 장애)**: 설계 당시 "RPC가 `p_actor_role:'teacher'`를 지원하니 새 마이그레이션 불필요"로 판단했지만, 그 파라미터는 로그에만 쓰였고 RPC 1단계의 **학생 신청 창구 게이트**(`status='open'` + `opens_at`/`closes_at` 윈도)는 호출자를 가리지 않았다. 학급 관리는 수요조사가 끝난 뒤 보정하는 기능이라 라이브 전 차수가 closed/finalized인 상태에서 **어떤 학생을 고르든 `round_not_open` → PostgREST 400**으로 100% 실패했다(dirty group 수만큼 POST가 반복돼 400이 여러 번 보인다).
  - **지금은 서버가 권한을 재검증해 privileged 호출자만 게이트를 건너뛴다**: `can_manage_course_selection_student(student_code)`(SECURITY DEFINER, 마이그레이션 `20260824120000`)가 admin·`부장`·`N학년 부장`·학년/반 태그·레거시 `resource.meta.grade+class_number` 담임을 판정하고, 통과한 호출자만 **마감 상태와 과목 정원(`override_capacity`)을 모두 무시**한다(2026-08-24 사용자 결정 — 교사 보정은 전권. 초과분은 반 배정·시간표 생성에 그대로 흘러가므로 감사 로그의 `diff.capacity_overridden`으로 추적). **`p_actor_role`을 게이트로 쓰면 안 된다** — 클라이언트가 자유롭게 주장하는 값이라 학생이 `'teacher'`로 보내면 마감된 차수를 고칠 수 있다(실측 확인: 지금은 서버 판정이 false라 거부되고, 감사 로그의 actor_role도 `student`로 격하 기록된다).
  - **서버 판정은 `useClassManagementAccess`의 거울이다**: `parseTeacherTag`가 **반 없는 학년 태그를 학년 전체 권한으로** 해석하므로 `"1학년 수업"`(27명)·`"2학년 수업"`(29명)·`"3학년 수업"`(33명) 보유 교사도 그 학년 전 학급을 편집할 수 있다. 문서상 의도(담임/부장)보다 넓지만 **화면이 이미 그렇게 동작**하고 있어 서버를 좁히면 버튼은 보이는데 저장만 실패한다 — 좁히려면 클라이언트와 함께 바꿀 것.
  - **감사 로그의 행위자 = 저장을 실행한 사람 (마이그레이션 `20260824123000`)**: 종전엔 `actor_name`에 `p_student_name`(대상 학생)이 들어가 교사가 대신 저장해도 로그가 "박하준 / teacher"로 찍혀 누가 고쳤는지 알 수 없었다. 지금은 `current_profile_name()`(없으면 학생명 폴백 — 이름 빈 학생 6명 대비)을 쓰고, 대상 학생은 `target_label`에 `"<선택군> · <학생명> (<학번>)"`으로 붙인다. **`target_label`을 고른 이유는 `LogsTab`의 검색·CSV 내보내기가 이미 그 컬럼을 읽기 때문**(프론트엔드 무수정으로 학생 이름·학번 검색이 된다). `StatusTab`은 diff를 안 보여주므로 학생을 label에 넣지 않으면 한 줄에서 사라진다.

  - **작은 글자 단계 (같은 날, 사용자 결정)**: 자동 배치가 학생 수마다 **보통 글자 → 작은 글자**(`SLIP_TEXT_SIZES`) 순으로 시도한다(8 보통 → 8 작게 → 6 보통 → …). 보통 글자로 맞는 배치에는 작은 글자를 쓰지 않고, 작은 글자는 문서 전체에 한 번에 건다(한 반 안에서 글자 크기가 들쭉날쭉하지 않게). 작은 글자 = 본문 8.5 → **8pt**, 칸 안쪽 여백 소폭 축소, **서명 자리 높이는 그대로**. 툴바에 «글자 작게»로 표시. 실측(2026 4차, Chromium): 1학년 **6명/장 41장(작은 글자, 최소 여유 5.8mm)**, 2학년 8명/장 27장(보통 글자 — 변화 없음). 첫 시도(7.6pt)는 최소 여유 11.7mm로 필요 이상 줄여 되돌렸다.

## 과목별 선택 — 학생 목록의 두 등급 (2026-09-30)

숫자를 눌러 여는 과목·학기별 학생 목록은 등급을 **두 칸**으로 보여 준다 — **그 과목의 과목군 등급**(강조)과 **전체 평균 등급**. 종전에는 한 칸이었고 그 값이 `getStudentGradeForSubject`(과목군 등급, 없으면 전체 등급으로 폴백)라 **어느 쪽인지 화면이 말하지 않았다**. 목록은 폴백 없는 `getStudentGradePair` 를 쓰고 과목군 등급이 없으면 `-` 로 둔다. 표의 학기 평균(등급 비교 열)은 종전대로 폴백 집계다. JSON 성적 소스에는 과목군 등급이 없어 전체 평균 한 칸만 그린다. 예상등급 탭의 `전체 / 과목군` 표시와 같은 두 값이다.
- **정렬**: 목록 머리글 `번호 · 이름 · <과목군> · 전체 평균` 을 누르면 정렬되고 다시 누르면 방향이 바뀐다(기본 = 반·번호순). 등급 오름차순 = 상위권 먼저, **성적 없음은 방향과 무관하게 맨 뒤**(내림차순에서 앞에 오면 최하위권처럼 보인다), 동점은 반·번호순. 엑셀 내려받기도 화면 순서를 따른다.

- **md(768px) 미만은 레이아웃이 다르다** — 판정은 `MainLayout` 의 `matchMedia('(max-width: 767px)')` 하나.
