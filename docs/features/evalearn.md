## 1. 모의고사 원본 데이터와 채점

시험 구조·마킹 결손·과목 표기·참고 등급 — **전부 "오류가 아니라 빈칸"으로 나타나는 것들**이다.

- **3학년 수학 시험 구조**: 1~15번 객관식(공통+선택 혼합), 16~22번 주관식 **공통**(`mock_problems.subject='공통'`, `major_category`는 수학Ⅰ/수학Ⅱ), 23~28번 객관식(선택과목), 29~30번 주관식 **선택과목**(`subject='확률과통계'/'미적분'/'기하'`)
- **mock_marking 정오 판정 단일 출처 = `src/features/evalearn/utils/mockGrading.ts` (2026-09-03)**: 리로스쿨 마킹표는 **객관식만 채점해 준다** — 수학 주관식은 `correct`가 비어 오고, 그 결손이 **두 모양**이라 한쪽만 처리하면 절반이 조용히 미채점으로 남는다: 1·2학년 수학은 `answers` 30개인데 `correct` **21개**(문항 22~30이 배열 밖 = `undefined`), 3학년 수학 선택은 `correct` **28개 + 16~22가 `null`**(문항 29~30은 배열 밖). 그래서 `correct[i] == null` 검사 하나로는 안 된다. 판정은 **①마킹값 우선 ②없으면 `mock_problems.answer`와 대조**이고, 소비처는 `gradeMarkingSubject()`만 쓴다(`useMockData`·`useWeaknessData`). 종전 `useWeaknessData`는 정오가 없으면 `continue`해 **수학 주관식이 취약점 분석에서 통째로 빠져 있었다**.
  - **`answer_type`을 보지 말 것**: 과거 적재분이 부정확하다(3학년 공통 22번 답 '457', 기하 29번 '360'이 `'객관식'`으로 저장돼 있다 — 2026-07 이후만 선택률로 정확히 판정). "정오가 없으면 정답과 대조"는 출제 형식을 몰라도 성립해 이 오염에 영향받지 않는다.
  - **학생 답 `0` = 무응답 = 오답**. 실측 근거: 0의 비율이 문항 난이도를 따라 단조 증가한다(1학년 수학 22번 3.6% → 30번 17.3%). 마킹 누락이면 고르게 퍼지거나 학생 단위로 몰릴 텐데 그렇지 않다. 미채점으로 빼면 **가장 못 푼 킬러문항이 취약점 분석에서 사라진다**. 소스 시스템도 무응답(`answers[i]`가 JSON null)을 `false`로 채점한다(196칸 확인). 정답이 `0`인 문항은 없다(주관식 113문항 전수 확인).
  - **정답 키가 숫자가 아니면 채점하지 않는다** — 통합사회 10행은 정답 자리에 단원명('환경과 행복ㅡ…')이 들어간 소스 오염이다. 그대로 대조하면 전부 오답이 된다.
  - **`item_count`를 루프 상한으로 쓰지 말 것** — 타입 주석대로 "빈칸 제외" 개수라 실제 문항 수보다 작다(라이브 125블록: 영어 44/45, 수학 29/30). 마지막 문항이 조용히 잘린다. `getMarkingItemCount()`가 `max(item_count, answers, correct)`로 처리한다.
  - **검증(2026-09-03)**: 같은 규칙을 정오가 **있는** 객관식 111,974칸에 적용해 공식 채점과 대조 → **불일치 0건**(인덱싱·과목 별칭·비교 로직 동시 증명). 유도 채점한 주관식의 교내↔전국 정답률 격차 **23.6%p**(공식 채점 객관식 24.5%p)로 사실상 동일, 상관 0.943. 회귀 = `npx tsx scripts/mock-grading-test/run.mts`(47건)
- **3학년 수학 시험 구조 참고**: 위 문항 번호 구간(1·2학년 22~30 / 3학년 공통 16~22·선택 29~30)은 `mockGrading`의 교차 검증용이며, 판정 자체는 번호가 아니라 "정오 결손 여부"로 한다
- **★ mock_marking 과 mock_result 는 과목 이름 표기가 다르다 (2026-09-03)**: 두 값이 **다른 파일에서 적재**돼 키가 어긋나는데, 어긋나면 오류가 아니라 **등급이 빈칸**으로 보여 아무도 눈치채지 못한다. 라이브 실측 3갈래 — ①가운뎃점 성적표 `사회·문화` ↔ 마킹 `사회문화`(**331명**) ②로마/아라비아 `생명과학1` ↔ `생명과학Ⅰ`(159명) ③1·2학년 통합과목 별칭 `공통사회`·`통합사회`·`사회` ↔ `사회탐구`(최대 632명). **`subjects[key]` 로 직접 꺼내지 말고 `findExamSubjectScore()`/`findExamGrade()`**(`utils/mockResult.ts`)를 쓸 것. 정확 일치 → 표기 정규화 → 별칭 순으로 찾고, 정확 일치가 항상 이긴다
- **성적표 CSV 오프라인 적재 = `scripts/mock-result-import/build-sql.mts` (2026-09-21)**: 관리 화면 업로드와 **같은 파서**(`parseMockExamCSV`)로 `00-check.sql`(쓰기 없음 — 좌석 미매칭·이름 불일치·기존 엔트리 보고)과 `01-apply.sql`(같은 (학년도,학년,월) 엔트리 교체, 멱등)을 만든다. 실행은 `npx supabase db query --linked -f`. 화면 업로드와 다른 점 둘은 모두 조용히 틀리는 자리다: ①**통합과목 키가 회차마다 흔들린다** — 2026-09 **2학년 파일만** `사회`/`과학`이고 같은 학생의 3·6월은 `공통사회`/`공통과학`이다. 그대로 넣으면 추이에서 한 과목이 두 계열로 갈린다 → 1·2학년은 `공통사회`/`공통과학`으로 맞춘다(**관리 화면 업로드는 아직 이 정규화를 하지 않는다**). ②**부분 결시가 0점으로 온다** — 등급은 비고 원점수·표준점수·백분위가 `0`(2026-09 2-2-18: 국어만 응시). 백분위 평균에 0 이 섞이므로 "등급 없음 ∧ 점수 전부 0/빈칸"은 버린다. 매칭은 (학년,반,번호)→재학 resource + **이름 일치 필수**, 이름 폴백 없음(같은 회차에 동명이인 3명이 실제로 있다). 파일의 `학년도` 칸(`2027` = 대입 학년도)은 파서가 읽지 않고 `--year` 가 정한다. **검증 = 마킹 대조**: 국어·영어는 45문항 100점(2점 35 + 3점 10)이라 `2c ≤ 원점수 ≤ 2c+min(c,10)`(c=마킹 정답 수)이 좌석 매칭과 무관하게 성립해야 한다 — 2026-09 1·2학년 795쌍 위반 0, r=0.998. 배점이 적재되지 않은 회차에도 쓸 수 있는 부등식이다(배점이 전부 2점이면 원점수 재구성은 불가능하다)
- **참고 등급(EBS 예상 등급컷) — `utils/referenceGrade.ts` (2026-09-03)**: 공식 성적이 아직 없는 회차에 원점수를 등급컷과 대조해 **참고 등급**을 낸다. **학생별 등급을 저장하지 않고 컷만 저장**(`mock_grade_cut`, `source='EBS'|'official'`)하고 읽을 때 계산한다 — 저장하는 순간 공식 등급과 섞이기 때문이다. **공식 등급이 있으면 계산 자체를 하지 않는다.** 원점수 = Σ(맞은 문항 배점)이고 이 식은 2026-03 에서 공식 원점수와 전원 일치 검증됨(영어 589/589 · 한국사 588/588 · 국어 399/399). **배점 합 ≠ 만점이면 등급을 내지 않는다** — 리로 CSV 에 배점이 없어 일부 회차는 전부 2점이라 국어가 90점 만점이 되고, 그 상태의 등급은 전원 오답 수준으로 틀린다. 배점 적재 = `scripts/mock-point-import/`(EBS 문제지 PDF → `point`, 트랙별 만점 24종 검증). 회귀 = `reference-grade-test`(26건)
  - **⚠️ EBS 예상컷은 회차가 끝날 때까지 계속 바뀐다 — 한 번 받아두면 끝이 아니다 (2026-09-04)**: 2026-09 3학년 컷을 하루 만에 다시 받았더니 **24과목 중 15과목이 달라졌다**(생활과윤리 2등급 42→41 · 한국지리 3등급 41→39 · 물리학1 5등급 26→24 …). 국어 2·수학 3·영어·한국사·생명과학2·지구과학2 **9과목만 동일**했다. 라이브 영향은 응시 339건 중 **등급이 달라진 18건(5.3%) · 학생 17명**으로 작지 않다(대부분 컷이 내려가 좋아지는 방향). 갱신 대상이 **탐구에 몰리는 이유**는 표본이 적어 초기 추정이 흔들리기 때문이고, 반대로 **영어·한국사는 절대평가 고정 구간이라 EBS 추정이 개입하지 않는다**(그래서 참고 등급 중 이 둘이 가장 믿을 만하다). 스냅샷 = `scripts/ebs-grade-cut/2026-09-grade3.json`(수집일 함께 기록), 수집 = EBS 풀서비스 페이지에서 **탐구는 '사회'/'과학' 탭을 눌러야** 표가 뜬다(`grdCutList(...)`). **WebFetch 는 EBS 방화벽에 막히므로 브라우저로 받아야 한다.** `national_mean`/`sd` 는 페이지가 직접 주지 않고 표준점수에서 역산해야 하는데 표준점수가 정수로 반올림돼 있어 어느 두 점을 쓰느냐로 답이 갈린다 — 등급 판정에 쓰이지 않고 '전국 평균 대비' 표시에만 쓰이므로 **추정치를 새로 지어내지 말 것**

## 2. 화면 — 집단 분석 · 문항 분석 · 6·9월 모평
