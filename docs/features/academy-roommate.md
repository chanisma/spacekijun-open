# 별빛 기숙사의 세린 · 자기이해와 하루 마음

2026-09-13 구현. 세린은 꿀빛 금발을 땋고 세이지색 옷을 입은 여성 룸메이트다. 따뜻하게 듣는 동급생이며, 탐구 성과나 입시 준비를 요구하는 인물이 아니다.

## 기존 마음의 별자리 정리

기존 `GrowthPanel/self`는 첫 탐구 질문·연속 의뢰 회고를 근거로 학생이 자기 설명을 적는 기능이었다. 카시안의 ‘마음의 별자리 펼치기’와 소지품의 해당 진입 버튼을 제거했다. 자기이해 진입은 기숙사의 세린으로 이동한다. 기존 `academy_self_discoveries` 기록과 NPC 기억 연결은 삭제하지 않는다. 튜토리얼 마지막 단계는 세린의 마음 질문 또는 자기이해 검사로 진행할 수 있고, 이전 자기 발견을 완료한 학생의 진도도 인정한다.

## 세 가지 자기성찰 도구

- **나의 다섯 가지 결**: Big Five 영역을 참고해 새로 작성한 한국어 20문항. 개방성·성실성·외향성·우호성·정서 민감성 각 4문항, 정방향과 역방향 혼합. 1~5 응답에서 역문항은 `6 - 응답`, 차원별 평균을 계산한다. 어느 쪽도 좋은/나쁜 성격으로 평가하지 않는다.
- **나의 배움 습관**: 최근 2주의 계획/환경 조절, 떠올리기/설명, 이해 점검/조정, 나누어 복습/도움 구하기를 16문항으로 돌아본다. ‘시각형/청각형’ 같은 고정 학습유형이나 지능·성적을 판정하지 않는다. 사용 중인 습관과 작은 실천 제안을 함께 보여준다.

세 도구 모두 **표준화·타당화된 검사가 아닌 자기성찰용 자체 문항**이다. 응답 전과 결과에 이를 명시한다. 평균 위치는 1~5 척도이며 백분위·다른 학생과의 순위가 아니다. 결과에는 각 축의 양쪽 설명, 돌아볼 질문, 시도할 행동을 함께 표시한다. 진단·직업 적합도·합격 가능성은 제공하지 않는다. 점수는 서버의 공통 모듈에서 계산하며 브라우저가 보낸 점수는 사용하지 않는다.

검사는 한 문장씩 선택하고 이전 문장으로 돌아갈 수 있다. 잠시 홈으로 돌아간 경우 같은 세린 화면 안에서 작성 중인 검사를 이어 쓸 수 있다. 저장 실패 시 응답과 요청 ID를 유지해 재시도하며, 응답 수정 시 새 ID를 만든다. 새로고침 전 미제출 응답은 메모리 상태이고, 제출한 검사 응답·점수는 계정에 저장한다. 이전 결과를 열거나 삭제할 수 있다. 검사 삭제가 과거 AI 대화에서 이미 언급된 내용을 지우지는 않는다.

### 학습 유형 결과 (learning_type)

‘나의 학습 유형’은 기존 `learning` 습관 검사와 별도로 12문항을 사용한다. 혼자 정리/함께 대화, 설명부터/직접 경험부터, 단계별 안내/자율 탐색의 세 축에 정방향 2개와 역방향 2개씩을 배치한다. 최근 한 달의 선호에 응답하며, 각 축은 역채점 후 평균이다.

평균에서 중앙값 3까지의 거리가 0.75 미만이면 양쪽 균형으로 표시한다. 그 이상인 축 중 가장 거리가 큰 축을 주요 유형으로, 나머지를 함께 나타난 성향으로 표시한다. 최대 거리가 같으면 모두 주요 성향에 포함한 ‘함께 빛나는 혼합형’, 모든 축이 중앙 부근이면 ‘균형 탐색형’이다. 이 경계는 제품의 설명 규칙이며 과학적 절단점이나 표준화 점수가 아니다.

| 축 | 왼쪽 선호 이름 | 오른쪽 선호 이름 |
| --- | --- | --- |
| 함께 배우는 방식 | 고요한 사색가 | 대화의 연결자 |
| 새로운 내용에 다가가는 방식 | 원리의 해석가 | 경험의 모험가 |
| 배움의 길을 정하는 방식 | 차근차근 설계자 | 자유로운 탐색가 |

결과는 주요 유형·혼합 성향·균형인 축·시도할 학습 방법을 함께 보여 준다. 선호하는 방법만 사용하라고 제한하지 않으며, 편안함과 실제 이해를 구분하여 확인하도록 한다. 학습법 제안은 아래 IES의 인출·설명·풀이 예시와 직접 적용·분산 복습을 참고한 실천 예시이고, 유형별 효과가 검증됐다는 의미는 아니다.

‘이 학습 유형을 세린과 이야기하기’는 결과 요약을 수정 가능한 대화 초안에 넣는다. 이미 작성한 초안은 덮어쓰지 않고 자동 전송하지 않는다. 첫 대화라면 기존 하루 질문을 먼저 생성하며, 새 일일 질문을 추가하지 않는다. 서버도 최근 검사 네 건에 대해 같은 함수로 산출한 유형 설명을 AI에 전달한다.

`20260913165101_academy_learning_type.sql`은 종류 CHECK에 `learning_type`만 추가했다. 기존 응답·점수·권한은 그대로이며 `(kind, version)`으로 문항을 구분한다. 세 도구의 최초 버전은 각각 `serin-v1`이다. 새 검사 채점·AI 설명을 포함한 `academy-roommate` 버전 3을 JWT 검증 활성화로 적용했다. 실제 DB 역할 테스트는 세 종류 공존·중복 저장 방지·새 유형의 다른 학생 접근 차단을 확인하고 롤백한다.

### 설계 근거

[IPIP Big-Five Factor Markers](https://ipip.ori.org/newBigFive5broadKey.htm)의 다섯 영역과 정·역방향 채점 원리를 참고했다. [IPIP 사용 허가](https://ipip.ori.org/newPermission.htm)는 public domain 사용을 허용하지만, 이번 한국어 축약 문항의 신뢰도·타당도를 보증하지 않는다. 원 검사의 문항 수나 신뢰도 수치를 자체 문항에 적용하지 않는다.

학습 결과의 실천 예시는 미국 교육부 IES의 [Organizing Instruction and Study to Improve Student Learning](https://ies.ed.gov/ncee/wwc/PracticeGuide/1)에서 설명하는 분산 학습, 인출 확인, 이해 점검, 설명 질문을 참고했다. 이를 참고해 새로 쓴 문항이며 별도의 검증된 학습 성향 척도는 아니다.

## 하루 한 번의 마음 질문

기숙사 입장이나 메뉴 열기는 질문을 생성하지 않는다. 학생이 **세린, 이야기해 줘**를 선택하면 AI가 질문을 만든다. 그 시각의 한국 시간대를 DB 서버에서 결정하고 해당 날짜 대화에 고정한다.

| 한국 시간 | 처음 건네는 질문 방향 |
| --- | --- |
| 05:00–11:59 | 오늘 어떤 마음으로 지내고 싶은지 |
| 12:00–17:59 | 지금 어떤 마음으로 하루를 보내고 있는지 |
| 18:00–다음 날 04:59 | 하루가 어땠고 어떤 마음이 남았는지 |

날짜는 한국 시간 **00:00**에 바뀐다. 시간대가 바뀌어도 같은 날짜의 이미 생성된 질문을 다시 만들지 않는다. 새벽은 그 한국 날짜의 저녁/회고 톤이다. 이후에는 그 질문과 학생이 선택한 주제(검사 결과에 대한 느낌 포함)로 대화한다. 최근 검사 결과 4개, 지난 대화 최대 3일의 일부만 참고한다. 학생의 감정을 단정하거나 제공되지 않은 기억을 만들지 않는다. 임상 진단·치료나 AI 의존을 유도하는 표현을 금지하는 지침을 둔다.

대기 대사·질문·답변을 저장한다. `(user_id, day)` 고유 키, revision 및 75초 작업 토큰으로 동시 창의 중복 생성을 막는다. 실패하면 전송했던 답을 보존하고 같은 작업을 재시도한다. 다른 창의 늦은 결과는 토큰 검증으로 반영하지 않는다. 지난 날짜 기록은 UI에서 열람만 제공한다.

## 데이터와 접근

`20260913160347_academy_roommate.sql`은 연결 프로젝트에 적용했다.

- `academy_self_assessments`: 응답·차원별 평균·버전·제출 시각. 사용자/요청 ID 고유 키. 학생 직접 INSERT/UPDATE 불가, 본인 SELECT/DELETE만 허용.
- `academy_roommate_conversations`: 한국 날짜/최초 시간대·대기/질문/답변·작업 임대. 본인 SELECT만 허용.
- `academy-roommate`: JWT에서 실제 사용자 확인 후 profiles의 학생 역할 검증. 개인 데이터 읽기는 호출자 JWT, 원자적 쓰기만 별도 service-role 클라이언트 사용. 검사 저장에는 AI 키가 필요하지 않다.
- `academy_private.roommate_read` + invoker 공개 래퍼: 기숙사와 같은 실제 관리자 검증을 거쳐 선택한 학생의 기록만 미리보기. 일반 학생은 타인 선택 불가. 관리자 선택 없음은 빈 개인 기록. 브라우저 미리보기에서는 모든 AI·응답·삭제를 막는다. 관리자 열람 가능성을 검사 시작 설명에 명시했다.

기존 학업·퀘스트 테이블은 변경하지 않았다. 이번 기능은 코인이나 학업 평가를 지급하지 않는다. 보안 advisors에서 새 테이블/함수 관련 지적은 없었다. 프로젝트의 기존 다른 영역 지적은 이 변경에 포함하지 않는다.

## 기숙사와 시간표

기본 진입은 계획 UI가 없는 방 화면이며 리아와 세린을 함께 표시한다. 화면 왼쪽의 책·옷·두루마리 아이콘으로 계획장·옷장·맞춤 공방 주문서를 열고, 인물 아래 이름 버튼으로 세린과 대화한다. 루온은 기숙사에 상주하지 않는다. 배경/인물 이미지는 입력을 받지 않으며, 방 보기와 계획 UI의 포커스 영역을 분리하고 ScenePanel의 포인터/클릭이 뒤 게임으로 전파되지 않도록 했다. 다른 포털의 Escape가 배경 ScenePanel까지 닫는 것도 방지한다.

시간표는 `D:\kidon\src\hooks\useTimelineDrag.ts`와 `components/timeline/TimelineGrid.tsx`의 15분 범위 선택·시간 블록 배치를 참고해 로판 디자인으로 새로 구현했다. 마우스로 빈 칸에서 위/아래로 드래그하면 범위를 채운 계획 편집기가 열린다. 저장 전에는 DB에 쓰지 않는다. 모바일은 ‘터치로 시간 선택하기’로 드래그를 켜고, 왼쪽 시각 영역은 계속 스크롤할 수 있다. 시각 버튼/기존 시작·마침 입력도 이용할 수 있다. 포인터 취소 시 계획을 만들지 않는다.

각 블록의 위치와 높이는 시작 분과 지속 시간에 비례한다. 겹치는 일정은 별도 열로 표시하며 연속한 일정은 겹침으로 보지 않는다. 하루의 끝은 기존 저장 형식에 맞춰 23:59로 제한한다. 기존 일정 편집·완료·날짜 선택·소유권 검증 및 `academy_tasks` 저장 구조를 재사용한다.

## 에셋과 검증
