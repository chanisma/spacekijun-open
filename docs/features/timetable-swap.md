# timetable-swap

> CLAUDE.md Component Architecture에서 분리한 수업 교체·대체 모달 상세. 스키마는 docs/database/timetable.md.

#### Timetable (`src/components/timetable/`)
- **TimetableView.tsx**: 주간 시간표 화면(헤더·그리드·교체 관리·메모 모달 소유)
- **수업 교체·대체 모달 6종 (2026-08-14 전면 오버홀)**: 진입 = 시간표 칸 우클릭 → `ClassSwapDialog`(교체/대체 탭) → `SwapRequestDialog`/`SubstituteRequestDialog` 신청 → 헤더 '교체 관리' → `SwapRequestList` → `SwapApprovalDialog` 검토 → `SwapDocumentDialog`(결강시 보강 계획서 HWPX). **디자인 규약은 `src/components/tasks/dialogDesign.tsx` 공용 부품**을 import한다(클래스 문자열 복붙 금지). 표시 원칙 = **가능한 대상 먼저, 겹쳐서 불가능한 대상은 접어서**. 후속 모달은 `ClassSwapDialog`의 **형제**로 렌더한다(DialogContent 안에 중첩하면 포커스 트랩이 겹친다)
- **교체 관리 모달 탭 3개 (2026-08-14)**: `SwapRequestList` = 받은 요청 / 보낸 요청 / **결재 문서**. 세 번째가 `ApprovalSubjectList`(subjectType=`timetable.swap_document`)로, 상신한 보강 계획서의 결재 진행과 내가 결재할 문서를 같은 자리에서 본다(상세 = `ApprovalActDialog`). 무한 스크롤 `IntersectionObserver`는 앞 두 탭 전용이므로 탭이 늘면 관측 대상 ref 분기를 함께 볼 것(비활성 `TabsContent`는 언마운트라 ref가 비어 안전하긴 하다). '보강 계획서' 버튼은 종전대로 **보낸 요청 탭에서만** 노출
- **교체의 의미(미리보기·전개 규칙의 단일 기준)**: `requester_swap_date`(내 요일)의 **내 교시**에는 **상대**가 자기 과목을, `approver_swap_date`(상대 요일)의 **상대 교시**에는 **내**가 내 과목을 한다. `useTimetableData`의 class_swap 전개가 이 규칙이며 화면 문구도 여기 맞춰야 한다(구 미리보기는 사람·교시를 둘 다 반대로 적고 있었다). 대체(`meta.type='substitute'`)는 **양쪽 날짜가 같다**. 날짜 선택지는 `class_swap`의 CHECK(`*_swap_date_matches_weekday`)가 ISO 요일 일치를 강제하므로 **해당 요일의 실제 날짜만** 만든다
- **교체 후보가 0건이면 `section` 부터 의심할 것 (2026-08-14 장애)**: 이 기능 전체가 학기 키 없는 레거시 `section` 표에 매여 있다(RPC의 INNER JOIN·`useTimetableData`의 grade/class/section_id·`class_swap`의 NOT NULL FK). 새 학기 시간표를 올려도 `section` 행은 자동으로 안 생겨 2026-2에 216개 분반이 비어 있었고 후보가 항상 0건이었다. 지금은 업로드가 `ensureSectionRows()`로 만들고(이름은 `teacherSectionName()` 규칙과 **정확히** 같아야 한다 — `section` SELECT RLS가 `resource.meta.section` 키 문자열 일치로 판정), 학년·반 표기는 **grade=숫자/class_number=문자열**로 통일한다(`3 !== '3'` 하나로 모든 후보가 조용히 사라진다 → 비교는 `timetableSwapUtils.sameClassroom()`). 상세 = `docs/database/timetable.md`
- **후보 정렬 = 상대 선생님 부담이 적은 순 (2026-08-14 사용자 요청)**: 교체·대체 후보를 요일·교시 순으로 늘어놓으면 신청자가 맨 위 사람에게 몰아서 부탁하게 된다 → `src/lib/swapBurden.ts`(React 비의존 순수 모듈)가 상대 교사의 주간 슬롯에 **내 시간을 더하고(교체는 상대 시간을 빼고)** 부담 증가량(delta)을 계산해 오름차순 정렬한다(동점=덜 바쁜 교사→이른 시간). **기준값은 새로 만들지 않고 시간표 자동생성기의 교사 부하 제약을 그대로 재사용**한다(`하루 4개·연속 2교시·7교시 주 3회`) — 잣대가 갈라지면 생성기가 지키는 규칙과 화면이 권하는 순서가 어긋난다. 요인 = 연강(가중치 3)·일일 초과(2)·수업 없던 날 소멸(2)·마지막 교시 초과(1). **악화된 개별 요인은 총점이 내려가도 그대로 노출**한다(상대가 반대할 근거를 숨기지 않는다). 대체는 `remove` 없이 계산돼 자연히 교체보다 무겁게 평가된다. 회귀 = `npx tsx scripts/swap-burden-test/run.mts`(29건)
- **교체를 막는 것은 동아리활동뿐이다 (2026-09-15 사용자 결정 — 2026-08-14 규칙 완화)**: 판정 단일 출처 = `timetableSwapUtils.isSwappableLesson()`. 정본은 `teacher_timetable.activity_type`(라이브 전 행 채워짐)이고 값이 없는 경로만 과목명 접두로 폴백한다. 내 수업이 동아리면 후보 0건(양방향 차단). **자율·자치활동과 진로활동은 교체할 수 있다** — 종전엔 창체 전체를 막았는데, 동아리와 나머지 창체는 성격이 다르다: 동아리는 학생이 **학급이 아니라 동아리 단위로 모이고** 담당 교사도 그 동아리에 묶여 있어 같은 학급의 다른 수업과 시간을 맞바꾼다는 개념이 성립하지 않는 반면, 자율·진로는 **학급 단위로 담임이 맡는 시간**이라 교과와 맞바꾸는 것이 실제 운영과 맞는다(라이브 2026-2 실측: 창체 슬롯마다 같은 학급의 다른 교사 수업이 ~30건, `section` 행 결측 0이라 `class_swap` 의 NOT NULL FK `section_id` 도 이미 있다). **대체는 처음부터 막지 않는다** — 그 시간에 누군가는 학생을 봐야 하므로 대신 맡아줄 교사를 찾는 건 정상적인 요구다. 동아리 칸에서 교체 탭을 열면 안내 + `수업 대체로 이동` 버튼을 낸다.
  - **판정을 허용 목록이 아니라 차단 목록으로 적는다** — `NON_SWAPPABLE_ACTIVITY_TYPES = {'club'}`. 파서(`parseTeacherTimetableXlsx`)가 `volunteer`·`self_study`·`other` 를 만들 수 있는데, `=== 'subject'` 형태로 두면 새 활동 영역이 생길 때마다 **오류 없이 조용히 교체 불가**가 된다(2026-08-14 규칙이 창체 전체를 묶어 버린 것이 같은 모양이다).
  - **RPC(`get_teacher_timetables_for_swap`)는 `activity_type` 을 내려줄 뿐 서버에서 거르지 않는다** — 그 결과가 충돌 판정·부담 계산 모집단이라 창체를 빼면 동아리 담당 교사가 비어 있는 것으로 보인다. 그래서 이 완화는 **DB 변경이 없다**.
  - 회귀 = `npx tsx scripts/swap-candidates-test/run.mts`(27건)
- **교체 후보는 수강생으로 판정한다 — 학년-반 표기는 학급이 아닐 수 있다 (2026-10-12 사용자 요청)**: 시간표의 `grade`·`class_label` 은 학급(담임 반)일 때도, 선택과목·수준별 **분반 번호**일 때도 있다(`미적분Ⅰ 2-7` 학생은 세 학급에서 온다 · 1학년 `공통수학2 1-4` 는 학급 1-4 와 같은 학생이 24명 중 3명). 표기만 같고 학생이 다른 수업과 맞바꾸면 그 시간에 학생이 두 수업에 동시에 들어가야 한다. **라이브 실측(2026-2, 무작위 150개 수업)**: 표기가 같은 후보 4,147개 중 **2,546개(61%)가 학생이 겹쳐 실제로는 불가**였고(3학년 1,092개 중 1,067 · 2학년 1,535 중 1,126 · 1학년 1,520 중 353), 150개 수업 중 149개가 가짜 후보를 하나 이상 보여 주고 있었다.
  - **성립 조건(학생 쪽)**: 상대 학생 중 내 수업에 없는 학생이 **내 시간**에 다른 수업이 없고, 내 학생 중 상대 수업에 없는 학생이 **상대 시간**에 다른 수업이 없을 것. 수강생이 같으면 저절로 성립한다. 실측에서는 «수강생이 다르지만 겹치지 않는»(`compatible`) 경우가 0건이었다 — 이 학교에서는 사실상 «명단이 같아야 한다»와 같다.
  - **판정은 서버 `get_swap_roster_fit`**(DEFINER, 교사·관리자 전용 — 겹치는 학생 이름 표본을 준다). 상태 유도·후보 선정은 순수 모듈 `timetableSwapUtils`(`rosterStatusOf`·`findSwappableClasses(target, all, rosterFit)`·`getRosterConflictReasons`), 훅 = `useSwapRosterFit`. 상태 4종 = `same`·`compatible`·`conflict`·`unknown`(어느 한쪽 명단이 비어 있다 — 공동 수업에서 학생 행이 한 교사에게만 달린 경우 등).
  - **후보 = 표기가 같은 수업 ∪ 표기는 달라도 수강생이 맞는 수업**. 표기가 다르고 학생이 겹치기만 하는 수업은 올리지 않는다 — 선택과목 학생이 듣는 수십 개 수업이 «불가» 목록을 채워 볼 것을 가린다. (뒤쪽 경로는 실측 0건이지만 판정 기준이 표기가 아니라 학생이므로 둔다.)
  - **화면**: 교체 가능한 후보에 `수강생 같음`/`겹치는 학생 없음`/`명단 미확인`(앰버) 칩. 불가 후보는 이유별로 따로 접는다 — **«수강생이 달라 교체할 수 없는 수업»**(같은 학생 수 + 누가 어느 시각에 겹치는지 이름 3명) / «선생님 시간이 겹쳐 불가능한 수업». 둘 다면 수강생 쪽(다른 주로 미뤄도 풀리지 않는 이유). 헤더 칩은 `N학년 M반` 이 아니라 `2-7 · 학생 23명`(분반 번호를 학급으로 풀어 쓰지 않는다).
  - **명단 조회가 실패하면 표기로만 고르되 화면이 말한다**(앰버 안내 + 모든 후보 `명단 미확인`) — 조용히 예전 판정으로 돌아가면 오판이 그대로 되살아난다. 배포 순서상 프런트가 먼저 나가도 이 경로로 동작한다.
  - ⚠️ **서버는 신청을 막지 않는다** — `class_swap` INSERT 는 종전처럼 클라이언트 직접 쓰기다. 판정은 후보 목록에서만 한다. 이 변경 전에 만들어진 대기 중 요청은 그대로 남는다.
  - 회귀 = `npx tsx scripts/swap-candidates-test/run.mts`(52건, §5 수강생 판정)
- **상대방 후보에서 `학교관리자`(교장·교감) 제외 (2026-08-14 사용자 결정)**: `useSwapExcludedTeacherIds`(`resource_tag_assignments` × `resource_tags`)로 걸러 교체·대체 **양쪽 목록**에서 뺀다. **제외는 상대방에만** — 학교관리자 본인이 자기 수업 교체를 신청하는 건 막지 않는다. **충돌 판정 모집단(`allTeacherEntries`)에서는 빼지 않는다** — 그들의 수업도 시간 점유는 실재하므로 목록에서만 걸러야 판정이 정확하다. 태그가 도착하기 전 한 프레임 노출되지 않도록 로딩 플래그에 합친다. **시험 감독 제외 목록(`supervisionService.SUPERVISION_EXCLUDED_TAGS` = 학교관리자 + 고사운영교사)과는 일부러 분리** — 고사운영교사는 감독 운영상의 제외이지 수업을 못 맡는다는 뜻이 아니다. **주의: `useAvailableTeachers`는 시간표 슬롯이 아니라 `resource` 교사 전원을 나열**하므로, 그 학기 수업이 하나도 없는 계정(학교관리자·상담교사·테스트 계정 `교사A` 등)은 모든 교시에서 "수업 없음"으로 잡혀 대체 후보 최상단에 온다(부담 정렬에서도 빈 시간표가 최소값). 대체 후보 정책을 바꿀 땐 이 목록을 먼저 볼 것
- **모달 UI 세부 결정 3가지**: ①**충돌·부담 사유는 인라인 텍스트**(hover 툴팁 금지 — 터치 기기에서 열리지 않아 "왜 안 되는지"가 모바일에서 통째로 사라진다) ②두 탭의 행은 `ActionRow` 하나로 통일하고 **행 안 동작 버튼은 폭 고정**(`w-[72px]`)해 세로 정렬시킨다(스캔 속도가 달라진다) ③좌우 2단 배치(교체 대상 카드·목록 탭+문서 버튼)는 좁은 화면에서 **세로로 쌓는다**
- **교시 스트립 인포그래픽 (`DayPeriodStrip.tsx`, 2026-08-14 사용자 요청)**: 신청 모달의 미리보기에 그날 1~7교시를 사각형 7개로 그려 추가(+)·제거(−)·기존 수업·공강을 색으로 보여준다. **설계 급소 = 같은 요일 교체**(`월2 ↔ 월5`) — 그때는 한 사람의 하루에 추가와 제거가 **동시에** 일어나므로 스트립 하나가 `added`·`removed`를 함께 받아야 한다(호출부가 두 요일이 같은지 따져 1줄 또는 2줄로 넘긴다). 슬롯 데이터는 `ClassSwapDialog`의 `slotsByTeacher`에서 프롭으로 내려주고, **없으면 그 섹션만 조용히 빠진다**(모달을 다른 곳에서 재사용해도 깨지지 않게)
- **구 `TimetableChangeDialog`는 삭제됨(2026-08-14)**: 신청을 DB에 저장하지 않고 성공 토스트만 띄우던 모달이다. 업무 흐름의 '수업 교체' WORK가 이걸 쓰고 있었고 지금은 `ClassSwapDialog`(+optional `onRequested` 콜백)를 쓴다. `class_swap` 행을 실제로 만드는 경로는 `useCreateClassSwap` 하나뿐

- **핵심 파일**: `TimetableView.tsx`(주간 시간표·교체 관리·메모 소유), 수업 교체·대체 모달 6종(`ClassSwapDialog`→`SwapRequestDialog`/`SubstituteRequestDialog`→`SwapRequestList`→`SwapApprovalDialog`→`SwapDocumentDialog`)
- **주의**: 교체 후보 0건이면 `section` 표부터 의심(학기 키 없음·자동 생성 안 됨, `ensureSectionRows`), 후보 정렬=상대 교사 부담 순(`lib/swapBurden.ts`), 교체를 막는 것은 **동아리활동뿐**(`isSwappableLesson` — 자율·진로는 2026-09-15 부터 교체 가능, 차단 목록 방식), 학교관리자 상대 제외(`useSwapExcludedTeacherIds`), 사유는 인라인 텍스트(툴팁 금지), `DayPeriodStrip` 인포그래픽
- **교체 후보 = 수강생 판정 (2026-10-12)**: 학년-반 표기(`grade`·`class_label`)는 학급일 때도 **선택과목·수준별 분반 번호**일 때도 있어 표기가 같다고 학생이 같지 않다(라이브: 표기 같은 후보의 61%가 학생이 겹쳐 실제로 불가였다). 판정 = 서버 `get_swap_roster_fit`(교사·관리자, 맞바꾸면 겹치는 학생 수 양방향) → `findSwappableClasses(target, all, rosterFit)`. ⚠️ 표기로 학급을 추정하는 새 코드를 쓰지 말 것 — 학생이 관계되면 `student_timetable` 명단으로 판정한다. 명단을 못 읽으면 표기로 고르되 화면이 «명단 미확인»이라 말한다
- **쉬는 날 판정 = `src/lib/schoolDay.ts` 단일 출처 (2026-10-11)**: 시간표는 요일 패턴이라 공휴일·방학·시험을 모른다. 날짜마다 `school`·`exam`·`weekend`·`holiday`·`vacation` — 근거 = NEIS 학사일정 `meta.sbtr_dd_sc_nm`(`공휴일`·`휴업일`), 시험 = 제목 `N차고사`(수업공제일명이 `해당없음`). 조회 = `useSchoolCalendar(range, {applyTerm})`/`useSchoolDay()`. 소비처 = 대시보드 오늘 시간표(쉬는 날 = 수업 대신 안내, **시험일 = 흐리게 남김** — 사용자 결정) · 시간표 화면 요일 머리 칩 + 쉬는 날 칸 흐림 · 다마고찌 수업 정지 · 급식지도 · 자습 감독. ⚠ ①`토요휴업일`(매주 토요일의 휴업일)은 닫힘으로 세지 않는다 — 세면 토요 자습을 영원히 배정할 수 없다 ②«방학식»은 수업일이다(다마고찌 옛 정규식 `/방학/` 이 쉬는 날로 봤다) ③다른 학기를 넘겨 보는 화면은 `applyTerm: false`(학사력 기간을 적용하면 다음 학기 주가 «방학»으로 덮인다 — 방학은 NEIS 가 이미 말한다) ④학년별 행사 구분은 NEIS 에 사실상 없어(사용자 확인) 수학여행은 메모로만. **손으로 넣는 학사일정에 «수업 없는 날 · 학년» (2026-10-11 사용자 요청)** — 일정 만들기·수정 창(학사일정만, `NoClassDayField`)이 NEIS 와 같은 값 `meta.sbtr_dd_sc_nm='휴업일'` + `meta.no_class_grades`(없음 = 전 학년)를 저장한다(저장 규칙 단일 출처 `noClassMetaPatch` — NEIS 공휴일을 고쳐도 `공휴일` 유지, 해제 시 NEIS 는 `해당없음`·손 일정은 null). 판정: 학년을 아는 화면(학생 대시보드·학생 시간표·학생 다마고찌·자습 감독)은 `grade` 를 넘기고, 여러 학년을 가르치는 교사 화면은 학교 전체로 판정한 뒤 수업 이름(`과목 2-3`)의 학년으로 `isClosedForGrade` 를 본다 · 다마고찌 선생님 펫도 같은 방식 — 일부 학년 휴업 날 그 학년 수업 교시만 `noClassPeriods` 로 뺀다(2026-10-13, `partialClosedPeriods`), 학사일정을 읽기 전에는 따라잡지 않는다 · ⚠ 급식지도는 학교 전체라 **일부 학년 휴업으로 쉬지 않는다**(`useMealDutySources` 가 그 항목의 dayKind 를 지운다). 회귀 = `npx tsx scripts/school-day-test/run.mts` + `run-screenshots.mjs`
