## 사용자 결정(인터뷰)
- 사용자 셋 동등 — 같은 동아리 페이지가 역할마다 다르게 보인다. 모든 관리를 MCP(`club.manage`, 교사 기본 켜짐)로도.
- 명단·출석·구매 = **교사 확정** · 활동 기록·성찰 = **학생 바로 반영**(창체) · 누가기록 = 교사 전용, **문장 생성은 MCP 로만**(웹엔 버튼 없음).
- 편성: 학생은 지망만, 면접 결과는 **기장이 입력**, 명단은 지도교사 확정. 정규 + 자율동아리.
- 요청: 가벼운 수집은 «요청»(입력 받기의 동아리 축), 큰 일은 업무. 담당자 = 태그 «동아리담당자».
- 화면: 지도교사 = 한 장 보기 + 탭 · 담당자 = 표 + 행 → 상세 모달.

**관리자 보기 전환(2026-11-11)** — 관리자(미리보기 아님)에게 머리 위 [담당자 화면 · 학생 화면]. 학생 화면은 학생을 골라 **그 학생 계정으로 읽은 그대로**를 보인다(서버 `club_view_as`, 읽기 전용 — 쓰기·교사 전용 읽기는 `clubService.call()` 이 막는다). 한 번도 로그인하지 않은 학생은 계정이 없어 볼 수 없다. 학생 화면의 쓰기 버튼(지원·지원 취소·개설 신청·부원 제안·활동 기록·물품 신청·면접 판정)은 자리는 그대로 두고 누를 수 없게 한다(`useViewAsReadOnly`). 앱 전역 «학생 미리보기»는 관리자 본인 신원으로 읽어 빈 화면이 되므로 이 전환을 쓴다.

**모양(2026-11-12 업무노트에 맞춤)** — 흰 카드 + 14px 카드 제목(`components/panel.tsx` `Card`·`PanelTitle`·`StatTile` — 공용 `SectionLabel` 11px 대문자는 모달에만), 동아리 색(`clubTone`)은 머리글자 표식에만(상태 색과 겹치지 않게). 한 장 보기 = 흰 머리(경로 → 큰 제목 → 정원 막대) + 본문(탭) · 오른쪽 곁칸(숫자·지도/기장/장소·지난 기록), 모달은 곁칸을 아래로.

한 장 보기 탭 = 개요(해야 할 것·부원 구성·지난 기록) · 부원 · 활동 · 누가기록(교사) · 예산·구매 · 요청(교사) · 지원(교사·기장). 빈 탭은 두지 않는다.

## 조용히 틀리는 자리
1. **`club_info` 는 파생이다** — 직접 고치면 다음 동기화가 덮는다. 명단은 `club_set_members`/`club_decide_members` 로.
2. **이름이 바뀐 해의 두 행**(옛 이름 = 3학년) — 합치거나 inactive 로 돌리면 대상 규칙·생기부·창체에서 3학년이 빠진다. 옛 이름 행은 `former_name`(기장 미정 경고를 내지 않는다).
3. **역할 판정 NULL** — `club_student_role` 은 아니면 NULL. `if not (a OR role = 'leader')` 는 거부를 건너뛴다(`coalesce`).
4. **동아리 축 목록 SQL 네 곳 ↔ TS** — 하나만 바꾸면 웹이 축을 «사람마다»로 바꿔 읽어 저장 때 «보낸 뒤 축 변경»으로 거부된다(회귀 ③).
5. **옛 창체 주최는 자동으로 잇지 않는다**(창체 결정 — `1` 꼬리·쉼표·철자 차이) — 제안만, 담당자 확정.
6. 요청 보내기는 할 일에 담당자를 넣지 않는다(대상자를 담당자로 끼우면 한 명 완료로 요청이 닫힌다 — collect-input 문서).
8. **학생으로 보기 읽기 목록은 SQL `club_view_as` ↔ `viewAs.ts` `VIEW_AS_READS` 두 벌**(회귀 `run.mts`) — 학생 화면이 새 읽기 RPC 를 쓰면 둘 다에 더할 것(빠뜨리면 그 칸만 «열 수 없습니다»). 쓰기를 넣지 말 것.
7. 담당자 링크는 `/tasks/mine?task=`(관리 표) · 지도교사 응답은 `/my-tasks?collect=`.
