# approval

> CLAUDE.md Component Architecture에서 분리한 결재(src/features/approval) 상세. 스키마·HWPX 날인·QR 서명.

#### 결재 (`src/features/approval/`, 2026-08-14 신설)
- **어떤 기능에나 붙는 유틸**: 화면에 `<ApprovalButton subjectType subjectId title payload />` 하나만 놓으면 결재가 붙는다. 대상은 `subject_type`+`subject_id`로 가리키고(기능마다 표가 달라 FK 불가), **허용 타입은 코드 allowlist**(`registry.tsx` — `workRegistry.ts`와 같은 원칙). 첫 적용 = 결강시 보강 계획서(`timetable.swap_document`, subject_id는 선택된 `class_swap` id들을 정렬해 이은 문자열 = 그 조합이 곧 하나의 문서)
- **결재선 = 직위 칸 + 사람 지정 (2026-08-14 사용자 결정)**: 계·부장·교감·교장 칸을 먼저 두고 칸마다 사람을 고른다(필요 없는 칸은 체크 해제). 자유 명단이 아닌 이유는 **HWPX 결재란이 그 4칸 표**여서 — `role_label`이 곧 서명이 찍힐 칸이다. 반려는 **전체 종료 후 재신청**(같은 결정)
- **취소·반려 후 재상신 가능 (2026-08-14)**: 서버는 원래부터 막지 않았다 — `create_approval_request`에 중복 검사가 없고, 부분 UNIQUE `approval_request_one_pending_per_subject`는 **동시에 pending 2건**만 막는다(취소·반려는 pending이 아니라 통과). 막고 있던 것은 `ApprovalButton`의 `approvals.find(pending) ?? approvals[0]` **폴백**이었다 — pending이 없으면 종료된 최신 건을 집어 버튼이 영구히 '결재 현황'으로 굳고 상신 모달로 가는 길이 사라졌다. 지금은 **상세 모달(`ApprovalActDialog`) 푸터의 '다시 상신'**(신청자 본인 + cancelled/rejected에서만 — 승인 완료는 제외)이 진입점이고, **이전 결재선을 씨앗으로 채운다**(`ApprovalRequestDialog.initialSteps`, 안 쓰던 칸은 체크 해제된 채 복원). 상세를 **닫지 않고 위에 쌓는다**(`ClassSwapDialog`와 같은 패턴) — 두 Radix 모달을 같은 틱에 닫고 열면 body의 `pointer-events`가 복구되지 않을 수 있고, 반려 사유를 보면서 결재선을 다시 짜는 것이 원래 목적이다. **씨앗 심기는 열릴 때 1회만**(`seeded` ref) — 폴링·재조회가 입력 중인 결재선을 지우지 않게. 재상신 경합(다른 탭에서 이미 상신)은 23505로 오는데 원문이 읽히지 않으므로 서비스가 한국어로 번역한다
- **승인에는 그 자리 서명이 필수**(서버 RPC가 거부): 연수 서명과 **같은 획 좌표 형식**을 쓰므로 `SignaturePad`·`SignatureStrokesView`가 그대로 재사용된다
- **휴대폰 서명 QR (2026-08-14)**: 마우스로 그린 서명은 획이 각져 실제 사인과 다르다 → 결재 화면의 서명 패드 **옆에 작은 QR**(`ApprovalSignQr`, 92px)을 상시 노출한다(별도 모달 없음 — 연수 QR과 달리 "받는 사람이 여럿"이 아니라 "지금 결재하는 나 한 명"이라 모달을 열 이유가 없다). 대상 = `/approval-sign/:requestId`(`pages/ApprovalSign.tsx`, 앱 셸 없는 단독 화면). **연수 QR과 같은 보안 결정**: 라우트를 public 화이트리스트에 넣지 않아 로그인이 필수이고, `act_on_approval_step`이 "지금 차례인 결재자 본인"을 서버에서 재검증하므로 **QR에 토큰·유효기간이 없다**. 로그인 왕복 후 복귀는 `RequireAuth`의 `sessionStorage` 경로가 그대로 처리한다. **화면 표시는 작게 하되 QR 원본은 크게(480px) 굽는다** — 저해상도로 만들어 확대하면 셀 경계가 뭉개져 카메라가 못 읽는다. 휴대폰에서 서명해도 **데스크톱 탭에는 focus 이벤트가 없어** 자동 갱신이 안 걸리므로, 상세 모달이 열려 있는 동안만 `useApprovalRequest(id, open, 5000)`로 폴링하고 결재가 끝나면 `refetchInterval`이 스스로 멈춘다
- **쓰기는 RPC 전용**: 두 표에 INSERT/UPDATE 정책을 두지 않았다 — 직접 쓰기를 허용하면 차례를 건너뛰거나 남의 칸에 서명할 수 있다. `act_on_approval_step`이 요청 행을 `FOR UPDATE`로 잠그고 차례·신원·서명을 검증한다. 두 표가 서로를 참조해 SELECT 정책에서 직접 조인하면 RLS가 재귀하므로 판정은 DEFINER 함수(`can_view_approval_request`)로 뺐다
- **발견 경로가 곧 사용률**: 결재자는 원본 화면(보강 계획서 모달)을 열 이유가 없다 → 교사 대시보드 **"결재 대기" 카드**(`ApprovalInboxCard`, 내 차례인 것만). 대기 0건이면 카드가 `null`을 반환해 줄이 통째로 사라진다(전폭 배치라 구멍이 안 남음)
- **기능 화면에 붙이는 결재 목록 = `ApprovalSubjectList` (2026-08-14)**: `subjectType` 하나만 주면 그 종류의 결재를 모아 보여주는 탭용 부품(행 = 제목·상태·`내 차례` 배지 + **`ApprovalLine` 축소판**으로 어느 칸까지 갔는지, 클릭 = `ApprovalActDialog`). 첫 적용 = **수업 교체 관리 모달의 [결재 문서] 탭**(`SwapRequestList`, 받은 요청·보낸 요청과 나란히). 대시보드 카드는 "내 차례"만 보여주므로 **상신자가 자기 문서의 진행 상황을 볼 곳이 없었다** — 이 목록은 RLS 범위(내가 상신 ∪ 내가 결재선) 전체를 보여줘 그 공백을 메운다. 탭 배지는 pending이 아니라 **`isMyTurn` 건수**(배지 = 눌러야 할 이유). `useMyApprovalsBySubjectType`은 `useMyApprovals`와 **같은 캐시를 필터**하므로 배지와 목록을 함께 걸어도 요청이 늘지 않는다. 행 클릭 = `ApprovalActDialog`이므로 **확인(미리보기 표)과 출력(`download`)까지 여기서 끝난다**. 다만 **재상신은 하지 않는다** — 출력은 "결재된 그 문서"를 그대로 뽑는 것이라 스냅샷이 정답이지만, 재상신은 "지금 상태를 새로 올리는" 행위라 스냅샷을 쓰면 그 사이 바뀐 원본과 어긋난다. 재상신은 원본 화면(`SwapDocumentDialog`)에서 라이브 `class_swap`으로 다시 만들 것. **문서 출처가 경로마다 다르다는 점을 기억할 것**: 원본 화면 다운로드=라이브, 결재 화면 다운로드=payload 스냅샷
- **결재 화면에서 문서 확인·출력 (2026-08-14)**: 레지스트리에 선택 필드 **`download(request)`**를 두어 `ApprovalActDialog` 푸터에 [문서 내려받기](서명이 있으면 [결재본 내려받기])가 뜬다 — 결재 기능은 양식을 모르고, 아는 것은 레지스트리 항목뿐이라는 `Preview`와 같은 구조. 덕분에 **결재 문서 탭·대시보드 결재함 어디서 열어도** 확인(미리보기 표)과 출력이 된다. **문서는 저장된 `payload` 스냅샷으로 만든다** — 결재자들이 보고 서명한 내용이 그것이라 그 사이 원본 `class_swap`이 바뀌어도 결재된 문서는 변하면 안 된다. 무거운 의존(JSZip 템플릿·rhwp WASM)은 **동적 import**로 미루고, WASM은 찍을 서명이 있을 때만 부른다(레지스트리는 결재 버튼이 있는 모든 화면에 로드되므로 정적으로 물리면 안 된다)
- **payload ↔ 문서 입력 변환 = `src/lib/swapDocumentPayload.ts` (순수)**: payload는 사람이 읽는 **`reasonLabels`(문자열)**를 담는데 채움기(`fillLessonSection0`)는 **`reasons`(인덱스 0..8)**를 받는다. **`ABSENCE_REASONS`의 순서가 곧 양식 결강사유 표의 열 순서라 재배열하면 이미 저장된 결재의 ○가 통째로 어긋난다**(미리보기는 라벨을 그대로 보여줘 화면상으론 멀쩡해 보인다 — 눈으로 못 잡는 버그). 그래서 순서를 회귀 테스트가 고정 값으로 못 박는다: `npx tsx scripts/swap-document-payload-test/run.mts`(23건, 라이브 payload 픽스처 포함). `SwapDocumentDialog`도 이 모듈의 `ABSENCE_REASONS`·`buildSwapDocumentPayload`를 쓰고 문서 입력을 `documentInput` 하나로 모아, **결재 화면에서 다시 만든 문서가 원본 화면 다운로드와 어긋날 수 없다**
- **HWPX 결재란 자동 날인 = zip + XML 문자열만, WASM 안 씀 (2026-08-14 전면 교체)**: 저장은 벡터지만 한글 그림은 BinData 비트맵이라 찍는 순간에만 PNG로 굽고(`lib/signatureRaster.ts`, 캔버스), 그림을 **셀 문단 안의 글자처럼**(`<hp:pos treatAsChar="1" vertRelTo="PARA" horzRelTo="COLUMN">`) 넣는다. 크기는 셀이 XML에 스스로 적어 둔 `<hp:cellSz>`−`<hp:cellMargin>`(HWPUNIT)에서 구하므로 레이아웃 엔진이 필요 없다. **칸은 텍스트로 찾는다** — 칸 이름 셀의 `cellAddr`를 읽어 **바로 아래 칸**(같은 colAddr, rowAddr+rowSpan)을 고른다. **셀 인덱스를 하드코딩하면 양식이 한 칸만 바뀌어도 조용히 엉뚱한 칸에 찍힌다**. 날인은 결재 문서를 내려받을 때만 실행된다
- **왜 `@rhwp/core`를 버렸나 (실제 장애)**: 구 구현은 core의 `insertPictureEx(cellPath)`를 썼는데, 그 API는 문서에 명시된 대로 **"표 셀 영역에 floating picture"**를 만든다 — 결과가 `treatAsChar="0" vertRelTo="PAPER" horzRelTo="PAPER"` + **용지 절대좌표**다. 그 좌표는 rhwp 레이아웃 엔진이 계산한 셀 위치인데 **한글은 자기 방식으로 다시 배치**하므로 어긋나면 서명이 칸 밖으로 나간다(실제 증상). `cellPath`를 비워 "본문 inline"으로 넣어도 `treatAsChar="0"` + PAPER(0,0)이라 소용없다 — core에는 글자처럼 넣는 모드가 없다. 부수 이득: 문서 전체 재직렬화가 사라져 **`Scripts/` 등 원본 요소가 보존**되고 WASM 로딩도 없다
- **그때 회귀 테스트가 왜 못 잡았나(교훈)**: 구 테스트는 "삽입 후 rhwp로 다시 열어 그림 x좌표가 셀 x좌표와 같은가"를 봤다. **자기가 쓴 좌표를 그대로 돌려받는 동어반복**이라 항상 통과한다. 게다가 크기는 `width:3000` 하드코딩이라 실제 크기 계산식을 한 번도 실행하지 않았다. 지금은 **좌표가 아니라 구조**를 본다(그림이 대상 `<hp:tc>` 안에 있는가 · `treatAsChar="1"`인가 · `RelTo="PAPER"`가 없는가 · 크기가 셀 여유 안인가 · 종횡비 보존 · 줄 캐시 제거 · 여러 칸 동시 삽입 시 오프셋 밀림). 앱과 같은 순서(`fillLessonSection0` 채움 → 날인)도 검사한다. `npx tsx scripts/approval-stamp-test/run.mts`(95건)
- **주의**: 순수 로직(칸 찾기·그림 XML 생성)은 `approvalCells.ts`, 캔버스·zip 조립은 `approvalStamp.ts`로 갈라 둔다 — 전자는 Node 회귀 테스트가 그대로 import한다. `stampApprovalSignatures`의 `rasterize` 옵션도 같은 이유(테스트가 고정 PNG를 주입). 편집은 **오프셋 큰 것부터** 적용해야 앞 편집이 뒤 오프셋을 밀지 않는다. 그림을 넣은 문단의 `<hp:linesegarray>`는 반드시 제거한다(줄 캐시가 남으면 한글이 옛 줄 높이로 그린다 — task-workflow에서 얻은 교훈과 같다)
