### 1. 페이지 뼈대 — `Layout` + `PageContainer`

```tsx
<Layout>
  <PageContainer>            {/* 또는 width="narrow" */}
    …
  </PageContainer>
</Layout>
```

- **머리글에 기능명·아이콘을 쓰지 않는다 (2026-09-22 사용자 규약)** — 사용자는 사이드바·주소로
  이미 어디에 들어왔는지 안다. 머리글 카드는 **그 화면의 필터·액션**만 담는다(예: 내 할 일 =
  왼쪽 상태 필터, 오른쪽 [사용 방법]·[계획표]). **예외는 생기부 분석(evalog)처럼 UI 구조가 완전히
  다른 앱형 화면**뿐이다 — 거기서는 이름이 "다른 앱에 들어왔다"를 알려 준다. 2026-09-22 에
  내 할 일·입시 정보·공지사항·구매 신청·전자서명·전화번호부·연수 이수 현황·발급번호·시험 시간표·
  시간표 생성을 정리했다. 제목 옆에 붙어 있던 **건수는 옮기지 않았다** — 바로 아래 탭·칩 배지가
  이미 같은 숫자를 말했다. **하위 화면의 제목은 대상이 아니다**(새 시험 시간표·새 모의고사 감독표·
  새 시간표 생성·시간표 이름 — "어느 흐름·어느 대상인가"는 사이드바가 말해 주지 못한다). 제목 대신
  **지금 해야 할 일**을 알려 주는 한 줄은 남겨도 된다(발급번호 동아리 탭의 안내). 머리글에 남는 것이
  하나도 없으면 머리글 카드 자체를 그리지 않는다(연수 이수 현황 — 일반 교사). **새 화면은 처음부터
  이 규약을 따른다.** 사용 방법 안내 목업도 실제 머리글과 같아야 한다(제목을 지우면 목업에서도 지울
  것). 회귀 = `npx tsx scripts/page-header-rule-test/run.mts`(24건 — 되살아나도 오류가 없는 부류다).
- **패딩은 `Layout`의 `<main>`이 준다** (`p-2 sm:p-3 md:p-4 lg:p-6`).
  페이지가 `p-6`·`px-4 py-6`을 또 얹으면 **이중 패딩**이 되어 다른 화면보다
  안쪽으로 밀린다. 2026-08-28 실측에서 중앙 정렬 화면 7개 중 **5개가 이 상태**였다.
- **폭은 `PageContainer`가 정한다**(`src/components/layout/PageContainer.tsx`).
  `max-w-*`를 페이지에 직접 쓰지 말 것 — 종전엔 폭이 5종(4xl·5xl·6xl·7xl·1600px)으로 갈라져 있었다.
- 세로 리듬(`space-y-4 sm:space-y-6`)도 컨테이너가 준다.

**폭을 고르는 기준은 하나다 — "이 화면은 넓을수록 좋은가?"**

| 값 | 언제 | 예 |
|---|---|---|
| `full` (기본) | 표·목록·카드 그리드·캘린더처럼 가로를 쓸수록 정보가 더 들어온다 | 구매 신청 · 업무 관리 · 스케줄 · 서류함 · 창의적 체험활동 |
| `narrow` | 폼·설정·검색 결과처럼 한 줄이 길어지면 오히려 읽기 나쁘다. 넓은 화면에서 가운데로 모인다 | 문서 생성 · 도구 모음 · 통합 검색 · 전화번호부 · 스마트 기기 |

**앱처럼 화면을 통째로 쓰는 경우**(생기부 분석·모의고사 분석·학생 대시보드·탐구 설계)는
`PageContainer`가 아니라 **`<Layout fullWidth>`**를 쓴다 — Layout의 패딩 자체를 없앤다.
구형 3개(evalog·evalearn·student-dashboard)는 음수 마진(`-m-2 sm:-m-3 …`)으로 같은 일을
하는데, **새 화면에서 그 방식을 따라 하지 말 것**(높이 계산을 직접 떠안게 된다).

### 3-1. 토스트 — `import { toast } from '@/lib/toast'` 하나뿐 (2026-09-12)

**`sonner` 를 직접 import 하지 말 것.** 종전엔 토스트 시스템이 **두 벌**이었다 —
Radix(`@/hooks/use-toast`, 호출 940건)와 sonner(506건)가 `App.tsx` 에 **동시에 마운트**돼
있어서, 같은 앱에서 토스트가 두 가지 모양으로 떴다(어느 파일이 어디서 import 했느냐에
따라 갈렸다). 지금은 sonner 한 벌이고 **`@/lib/toast` 가 유일한 입구**다(`sonner` 직접
import 는 `ui/sonner.tsx`·`lib/toast.ts` 두 파일에만 허용 — 회귀가 검사한다).

- **구 `toast({ title, description, variant })` 는 그대로 동작한다** — `@/hooks/use-toast`
  가 sonner 위의 어댑터가 됐다(호출부 940곳 무수정). 이게 가능했던 이유는 실사용 표면이
  좁았기 때문이다: 반환값·`action:`·`duration:`·JSX 제목이 전부 **0건**이었다.
  **새 코드는 `toast.success('저장했습니다')`** 를 쓸 것(제목/설명 두 칸을 채우지 않는다).
- **색·문구 정리는 `src/lib/toastMessage.ts` 단일 출처**. ①`variant: 'destructive'` 가
  무엇보다 먼저 ②정보 없는 제목(`성공`·`오류`·`알림`)은 버리고 설명문을 본문으로 올린다
  ③제목을 되풀이할 뿐인 설명문은 버린다(**양방향 일치**여야 한다 — 한쪽 포함으로 판정하면
  `서명 완료 ┃ 연수 참석 서명이 저장되었습니다` 처럼 **무엇에 대한 것인지**를 말해 주는
  설명까지 지워진다) ④그래도 tone 을 모르면 제목에서 유추하되 **실패를 먼저 본다**
  ('삭제 실패' 가 '삭제' 때문에 초록이 되면 안 된다).
- **⚠️ 토스트 색을 CSS 파일에 적지 말 것.** sonner 는 자기 CSS 를 **런타임에 주입**하고
  팔레트를 `[data-sonner-toaster][data-theme=light]`(특이도 0-2-0)로 정의한다.
  `index.css` 에 `html body [data-sonner-toaster]`(0-1-2)로 적으면 — 길어 보여도 —
  **져서 조용히 무시된다**(2026-09-12 에 실제로 그렇게 만들었고, 브라우저에서 계산값을
  재 보기 전까지 아무 신호도 없었다. 색이 비슷해 눈으로도 구분이 안 됐고, "변수가
  index.css 에 있는가" 라는 정적 검사도 통과했다). 팔레트는 **인라인 style**
  (`src/lib/toastPalette.ts` → `<Toaster style>`)로 넘긴다. 위치처럼 미디어 쿼리가
  필요한 것만 `index.css` 에 남는다.
- **닫기 버튼은 모든 토스트에 상시 표시**(`closeButton`). 구 Radix 토스트의 닫기 버튼은
  `opacity-0 … group-hover:opacity-100` 이라 **hover 가 없는 휴대폰에서 닫을 수단이
  아예 없었다**. 모바일 여백은 하단 네비 5칸 위(`--mobile-nav-height`) — sonner 가
  600px 이하에서 `bottom: 20px` 를 **하드코딩**해 `offset` prop 으로는 못 올린다.
- **토스트를 새로 추가하기 전에 "화면이 이미 이걸 말하고 있는가"를 물을 것.**
  다이얼로그가 닫히고 목록이 갱신되는 CRUD 성공은 토스트가 필요 없다(2026-09-12 에
  그런 **123건을 삭제**했다). 남길 값어치가 있는 것은 **건수·부분 실패·내려받기·
  서명/결재처럼 되돌리기 어려운 행위·비동기(AI·업로드) 결과·다른 화면에 생기는
  부수효과·"다음에 무슨 일이 일어나는지"** 다.
- 회귀 = `npx tsx scripts/toast-system-test/run.mts`(59건 — 토스트가 두 벌로 갈라지거나
  닫기 버튼이 빠지거나 색 대비가 무너져도 **빌드·타입 검사는 통과**하므로 이게 방어선이다)

### 5. 기능 안내 모달 — 왼쪽 시연 · 오른쪽 설명 (2026-09-04)

기능 사용법은 글머리표로 쓰면 죽는다("서명자를 추가하고 위치를 지정한 뒤 요청합니다"를
읽고 나서도 **어디를 눌러야 하는지 모른다**). 반대로 시연만 있으면 화면은 흘러가는데
**왜 그렇게 하는지**가 안 남는다. 그래서 한 단계에 둘을 짝지어 놓는다 — `WalkthroughDialog`.

- **저작은 스킬 `/feature-guide-dialog`가 절차·수칙을 갖는다.** 새 안내를 만들 땐 이걸 먼저 볼 것.
- **런타임은 presentation 프로젝트에서 옮겨 온 것**(`src/lib/walkthrough/` = 저쪽 `src/walkthrough`+`src/scene`,
  503줄·새 npm 의존성 0). 덱 엔진(네비·썸네일·발표자 모드·export)은 **가져오지 않았다** — 여기서
  필요한 것은 "모달에 절차 한 편 재생"이지 발표 도구가 아니다. 씬 문법이 같아 저쪽 코드를 그대로 옮길 수 있다.
- **무대는 960×540 고정 캔버스를 축소 배치**(`WalkthroughStage`). 폭을 따라가게 두면 ①글자가 화면마다
  달라지고 ②**포인터가 버튼 위에 있는지가 폭마다 달라진다**(목업은 px, 포인터는 %라 함께 늘어나지 않는다).
- **포인터 좌표를 손으로 계산하지 말 것** — 원본 문법은 산수 후 캡처로 눈 확정을 요구하지만(±2% 오차),
  여기서는 자리를 `Rect` 상수로 한 번만 적고 `boxOf`(목업)와 `centerOf`(포인터)가 **함께 참조**해
  포인터가 대상 위에 오는 것이 **구성으로 보장**된다.
- **글은 시연을 되풀이하지 않는다** — "버튼을 누릅니다"는 왼쪽이 이미 말했다. 글이 맡을 것은
  ①왜 그렇게 되어 있는지 ②오해하기 쉬운 것 ③**모르면 손해 보는 것**(7일 뒤 파일 삭제, 승인≠완료,
  비공개면 담당자에게 안 보임) 셋뿐이다.
- **목업 라벨은 실제 화면 문구를 코드에서 채집**한다(기억으로 쓰면 없는 버튼을 안내하게 된다).
  씬 파일 상단에 어느 컴포넌트에서 가져왔는지 적어 문구가 바뀔 때 함께 고칠 수 있게 한다.
- **씬 안의 화살표·연결선은 데이터다 (2026-09-04)**: 단계의 순서와 방향을 말하는 유일한 표시라 dataviz 규약(표면 대비 3:1↑)이 그대로 적용된다. `--hair`(#e2e8f0)는 **경계선용**이라 흰 배경 대비가 1.20:1 이고, 이걸 연결선에 쓰면 실사용에서 "화살표가 안 보인다"가 된다 → `--fg-muted`(4.76:1). **화살촉도 반드시 그릴 것** — 머리 없는 선은 화살표로 읽히지 않는데 배너 문구는 "화살표"라고 말한다. 그리고 **포인터 좌표를 손으로 적지 말 것**(stageCoords 규약): 패널 안 행처럼 부모-로컬 좌표를 쓰는 목업은 포인터 쪽에서 부모 오프셋을 다시 더해야 하는데, 그걸 손으로 적으면 **한 행씩 조용히 어긋난다** — 업무 흐름 ②에서 포인터가 "문서 생성" 대신 그 위 "없음" 행을 36px 차이로 가리키고 있었다. 행 자리를 상수로 올리고 `boxOf`(목업)·`centerOf`(포인터)가 함께 참조하게 한다. 회귀 = `npx tsx --tsconfig tsconfig.app.json scripts/workflow-guide-test/run.mts`(12건 — 렌더는 성공하고 그림만 틀리므로 SSR 마크업과 좌표 산술로 못 박는다).
- 진입점 = 기능 헤더 액션 묶음의 **맨 왼쪽**에 `HelpCircle` ghost 버튼("사용 방법") — **이 버튼 왼쪽에는
  아무 버튼도 두지 않는다**(2026-09-04 사용자 규약, 탭 전환기도 오른쪽). 현재 적용 = **NEIS 화면(수집본에서 씬 생성 — `neis/NeisGuideScenes.tsx`)**·전자서명(4단계)·
  구매 신청(3단계)·문서 생성(4단계)·**탐구 설계(4단계)**·**수시 지원(4단계)**·**생기부 분석(4단계)**·**업무 관리(보기별 5벌)**·**창의적 체험활동(세그먼트별 3벌 — 전체·내 담당 4단계 / 제안함 3 / 탐구 탐색 3)**. **자체 헤더가 있는 앱형 화면은 그 헤더에 붙인다** — 생기부 분석·수시 지원은 `Layout fullWidth` 지만 자기 글래스 헤더를 갖고 있어, 콘텐츠 안이 아니라 **헤더 액션 묶음 맨 왼쪽**이 자리다(2026-09-04 사용자 지시). 수시 지원은 그래서 `WishlistView` 안에 있던 버튼을 `layout/Header` 로 옮겼는데, **학생 뷰는 그 헤더가 없다** — 옮기기만 하면 학생 630명이 안내를 통째로 잃으므로 `showGuideButton` prop 으로 헤더 없는 화면에서만 콘텐츠 안에 그린다(같은 버튼이 두 개 보이는 것도 막는다).
  **탭이 여러 개인 기능은 탭마다 안내를 따로 만든다**(2026-09-04 사용자 지시) — [사용 방법]은
  **지금 보고 있는 탭의 안내**를 연다(`TaskGuideDialog tab={activeTab}`). 한 모달에 네 탭을 몰아넣으면
  ①지금 쓰지도 않는 탭의 단계를 넘겨 가며 봐야 하고 ②정작 그 탭에서 알아야 할 것이 한 단계로
  압축돼 빠진다 — 업무 관리는 탭 하나하나가 사실상 다른 기능이다. 업무 관리 = 내 업무 3 ·
  이벤트 관리 3 · 업무 흐름 3 · 타임라인 2 · **학교 전체 3**단계(**억지로 늘리지 않는다** — 3~4단계는 상한이지
  하한이 아니다. 학교 전체가 3인 것은 반대 이유다 — **빈 칸의 뜻**을 보여 주지 않으면 반드시
  오해하므로 한 단계를 통째로 거기에 쓴다). 다섯 안내의 씬이 **같은 머리 줄을 이고 있어야**(`TabBar` 공통 부품) 자기가 앱의
  어느 자리에 있는지 잃지 않는다. **2026-10-05 탭이 페이지가 되면서** `tab` 은 **보기 값**(`taskViewOf` — 업무 목록은 범위에 따라 두 보기)이고,
  `TabBar` 자리에는 탭 줄 대신 업무 목록의 범위 전환을 그린다(다른 페이지는 비움 — 좌표 불변). **헤더가 없는 화면**(`Layout fullWidth`)에서는
  그 화면의 유일한 액션 줄 왼쪽에 붙인다 — 탐구 설계는 캔버스 상단 모드 토글(탐구 설계/AI 종합 분석/분석 이력) 왼쪽.
  **가르는 단위는 "탭 개수"가 아니라 "다른 기능인가"다 (2026-09-10)** — 창의적 체험활동은 세그먼트가

  `제안함`·`탐구 탐색`은 데이터 출처부터 다른 화면이다(그 둘에서는 검색·범주 칩이 아예 감춰진다).
