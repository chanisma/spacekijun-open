## 화면과 접근

- 학생·교사·관리자의 본인 계획장이다. 데스크톱의 상단 일반 메뉴와 모바일 전체 메뉴에 `계획장`을 제공한다. 기존 모바일 하단 바로가기 순서는 유지한다.
- 월간 달력, 날짜 이동, 날짜별 실천율, 전체/할 일/완료 필터, 계획 작성·수정·삭제, 시간·중요도·메모, 다음 날 반복, 돌아보기 작성 기능을 제공한다.
- 목표 작성·수정·완료·보관·복원·삭제와 목표에 연결된 계획 수·누적 실천 수를 표시한다. 기존 계획을 선택해 같은 계획의 실천을 이어갈 수 있다.
- 관리자 역할 미리보기에서는 본인 데이터 조회와 쓰기를 하지 않는다. 직원 역할은 기존 서버 RPC 허용 역할에 포함되지 않으므로 메뉴와 라우트에서도 제외한다.
- 모바일에서는 달력과 기록을 한 열로 배치한다. 게임 원화·대사 없이 일반 카드와 입력 대화상자를 사용한다.

## 데이터 연동

계획·목표는 별도 테이블이나 데이터 복사 없이 연동한다. `src/features/planner/plannerService.ts`가 기존 `academy_dormitory_read`와 `academy_dormitory_write` RPC를 호출한다. 아카데미의 `fetchDormitory`도 이 읽기 함수를 사용하고 공방 이미지 서명만 추가한다. `writeDormitory`는 같은 쓰기 함수를 재노출한다.

`academy_user_goals`, `academy_plans`, `academy_tasks`, `academy_task_feedback`의 기존 ID를 유지한다. 다음 날 반복은 `plan_id`를 유지하고 날짜별 실천 ID만 새로 만든다. 같은 계획의 제목·중요도를 수정하면 다른 날짜에도 적용된다는 안내를 표시한다. 시간은 같은 날의 시작·종료를 함께 입력하거나 둘 다 비워야 한다.

저장 후 `['academy-dormitory', userId]`와 `['academy-chapter', userId]` 캐시를 무효화한다. 일반 화면의 조회는 독립된 하위 키를 사용하며 진입 시 및 30초 간격으로 다시 읽는다. 게임 화면에서 저장해도 같은 캐시 접두사로 일반 화면의 기록이 갱신된다. 별자리 실천 누적, 첫 실천 보상, 소유권 검사 및 삭제 시 챕터 처리 규칙은 기존 서버 로직을 따른다. 일반 화면에서 게임 대화 단계를 자동 진행하지 않는다.

일반 계획장 분리 자체에는 DB 변경이 없다. 아래 포모도로 확장에서 집중 실행 기록 테이블을 추가했다.

## 시간별 계획과 포모도로 (2026-09-20)

- `하루 계획 → 시간별 계획`에서 24시간을 15분 단위로 표시한다. 빈 구간을 마우스로 끌거나 터치 선택 모드에서 드래그하면 그 시간의 계획 작성창을 연다. 겹친 계획은 나란히 배치하고, 블록 높이는 계획 시간에 비례한다. 시각 버튼은 키보드로도 사용할 수 있다.
- 계획 작성·수정창의 `시간표에서 선택`에서도 시간을 고른다. 선택한 날짜의 기록을 별도로 읽으며 이미 작성 중인 제목·목표·메모는 유지한다.
- 시간표의 범위 선택과 겹침 배치는 `PlannerTimeline`/`timelineModel`로 공유한다. 아카데미 `DormTimeline`은 기존 테마를 전달하는 래퍼로 유지한다.
- 계획 행의 재생 버튼이나 상단 계획 선택에서 집중을 시작한다. 기본값은 **25분 집중 → 5분 휴식**, 온전한 집중 **4회 후 15분 긴 휴식**이다. 시작 전 각 시간을 1~120분으로 조절할 수 있다. 다음 집중과 휴식은 사용자가 직접 시작한다.
- 일시정지·이어하기, 중간 종료 후 부분 집중 기록, 종료 후 저장·다시 시도를 지원한다. 저장된 온전한 집중만 회차를 올린다. 타이머가 끝났다는 이유로 계획을 자동 완료하지 않는다. `계획 완료 표시`와 `돌아보기`는 기존 아카데미 RPC로 연결한다.
- 날짜별·계획별 실제 집중 시간/완료 회차와 시간순 실행 기록을 제공한다. 날짜별 합계는 **선택한 계획 날짜에 연결된 실행 기록**이다. 개별 기록에는 실제 시작 시각을 표시한다. 휴식과 일시정지 시간은 집중 합계에 포함하지 않는다.

### 타이머 복구와 저장

진행 중 타이머는 `planner:pomodoro:v1:<userId>`에 저장한다. 절대 종료 시각을 기준으로 계산하므로 백그라운드 탭의 느린 interval 때문에 시간이 늘어나지 않는다. 새로고침·페이지 이동 후 돌아와도 복원하며, 오래 자리를 비웠어도 종료한 한 회차만 저장 대기 상태로 남긴다. 저장 불가 시 사용자에게 알리고 메모리 상태를 유지한다.

같은 브라우저의 탭끼리는 storage 이벤트와 Web Locks로 상태를 공유한다. **다른 기기 간 진행 중 타이머는 공유하지 않는다.** 저장을 마친 집중 기록은 DB에 있어 다른 기기에서도 읽을 수 있다. 저장 전 기록을 버릴 때는 확인을 받는다. 관리자 역할 미리보기에서는 타이머와 실행 기록을 조회하지 않는다.

`20260920110000_planner_focus_sessions.sql`은 `planner_focus_sessions`와 `planner_focus_read(date)`/`planner_focus_record(jsonb)`를 추가한다. `academy_tasks.id`를 참조하고 계획 삭제 시 그 계획의 집중 기록도 삭제된다. 기록 UUID를 사용해 재전송을 중복 집계하지 않는다. 같은 UUID에 다른 내용을 보내면 거부한다. 서버에서 역할·계획 소유권·기간·미래 시각을 검사하며 직접 쓰기는 허용하지 않는다. 보상·기존 피드백 필드를 변경하지 않는다.

연결 DB에 새 스키마와 마이그레이션 이력을 한 트랜잭션으로 적용하고 PostgREST 스키마를 갱신했다. 적용 전·후 SQL 권한/무결성 검사는 모두 롤백했다. 생성된 `src/integrations/supabase/types.ts`는 Supabase CLI로 재생성했으며, 연결 DB에 이미 있던 면접 준비 테이블·뉴스 키워드 등 미반영 타입도 포함한다. `client.ts`는 수정하지 않았다. 프런트엔드 호스팅 배포는 수행하지 않았다.

- 브라우저 추가 검사: 데스크톱 드래그·모바일 터치·폼 시간 선택·블록 높이/겹침, 계획 연결 집중, 일시정지·새로고침·탭 간 상태 공유, 저장 실패·재시도, 명시적 완료 표시, 휴식 제외. 화면: `timeline.png`, `timeline-mobile.png`, `pomodoro.png`.
- SQL 추가 검사: 본인 기록만 읽기/쓰기, 타인 기록 차단, 비로그인 차단, 직접 쓰기 차단, 중복 재전송, 변경된 재전송 거부, 잘못된 기간/미래 시간 차단, 자동 계획 완료 없음.
- 인계 후 재검증(2026-09-20): 계획 저장·삭제 직후 현재 날짜의 집중 기록을 다시 조회하고 다른 날짜의 캐시도 무효화하는 브라우저 회귀 검사를 추가했다. 계획장/포모도로 단위 검사 9개, 전체 계획장 브라우저 검사, 관련 파일 ESLint와 프로덕션 빌드를 다시 통과했다. DB 적용 상태는 앞선 적용 기록을 유지하며 이번 재검증에서 DB를 재적용하지 않았다.

인계 후 전체 TypeScript 검사에서도 계획장과 공유 기숙사 변경 파일의 진단은 0건이었다. 다른 기능의 타입 오류가 남아 있어 전체 타입 검사 통과로 간주하지 않는다. 브라우저 검사 중 개발 서버 HMR WebSocket의 로컬 네트워크 접근 경고가 발생했으나 기능 검사와 페이지 재로딩 검사는 통과했다.

브라우저 검사 재현: Vite 실행 후 `node scripts/planner-test/browser.mjs`. 기본 주소는 `http://localhost:8080`이며 `PLANNER_TEST_URL`로 변경 가능하다. Playwright가 별도 위치에 있으면 `PLAYWRIGHT_MODULE`에 `playwright/index.mjs`의 절대 경로를 지정한다.

SQL 재현: `node scripts/planner-test/prepare-sql.mjs` 후 `npx supabase db query --linked --file output/planner-ui/focus-sql-check.sql`. 미적용 DB에서 마이그레이션까지 롤백 검증하려면 준비 명령에 `--with-migration`을 붙인다. `--prepare-apply`는 스키마와 이력을 함께 적용할 별도 SQL 파일만 준비하고 실행하지 않는다.

## 주간 계획 (2026-10-03) — 처음 화면

사용자 지적: «주별로 계획을 세우는 UI 가 필요 · 지금 UI 는 너무 경직». 종전 화면은 하루씩만 보였고 모든 작성이 모달 하나로만 됐다.

- **보기 탭 셋**(주간 계획 · 하루 계획 · 나의 목표), 처음은 주간. 마지막으로 고른 보기를 `planner:view:v1`(safeLocalStorage)에 기억한다.
- 월~일 일곱 칸(`PlannerWeekView.tsx`, 스타일 `week.module.css`). 칸마다 **바로 적는 입력줄**(Enter = 추가), 카드 체크로 완료, 카드를 눌러 기존 편집 창, **끌어서 다른 날로 옮기기**(같은 실천 id·계획 유지), 터치용 **‹ ›** 하루 이동, 요일 머리 → 그날의 시간별 계획.
- **지난 날에 남은 일 → 오늘로 가져오기**(같은 계획이 오늘 이미 있으면 서버의 (계획, 날짜) 유일 제약에 걸리므로 남기고 개수를 알린다).
- **목표 칩**: 목표마다 늘 같은 색 점(`goalColor` — id 해시), 칩을 누르면 그 목표의 일만 보이고 **새로 적는 일도 그 목표에 붙는다**.
- 집중 타이머는 하루의 할 일에 묶여 있어 주간 화면에서는 **돌고 있을 때만** 보인다(멈춰 있으면 일곱 칸을 위로 올린다).
- 체크·옮기기·바로 적기는 토스트를 띄우지 않는다(화면이 바로 바뀐다 — CLAUDE.md 토스트 규칙). 편집 창 저장 뒤에도 주간에 머문다.
- **저장 구조 변경 없음.** 읽기 RPC 가 `p_date ±3일`을 돌려주므로 그 주의 **목요일로 한 번** 부르면 월~일이 온다(`weekCenter`). 옮기기는 `save_task` 에 id + 새 날짜(`movePayload`).
- ⚠️ 카드 본문을 `<button>` 으로 두지 말 것 — 크롬은 버튼 위에서 시작한 끌기를 바깥의 `draggable` 카드로 넘기지 않아 카드 대부분에서 끌기가 안 된다(그래서 `div role="button"` + Enter/Space).
- 회귀: `npx tsx --test src/features/planner/__tests__/week.test.ts`(4건) + `node scripts/planner-test/week-browser.mjs`(실제 화면 — 바로 적기·체크·옮기기·끌기·가져오기·목표 거르기·주 이동·1360/800/390 넘침). ⚠️ HTML5 끌기 검사는 마우스를 **여러 단계로** 움직여야 dragstart 가 난다(Playwright `dragTo` 한 번으로는 시작되지 않았다).
- 기존 `browser.mjs` 는 처음 화면을 하루 계획으로 고정해 둔다(`planner:view:v1=day`). 그 검사의 포모도로 시간 단언(«00:40» 기대 / «01:00» 측정, `execution-checks.mjs:75`)은 이번 변경 전부터 실패한다.
