# NEIS 업무 화면 실행 (`neis.screen`)

2026-09-23 신설. 할 일(Task)에 **나이스에서 처리할 화면**을 붙이는 실행(Action) 유형.

## 무엇을 하고 무엇을 하지 않는가

- **한다**: 학교 NEIS 메뉴 1,384개 중에서 이 할 일을 처리할 화면을 가리키고(메뉴 경로·용도·
  누구의 나이스에 보이는지·화면 안 탭), 매니저의 처리 안내를 담당자에게 보여 준다.
  [나이스 열기]와 [화면 이름 복사]로 나이스까지 데려다준다.
- **하지 않는다**: 나이스를 조작하지 않는다. 웹에서는 인증서 로그인·보안 프로그램 때문에
  불가능하고, 가능하더라도 생활기록부에 남는 저장·마감을 자동화하지 않는다
  (NEIS_helper 의 원칙과 같다 — "저장·마감·삭제는 하지 않습니다").
- **완료**는 담당자가 **내 할 일에서 체크**한다. 설정 창에는 [처리 완료 기록]을 두지 않는다
  (2026-09-23 사용자 지적 — 설정하는 자리에 완료 버튼은 맥락이 맞지 않는다). 실행·검수 이력 서랍도 없다.

## 왜 유형 하나에 설정값인가

화면이 1,384개라 화면마다 레지스트리 항목을 만들면 연결 목록이 NEIS 메뉴로 뒤덮이고,
메뉴가 바뀔 때마다 코드를 고쳐야 한다. 그래서 `document.spec_fill`(유형 하나 + 양식은
설정값)과 같은 모양으로, **유형 = `neis.screen` 하나, 화면 = `task_action.config.neis`**.
레지스트리의 `kind: 'external'` 이 이 부류(앱 밖 시스템을 안내 + 수동 완료)를 뜻한다.

**NEIS 작업은 한 할 일에 여러 개, 한 작업에 화면도 여러 개(최대 10) (2026-09-23)**. 처음에는
`UNIQUE(task_id, created_by, action_type)` 때문에 한 할 일에 NEIS 연결을 사람당 **하나밖에** 못 만들었다 —
사용자가 짚은 문제는 이것("추가해야 하는데 추가할 수 없었다")이었다. 유일 제약에 `instance_key` 를 더해
(마이그레이션 `20260923120000`, 운영 적용) NEIS 는 연결마다 고유 키를 받는다(레지스트리 `multiple: true`).
⚠️ 한때 "작업 하나 = 화면 하나"로 강제했다가 **같은 날 되돌렸다** — 한 작업에 여러 화면이 묶이는 것
자체는 문제가 없다는 사용자 정정. 과정을 나눌지(작업 여러 개) 묶을지(한 작업에 화면 여러 개)는 관리자가 정한다.

```ts
config.neis = {
  version: 1,
  screens: [{ key, name, path: [업무영역, 단위업무, 세부업무, 메뉴그룹], innerTab? }],  // 최대 10
  note?: string,   // 처리 안내, 1,000자
}
```

**경로를 복사해 둔다** — 카탈로그 key 만 참조하면 메뉴목록을 새로 받았을 때 없어진 화면을
가리키던 할 일이 무엇을 가리켰는지 잃는다. 없어진 화면은 러너가 "지금 메뉴목록에는 이 화면이
없습니다"라고 말한다. config 병합은 `mergeNeisActionConfig` 로만 — 다른 키(`origin` 등)를
통째로 덮으면 조용히 사라진다. 저장 시 제목도 `NEIS · <첫 화면> 외 N개` 로 맞춘다(카드가
무엇을 가리키는지 보이도록).

### 메뉴목록을 새로 받았을 때

1. 업무포털에서 「학교업무분장 메뉴목록」을 내려받는다.
2. `npx tsx scripts/neis-catalog/build.mts "<파일>"` — 생성물은 화면 하나가 한 줄이라
   `git diff` 가 바뀐 화면만 가리킨다.
3. 회귀의 개수 단언(1,384·150·1,234·47)을 새 값으로 고친다. 담임 부분 대조는 NEIS_helper
   정본도 같은 엑셀로 다시 만든 뒤에 돌린다.
4. 용도 사전이 NEIS_helper 에서 늘었으면 `neis-glossary.json` 을 다시 내보낸다
   (`SCREENS` → `{purpose, aliases}`).

## 누가 무엇을 보나

| 사람 | 화면 |
|---|---|
| 연결을 만든 사람 | **설정 창** — 화면 검색·추가·빼기, 화면 안 탭, 처리 안내. 바꾸면 바로 저장되고 머리글이 `저장됨 · 시각`을 말한다. [담당자 화면 미리보기]는 담당자 안내와 **같은 부품**(`NeisGuideView`)을 그린다 |

## 나중에 (2단계 — 보류)

스페이스기전 데스크(NEIS_helper `app/`)는 이미 `assigned_tasks` 를 읽고 있고, 개발 중인
NEIS 도우미는 화면 이름만으로 그 화면까지 이동·조회한다(저장은 안 함). 그래서 웹이 데스크를
부르는 통로를 새로 만들 필요 없이 **데스크가 `task_action.config.neis` 를 읽어 [나이스 화면
열기]를 띄우면** 된다. 데스크는 받는 화면 이름을 자기 정본에 있는 것만 허용할 것. NEIS 도우미가
데스크에 들어간 뒤 진행한다.

또 하나 — NEIS_helper `output/업무분석/업무목록.json`(업무 176건, 월·반복·분장 자리)은 "언제·
누가"를, 이 카탈로그는 "어디서"를 답한다. 둘을 잇는 것은 연간 업무 가져오기·인수인계와 함께 한다.

## 나이스 밖 — 작업 「외부 시스템에서 처리」(`external.screen`, 2026-09-24)

라이브 작업 30건의 **절반(15건)이 `neis.screen`** 이다 — 학교 업무의 본체는 «밖에 나가서 사람이 처리하는 일»인데, 지금까지는 **NEIS 밖을 가리킬 방법이 아예 없었다**(K-에듀파인·리로스쿨·교육청 업무포털). 그래서 같은 성격(`kind: 'external'`)의 유형을 하나 더 뒀다.

**왜 `neis.screen` 을 일반화하지 않았나**: NEIS 는 화면 1,384개짜리 **카탈로그에서 고르는** 경험이고(동적 import 383KB), 나머지 시스템에는 그런 목록이 없어 **적는** 경험이다. 한 유형에 합치면 설정 화면이 «카탈로그가 있는 시스템인가»를 먼저 묻는 갈림길부터 시작하고, 라이브 15건의 설정 모양(`config.neis`)도 건드려야 한다. 저장 칸을 나누면(`config.external`) 둘 다 안 건드린다.

- 설정 = 시스템 이름(+대문 주소) · 화면 목록(이름·메뉴 경로·주소, 최대 10개) · 처리 안내. **화면을 안 적어도 된다** — 시스템과 안내만으로 충분한 일이 많다.
- **주소는 `http(s)` 만 받는다**(`safeExternalUrl`). 설정값은 다른 교직원이 적은 것이라 «우리가 쓴 값»이 아니다 — `javascript:` 를 그대로 링크에 넣으면 누르는 순간 스크립트가 된다. 외부 링크는 `rel="noopener noreferrer"`.
- 편집은 **연결을 만든 사람**만(`task_action` UPDATE RLS = `created_by`). 담당자에게는 안내만 보인다 — 버튼을 보여 놓고 42501 로 거절되면 고장처럼 보인다.
- 저장 때 **제목도 함께 맞춘다**(`시스템 · 첫 화면 외 N개`) — 목록에서 «무엇을 가리키는지»가 제목만으로 읽혀야 한다(NEIS 와 같은 규칙).

### ⚠️ `kind === 'external'` 로 분기하는 자리는 이제 NEIS 전용이 아니다

러너 선택·주 동작 문구·관리 요약·사용 요약 네 곳이 `kind` 로만 보고 있었다. 하나라도 남으면 새 유형이 **조용히 NEIS 쪽으로 빠져** "나이스 화면을 고르세요"라고 말한다(오류가 아니라 «엉뚱한 안내»다). 지금은 네 곳 모두 **`action_type` 으로 먼저 가른다** — 특히 러너 분기는 **NEIS 분기보다 앞**에 있어야 한다.

회귀 = `npx tsx scripts/external-screen-test/run.mts`(38건 — 주소 검사·파싱·제목/요약·NEIS 문구 누출·분기 순서).
