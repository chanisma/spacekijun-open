# 알림 표시 갱신

2026-09-10

## 변경 사항

- PC Header와 MobileNavigation의 읽지 않은 알림 숫자는 알림 목록과 같은 `['notifications', resourceId]` 캐시를 사용한다. 모바일의 별도 최초 1회 개수 조회를 제거했다.
- PC 종 아이콘에도 읽지 않은 알림 배지를 표시한다. PC·모바일 모두 10개 이상은 `9+`로 표시하며 접근성 이름에는 실제 개수를 제공한다.
- 기존 앱 전역 Realtime 구독에서 INSERT 수신 시 공유 캐시를 갱신한다. UPDATE도 구독하여 다른 기기의 읽음 처리를 반영한다.
- 최초 구독 및 재연결 성공 시 다시 조회하여 연결 공백 동안 누락된 알림을 가져온다. 해제된 구독의 늦은 콜백은 무시한다.
- 탭 복귀와 네트워크 재연결 시 캐시의 신선도와 관계없이 다시 조회한다. 화면이 활성화된 동안 30초 간격으로 보조 조회하고, 백그라운드 주기 조회는 하지 않는다.
- 읽음·삭제의 기존 낙관적 업데이트도 배지에 함께 반영된다. 다른 기기의 삭제는 보조 조회 또는 복귀 시 반영한다.

## 확인 항목

- 수신자가 앱을 연 상태에서 새 알림을 받으면 목록과 배지가 갱신되는지 확인한다.
- 읽음 처리·삭제 직후 배지 숫자가 줄고, 실패 시 함께 복구되는지 확인한다.
- 다른 탭에서 돌아올 때 및 연결 복구 시 누락된 알림이 조회되는지 확인한다.
- 실시간 이벤트가 도착하지 않아도 활성 화면에서 30초 주기 조회로 갱신되는지 확인한다.

DB 스키마 및 권한 변경은 없다. 실제 배포 환경의 수신 시간과 모바일 절전 상태 동작은 로그인된 기기에서 확인해야 한다. 앱 탭이 종료된 상태의 Web Push는 이번 변경에 포함하지 않는다.

## 로컬 검증

- `npm run build` 통과.
- 실제 `useNotifications` 조회 함수를 모의 Supabase 응답과 QueryObserver로 실행: 수신자 필터, 배지·목록 캐시 공유, 읽음 반영, fresh 캐시에서도 포커스·재연결 시 재조회, 수신자 없는 경우 조회 차단을 확인했다.
- 변경 파일 ESLint: `useNotifications.ts`에 이미 존재하던 `any` 오류 2건으로 실패. 나머지 변경 파일은 통과.
- 전체 TypeScript 검사는 `App.tsx`의 `Profile` 중복 선언 등 프로젝트 오류 230건으로 실패. 이번에 수정한 4개 소스 파일의 타입 진단은 없다.
