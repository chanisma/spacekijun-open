# admission-wishlist

> CLAUDE.md 에서 분리한 상세 문서. 스키마·마이그레이션은 `docs/database/*.md` 참조.

학생 수시 지원 학교 관리 (교과·종합, 정시 제외). 학생=본인 입력/열람, **admin=전 학생·담임=자기 반·학년부장=자기 학년 전체 대신 신청(쓰기)**, 상담교사=접근 불가. 저장 항목에 adiga 커트라인·gyogwa 교과반영·jonghap 종합평가/면접·내 성적 적합도 매칭 표시.

**적합도(`utils/fit.ts` computeFit)=분위 3-컷**: 학생 내신(9등급 환산)을 25%/50%/70% 컷과 비교(낮을수록 우수) → 25%컷보다 우수=안정·50%컷=적정·70%컷=소신·미달=위험. 25%컷은 직접 데이터가 없어 50/70%컷에서 **대칭 외삽** `g25=2·g50−g70`. 50%컷 없거나 컷 비단조(g70≤g50)면 grade70 단독 ±0.3 밴드로 폴백.

**5등급제→9등급제 환산(2026-07-29 전면 교체, `utils/gradeScaleConvert.ts`)**: adiga 컷은 9등급 척도인데 1·2학년 내신은 5등급제라 직접 비교 불가 → **잠재특성 정규모형 + 이산우도 사후평균**으로 환산(잠재학력 z~N(0,1), 과목성적 s=ρz+√(1−ρ²)ε, ρ=0.935; n과목 등급합 분포를 DP로 구해 베이즈 사후평균). 구 구현(등급→누적상한 백분위→역보간)은 학생을 항상 등급구간 **바닥**으로 취급해 **전 구간 평균 +0.34등급 불리하게** 환산했다(RMSE 0.380·60.6%가 0.3등급 초과 오차). 신 모형 RMSE 0.167·편향 −0.008·판정 불일치 1.9%.

**점역산이 아니라 사후평균인 이유**: 전 과목 1등급(g5=1.000)이면 E[g5|z]=관측값 방정식이 z→∞로 발산해 9등급도 1.000으로 붕괴 — 이산우도 P(전과목 1등급|z)=p₁(z)ⁿ은 유계라 붕괴하지 않는다(실측 정답 1.244를 정확 재현).

**검증**: 정답지=2025 입학 코호트 1학년 193명의 생기부 **원점수로 석차백분율 재구성 후 9등급 경계 적용**한 반사실 내신이고, 그 분포(mean 5.013/sd 1.752)가 실제 9등급 코호트 2023(4.966/1.749)·2024(4.953/1.720)와 일치. 외부 앵커=경기진학지도협의회 전국 배치분석 "5등급 1.583=누적 9.06%→9등급 2.45"를 1.544/2.472로 재현(과적합 아님).

**환원불가 한계**: 5등급제가 상위 10%를 한 등급으로 묶어 세부 순위가 소실 → 잔차 SD 0.167(95% ±0.33등급)이 하한. 회귀 `npx tsx scripts/naesin-scale-test/run.mts`(모형 비교는 `research.mts`).

**등급 척도 판정(`utils/naesinScale.ts`)**: 학번 접두사(`25-`→2025 입학)만으로 판정하면 **전입생이 오판**된다(실측 `00-00645`=3학년 9등급제인데 접두사가 25). `rank≥6`은 5등급제에서 구조적으로 불가능하므로 그런 기록이 있으면 9등급제로 **확정**하고, 없으면 접두사 폴백(역방향 "rank≤5→5등급제" 추론은 금지 — 3학년 216명 중 53명이 최대 5 이하). 확정 보정은 과목 기록이 함께 있는 `WishlistView`에서 수행.

**화면 표시**: 5등급제 학생 카드는 `2.15 → 3.55 vs 3.4등급`처럼 **환산값을 병기**한다(구 표시는 5등급 원값과 9등급 컷을 나란히 놓아 배지와 정반대 인상을 줬음).

**최근 추이 그래프**(`WishlistItemCard` TrendGraph)=좌(70%컷+경쟁률)·우(50%컷+경쟁률) 미니차트 2개 병렬.

**전형 반영 내신(`utils/naesinRule.ts`) = 재현 가능할 때만 계산(2026-08-06 정책 전환, 사용자 지시 "정확도가 중요")**: gyogwa 반영방법을 파싱해 `certain=false`면 **숫자를 만들지 않고 보류**(`NaesinResult.withheld`)하고 사유(`NAESIN_UNCERTAINTY_LABELS` 14종)+반영방법 원문을 카드에 띄운다. 구 구현은 못 푼 규칙을 단순화해 계산하고 `simplified` 플래그만 달았는데, 한서대 항공관광 `"국,수,영(외,한문),(사,과,한)중 8과목(교과별 2과목)+진로선택 2과목=총 10과목"`이 ①괄호 교과 묶음 평탄화로 **전 교과 통과**(필터 무력화) ②"중 8과목"이 진로선택 섞인 pool에 적용돼 별도 쿼터 소실 ③진로선택 환산이 `A=9.5점`(점수)인데 **기본 등급환산 A=1로 대체**되고도 `simplified`에 안 걸려 "전형 반영 내신"으로 표시됐다.

**기본 환산(DEFAULT_CAREER_CONV) 제거** — 전형이 등급 환산표를 명시한 경우에만 진로선택 반영, 아니면 제외(카드에 명시). 보류 트리거=학과·학년 분기/괄호 교과 묶음/복합 쿼터(`+`·`=`·진로선택 N과목)/이수단위·원점수/N개 교과/필수/교과별N+기타교과(`기`는 생기부 교과군 3개에 걸침)/진로선택 환산 불가·불완전(A만 등급)·조건부(원점수)·별도 쿼터(`3과목`·`10% 반영`)·범위 불일치/학년비율 미적용/**잔여 텍스트**(해석한 토큰을 소비하고 남으면 보류 — 새 표기가 조용히 무시되지 않게 하는 일반화 안전장치).

**변형 선택은 전형명 매칭 (`selectSubjectVariant`, 2026-09-01 화면까지 확장)**: `subjects_all`은 **그 대학의 모든 전형 규칙**을 담는다(라이브 376행 중 52행이 2건 이상) — 구 구현의 "가장 긴 문자열" 선택은 남의 규칙을 조용히 적용했다. 지금은 행 `admission`으로 **하나로 좁혀질 때만** 확정하고 아니면 보류한다.

**단계 3개를 순서대로** 시도하며 순서가 곧 안전장치다 — ①전형명 토큰 정확 일치(변형은 `"일반학생, 교과성적우수자"`처럼 여러 전형을 묶어 적어 쪼개서 본다) ②통째로 같은 문자열(①은 **변형만** 쪼개서 행에도 쉼표가 있으면 어긋난다 — 인제대 행 `의예,약학` ↔ 변형 `의예, 약학`) ③한쪽이 다른 쪽을 포함(송원대 `학생부 우수자` ↔ `학생부우수자 (일반)`).

**③을 맨 뒤에 둬야 한다** — 혼자 두면 `교과`가 `교과면접`까지 잡지만, ①이 먼저라 이미 확정되던 답은 바뀌지 않는다. 어느 단계든 둘 이상 걸리면 보류.

**계산이 옳아도 표시가 전부 이어 붙이면 소용없다** — 비교표 `반영 교과` 행이 `subjects_all`을 통째로 나열해 남의 전형 교과가 섞여 보였고(경기대 `학교장 추천`에 `교과성적우수자` 규칙이 함께), 지금은 **고른 것만** 적고 전체는 근거 모달에 담는다(보류면 종전대로 전체 표시 — 확실하지 않은 것을 골라 놓으면 그게 정답인 줄 읽는다). 실측 52건 중 **50건 확정·2건 보류**이고 보류 2건은 `admission` 칸에 전형이 아니라 **학과명**(`군사학과`)이 들어 있어 원리상 불가. 감사 = `npx tsx scripts/admission-wishlist-test/audit-reflected.mts`(라이브 전수, SQL로 어림하지 말 것 — 정규화 규칙이 코드에 있어 옮겨 적으면 다른 값을 잰다). 라이브 376 전형 중 교과 규칙 표현 가능 148건·진로선택까지 재현 64건(≈17%)만 계산되고 나머지는 보류(커버리지보다 정확도 우선). 보류 시 카드 숫자는 **전형 무관 전과목 평균**이며 라벨이 `내 내신 평균`으로 바뀐다(적합도 배지는 종전대로 그 값 기준). 회귀 `npx tsx scripts/admission-wishlist-test/run-naesin.mts`(54건). 쓰기 RLS=`is_wishlist_owner OR can_write_wishlist`(admin/담임/학년부장), 읽기 RLS=`is_wishlist_owner OR can_read_wishlist`(=can_write와 동일), `is_wishlist_owner` EXECUTE는 authenticated 필요(anon만 revoke).

**화면 4층 구조 (2026-09-01 전면 개편)**: 종전엔 카드가 세로로만 쌓여 두 학교를 동시에 볼 수 없었는데, 상담의 실제 장면은 "이 학교 하나가 어떤가"가 아니라 **"6개를 늘어놓고 무엇을 뺄까"**다 → ①**통합 목록**(`WishlistList`) — 지원희망(1~6지망)과 관심대학을 **한 리스트**에 세로로 잇고 **배경색으로 두 층을 가른다**(지원희망 위·옅은 브랜드 톤). 카드 그리드에서 리스트로 바꾼 이유(2026-09-01 사용자 결정): 두 묶음을 각각 카드로 그리면 화면이 둘로 갈라져 "지금 몇 곳을 보고 있는지"가 흐려진다. 지원희망은 **빈 자리까지 행으로 그려** 잔여 칸이 먼저 읽히고, 위/아래로 지망 순서 변경(=`sort_order` 0..n-1 재기록)·`관심↓`/`지원희망↑` 로 상호 이동한다. (구 `WishlistBoard`·`InterestList` 는 삭제됨) **카드 그리드가 아니라 리스트인 이유**: 지원희망과 같은 카드로 두 번 그리면 두 영역이 겹쳐 보여 어느 쪽이 본론인지 흐려진다(실제로 그렇게 만들었다가 되돌렸다) — 관심대학은 '결정 전 담아 두는 후보'라 한 줄 한 항목으로 훑고 평소엔 접어 둔다. 행 = `[적합도] 대학·학과·전형 … 내신vs70%컷 · 경쟁률 · 최저` + `[상세][지원희망↑][삭제]`, 보드 카드에는 `[관심↓]`.

**좁은 화면에서는 수치 묶음을 감춰** 대학명이 잘리지 않게 한다.

**추가 모달은 담아도 닫히지 않는다**(2026-09-01 사용자 요청) — 닫으면 다시 열 때 검색어와 지역·컷·정렬 필터를 처음부터 다시 잡아야 하는데, 여러 곳을 담는 것이 이 화면의 정상 사용법이다. 담은 항목은 목록 갱신과 함께 행이 '추가됨'으로 바뀌어 중복을 막고, 직접 입력은 값이 섞이지 않게 **입력만** 비운다. 스스로 닫히지 않으므로 **푸터에 닫기(`완료`)를 항상 노출**하고 담은 개수를 함께 적는다.

**그래서 정원 검사가 모달 안에도 있어야 한다** — 종전엔 여는 쪽(`WishlistView.openAdd`)에서 한 번만 봤는데, 한 번 열고 계속 담을 수 있게 되면서 그것만으로는 관심대학 15개 상한을 넘길 수 있다(`AddProgramDialog` 가 `canAccept`/`rejectReason` 을 다시 호출하고 푸터에 `N/15` 를 표시).

**정원 규칙 단일 출처 = `utils/tierRules.ts`이고 두 상한의 성질이 다르다**: 지원희망 6은 제도상의 사실이지만 목록을 짜는 도중 넘겨 담는 것이 정상이라 **막지 않고 경고**(`applyOverflow`), 관심대학 15는 화면·비교의 실용 한계라 **실제로 막는다**(`canAccept`/`rejectReason` — 거부 문구는 상한 수치와 **다음에 할 일**을 함께 적는다). DB 에 개수 제약을 두지 않은 이유는 행 개수는 CHECK 로 표현이 안 되고 트리거로 막으면 대량 정리가 중간 상태에서 걸리기 때문.

**`tier` 없는 레거시 행은 지원희망으로 읽는다**(`splitByTier`) — 관심대학으로 떨어뜨리면 기존 지망이 화면에서 통째로 사라진다. ②**지망 비교표**(`ComparisonTable`, 지망=열/항목=행. 과년도 3개년 지표·전형요소·수능최저·**6월/9월 충족여부 자동 판정**·직접 입력 5종) ③**상세 모달**(`ItemDetailDialog` 안에 기존 `WishlistItemCard` — 개요가 생겨도 반영 내신 근거·면접 기출을 잃지 않게 옮겨 담았다).

**파생 판단값 단일 출처 = `utils/itemInsight.ts`**(전형 반영 내신·9등급 환산·적합도·수능최저) — 종전엔 카드 안 `useMemo` 에만 있었고, 표가 같은 계산을 다시 적으면 **같은 학생·같은 전형인데 카드와 표의 숫자가 갈라진다**(상담 중 그게 드러나면 두 숫자 다 못 믿게 된다). 카드도 이 모듈을 쓴다.

**비교표 행 정의 단일 출처 = `utils/comparisonRows.ts`** — 화면·인쇄(A4 가로)·엑셀이 같은 정의를 읽어 "화면엔 있는데 엑셀엔 없는 항목"이 생길 수 없다. 각 행이 `text()` 를 항상 갖고 배지 행만 화면 렌더를 얹는다.

**빈 지망도 열로 남긴다**(6회 제한이 곧 전략이라 잔여 칸이 표에서 읽혀야 한다).

**메모 칸은 내용에 맞춰 세로로 자란다**(`AutoGrowTextarea`) — 표 안이라 폭이 고정이라 길이는 세로로만 흡수할 수 있고, 한 줄 `<input>`이면 적은 메모가 좌우로 흘러 나가 보이지 않으며 인쇄물에는 첫 줄만 남는다. 늘리는 방법은 `height:auto`로 **되돌린 뒤** `scrollHeight`를 넣는 것이고 되돌리는 단계를 빠뜨리면 내용을 지워도 줄어들지 않는다. 열람 전용일 때도 `whitespace-pre-line`으로 줄바꿈을 살린다(적은 사람과 읽는 사람이 다른 것을 보면 안 된다). 숫자는 **소수 2자리 고정**(표는 가로로 훑는 물건이라 자릿수가 들쭉날쭉하면 눈이 소수점을 다시 찾는다 — 카드는 한 값만 보이므로 종전 표기 유지).

**직접 입력 컬럼**(`converted_score`·`interview_date`·`first_announce_date`·`final_announce_date`): 환산점수·면접일은 대학마다 척도·표기가 달라 **text**, 발표일은 date.

**입력 컨트롤이 있는 칸(`edit`·편집 중인 `csatRound`)은 셀을 통째로 감싸지 않는다** — `<button>` 안에 `<select>`/`<input>` 을 넣으면 드롭다운을 고르는 클릭이 부모까지 올라가 근거 모달이 함께 열리고(실제 발생), HTML 상으로도 상호작용 요소 중첩이라 잘못이다. 그런 칸은 옆에 작은 ⓘ 버튼만 붙인다. 판정은 순수 함수 `cellHasControl`/`shouldWrapCell` 이고 회귀가 고정한다.

**비교표 `최저 기준` 행은 내 세부전공 조건만 보여준다**(`insight.csatApplied`) — 원문은 한 칸에 8~9개 분기가 들어 있는 경우가 흔해(전북대 일반학생) 그대로 두면 셀이 문단이 되고 "그래서 내 학과는 뭔데?"를 눈으로 찾아야 한다. 규칙이 범위를 못 가르면 원문 전체로 폴백. 판정 우선순위 = 학과 > 계열 > 기본이고 **학과 규칙이 둘 이상 걸리면 보류**(`ambiguous`). 계열은 호출부가 알려 줄 때만 쓴다(추측이 곧 오답). `AdmissionWishlistPage.tsx`, `components/WishlistList.tsx`·`ComparisonTable.tsx`·`CellDetailDialog.tsx`·`ItemDetailDialog.tsx`·`layout/RightPanel.tsx`, `services/wishlist.ts`, `hooks/useWishlistAccess.ts`, **인쇄는 지망 비교표만 A4 가로로**(2026-09-09, 아래 절): `body.printing-area` + `.comparison-print-area`(`ComparisonTable` 루트). 표는 `table-layout:fixed`·7pt 로 폭에 맞추고 sticky 를 해제한다.

### ⚠️ 범위를 CSS 만으로 좁힐 수 없다 (2026-09-09, 사용자 실사용 PDF 로 발견)

처음 구현은 흔한 방법 — `body.printing-area *{visibility:hidden}` 으로 전부 감추고 대상만
되살린 뒤 `position:absolute; top:0` 으로 끌어올리기 — 였는데 **실제 출력에서 두 가지가
함께 깨졌다**(사용자 제보 "페이지가 넘어가는데 잘려서 나옴", "윗 공간도 비워져서 나옴"):

- **잘림** — 절대 위치 상자는 **페이지 경계에서 조각나지 않는다**. 1쪽에서 잘리고 나머지가
  통째로 사라졌다(제보 PDF 실측: 2쪽 **텍스트 0자**, 완전 백지).
- **상단 공백** — `top: 0` 은 페이지가 아니라 **가장 가까운 위치 지정 조상** 기준이다.
  앱 셸의 `relative` 조상 때문에 1쪽 위쪽 약 1/4 이 비었다.

**고침 = `utils/printScope.ts`**. 대상의 **조상 사슬을 훑어 형제를 `display:none`**(`data-print-hide`)
으로 지우고 조상에는 폭·여백·스크롤 제약 해제 표시(`data-print-through`)를 단다. 자리까지
사라지므로 표가 **정상 흐름**으로 종이 맨 위에서 시작하고, 정상 흐름 상자는 브라우저가
페이지에 나눠 담는다. **표시는 `afterprint` 와 타이머 양쪽에서 반드시 되돌린다** — 남으면
화면에서 앱의 나머지가 통째로 사라진다.

**하니스가 이 버그를 못 잡은 이유도 결함이었다.** 처음 만든 미리보기는 표만 상자에 넣어
그렸는데, 두 증상 모두 **위치 지정 조상**과 페이지 조각내기에서 나오므로 조상이 없으면
재현되지 않는다. 지금 `print-preview.mts` 는 사이드바·헤더·스크롤 컨테이너·`max-w` 래퍼·
표 위 긴 목록을 실제 앱과 같이 두르고, **범위 좁히기 코드는 실제 모듈을 직렬화해 주입**한다
(하니스가 사본을 들면 정작 화면에서만 깨지는 버그를 놓친다). `--tall` 로 표가 여러 장에
걸치는 경우도 만든다.

**검증(진짜 PDF)**: 고친 뒤 Chrome `page.pdf()` 실측 — 2쪽 모두 내용 있음(1,299·3,903자),
**머리글이 두 쪽 다 반복**, 메모 12행까지 잘림 없음, 두 쪽 모두 첫 글자 y≈23pt(=여백 8mm,
상단 공백 없음), 앱 셸 누출 0.

**인쇄는 조용히 실패한다** — 화면은 멀쩡한데 종이만 깨지고, 알아차리는 건 상담 직전에
출력해 본 사람뿐이다. 그래서 회귀
`npx tsx --tsconfig tsconfig.app.json scripts/admission-wishlist-test/render-print.mts`(46건)
가 ①범위 좁히기 로직(가짜 DOM 으로 조상 사슬·되돌리기) ②**CSS ↔ JSX 정합**(속성 이름,
그리고 **`position:absolute`·`visibility:hidden` 이 되살아나지 않는지**) ③SSR 마크업을 함께 본다.
정합 검사는 **CSS 주석을 걷어내고** 봐야 한다 — "쓰지 않는다"는 주석 자체에 그 글자가 들어 있다.

### 종이에서만 드러나는 것 5종 (실측으로 고침)

브라우저 인쇄 미리보기를 열지 않으면 보이지 않는 것들이라
**`scripts/admission-wishlist-test/print-preview.mts`** 로 확인했다 — 앱 셸까지 재현한 HTML 을
만들고(`npm run build` 선행), 브라우저로 열어 Ctrl+P 하거나 `page.pdf()` 로 진짜 종이를 본다.

- **머리글이 어느 대학인지 말하지 않았다.** `<thead>` 는 `1지망`~`6지망` 뿐이고 대학명은
  본문 `대학` 행에 있다. 표가 44줄이라 실사용에서 2페이지로 넘어가는데, 머리글은 페이지마다
  반복되므로 2페이지에서 어느 열이 어느 대학인지 알 수 없어 **1페이지로 되돌아가야 했다**
  → `hidden print:block` 으로 `대학 · 학과`를 머리글에 넣고 `display: table-header-group` 을 명시.
- **좌측 두 열이 지망 열과 같은 폭을 먹었다.** `table-layout: fixed` 는 첫 행에서 폭을 잡는데
  그 행의 첫 칸이 `colspan=2` 라 항목/세부를 가를 수 없다 → **`<colgroup>`** 을 넣어 28mm/13mm
  로 고정. 실측 지망 열 **33mm → 39.9mm(+21%)**, 그만큼 덜 접힌다.
- **6회 초과 열이 종이에서 사라졌다.** 화면은 앰버 배경으로 구분하는데 **브라우저는 배경을
  기본으로 인쇄하지 않고** `title` 툴팁도 인쇄되지 않는다 → `· 6회 초과` 를 글자로 적는다.
  같은 이유로 **영역 머리글 띠도 배경 대신 선**(`border-top: 1pt`)으로 구분한다.
- **각주 한 줄 때문에 2페이지가 됐다.** 각주가 화면 크기(10.5px) 그대로라 본문 7pt 보다 크고
  9mm 를 먹어 총 **196.9mm**(한 장 194mm) → 각주 6pt + 바깥 여백 1.5mm 로 **191mm**(여유 3mm).
  자료가 적은 표는 한 장에 들어간다.
- **화면 안내문이 종이에 실렸다**(`같은 항목을 나란히 놓고 비교합니다`) → `print:hidden`.

**출력일을 머리글에 적는다** — 이 표는 경쟁률·컷·일정처럼 시간이 지나면 달라지는 값을 담아,
언제 뽑은 종이인지 없으면 몇 달 뒤 낡은 자료를 최신으로 읽는다.

**남은 한계**: 인쇄 시점에 참고 자료(입학처·복수지원·고사 일정)를 아직 못 받았으면 그 칸이
`불러오는 중…` 으로 인쇄된다. 표를 보고 나서 누르는 것이 정상 경로라 실사용에서는 드물다.
