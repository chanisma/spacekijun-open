# 업무 진행 (모달) — 반자동 파이프라인

2026-09-27 구현. 연구·경위 = [`docs/plans/2026-09-27-task-automation-research.md`](../plans/2026-09-27-task-automation-research.md).
**모달이다**(`WorkPipelineDialog` — 화면 이름은 2026-10-05 «진행 화면» → **«단계별 진행»** — 같은 날 페이지로 만들었다가 사용자 요청 «진행 화면을 모달로 구성해야 보기 좋을 것»으로 옮겼다).
진입점 = 업무 목록 «내가 책임자인 업무» 카드의 [진행] · 업무 상세 창 푸터의 [단계별 진행](전체 업무·타임라인·통합 검색에서도 열린다) · **할 일 상세 창 푸터의 [단계별 진행]** — 담당자의 입구(내 할 일·홈 대시보드, 그 할 일을 고른 채 연다). 담당자는 업무 상세를 거치지 않으므로 처음엔 입구가 없었다(2026-09-27 보완).
두 상세 창은 진행 모달을 **자기 위에 겹쳐** 띄우므로, 그 창을 쓰는 화면(내 할 일·홈·검색·스케줄·타임라인)이 코드 수정 없이 입구를 함께 얻는다.
딥링크 = `/tasks/mine?pipeline=<업무>&pipelineTask=<할 일>`(`src/lib/workPipelineLink.ts` 의 `workPipelineHref` — 2026-10-05 페이지 분리 전엔 `/tasks?pipeline=`, 구 주소도 넘겨 준다) — 업무 관리가 한 번 읽고 지운다. 옛 주소 `/tasks/works/:workId?task=` 는 여기로 넘긴다.

## 무엇인가

업무 하나를 **단계 줄**로 펼쳐 놓고, 지금 할 일을 열면 **앞 단계가 남긴 것이 옆에 보이고**, 형태가 맞으면
다음 작업의 설정 칸으로 **끌어온다**. AI 는 **사람이 버튼을 눌렀을 때만** 초안·정리·점검을 한다.

| 누가 | 하는 일 |
|---|---|
| 사람 | 결정 · 발송·저장 버튼 · 외부 제출(나이스·교데통·에듀파인은 범위 밖) |
| 엔진(코드) | 단계 진행 · **단계 사이 데이터 흐름** · 합계 계산 · 코드 점검 |
| AI(버튼) | 교차 점검 · 표기 묶기 · 표를 글로 — 결과는 [적용]/[무시] 카드, 설정을 직접 바꾸지 않는다 |

## 단계

**같은 `order_index` = 같은 단계**(동시에 하는 일). 절차형 순서 칸이 이미 이 뜻으로 쓰인다(라이브: 시스템 운영 = 전부 1 → 병렬 4개).
처음 열면 **아직 안 끝난 가장 앞 단계의 첫 할 일**. 단계 색 = 에메랄드(끝남)·블루(지금)·슬레이트(예정).

## 산출물 — 운반 형태 여섯

| 형태 | 어디서 오나 |
|---|---|
| 신호 | 선언도 원천도 없으면(끝났다는 사실) |
| 값 · 명단 · 표 | **사람이 남긴다** — `task_output_value`(스냅샷, RPC 전용) |
| 표 | 입력 받기(`get_collect_board` — 비공개 수합 보호), 표 제출, 값 제출(담당자 × 항목) |
| 스펙 문서 | 스펙 문서 생성(**만든 사람만 본다** — RLS) |
| 파일 | 파일 제출(드라이브 링크) |

- **선언이 이긴다**: `task.meta.output = {kind, label?}`. 없으면 자동 원천의 형태(메시지는 «보냈다»가 결과라 신호로 친다).
- 원천이 가진 가시성 판정을 **우회하지 않는다**. 그래서 같은 화면이라도 사람마다 보이는 산출물이 다르고,
  못 본 것은 «비었다»가 아니라 **«볼 수 없다»**로 말한다(`ResolvedOutput.unavailable`).
- 지금 할 일 + 앞 단계 할 일만 원천에서 읽는다(전부 읽으면 입력 받기 표를 업무 전체만큼 읽는다).

## 흐름 — 보여주기 · 채워주기 · 변환

| 수준 | 무엇 | 누가 |
|---|---|---|
| L1 보여주기 | 앞 단계 산출물을 «앞 단계에서 넘어온 것»에 | 항상 |
| L2 채워주기 | 명단 → 메시지 받는 사람·입력 받기 대상 / 값·표·문서 → 메시지 본문 / 값·표·문서 → 스펙 문서 맥락 / 표 → 이 할 일의 표(행 고르기) | 매니저가 누른다(서버 RPC 가 권한·잠금 재검증) |
| L3 변환 | 표 → 글 | AI 버튼 |

- 받는 사람으로 넘길 때 **계정 없는 이름은 빠진다**(대상 규칙은 id 로만 가리킨다) — 확인 줄이 몇 명이 빠지는지 말한다.
- 받는 사람 «더하기»는 기존 «직접 지정» 조건에 **합친다**(조건이 갈라지면 요약이 «직접 지정 · 직접 지정»이 된다). 다른 조건은 건드리지 않는다.
- 다른 작업의 설정을 바꾸므로 **[더하기]/[바꾸기]/[취소]**를 한 번 묻는다(모달이 아니라 그 자리에서).
- **행 고르기 = 스냅샷**. 덧붙일 열(예: «결정»)을 만들 수 있고, 다시 골라도 **같은 행의 결정 값은 살아남는다**.
- **스펙 문서 맥락**: 러너는 컨텍스트가 있을 때만 앞 단계 글을 «앞 단계» 맥락으로 **기본 포함**한다(뺄 수 있고 되돌릴 수 있다).

## AI 버튼 3종

| 버튼 | 입력(코드가 줄인 것) | 결과 |
|---|---|---|
| AI 점검 | 업무·할 일 설명 + 작업 설정의 **글만**(담당자·진척·규칙 id 제외) | 지적 카드 + 원문 인용 · [맞아요·고칠게요]/[무시] |
| AI 표기 묶기 | 한 열의 **고유값과 개수만** | 묶음 카드 · [적용]/[무시] — 적용해도 저장은 사람이 |
| AI 글로 정리 | 표의 줄 글 + **코드가 계산한 합계** | 글 카드 · [본문에 넣기]/[복사]/[무시] |

- 추론 끔(`reasoningEffortFor('extraction')`), 100초에 포기(게이트웨이 150초보다 먼저), 같은 입력은 7일간 캐시(`input_hash` = 프롬프트 버전 포함).
- 결정은 `task_ai_suggestion.decisions` 에 남는다 = **AI 칸별 수락률**.
- **잘린 응답 판정**(`finishReason === 'length'` → 던지고 캐시하지 않음)은 solar-proxy 가 `finishReason`·`usage` 를 돌려주기 시작한 **v75(2026-09-27)부터 실제로 동작한다** — 그 전에는 항상 null 이라 이 검사가 빈 검사였다(적대적 검증 후 재배포).

## 조용히 틀리는 자리

1. **«입력 항목이 없다» 오탐** — 모델이 입력 받기 작업이 없는 체크리스트형 할 일에 `missing_field` 를 붙인다.
   프롬프트로 금지하고, **코드가 한 번 더 버린다**(`parseWorkCheck` — 입력에 «입력받기»가 없으면). 프롬프트만으로는 실측에서 8건이 새어 나왔다.
2. **인용 대조는 정밀도를 사고 재현율을 판다** — 타당한 지적이라도 근거를 원문이 아니라 **자기 설명**으로 적으면 버린다(실측 1건).
   줄임표(«…»)로 줄인 인용은 조각마다 대조해 살린다(`quoteFound`). 근거를 확인할 수 없는 지적은 올리지 않는다는 원칙이 우선이다.
3. **스펙 러너의 맥락 선택과 섞지 말 것** — 라이브러리 다이얼로그가 선택을 다시 만들 때 라이브러리에 없는 id 가 조용히 빠진다.
   앞 단계 맥락은 따로(`excludedUpstreamIds`) 두고 프롬프트에서만 합친다. **이력 복원도 앞 단계 맥락을 되살리지 않는다**(옛 사본이 섞인다).
4. **진행 모달을 «바꿔치기»로 열지 말 것** — 상세 창을 닫고 진행 모달을 여는 대신 **겹쳐 띄운다**(docs/nested-modal-pitfalls.md). 닫으면 보던 상세로 돌아온다. 진행 모달 안의 할 일 상세는 `showPipelineLink={false}` — 자기 자신으로 가는 입구는 무한 중첩이 된다.
   - **딥링크 파라미터를 `?task=` 로 쓰지 말 것** — 그 이름은 할 일 상세 모달의 딥링크라 두 모달이 함께 열린다. 읽은 즉시 지워야 닫자마자 다시 열리지 않는다.
   - **`DialogContent` 에 `overflow`·`flex` 를 주지 말 것** — 스크롤은 기본 viewport 가 맡고(머리글·바닥글 sticky), 행 고르기·러너의 선택기는 바깥 표면으로 포털돼 잘리지 않는다. `flex` 를 주면 tailwind-merge 가 viewport 의 `grid` 를 지워 휴대폰 전체화면 규칙(`modal.css` 의 `.grid`)이 비껴간다.
   - 저장 안 한 «남기는 것»이 있으면 **첫 닫기(뒤로가기 포함)를 거부**하고 경고한다 — 두 번째에 닫힌다(할 일 옮기기와 같은 규칙).
5. **완료 체크를 이 화면에 두지 말 것** — 수행 진입점이 둘이 되면 «제출 없이 완료» 가드를 두 곳에서 지켜야 한다(2026-09-04 사고). 완료는 [할 일 상세 · 완료].
6. **휴대폰에서 그리드 열을 `auto` 로 두지 말 것** — 암묵적 auto 트랙은 자식의 최소 내용 폭(안쪽 표의 `min-w-max`)까지 늘어나
   **화면 전체가 가로로 밀린다**(390px → 441px). 정적 검사·SSR 은 통과했고 **실제 스크린샷에서만** 드러났다 →
   `grid-cols-[minmax(0,1fr)]` + 자식 `min-w-0`.
   - **순서 없는 할 일은 단계 줄 «아래»에 가로로 늘어놓고 자동 줄바꿈한다**(2026-09-27 사용자 요청 — 세로로 쌓으면
     «동시에 하는 한 단계»로 읽힌다). ⚠️ 단계 줄(`min-w-max`, 가로 스크롤) **안**에 두면 `flex-wrap` 이 일하지 않는다 —
     내용만큼 늘어나는 상자에는 줄을 바꿀 폭이 없다. 단계 사슬은 순서가 의미라 줄을 바꾸지 않고 스크롤한다.
7. **`task_ai_suggestion.work_id` 는 업무 id 다** — 어휘 회귀(`task-vocabulary-test`)의 «구 컬럼 이름 work_id» 검사는 옛 `task_work_run.work_id`(작업 id)를 잡으려는 것이라 이 파일만 좁게 뺐다.

| 중간 | 비공개 수합이 행 고르기로 복사되면 담당자 전원에게 열림 | `restricted` 산출물 = 매니저만 열람(RLS) + 고르기 전에 경고 |
| 중간 | 명단 이름 위조(화면 «김교사» → 실제 수신 X) | 서버가 `resource.name` 으로 다시 씀 · 확인 상자에 이름 목록 |
| 중간 | 선언 저장이 `task.meta` 통째로 되써 담당자 상태·제출 변경 유실 | `set_task_output_decl` RPC(그 키만) |

### 구조 필드 가드 — 앱 전체에 걸린다

`guard_task_structure` / `guard_work_structure` 트리거(**SECURITY INVOKER**). 직접 PostgREST 쓰기(`current_user =
'authenticated'`)에서만:
- task: 담당자 **id 집합** 변경 · 다른 업무로 옮기기 · 담당자가 든 할 일 넣기 · 지우기 → 그 업무의 **매니저·만든 사람·관리자**만
- work: 매니저(`manager_id`·`meta.managers` id 집합) 변경 · 지우기 → 기존 매니저·만든 사람·관리자만 · `created_by` 는 서버가 정하고 못 바꾼다

담당자 **상태**만 바뀌는 변경은 통과(«담당자 아님» 등), DEFINER RPC(담당자 상태·제출·단위)는 소유자 권한이라 통과.
롤백 드라이런 21항목: 공격 7종 전부 거부 · 정상 경로(매니저 편집·담당자 이슈·RPC·가져오기 모양·자기 업무 삭제) 전부 통과.
