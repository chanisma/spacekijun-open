## 사용 방법

- **내 업무**: 상태별 목록과 업무 계획표를 제공한다. 할 일·완료·전체 필터는 업무 관리 헤더에 배치하며 내 이벤트 필터와 같은 디자인을 사용한다. 별도 요약 카드·검색·내 업무 제목/건수 상자는 표시하지 않는다.
- 잘못 배정된 업무는 **업무 상세 모달**의 **제 담당 업무가 아닙니다**에서 사유를 입력한다. 배정과 완료 상태는 그대로 유지되며, 본인이 표시를 취소할 수 있다. 관리자는 업무 카드의 **담당자 확인 N건**과 상세 화면의 사유를 확인하고 담당자를 조정한다. 배정되지 않은 조회자에게는 담당자가 아니라는 안내도 표시한다.
- 업무 생성·수정에서 제출을 켜고 **스프레드시트로 받기**를 선택한다. 컬럼명을 정하고 **본인 제출만 공개** 또는 **담당자 모두에게 전체 제출 공개**를 선택한다. 관리자는 항상 전체를 조회한다.
- 담당자는 표에 직접 입력하거나 엑셀·구글 스프레드시트의 여러 셀을 붙여넣는다. 제출한 표를 다시 수정할 수 있다. 과제 단위 업무는 단위를 선택한다.
- 양식(spec)과 스프레드시트 제출 모두 표 확인·복사·Excel(.xlsx) 다운로드를 제공한다. 양식의 반복 행·중첩 값·row_values는 컬럼으로 펼쳐 실제 값을 보존한다. 기존 CSV 다운로드도 같은 값을 제공한다. XLSX는 텍스트 셀로 저장해 `001`과 수식처럼 보이는 입력을 그대로 보존하며, CSV/클립보드는 수식 실행을 방지한다.
- 제출·수정·취소 및 담당자 아님 표시는 관련 목록을 갱신한 뒤 완료한다. 작성 중 닫기는 확인창을 표시하고, 다른 창에서 수정된 제출을 덮어쓰지 않는다. 충돌 시 작성 내용 복사·다운로드로 입력을 보관할 수 있다.

## 이벤트 헤더 정리

내 이벤트·이벤트 검색의 새 이벤트 버튼은 헤더 첫 줄에 배치한다. 업무 관리 모든 탭의 헤더 새로고침은 제거한다. 내 이벤트의 이벤트·업무 건수는 헤더 두 번째 줄 왼쪽에, 모두 펼치기/접기는 같은 줄의 아이콘 버튼으로 표시한다. 이벤트 검색의 전체 펼침/접기는 제거하고, 정렬 선택은 제거하고 기존 부서 필터를 두 번째 줄 초기화 왼쪽으로 옮겨 높이 36px로 배치한다. 목록은 최근 수정순으로 유지한다. 이벤트 검색의 별도 이벤트 목록 상자와 완료·진행 중 건수는 표시하지 않는다. 목록 도구는 React 포털로 헤더에 렌더링한다.

## 데이터와 권한

- `task.meta.submission`: `mode: spreadsheet`, 안정적인 `columns[{key,label}]`, `visibility: own | all`.
- `task_submission.spreadsheet_data`: 제출 당시 컬럼과 문자열 행 배열. 담당자·과제 단위당 현재 제출 1건이며 재제출 시 갱신한다. 별도의 버전 이력은 보관하지 않는다.
- `submit_task_spreadsheet_submission`: 로그인, 실제 담당자, 제출 방식, 컬럼 버전, 입력 크기, 과제 단위, 이전 갱신 시각을 검사한다. 저장과 완료 상태 갱신은 한 트랜잭션이다.
- `delete_task_submission`: 기존 취소 RPC를 재사용하며 마지막 제출 취소 시 미완료로 되돌린다.
- RLS에서 전체 공개도 해당 업무 담당자로 제한한다. 공개 여부로 수정·취소 권한이 확대되지 않는다. 직접 INSERT/UPDATE/DELETE 권한은 제거하고 제출 RPC를 사용한다.
- 제출이 있으면 방식·컬럼 변경을 서버에서 막는다. 공개 범위는 변경할 수 있다. 기존 파일·spec 제출과 혼합되지 않도록 트리거로 검사한다.
- `report_task_assignment_issue`: 담당자 본인의 `task.meta.assignmentIssues[resourceId]`만 설정·해제한다. 사유 1~500자.
- 입력 제한: 컬럼 1~30개, 컬럼명 1~80자/중복 불가, 제출 1~500행, 셀 5,000자, 서버 JSON 크기 2MB. 다중 마감 업무는 기존 규칙에 따라 제출을 지원하지 않는다.

Supabase 보안 점검의 [로그인 사용자가 호출 가능한 SECURITY DEFINER 경고](https://supabase.com/docs/guides/database/database-linter?lint=0029_authenticated_security_definer_function_executable)는 새 RPC 3개에 대해 검토했다. 직접 테이블 변경을 차단한 상태에서 로그인 사용자에게 제공하는 의도된 진입점이며, 각 함수는 로그인·현재 담당자 권한을 검사하고 검색 경로를 고정한다. 익명 호출은 허용하지 않는다.

- `npx tsx --test src/lib/__tests__/submissionSpreadsheet.test.ts`: 붙여넣기, 값 보존, 수식 처리, 입력 설정 검증.
- `npx tsx scripts/task-spec-submission-test/run.mts`: 기존 파일/spec 판정과 CSV 회귀 검사.
- `supabase/tests/task_spreadsheet_submissions.sql`: 트랜잭션 롤백 방식으로 본인/동료/관리자/외부인 권한, 재제출 충돌, 입력 검증, 제출·취소 상태, 단위 제출, 담당자 아님 표시를 검증. 테스트 데이터는 남기지 않는다.
- `scripts/modal-ui-test/run-task-previews.mjs`: 실제 UI와 메모리 모의 서비스로 붙여넣기·저장·재수정·복사·실제 XLSX 값·취소·모바일 스크롤/푸터·중첩 확인창·헤더 상태 필터와 선택 메뉴 hover·양식 반복 값을 검증한다. 기존 사용자 세션이나 실제 제출 데이터를 변경하지 않는다.
