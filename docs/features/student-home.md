# 학생 홈 대시보드

## 화면 순서 개편 (2026-09-12)

사용자 지시로 두 묶음을 옮겼다. **현재 순서가 정본이다** — 아래 옛 절들의 순서 기술은
그 시점의 기록이므로 이 절과 어긋나면 이 절을 따른다.

```
학교생활 브리핑(오늘의 자습)
→ 오늘의 시간표 · 이번 주 일정 · 급식
→ 요즘 세상
→ 구매 신청 · 최근 입시 정보
→ 창의적 체험활동 제안        ← 최근 입시 정보 다음으로 이동
→ 기존 정보 카드
→ 수강신청 마감 · 내 자습 예약  ← 하단으로 이동
```

- **활동 제안이 '최근 입시 정보' 바로 다음**이다. 소식(요즘 세상 → 입시 정보)을 읽고 나서
  활동으로 잇는 흐름이라, 종전처럼 요즘 세상과 입시 정보 사이에 끼어 소식 흐름을 끊지 않는다.
- **수강신청 마감·내 자습 예약은 맨 아래**다. 개인 신청·예약은 필요할 때 찾아가는 것이라
  매일 보는 시간표·소식보다 뒤에 둔다.
- **그리드 자식 순서가 곧 화면 순서**다(`StudentHome.tsx`). CSS `order` 를 쓰지 않으므로
  JSX 한 곳만 고치면 데스크톱·모바일이 함께 따라온다 — 한쪽만 바뀌어 어긋날 여지가 없다.
  모바일에서도 위 순서 그대로 세로로 쌓인다.

## 요즘 세상 안내

- 시간표·일정·급식 다음, 구매·입시 정보 앞에 `WorldTodayHomeCard`를 배치했다. 학교생활을 확인한 뒤 소식으로 넘어가는 자리다(2026-09-12 개편 전에는 신청·예약 카드 다음이었다 — 위 순서 절 참고).
- 리아·루온의 탐구 아카데미 컨셉과 아이보리·보라색을 사용해 ‘소식 읽기 → 질문 찾기 → 관측 일지’ 과정을 소개하고 `/world-today`로 연결한다.
- 로그인 및 기존 메뉴 공개 설정을 따른다. 메뉴 로딩·오류·비활성화 상태에서는 카드 표시와 기사 조회를 생략한다.
- 오른쪽에는 ‘요즘 세상’ 목록과 동일하게 발행일 DESC NULLS LAST → ID DESC 기준으로 `keep=true` 기사 한 편을 조회해 제목·핵심 내용·분류·출처·발행일을 표시한다. 기사를 누르면 `/world-today?story=ID`로 관측 일지를 바로 연다.
- 필요한 요약 컬럼만 1행 조회하고 사용자별 5분 캐시와 5분 주기 갱신을 사용한다. 로딩·조회 실패(재시도)·기사 없음 상태를 구분하며, 개인 일지는 홈에서 조회하지 않는다.
- 모바일은 소개와 탐구 과정을 세로로, 넓은 화면은 두 열로 배치한다. 대용량 삽화나 반복 애니메이션을 추가하지 않는다.

## 디자인 개선 (2026-09-09)

- `StudentHome`은 교사 홈 V2의 `DashboardCardShell`, 브리핑 스타일, 정보 카드를 재사용한다. 흰색 카드, 옅은 테두리, 역할별 아이콘 색상과 제목 위계를 통일한다.
- 상단에 날짜와 오늘의 자습 예약 요약을 제공한다.
- 모바일에서도 데스크톱과 같은 세로 순서로 표시한다(현재 순서는 위 `화면 순서 개편` 절이 정본. 이 문단을 쓴 시점에는 시간표 → 주간 일정 → 급식 → 신청·예약 → 구매·입시 → 정보 카드였다). 중간 화면은 2열, 넓은 화면은 시간표·일정·급식을 5:4:3 비율로 배치한다.
- 시간표는 모든 교시를 보여 주며 현재 수업, 다음 수업, 수업 종료 상태를 구분한다. 교시 상태는 기존 `useCurrentTime`과 `getPeriodTimeStatus`를 사용해 분 단위로 갱신한다.
- 급식은 중식·석식과 기존 칼로리 정보를 유지한다. 두 메뉴 모두 없으면 빈 상태를 표시한다.
- 학생용 시간표·일정 조회 경로와 `학사 정보 알림` 제외 조건을 유지한다. 데이터베이스 변경은 없다.

## 개인 신청·예약 연결 (2026-09-09)

- 시간표·주간 일정·급식 다음에 **수강신청 마감**과 **내 자습 예약**을 추가했다. 구현은 `src/features/student-home/`에 모은다.
- 수강신청: 공개 상태 `open`인 차수 중 입학연도(지정된 경우 우선) 또는 학년이 맞는 차수만 마감순으로 최대 3건 표시한다. 아직 시작 전인 공개 차수는 `신청 예정`으로 구분한다. 종료된 차수는 분 단위 시각 갱신에서 제거한다. 메뉴 관리에서 수강신청을 끄면 카드도 조회·표시하지 않는다.
- 신청 내역은 본인의 `student_code`와 대상 `round_id`로 제한해 조회한다. 선택군 하나만 저장해도 submission 행이 생길 수 있으므로 **`저장 내역 있음`만 표시하고 신청 완료로 간주하지 않는다**. 모든 선택군의 저장 여부는 기존 신청 화면에서 확인한다.
- 자습 예약: 로그인 학생의 프로필 ID로 오늘부터 7일간을 조회한다. 최대 7행을 받아 6건만 표시하고 추가 내역이 있음을 안내한다. 열람실 이름·좌석·설정된 교시 시간만 보여 주며 출결 피드백은 읽지 않는다. 별도 예약 서비스의 시간표를 사용하고 학교 정규 수업 시간을 대입하지 않는다.
- 실제 학생 계정과 선택된 학생 미리보기의 캐시를 분리한다. 관리자 미리보기는 명시적으로 선택한 학생만 `student_identity_map`으로 연결하며 일반 역할 미리보기에는 개인 카드를 표시하지 않는다. 기존 `useCurrentActor`의 역할 캐시 키와 조회 오류 처리를 보완해 잘못된 신원 캐시나 조회 실패를 정상 빈 데이터로 사용하지 않게 했다.
- 조회 오류·로딩·예약 없음·학생 계정 미연결을 구분한다. 창 복귀·홈 재진입·1분 주기에 갱신하며 예약 날짜 키는 자정에 변경된다.
- 학생 대상 공지는 아직 연결하지 않는다. 실제 `department_notice` SELECT 정책과 `/notices` 라우트는 교사·관리자·교직원 전용이다. 학생 공개 대상을 정할 별도 정책과 데이터 모델이 필요하다.
- DB와 공유 예약 테이블은 읽기만 수행했다. 현재 신청·예약 테이블에는 인증 사용자 전체 읽기를 허용하는 기존 정책이 있으므로, 이번 홈의 본인 필터는 새 보안 경계를 만드는 RLS 변경이 아니다.
- 검증: `npx tsx --test src/features/student-home/__tests__/studentHomeData.test.ts`(대상자·마감·본인 필터·조회 실패·교시 표기 9건). 학생 역할을 적용한 읽기 전용 트랜잭션으로 실제 조회 컬럼과 권한을 확인했다. 확인 시점에 공개 상태의 수강신청 차수는 0건이었다.
- 로컬 Edge의 학생 미리보기에서 데스크톱 카드 배치와 신청·예약 빈 상태를 확인했다. 모바일 실기기와 데이터가 있는 신청·예약 화면의 시각 검증은 남아 있다.

## 홈 구성 후속 반영 (2026-09-09)

- 화면 순서(이 시점 기준): 학교생활 브리핑 → 시간표·이번 주 일정·급식 → 수강신청 마감·내 자습 예약 → 구매 신청·최근 입시 정보 → 기존 정보 카드. **2026-09-12 에 바뀌었다 — 위 `화면 순서 개편` 절이 정본이다.**
- 브리핑의 세 바로가기를 **오늘의 자습**으로 교체했다. 아래 예약 카드와 같은 쿼리를 재사용하며 오늘 예약의 열람실·좌석·교시를 최대 2건 요약한다.
- 구매 신청은 `target_roles`에 `student`가 포함되고, 보관되지 않았으며 현재 신청 기간 중인 페이지를 마감순으로 표시한다. 목록 항목은 `/purchase-requests/:id`로 연결한다.
- 입시 정보는 기존 `get_ipsi_hub_feed` RPC의 최신순으로 글·영상 합계 5개를 읽고 원문을 새 탭으로 연다. 전체 버튼은 `/ipsi`로 연결한다. 구매 신청과 입시 정보 카드는 각각 메뉴 관리의 활성화 상태를 따른다.
- 회귀 테스트는 기존 9건에 구매 대상·기간 필터와 입시 5건 제한·안전한 원문 링크 검증을 더해 총 11건이다.
- 이번 주 일정에는 본인의 개인 일정과 소속 학급 일정도 합쳐 표시한다. 공개 범위와 저장 권한은 [개인·학급 일정](school-life-schedule.md)의 별도 테이블 및 RLS를 따른다.

## 후속 콘텐츠 제안

1. **다른 신청·제출 마감**: 수강신청 외 항목도 대상자·제출 완료 여부가 확보되면 같은 카드에 확장한다.
2. **상담 등 다른 예약**: 현재 연결된 자습 좌석 외에도 본인이 신청한 항목의 시간·장소·승인 상태를 보여 준다. 실제 제공 중인 기능에 맞춰 구성한다.
3. **학생 대상 중요 공지**: 학년·학급별 공지를 표시한다. 교직원 공지와 학생 공개 범위를 구분한 뒤 도입한다.

성적 등 상세 분석은 별도 화면에 두고 홈은 오늘 확인하거나 행동할 정보에 집중한다.
