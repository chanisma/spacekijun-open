# NEIS 화면 지식 (2026-10-05)

할 일의 「NEIS 작업」(`neis.screen`, `neis-actions.md`)이 **어느 화면인가**만 가리키던 것을 넘어,
**그 화면 안에 무엇이 있고 어떻게 쓰는가**를 보여 주는 기반. 저장소 계약(스키마·ID·갱신 절차)은
**`neis-kb/README.md`** 가 정본이고, 이 문서는 설계 판단과 운영 실측을 남긴다.

## 목표 — 두 단계

1. **지금**: 담당자가 할 일 카드에서 **[사용 방법]**을 누르면 앱의 다른 기능 안내와 **같은 모달**
   (`WalkthroughDialog` — 왼쪽 시연 · 오른쪽 설명)로 그 나이스 화면의 사용법을 본다(2026-10-05 사용자 지시
   «UI 구조는 각 feature 에 있는 사용 방법 기능 참고»).
2. **나중**: AI 에이전트(Claude Code)가 이 지식을 읽고 나이스 업무를 계획·처리한다(사용자 정의 — 이 웹이 자동 처리하는 것이 아니라 AI 에게 시키는 것).

2단계가 목표라서 1단계를 «보기 좋은 그림»이 아니라 **기계가 읽을 수 있는 화면 모델**로 만들었다.
그림은 그 모델의 한 가지 표현일 뿐이다.

## 설계 판단

### 스크린샷이 아니라 구조를 수집한다 (실측 근거)

`학급담임편성관리` 는 **화면을 여는 것만으로** 교원 63명의 이름·나이스 아이디가 왼쪽 표에 채워진다
(2026-10-05 실측 — 조회를 누르지 않았다). 스크린샷을 저장하면 저장소에 개인정보가 들어간다.
구조만 남기면 ①데이터가 없고 ②그림의 모든 칸이 데이터(요소 ID)라 안내가 «이 칸»을 가리킬 수 있으며
③나이스가 바뀌어도 재수집만으로 그림이 따라간다(스크린샷은 다시 찍고 다시 표시해야 한다).

값은 **브라우저 안에서** 종류(`valueKind`)로 바꾼 뒤에만 꺼낸다 — 수집기 프로세스에도 원값이 닿지 않는다.
그리드는 머리글만, 라벨은 «aria 와 글자가 맞을 때만»(aria `성명` + 글자 `홍길동` 은 값이라 버린다).
회귀가 저장소의 수집본 전체에서 이메일·긴 숫자·아이디 꼴을 찾는다.

### 사실과 의미를 나눈다 (NEIS_helper 의 교훈)

NEIS_helper `담임-메뉴.md` 의 원칙 «지식의 출처가 셋이다. 섞지 말 것»을 따랐다. 수집본(기계, 덮어씀)과
안내(사람·AI, 보존)를 다른 파일에 두고, 안내는 요소 ID 로만 수집본을 가리킨다. 나이스 변경에 대한
대응이 «다시 긁고 → `check.mts` 가 고칠 안내를 짚는다»로 끝난다.

### 저장소 안의 파일이다 (DB 가 아니라)

- AI 에이전트가 읽기 쉽다(파일 하나 = 화면 하나, 2단계의 독자).
- `git diff neis-kb/captures` 가 곧 **나이스 변경 기록**이다.
- 앱은 `import.meta.glob` 지연 로딩으로 화면을 펼칠 때 그 파일만 받는다(색인 `index.json` 만 먼저).
- 권한 경계가 필요 없다 — 개인정보가 없고, 화면 구조는 나이스 사용자 누구나 보는 것이다.

### 수집기는 NEIS_helper 의 탐색 코드를 import 한다

인증서 로그인·공지 팝업(겹친 것은 맨 위부터)·메가메뉴·메뉴 검색의 함정이 NEIS_helper `app/core/neis_nav.py`
에 실측으로 모여 있다. 다시 만들면 같은 함정을 다시 밟는다. 그래서 `collect.py` 는 `NEIS_HELPER_DIR`
(기본 경로) 의 `core` 를 import 하고, 화면 안 수집 코드(브라우저에서 도는 JS)만 새로 썼다.
경로 규칙(`neisKbPath`)은 TS 한 곳에만 있고 수집기는 `targets.json` 으로 받는다 — 두 언어에 같은 규칙을 두면 언젠가 갈라진다.
요소 ID 규칙만은 두 언어에 있으므로(수집 중에 매겨야 해서) `validateCapture` 가 다시 계산해 대조한다.

### 버튼의 성격이 자동화의 안전선이다

`neisButtonEffect` 가 이름으로 `read`·`export`·`navigate`·`write` 를 추정한다. **모르면 `write`** 로 본다(안전한 쪽으로 틀린다).
2단계에서 AI 는 `write` 를 사람 확인 없이 누르지 않는다. 지금은 그림의 요소 정보에서 «자료를 바꿈»(로즈)으로 보인다.

### 사용 방법 = 다른 기능과 같은 껍데기, 씬만 데이터에서 생성

처음에는 카드 안에 펼치는 «화면 그림 + 요소 정보» 패널을 만들었다가, 같은 날 사용자 지시로 앱의 **사용 방법
모달**(`WalkthroughDialog`)로 옮겼다 — 화면마다 다른 안내 UI 를 두지 않는다. 다른 기능은 씬을 손으로 그리지만
나이스 화면은 수백 개라 **수집본에서 생성**한다(`NeisGuideScenes.tsx`). 그래도 스킬의 수칙을 그대로 지킨다:

- **포인터는 자리 상수에서 유도** — 수집본의 box 가 곧 `Rect` 다. 탭 칸 자리도 그림과 포인터가 같은 함수
  (`neisTabItemBoxes`)를 써서 포인터가 대상 위에 오는 것이 계산이 아니라 구성으로 보장된다.
- **글자 하한** — 나이스 화면(≈1,600px)을 960 무대에 통째로 넣으면 7px 이 된다. 그래서 **카메라**가
  전체(어디쯤인지) → 대상(무엇인지)으로 다가가고, 대상이 여럿이면 **대상마다 미끄러져 따라간다**
  (흩어진 대상을 한 화면에 넣으면 확대가 안 된다). 배율 상한 0.85·여백 140 — 더 다가가면 맥락을 잃는다(실측).
- **3~4단계** — 안내 단계를 목적으로 묶고(`targets` 여럿), 앞뒤에 [화면 찾기]·[주의]가 자동으로 붙는다.
  처음 쓴 표본은 칸마다 한 단계라 8단계였다 → 묶어서 5장(찾기 + 3 + 주의).
- **클릭이 없는 단계**(화면 구성·주의)는 포인터 없이 비추기만 한다.
- 빈 «자료 영역»은 **접는다**(`neisVerticalMap` — 다른 요소가 걸치지 않은 그리드 몸통만 120px 로, 구간별 선형 사상).
- 단계 계획은 순수 함수(`src/lib/neisWalkthrough.ts`), 그리기는 `NeisViewLayer`(좌표 그대로) + 씬(카메라).

## 조용히 틀리는 자리

1. **aria 없는 라벨** — `기타일정관리` 의 날짜칸 라벨은 aria-label 이 없다. aria 있는 라벨만 받으면 칸이 통째로 빠진다
   (오류 없음). 짧은 글자는 «컨트롤과 짝지을 때만» 라벨로 받는다.
2. **기간의 끝 칸** — 라벨이 `~` 뿐이다. 같은 줄 왼쪽 날짜칸 이름에 `~` 를 붙인다(`등록일자~`).
3. **안쪽 탭 이름의 띄어쓰기** — 메뉴목록은 `연간학사일정관리`, 화면은 `연간 학사일정관리`. 맞출 때 정규화한다
   (`neisViewForInnerTab`). 그대로 비교하면 할 일에 지정한 탭이 영원히 안 열린다.
4. **화면 루트** — `.app-tit` 첫 번째를 잡으면 닫힌 화면의 것(크기 0)이 나온다. 보이는 가장 바깥 `cl-embeddedapp` 를 루트로 한다.
5. **하단 MDI 탭도 `cl-tabfolder`** 다 — 안쪽 탭을 찾을 때 `cl-mdifolder` 와 그 안을 뺀다.
6. **지문에 좌표를 넣지 말 것** — 창 크기만 달라도 모든 안내가 «검토 필요»가 된다.
7. **수집기를 고치면 지문이 바뀐다** — 2026-10-05 에 `~` 규칙을 넣자 이미 찍은 안내가 «화면 구성이 바뀌었습니다»로 떴다.
   나이스가 아니라 수집기가 바뀐 것이므로, 수집기를 고친 뒤에는 안내를 확인하고 `basedOn` 을 지운 뒤 `--stamp`.

8. **안쪽 탭이 «큰 버튼»인 화면** — 전입·전출·통폐합·위탁 같은 절차형 화면은 탭 폴더가 아니라 본문 윗줄의 큰 단계 버튼
   (`전출자료요청접수 → 월출결자료등록 → … → 학적반영`)으로 화면을 바꾼다. 탭 폴더만 찾으면 view 가 하나로 끝나고
   **오류가 없다**(첫 전체 수집 78개 중 4개가 이렇게 반쪽이었다). 높이 38px 이상 버튼 줄 + 메뉴목록의 안쪽 탭 이름을 힌트로 찾는다(`via: 'buttons'`).
9. **이름에 붙는 학년도** — `전출자료요청접수 (2026학년도)`. 그대로 ID 에 넣으면 해가 바뀌는 날 모든 안내가 «대상 없음»이 된다. 떼고 기록한다.
10. **정본(엑셀)과 화면의 표기가 다르다** — `월출결자료등록` ↔ `월출결자료등록(선택)`, `학생생활기록부생성` ↔ `학교생활기록부생성`,
    `학직반영`(엑셀 오타) ↔ `학적반영`. 엑셀 이름으로 화면을 찾을 때는 포함 관계·한 글자 차이까지 같은 것으로 본다.
    **수집본의 이름은 화면 표기**다 — 안내 문장도 화면 표기로 쓴다.
11. **처음 선택된 안쪽 탭이 0번이라는 보장은 없다** — 첫 스냅숏은 «선택된 탭»의 것으로 붙이고 나머지만 누른다.

12. **경로의 `#`** — 세부업무 `대입전형#고등학교`·`보건#학교`·`입학#고등학교`의 `#` 이 파일 경로에 들어가면, 앱이 그 경로를
    import 지정자로 쓸 때 `#` 뒤가 URL 조각으로 잘려 **로더 모듈 전체가 500** 이 되고 모든 화면의 사용 방법이 함께 죽는다
    (오류는 개발 서버 로그에만 남는다). `neisKbPath` 가 `#`·`%` 를 `_` 로 바꾸고 회귀가 검사한다. 파일럿 화면에는 그런 이름이 없어 전체 수집 뒤에야 드러났다.
13. **화면 첫 탭이 빈약할 수 있다** — `건강기록부전송관리` 첫 탭은 승인 라디오와 [저장]뿐이다. 안내가 없을 때 [화면 구성]은 요소가 가장 많은 탭을 보여 준다.
14. **글·링크 위주 화면은 빈약하게 잡힌다** — `OMR카드리딩프로그램관리`(프로그램 내려받기)는 안쪽 탭만 잡힌다. 수집 규칙이 필드·버튼·표·※안내만 보기 때문이다.

## 조회까지 눌러 받기 (`--query`, 2026-10-05 — 정보공시에만)

정보공시 «자료등록»은 처음 열면 본문이 통째로 비어 있다(스크린샷 확인 — 수집 실패가 아니다). [조회]를 눌러야 그려지는
화면이 전체 618개 중 66개였다. 사용자 승인으로 정보공시 21개에 [조회]까지 눌렀더니 **본문보다 알림이 더 큰 지식**이었다:

- 자료등록·자료가져오기·자료검증·작성자마감·확인자마감·교육통계자료재연계 6개 = «현재 공시차수 N차는 조사가능일이 아닙니다»
  → **조사 기간에만 열린다**. 차수를 바꿔도(수시·1·2·3차) 같았고, 수시는 «조회된 항목이 없습니다 … [담당자관리]에서 담당자
  지정이 되어 있는지 확인» → **작성자로 지정돼야 항목이 보인다**. 둘 다 사람이 "왜 안 열리지"로 막히는 자리다.
