# 입시 정보 (`src/features/ipsi-hub/`)

입시 뉴스 기사와 입시 영상을 한 피드로 모아 보여 주고, 여러 자료를 묶어 AI 복합 분석을 돌리는 기능. 라우트 `/ipsi`.

## 접근 권한

| 역할 | 피드 열람 | 동영상 추가 | AI 분석 |
|---|---|---|---|
| 학생 | ✅ | ❌ | ✅ (2026-09-11) |
| 교사 · admin | ✅ | ✅ | ✅ |
| 직원(staff) | ❌ | ❌ | ❌ |

- **직원이 빠지는 것은 이 기능의 결정이 아니다** — `/ipsi`가 `routeAccess.ts`의 `STAFF_BLOCKED_PREFIXES`에 있어 라우트 단계에서 막힌다. 권한을 넓힐 땐 그 목록부터 봐야 한다.
- 판정은 **`effectiveRole`**로 한다(`IpsiHubApp`). `profile.role`을 직접 비교하면 admin의 역할 미리보기 중에도 교사 화면이 그대로 비친다.
- `educational_news`·`educational_videos`의 SELECT 정책은 `true`(전원 열람)다. 그래서 **자료는 원래 학생도 다 볼 수 있었고, 분석만 교사 전용이던 것에 데이터 상의 근거가 없었다** — 2026-09-11에 학생에게 열었다.

## 검색 (2026-09-22)

요구: "입시 정보 기능에 검색 기능이 있으면 좋겠음. 제목, 내용 등 상관 없이 검색이 되도록."
이어서: "모바일에서는 태그 필터를 드롭다운으로 간단하게 표시하고 검색을 추가하면 좋겠음."

### 무엇을 찾나

**서버(`get_ipsi_hub_feed` 의 `p_query`)가 찾는다.** 피드가 서버 페이지네이션이라 화면에서 거르면
**지금 페이지(20~30건) 안에서만** 찾게 된다.

| 대상 | 필드 |
|---|---|
| 공통 | 제목 · 요약 · 카테고리 |
| 뉴스 | 출처 이름(진학사·유웨이·리로스쿨) · 핵심/전략/수치/주의 포인트 · **기사 본문(`content`)** |
| 동영상 | 채널명 · `meta` 의 모든 문자열(설명·포인트·핵심 개념·타임스탬프 메모) · **자막(`transcript`)** |

- **여러 단어 = 모두 포함(AND)**, 최대 8단어·100자. 대소문자 무시.
- **띄어쓰기를 무시한다** — 문서와 검색어 양쪽의 공백을 지우고 비교한다("정시모집" ↔ "정시 모집").
- `strpos` 로 비교하므로 `%`·`_` 가 와일드카드가 되지 않는다(`100%_` → 0건).
- 검색 중에는 `video_count`/`news_count`(종류 칩 배지)가 **검색에 맞는 수**다 — 종류·태그 필터와 무관.
  그래서 빈 결과에서 "이 분류에는 없지만 **전체 분류에서 N건**"을 말할 수 있다.
- 결과마다 `match_field`/`match_snippet` — 제목·요약에 **안 보이는** 검색어를 어디서 찾았는지
  (`기사 본문`·`핵심 내용`·`영상 설명`·`자막`)와 주변 약 100자. 본문·자막에서만 찾은 결과가
  "왜 나왔는지"를 화면이 말한다(없으면 사용자는 결과를 의심한다).

### 화면

- 검색어의 정본은 URL **`?q=`**(종류·태그·보기 방식과 같다) — 새로고침·링크 공유에 남는다.
  입력창은 초안을 따로 들고 **300ms** 멈추면 확정한다. Enter = 바로, Esc/✕ = 지우기.
- **데스크톱**: 검색창이 버튼과 같은 줄 왼쪽(머리글에 기능명·건수 없음 — 건수는 종류 칩이 말한다), 태그는 종전 칩 그대로.
- **휴대폰**: 태그 칩 줄 → **드롭다운(`CategoryFilterSelect`)**, 그 옆에 검색창 한 줄.
  칩 8개가 두세 줄로 접혀 헤더를 키우고 검색창 자리가 없었다. 칩과 드롭다운은
  **같은 목록**(`categoriesForType`)이다.
- 검색창은 헤더에서 **한 번만** 그린다 — `flex-wrap` + `order` 로 데스크톱은 제목 줄에,
  휴대폰은 아래 줄에 선다(두 벌을 숨김 처리하면 값·포커스가 갈린다).
- 일치 부분은 형광펜(`mark`). **띄어쓰기가 다른 일치는 강조하지 않는다** — 서버는 찾지만
  글자 위치를 특정할 수 없어서다(결과에는 나오되 발췌로 이유를 보여 준다).

### 조용히 틀리는 자리

- **⚠️ 화면과 서버의 검색어 규칙은 한 쌍이다.** 100자·8단어 한도가 `utils/search.ts` 와 SQL 에
  각각 있다. 어긋나면 서버는 앞 8단어로 찾았는데 화면은 9번째까지 강조하는 식으로 결과와 표시가
  갈린다. 회귀가 두 값을 대조한다.
- **⚠️ 검색하지 않을 때는 `p_query` 를 보내지 않는다** — 검색 없는 조회는 종전과 요청이 같아야 한다.
- **성능**: 인덱스 없이 매번 약 2.6MB(본문 0.9MB + 자막 1.7MB)를 훑는다. 실측 **225~354ms**
  (검색 없음 13ms). 자료가 몇 배로 늘면 저장형 검색 컬럼(+ `pg_trgm` 은 이미 설치됨)을
  검토할 것 — **표 구조 변경이라 사용자 확인이 필요하다.**

회귀 = `npx tsx scripts/ipsi-hub-search-test/run.mts`(36건) · 브라우저 fixture =
`/scripts/ipsi-hub-search-test/index.html`(라이브 RPC, 로그인만 스텁 — `main.tsx` 머리말).
2026-09-22 실측(390×844): 태그 드롭다운·검색창 같은 줄(y=72), 입력 16px, 칩 줄 없음,
가로 넘침 없음 / 1280×800: 검색창·버튼 한 줄, 종류 칩 `전체 (244)`, 빈 결과 → "전체 분류에서 12건 보기".
(같은 날 머리글 규약으로 제목·"검색 결과 N건"을 뺐다 — CLAUDE.md "UI 큰 틀 규약" §1)

## AI 복합 분석

### 흐름

`AiAnalysisPanel`(우측 서랍) → 선택 → 검토 → 결과, 그리고 이력 탭.

```
NewsSelectionStep → ReviewStep → [runCompoundAnalysis] → ResultStep → (저장) → HistoryStep
                        ↑                   │
                        └── 실패 시 여기 머문다 (AnalysisFailureNotice)
```

### 대상(audience)별로 갈리는 것

`AnalysisAudience = 'teacher' | 'student'`. 프롬프트를 통째로 갈라 두지 않고 **세 조각만** 바꾼다(`AUDIENCE_BLOCKS`).

| | 교사 | 학생 |
|---|---|---|
| 화자 | 진학지도 전문가 | 진학 코치 |
| `strategy`의 뜻 | 학교 현장에서 활용 가능한 행동 | **본인이 이번 학기에 직접 할 수 있는 행동** |
| 추가 규칙 | 없음 | 합격 가능성 단정 금지 · 특정 대학 권유 금지 · 개인 성적 판정 금지(담임·진학 담당 교사 상담으로 넘긴다) |

- **`strategy`가 핵심 차이다.** 교사용 전략을 학생에게 그대로 주면 자기가 할 수 없는 일을 조언으로 받는다.
- **JSON 스키마는 두 대상이 완전히 같다.** 갈라 두면 저장·표시·이력 조회가 대상마다 달라져야 하고, 학생이 만든 이력을 교사가 열었을 때 필드가 비어 보인다.
- 관점 프리셋에도 `audience`가 붙는다(`ANALYSIS_PERSPECTIVE_PRESETS`). 학생에게 "교사 입시지도용"·"학부모 브리핑용"을 보여 주면 자기 얘기가 아닌 관점을 골라 3인칭 지도 조언을 받게 된다. **기본값은 반드시 그 대상의 목록 안에 있어야 한다** — 밖이면 어떤 칩도 선택돼 보이지 않는다(회귀가 검사한다).

### ⚠️ `JSON을 찾을 수 없습니다` — 원인과 4중 방어 (2026-09-11)

**원인은 프롬프트가 아니라 조용히 버려진 파라미터였다.** 서비스가 `maxCompletionTokens: 12000`을 적어 두었는데 `aiChat`이 그것을 `provider === 'openai'`일 때만 실어 보냈고, 기본 공급자는 solar다. 즉 **이 호출은 출력 예산을 정한 적이 없다.** 추론 토큰과 최종 출력이 같은 예산을 나눠 쓰는 모델에서 답이 중간에 끊기면 `extractJson`이 그 한 줄을 던지고 **원문까지 버렸다** — 30~120초 걸린 분석이 통째로 사라지는데 화면은 원인도 말해 주지 못했다.

증거: 저장된 분석 2건이 모두 **2026-04 · `gpt-5-mini`/`gpt-5.4-mini`** 산이다(=예산이 실제로 전달되던 OpenAI 경로). 기본 공급자가 solar로 바뀐 뒤 이 호출부만 예산을 잃었다.

방어를 네 겹으로 둔다.

**① 예방 — 예산이 실제로 전달되는 경로로 옮긴다 (2026-09-11 사용자 결정)**
- **공급자·모델 = OpenAI `gpt-6-luna`**(`ANALYSIS_PROVIDER`·`ANALYSIS_MODEL`). Solar 경로는 예산을 전달할 방법이 없으므로(`solar-proxy`가 `max_tokens`를 보내지 않는다) 예방 계층을 세울 수 없다. **엣지 함수를 고치지 않고 호출부만 바꿔 끝낸다** — 같은 문제를 겪은 스펙 채움(문서 생성)도 `luna 단독`으로 옮긴 선례가 있다.
- **모델을 명시한다.** 생략하면 엣지 함수 기본값에 기대게 되고, 그 탓에 구 모델 폐기 때 한 경로만 홀로 죽은 이력이 있다(`specFillService`의 교훈).
- `ANALYSIS_MAX_TOKENS = 16000`. 성공 사례의 실측 출력이 JSON 2,173~2,625자(≈1,300토큰)이고 최악의 추론 비중(실측 79~85%)을 적용해도 9,000토큰 안쪽이다. `openai-proxy` 기본값 10,000으로는 빠듯하므로 **원인에서 배제되도록** 그 위로 잡았다. 상한은 "그만큼 쓰라"가 아니라 "그 전에는 끊지 말라"이므로 크게 잡아도 느려지지 않는다.
- 온도 **1.0 → 0.3**(재시도 0.1). 1.0은 창작용 값이고 형식 이탈 확률을 키운다. ⚠️ 다만 **반영되지 않을 수 있다** — reasoning 계열 모델은 custom temperature를 거부하고 `openai-proxy`가 400을 받으면 temperature만 떼고 재시도한다. **형식 준수를 온도에만 의존하지 말 것**(그래서 ②③이 함께 있다).
- **Solar로 되돌리지 말 것.** 되돌리는 순간 `ANALYSIS_MAX_TOKENS`가 조용히 무의미해지고 원래 버그가 재발한다 — 회귀가 `ANALYSIS_PROVIDER === 'openai'`를 검사한다.

**② 복구 — 잘린 JSON을 살린다** (`utils/analysisJson.ts`, 순수 모듈)
- 사고 블록(`<think>`)·코드펜스를 벗긴다. **닫히지 않은 펜스·닫히지 않은 사고 블록까지** 처리한다(둘 다 "잘렸다"의 신호다).
- **괄호 균형을 세어** 객체 경계를 찾는다. 종전 `lastIndexOf('}')`는 객체 뒤에 중괄호를 포함한 잡담이 붙으면 그 괄호를 집어 조용히 틀린 슬라이스를 만들었다.
- **"뒤로 물러나며 닫기"**: 구조 경계(쉼표 직전·닫는 괄호 직후)를 뒤에서부터 하나씩 물러나며 열린 괄호를 닫아 보고, 처음 파싱되는 후보를 쓴다. 각 시도가 내용을 줄이므로 반드시 종료된다.
- **반쪽 문장은 만들지 않는다.** 문자열 한가운데서 잘렸으면 따옴표를 닫아 붙이지 않고 그 항목을 **버린다** — 파싱은 되지만 "…평가 요소가 확대되" 같은 미완성 문장이 학교 분석 보고서에 박힌다. 파싱 성공이 곧 쓸 수 있는 결과는 아니다.
- **건진 것이 없으면 복구 실패로 취급한다.** `{` 하나만 도착해도 복구는 `{}`를 만들어 파싱에 성공하는데, 그걸 성공으로 돌려주면 원인이 "형식은 맞췄는데 내용이 비었다"로 보고된다 — 실제로는 잘린 것이다.

**③ 자동 재시도 1회**
- 파싱 실패·빈 결과면 시스템 프롬프트 끝에 `JSON_ONLY_REINFORCEMENT`를 붙여 한 번 더 보낸다.
- **보강 지시는 짧아야 한다** — 추론과 출력이 같은 예산을 나눠 쓰므로, 길면 답에 쓸 예산이 줄어 "형식을 고치려다 더 심하게 잘리는" 상태가 된다.
- **네트워크·인증·쿼터 오류는 재시도하지 않는다**(다시 보내도 같다). `AnalysisParseError`만 재시도 대상이다.
- 2회가 상한이다. 한 번에 30~120초라 그 이상은 사용자가 기다리지 않는다.
- 재시도는 화면에서 한 번의 실행으로 보이므로 **버튼이 그 사실을 말한다**(`형식 교정 재시도 중… (2/2)`). 숨기면 이유 없이 두 배로 느려진 실행으로 보인다.

**④ 화면이 원인을 말한다**
- 실패하면 **토스트가 아니라 검토 단계에 머문다**(`AnalysisFailureNotice`). 토스트는 몇 초 뒤 사라지고, 그러면 오래 기다린 사용자에게 남는 것이 아무것도 없다.
- 원인별로 다른 **다음 행동**을 준다. "다시 시도하세요"만 쓰지 않는다 — 잘림은 다시 눌러도 같은 자료면 같은 길이가 나오므로, 사용자가 바꿀 수 있는 것(자료 수·"짧게 써 줘")을 말해야 한다.
- **AI 응답 원문을 펼쳐 보고 복사할 수 있다.** 같은 실패가 반복돼도 무엇이 왔는지 알 수 없던 것이 이 오류를 고치기 어려웠던 이유다.
- `finish_reason`이 오면 그대로 보여 준다(`aiChatDetailed`가 꺼낸다). **`length`면 출력 길이 제한이 확정**이므로 다음 사람은 추측하지 않고 `ANALYSIS_MAX_TOKENS`를 올리면 된다. ⚠️ **2026-09-11 현재 두 프록시 모두 이 값을 돌려주지 않아 배지가 뜨지 않는다** — 켜려면 `openai-proxy`의 `chatCompletion` 응답에 `finishReason: data.choices?.[0]?.finish_reason ?? null` 한 줄을 더하고 재배포하면 된다(기존 호출부는 `result`만 읽으므로 하위 호환).
- 부분 결과는 결과 화면이 **밝힌다**(`repaired` 배너). 조용히 짧은 결과를 완성본으로 보여 주면 "왜 트렌드가 2개뿐인가"를 알 길이 없고, 그 상태로 저장돼 이력에 남는다.
- 자료가 12건을 넘으면 **누르기 전에** 잘릴 수 있다고 알린다(막지는 않는다 — 정당한 사용일 수 있다).

**이 회귀가 유일한 방어선이다** — 실패 입력은 모델이 만들고 우리는 재현할 수 없다. 게다가 잘못 파싱해도 예외가 아니라 **그럴듯한 부분 결과**가 나온다(잘린 배열을 조용히 버리거나 반쪽 문장을 싣는다). 그래서 망가진 응답 모양을 표본으로 못 박는다.

## 스키마 — `educational_news_compound_analysis`

분석 결과 저장소. `source_news_ids`·`source_video_ids`(uuid[]), 결과 5필드, `raw_response`(jsonb), `model`, `created_by`.

- **`min_sources` CHECK**가 있다 — 자료 id가 하나도 없는 행은 거부된다.
- RLS (2026-09-11 개편):
  - **INSERT** = `created_by = auth.uid()` ∧ role ∈ {student, teacher, admin}. 직원을 제외한 것은 라우트와 짝을 맞춘 것이다 — 화면에 없는 권한을 API에만 열어 두면 "메뉴는 없는데 API로는 열린" 상태가 된다.
  - **SELECT** = 교직원(`is_teacher_or_admin`)은 전부 / **학생은 본인 것만**. 학생에게 화면을 열어 주는 순간 교사가 적은 분석 관점·추가 지시사항이 전교생에게 열리는데, 교사는 그것을 교사 도구로 쓰며 남긴 메모다.
  - **UPDATE·DELETE** = 작성자 ∨ admin (종전 그대로).
- 실사용자 컨텍스트 검증(2026-09-11): 익명 열람 0행·저장 거부 / 학생 본인 명의 저장 허용 · **교사 명의 사칭 거부** · 열람 본인 1건 / 교사 열람 전부 / 학생 본인 것 삭제 허용.

## 그 밖에 알아둘 것

- **`useEducationalNews`는 `.limit()`이 없다.** PostgREST가 요청당 1000행에서 **오류 없이 자른다**. 현재 458행이라 문제가 없지만, 넘어가면 오래된 기사가 조용히 사라진다(CLAUDE.md "무제한 select는 조용히 잘린다" 참고).
- 피드 정렬은 `articleDate` 내림차순이고 뉴스·영상 두 매퍼가 모두 `article_date → collected_at` 폴백을 거치므로 단일 키 비교로 일관된다.
- 선택 키는 `${kind}:${id}` — 뉴스와 영상의 id가 충돌할 수 있다.

## 기사 출처 단일 출처 · 에이전트(MCP) 연결 (2026-11-09)

- **출처 표는 `utils/newsSources.ts` 한 곳**이다(`NEWS_SOURCES`·`NEWS_SOURCE_LABEL`·`newsSourceMeta(source, 'strong'|'soft')`). 종전에는 `NewsCard`·`ListView`·`NewsSelectionStep`·`ReviewStep`·`newsAiAnalysisService` 가 각자 표를 들고 `SOURCE_META[source].label` 로 읽어, **DB 에 모르는 출처 값이 하나만 와도 피드 화면 전체가 깨졌다**. 이제 모르는 값은 회색 배지(값 그대로)로 그린다. 타입 `NewsSource` 도 여기서(`types/feed.ts`·`types/aiAnalysis.ts`·`useEducationalNews`·`useUniversalSearch`).
- 새 출처 **`manual`(«직접 추가», amber 배지)** — 에이전트 도구 `add_ipsi_news` 로 교사·관리자가 더한 기사(진학사·유웨이 주소가 아닌 것). ⚠️ 출처 이름은 네 벌이다: DB CHECK `educational_news_source_check` · SQL `mcp_private.ipsi_source_label` · `get_ipsi_hub_feed` 의 검색용 이름 · 이 파일.
- `riroschool` 은 리로스쿨 사이트가 아니라 **수집기가 리로스쿨 enews 로 모은 60여 언론사 기사 묶음**이다(주소는 조선에듀·교육플러스·베리타스알파 등) — 주소로 출처를 판정할 수 없다.
- 에이전트(MCP `ipsi.hub`)가 피드 검색·읽기, 복합 분석 이력·저장, 영상 추가·고치기·지우기, 기사 직접 추가(고치기·지우기는 관리자)를 한다 — 같은 표·같은 RLS·같은 검색 RPC. 상세 `docs/features/mcp-agent.md` «입시 정보». 에이전트가 넣는 영상 주소는 웹 플레이어(`extractYouTubeId`)가 읽는 `watch?v=` 모양으로 바뀌어 들어간다.
