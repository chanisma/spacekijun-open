# 창가의 하늘 · 목표는 별자리, 계획은 별 (설계안, 2026-09-14)

> **2026-10-02 개편 — §11 이 현재 화면이다.** §4 의 «여러 하늘 × 별자리 그리기»(격자·별 놓기·두 별 잇기·하늘 이름)는 걷어냈다. §1~§10 은 데이터 설계(계획 실체·별 = 실천)와 제5장의 뼈대, 그리고 기각 기록으로서 남긴다.

**상태: 기존 기능 구현·검증 완료. §4의 하늘 지도 개편은 2026-09-15 연결 DB 영구 적용·이력 등록·스키마 캐시 갱신 및 적용 후 회귀 검사 완료. 2026-09-14 DB 마이그레이션 4개 영구 적용·이력 등록·스키마 캐시 갱신 완료. 이번 RPC 오류 수정에는 프런트엔드 재배포가 필요하지 않다.** 계획장(목표·계획)을 게임의 하늘로 표현하는 기능과, 그 기능을
소개하는 **제5장**의 구성을 함께 정한다. 결정과 함께 **기각한 안**도 남긴다 — 같은
제안이 몇 달 뒤 다시 올라온다. kidon 에서 물려받은 계획 시스템은 §5 에서 **적대적으로**
검토했고(사용자 지시), 데이터 설계는 그 결과를 따른다.

## 1. 한 줄 정의

**목표 하나 = 별자리 하나, 그 목표를 위한 계획 하나 = 별 하나.** 계획을 실천하면 별이
밝혀지고, 학생이 그 별을 하늘에 놓고 다른 별과 이어 모양을 만들며, 목표를 마치면
별자리에 이름을 붙인다. 하늘은 **기숙사 창가**에서 본다 — 제3장에서 세린이 "창가 쪽
책상은 리아 자리로 비워 뒀어요"라고 한 그 자리다.

## 2. 세계관 설정 — 맥락이지 데이터가 아니다

```
은하        = KG 에서 Thread·Interest 를 중심으로 묶이는 집합     ← 대사에서만
 ├─ 활동    = 관측된 별  (망원경·KG, 카시안의 영역)
 └─ 목표    = 별자리     (창가의 하늘, 계획장)
      └─ 계획 = 별자리를 이루는 별
```

- 활동도 별이고 계획도 별인 이유를 "같은 은하 안의 다른 천체"로 설명한다. 그래서
  **같은 낱말을 써도 뜻이 섞이지 않는다.** 화면은 분리, 세계관은 통합.
- **KG 표(`student_kg_*`)와 계획장 표를 잇지 않는다.** 목표에 KG 노드를 연결하는
  컬럼도 두지 않는다. KG 는 재추출마다 노드가 바뀌므로(v7→v8) 거기 붙인 목표는
  세대마다 고아가 된다. 별자리는 학생이 만든 것이라 KG 세대와 무관하게 남아야 한다.
- 관측소의 망원경(Cytoscape, `InquiryGraphCanvas`)은 손대지 않는다. 창가의 하늘은
  별도 패널이다.

## 3. 대응표

| 계획장 | 하늘 |
|---|---|
| 목표 | 별자리 |
| 목표를 세운 이유 | 별자리의 전설 — 이름표를 펼치면 보인다 |
| 계획(§5 의 `academy_plans`) | 별 |
| 그 계획의 날짜별 실천 | 별의 밝기(등급) — 반복이 한 별에 쌓인다 |
| "가장 중요한 일" ★ (계획장이 이미 표시) | **으뜸별** — 1.6배 |

| 목표 보관 | 미완의 성도 — 회색으로 남고 지우지 않는다 |

## 4. 화면 — 하늘 지도 / 하늘 / 별자리 (2026-09-14 개편)

**진입:** 계획장 하단 메뉴에서 `시간별 계획` 오른쪽의 `밤하늘 보기`. 기숙사 방과 월드의 `window` 버튼을 제거했다.
계획 적기는 목표 사전 선택을 생략하고 바로 폼을 연다. 목표 연결은 폼의 `이어갈 목표`에서 정한다. 목표에서 직접 계획을 추가하거나 제3장 안내로 작성할 때는 해당 목표를 미리 선택한다. 실천 후 안내와 목표 완료 시 이름 붙이기는 유지한다. 하늘을 닫으면 계획장으로 돌아온다. 헤더는 작은 제목과 안내만 표시하며 별도 계획장 버튼은 두지 않는다. 닫기는 44×44px 원형 버튼이다.

1. **전체 하늘:** 12칸 격자와 이전·다음 페이지. 각 칸의 이름, 별자리 수, 작은 모양 미리보기.
   목표가 많아도 전체 별을 한 캔버스에 렌더링하지 않는다. 이름 검색 목록에서 소속 하늘로 이동한다.
2. **선택한 하늘:** 최대 8개의 별자리를 담는다. 선택 이름은 60자까지이며 지우면 `하늘 N`으로 표시한다.
   `별자리 가져오기`를 누르면 외부·미배치 별자리만 표시하고 이름을 한 번 눌러 가져온다. 후보가 7개 이상일 때만 검색창을 표시한다. 현재 하늘의 별자리 목록은 접어 둔다. 자리 옮기기는 별자리 전체 좌표만 바꾼다.
   모양을 둘러싼 원은 없고, 상세 화면에 저장한 별 좌표와 연결선을 축소해서 그린다.
3. **별자리 상세:** 별의 이름을 항상 표시한다. 실천한 별을 선택해 `별 놓기` 후 원하는 곳을 탭하거나
   마우스로 끈다. `두 별 잇기` 후 두 별을 차례로 고른다. 연결선 목록에서 이름을 확인하고 삭제한다.
   선택한 별의 실천 날짜·피드백, 으뜸별, 밝기, 완료 별자리 이름 붙이기를 유지한다.

- 터치에는 탭-탭 배치, 마우스에는 드래그, 키보드에는 방향키 + Enter를 제공한다.
- 배치·연결 중 Esc는 작업을 취소하며 모달을 닫지 않는다. 저장 실패 시 새 revision을 읽고 재시도한다.
- 모바일 별 터치 영역은 최소 44px. 상세 정사각형의 안쪽 80%에 좌표를 매핑하여 가장자리 이름 여백을 둔다.
- 보관한 목표는 열람만 가능하다. 완료하고 이름 붙인 별자리의 연결선은 기존과 같이 고정된다.
- 학생 미리보기는 읽기 전용이다. 제5장 첫 배치는 실천한 목표의 상세 화면으로 바로 들어간다.

**저장:** `academy_sky_regions(user_id, region, name, revision)`과 목표의 `sky_region`.

### 계획 실체 — 권장 모양

```sql
create table academy_plans (
  id uuid primary key default gen_random_uuid(),
  user_id uuid not null,
  goal_id uuid references academy_user_goals(id) on delete set null,  -- null = 별자리 없는 자유 계획
  title text not null,
  priority text not null default 'medium' check (priority in ('high','medium','low')),
  default_start time, default_end time,
  sky_x numeric, sky_y numeric,           -- 0~1, null = 아직 안 놓음
  is_archived boolean not null default false,
  created_at timestamptz not null default now(), updated_at timestamptz not null default now()
);
alter table academy_tasks add column plan_id uuid references academy_plans(id);
-- academy_tasks = "그 계획의 어느 날 실천" (occurrence). title 은 plan 에서 파생, 남겨 두면 표시 캐시.
```

- **별 = `academy_plans` 행.** 밝기 = `count(academy_tasks where plan_id and completed)`.
  예정 자리 = 실천 0. 좌표는 plan 에 있으니 제목을 바꿔도 별은 그대로다.
- **날짜별 달력·시간표 UI 는 그대로 산다.** `academy_tasks` 는 계속 "그 날의 칸"이고
  `plan_id` 만 얻는다. 전면 재작성(가상 반복 생성)이 아니라 FK 하나로 정체성을 세운다.
- "계획 적기"는 **plan 을 만들고 첫 occurrence 를 같이** 만든다. 같은 계획을 다른 날에
  또 넣으면 occurrence 만 는다("어제 계획 다시 넣기"·반복 체크). 제3장의 `task_id` 는
  occurrence 를 가리키므로 그대로 두고, 제5장은 `plan_id` 를 저장한다.
- **기본 경로 뒤집기**: [＋ 계획 적기]는 먼저 "어느 별자리의 별인가요?"(목표 고르기)를
  띄우고, 맨 아래 [별자리 없이 적기]로 빠질 수 있다. 목표가 하나도 없으면 목표 적기로
  안내한다. 스키마보다 이 한 줄이 하늘에 별이 생기느냐를 정한다.

**별자리 쪽 추가 컬럼**
```sql
alter table academy_user_goals
  rename column position_x to sky_x; -- , position_y → sky_y
alter table academy_user_goals
  add column constellation_name text,
  add column constellation_lines jsonb not null default '[]',   -- [[plan_id, plan_id], …]
  add column constellation_revision integer not null default 0, -- 선·이름 RMW 보호
  drop column completion_status, drop column sub_goals,
  drop column continent_id, drop column position_q, drop column position_r;
drop table academy_continents;
alter table academy_tasks drop column related_sub_goal,
  alter column start_time type time using nullif(start_time,'')::time,
  alter column end_time   type time using nullif(end_time,'')::time,
  add constraint academy_tasks_priority check (priority in ('high','medium','low'));
```

**최소 대안(계획 실체를 안 만들 때)**: `academy_tasks` 만 쓰고 별을 `(goal_id, lower(trim(title)))`
로 묶는다. 제목 변경 시 별이 갈라지는 결함을 화면에서 설명해야 한다. 권장하지 않는다.

**RPC — 계획장 쓰기와 같은 틀(`academy_private` 내부 함수 + public invoker 래퍼).**
`academy_sky_write(p_action, p_goal, p_plan, p_x, p_y, p_lines, p_name, p_revision)` ·
`place_constellation` / `place_star` / `set_lines` / `name`. 검사 순서 = `auth.uid() is null`
먼저(3값 논리 구멍) → 목표·계획 본인 소유 → `plan.goal_id = goal` → **놓기는 실천 ≥ 1**
(놓는 순간이 보상이라 그 전에 배치하게 두면 보상이 사라진다) → 선의 양끝이 그 목표의
계획 → revision 일치. 관리자 미리보기는 읽기 전용(`academy_dormitory_read` 확장).

## 6. 경제 — 바꾸지 않는다

하루 첫 실천 5코인은 그대로(§5 의 대안은 사용자 결정). **별·별자리에 코인을 붙이지
않는다.** 코인은 꾸미기(세속), 별은 뜻. 실천 표시는 자기 기록이라 보상을 달면 기록에
거짓말할 압력이 된다(제3장 문서의 원칙). 별자리에 이름을 붙이는 것 자체가 보상이고,
완성한 별자리는 여정 메뉴에 남는다. 인장은 나중에 검토.

## 7. 제5장 — 내가 긋는 별자리

### 대사 흐름 보완 (2026-09-14)

리아가 계획장을 가져와 첫 계획을 함께 펼치는 장면에서 시작한다. 실천 여부에 따른 루온의 대사는 해당 기록만 확인하고, 리아가 계획을 다시 읽으며 느끼는 망설임으로 이어진다. 제5장 진입까지 걸린 시간을 단정하지 않도록 제3장의 등불을 ‘어제’가 아닌 ‘처음 기숙사에 갈 때’의 기억으로 부른다.

등불이 켜지는 것을 보고 걷기 → 사다리에서 내려오는 테오 기다리기 → 첫날 길을 찾았던 이야기 → 등불의 줄과 별을 비교하는 리아의 관찰 → 테오의 짧은 답 → 창가에서 더 보고 싶다는 리아의 선택 순으로 귀가의 이유를 만든다. 루온은 입구까지 동행하며 약속했던 실천의 별을 소개한다.

기숙사에서는 세린이 읽던 책을 덮고 함께 창밖을 본 뒤, 책상에 자리를 내어 계획장을 펼친다. 리아가 실천과 별의 관계를 물으면 세린이 설명하고, 첫 별을 직접 놓은 뒤에 잇기와 기록 읽기를 안내한다. 목표 변경에 대한 리아의 걱정에 보관과 이름 붙이기를 답한다. 마지막은 모든 답을 얻었다는 선언 대신 조용히 별을 바라보는 대화와 속마음으로 마무리한다.

대사 29개와 행동 단계(`arrive` 16, `light` 21, `place` 22), 완료 단계 29는 유지한다. 저장된 책갈피와 DB 진행 조건을 바꾸지 않는 대사 수정이다.

**제목 후보**: 「내가 긋는 별자리」 / 「같은 밤을 잇는 선」 / 「창가에 남긴 첫 별」.
**챕터 키 `sky_first_light`** (`first_star` 는 제1장이 쓴다).

### 새 장소는 만들지 않고, 새 인물은 하나 만든다

| | 판단 | 근거 |
|---|---|---|
| 새 장소 | **안 만든다** | 광장 원화가 "건물 넷"을 좌표까지 못 박고 있어 다섯째 목적지는 광장 재생성이다. 하늘은 창가 패널로 충분하고, 제5장의 주제(반복·지속)에는 "새 곳"보다 **"아는 곳을 다르게 본다"**가 맞다. 나중에 물리 공간이 필요하면 기숙사에서 올라가는 **옥상**이 광장을 건드리지 않는 길이다. |
| 새 인물 | **등불지기 1명** | 제1~4장은 장마다 새 얼굴을 소개했다. 제5장이 새 장소도 새 얼굴도 없으면 가장 납작한 장이 된다. 그리고 "왜 하늘을 올려다보는가"를 말해 줄 사람이 없다 — 세린은 계획장을, 카시안은 지식을 맡아 **매일 밤 밖에 있는 사람**이 비어 있다. |

**등불지기 테오** (사용자 확정 이름). 짙은 갈색의 흐트러진 머리, 호박색 눈, 황동 장식과 금색 테두리가 있는 남색 롱코트, 아이보리 셔츠와 갈색 가죽 장갑·부츠, 따뜻한 황동 등불. 로맨스 판타지 원화에 맞춘 성인 남성으로 리아보다 크게 표현한다.
남성, 아카데미 잡역. 매일 저녁 같은 순서로 광장의 등불을 켠다. 아무도 안 걷는 밤에도
켠다("길이 있다는 걸 누군가는 알아야 하니까요"). 밤마다 밖에 있어 하늘을 잘 알지만
학자는 아니다 — 그래서 카시안의 영역을 침범하지 않고 **"별자리는 하늘이 준 게 아니라
사람이 그은 선"**을 말할 수 있다. 제3장에서 루온이 "광장에 등불이 켜졌네요… 저 등불을
따라가면"이라고 한 그 등불을 켜는 사람이라 세계에 이미 자리가 있다.
말투: 담담한 존댓말, 짧게 말하고 오래 듣는다. 피할 것: 훈계, "노력하면 된다"류 응원,
관찰하지 않은 실천을 봤다는 주장. → `academyCharacters.ts` 와 `academy-characters.md` 에
함께 추가(문서 규칙).

**제5장 이후**: 광장 핫스팟 `lamplighter`(제5장 시작 후 노출 — 제4장의 노엘 잠금과 같은
조건부). 대화 = 정적 저녁 인사 + [창가의 하늘 보기] + [오늘 실천 표시하러 가기].
**AI 대화는 v1 에 넣지 않는다**(이후 `academyCharacterPrompt` 로 격려 추가 가능).

## 8. 기각한 것

| 안 | 기각 이유 |
|---|---|
| 땅 키우기(kidon) | 농경의 어휘 — 왕립 관측소의 격과 안 맞고, 반쯤 키운 땅은 황무지로 보인다 |
| 집 짓기 | 세계에 건축이 없다. 굳이 집이면 기숙사 방인데 코인 꾸미기가 이미 차지. 반쯤 지은 집은 부서진 것으로 보인다 |
| 책 엮기 | 목표·계획 기록은 창작이 아니라 일기에 가깝다(사용자). 도서관 책=활동과도 겹친다 |
| 목표 = 은하 | 은하는 KG 의 Thread·Interest 집합. 목표는 그 안의 별자리(사용자 정정) |
| 목표를 KG 노드에 연결 | 재추출마다 고아. 은하는 맥락이지 조인이 아니다 |
| 새 장소(옥상·별빛 탑) | 광장 재생성 비용. 주제상 "아는 곳을 다르게"가 맞다. 옥상은 기숙사 하위 공간으로 남겨 둔 선택지 |
| 별마다 놓기 | 습관 30일 = 놓기 30번. 한 계획 = 한 별, 반복은 밝기 |
| 제목 정규화로 별 묶기 | 계획 실체가 없는 것을 화면에서 땜질. 제목을 고치면 별이 갈라진다 → `academy_plans` |
| 별·별자리에 코인 | 자기 기록에 거짓말할 압력. 코인은 꾸미기에만 |
| Cytoscape 재사용 | 물리 배치 불필요, 1.3MB, 키보드 접근성은 `<button>` 이 낫다 |
| AI 로 별의 기록·이름 생성 | "AI 는 학생 사실을 만들지 않는다"는 세계 규칙과 충돌 |
| 실제 시각(저녁)에 게이팅 | 제4장 규칙 — 기다리게 하지 않는다 |
| kidon 육각 땅·하위목표 보존 | 라이브 데이터가 테스트분뿐(사용자 확인). 두 공간 모델 병존은 혼란만 남긴다 |

## 9. 구현 결정

1. 이름 **테오**는 사용자 확정, 로맨스 판타지 외형은 위 설정으로 결정했다.
2. 제5장 제목은 **내가 긋는 별자리**. 테오가 말한 ‘사람이 그은 선’과 리아가 직접 정한 첫 별의 자리를 잇는다.
3. 연결에 참여하는 별은 **최대 12개**. 별 자체의 수는 제한하지 않는다.
4. 세 방 원화의 창을 확인해 핫스팟을 **x 60%, y 25%**로 통일했다.
5. **하루 첫 실천 5코인 유지**. 하늘 배치·잇기·이름에는 코인을 주지 않는다.
6. 관측소 화면과 KG는 그대로 두고 창가의 하늘을 별도 패널로 제공한다.

## 10. 구현 및 검증 기록

- `academy_plans`가 계획의 고정 ID를 갖고 날짜별 `academy_tasks.plan_id`가 반복 실천을 연결한다. 기존 발생 건마다 별도 계획을 만들며 제목으로 자동 합치지 않는다. 반복 기록은 같은 별의 밝기로 쌓이고 제목 수정 후에도 ID와 피드백이 유지된다.
- 목표 우선 계획 작성, 목표 없는 자유 계획, 기존 계획 이어 쓰기, 다음 날 반복, 목표 보관·다시 꺼내기를 제공한다. 기숙사 창문·계획장·실천 완료 안내에서 하늘을 연다.
- 별 배치와 별자리 이동은 마우스 끌기, 선택 후 탭, 방향키와 Enter를 지원한다. SVG 선을 선택해 삭제할 수 있고 보관은 회색, 이름 붙인 완료 목표의 선은 금색이다. 읽기 전용 학생 미리보기에는 쓰기 조작을 막는다.
- 제4장 후 광장 마무리 대화 → 한 목표의 계획 5개 달성 → 광장에서 제5장 시작 → 테오와 대화 → 기숙사 이동 → 실천 확인 → 첫 별 배치 → 29단계 완료. 필수 행동은 일반 다음으로 넘길 수 없다. 이미 저장된 별로 이어가기와 새로고침 복귀를 지원한다. 최초 완료 50코인은 기존 보상 원장이 보장한다.
- 초상 1장과 CG 4장을 `public/images/academy-game/`에 저장했다. built-in image_gen으로 제작하고 기존 절차로 초상의 알파를 처리했다. 프롬프트·원본 경로·검증은 `manifest-sky-chapter.json`에 있다. 390px에서는 CG 전체를 보여 인물과 하늘이 잘리지 않도록 한다.

검증: 실제 DB 역할의 소유권·실천 0·좌표·revision·선 양끝·12개 한도·이름/보관·단계 게이트·원자적 저장·복구·중복 없는 50코인 테스트를 전부 롤백했다. UI에서는 끌기/키보드/모바일 배치, 실패 후 재시도, 반복 계획, 제3장 실천 여부의 두 대사 분기, CG 네 장의 1440px/390px 표시, 읽기 전용과 동작 줄이기를 검사했다. 실제 AcademyGame의 광장 자동 시작·기숙사 이동·새로고침 이어하기·완료 후 하늘 열기도 통과했다.

## 11. 2026-10-02 개편 — 하나의 하늘, 노력의 지식그래프

**왜 바꿨나 (사용자 결정)**: 여러 하늘에 별자리를 «그리는» 일은 중요하지 않았다. 망원경의 지식그래프가 탐구 방향을 연구하는 도구라면, 이 하늘은 **학생의 노력**을 그린다 — 노력이 늘 성공으로 이어지지는 않아도 작은 실천은 겉으로 드러나든 아니든 학생의 일부가 된다. 옵시디언의 그래프처럼 **하나의 보드**(망원경 지도와 같은 크기 = `ScenePanel`)에 목표·계획이 놓이고, **뜻이 비슷한 계획끼리 서로 끌어당겨 모이며**, 별을 끌면 이어진 별이 따라 움직인다.

### 모양 — `skyGraph.ts` (순수)
- **노드**: 목표 = 큰 별(반지름 = 켜진 계획 수), 계획 = 작은 별(반지름 = `1+log2(실천 횟수)`), 실천 0 = 작은 점선 테두리. 색은 **소속 목표의 결정적 색상**(`hueOf`), 이름 붙인 완료 목표는 금테. 보관·미실천은 필터(`SkyFilter`).
- **엣지 2종**: `belongs`(계획→목표, 구조) · `kin`(뜻이 비슷함, 유사도 0~1). kin 은 **같은 종류끼리**(계획↔계획·목표↔목표), **목표가 다른 계획 사이에서만**(같은 목표는 이미 belongs 로 묶인다), 노드마다 상위 2개·문턱 이상(`EMBEDDING_KIN` 0.45 / `LEXICAL_KIN` 0.25).
- **자리는 저장하지 않는다.** 배치는 살아 있는 물리(d3-force)이고, 첫 자리는 id 해시의 나선(`seedPosition`)이라 열 때마다 같다. `sky_x/sky_y`·`constellation_lines`·`academy_sky_regions` 는 **DB 에 그대로 남지만 화면이 읽지 않는다**(제5장 `place` 책갈피가 좌표를 요구하므로 `normalizePosition` 으로 그 순간의 자리를 0~1 로 넣는다 — 마이그레이션 0건).

### 끌림 — 임베딩이 곧 힘이다 (AI 메타데이터 대신)
- «AI 로 노드를 분석해 메타데이터(범주)를 붙이는» 안을 재 보고 **임베딩 거리**를 골랐다: ①유지할 분류 체계가 없다(범주는 학생마다·학기마다 어긋난다) ②결정적이다(같은 글 = 같은 벡터) ③**연속값이라 그대로 스프링이 된다**(범주는 같다/다르다뿐이라 «얼마나 가까운가»를 못 준다) ④싸다(별 200개 = 한 번 호출·수 KB). 범주 이름이 필요해지면 **무리가 생긴 뒤** LLM 에게 이름만 짓게 하는 것이 순서다(사실을 만들지 않는다 — §8 의 세계 규칙).
- 엣지 함수 **`academy-sky-embed`**: `{texts:[{key,text}]}` ≤300건 → OpenAI `text-embedding-3-small`, **`dimensions: 256`**(짧은 제목의 뜻을 가르는 데 충분하고 브라우저 캐시에 들어간다). 게이트웨이 JWT + 함수 안 `auth.getUser` 이중 확인. 저장하지 않는다.
- 클라이언트 **`skyEmbeddingService.ts`**: 캐시 열쇠 = **글의 해시**(`hashText`, localStorage `academy-sky-embeddings:v1`, 800건 상한) — 제목을 고친 별만 다시 받고 같은 글은 한 번만. 호출 실패 시 **글자 2-gram 겹침**(`lexicalText` — «목표:» 같은 틀 낱말은 뺀다, 모든 계획이 공유해 겹침을 부풀린다)으로 대신하고 범례가 «끌림 = 글자 겹침»이라 말한다. 하늘이 비어서는 안 된다.

## 2026-10-03 · 고칠 때 목표 바꾸기 (`plan_write`)

플래너 양식에서 «이어갈 계획» 고르기를 걷고 «어떤 목표의 계획인가요?»만 남기면서(사용자 결정), 이미 있는 실천의 목표를 바꾸면 «같은 계획의 별자리는 바꿀 수 없어요» 로 거부하던 규칙을 고쳤다(마이그레이션 `20261003170000_academy_plan_goal_change.sql`).

- 같은 계획의 실천이 여럿 → **이 실천만 새 계획**으로 옮긴다. 다른 날의 실천과 그 별의 밝기는 옛 목표에 남는다.

## 2026-10-03 · 장기 목표 · 하늘의 선은 구조만

- 목표가 두 층이 됐다(`horizon` long/short, `parent_goal_id`). 하늘에서 장기 목표는 가장 큰 별(바깥 금빛 고리), 단기 목표가 `part` 선으로 매달리고, 갈래 전체가 장기 목표의 색이다. 장기 목표의 밝기는 단기 목표들의 계획까지 더한다.
