# NEIS 화면 지식 (`neis-kb/`)

샘플고 나이스(전북 `jbe.neis.go.kr`) 화면이 **어디에 있고, 안에 무엇이 있고, 어떻게 쓰는지**를
기계가 읽을 수 있는 형태로 모아 둔 곳이다. 두 독자를 위해 만든다.

- **사람** — 스페이스기전 할 일의 「NEIS 작업」 카드에서 **[사용 방법]**을 누르면, 앱의 다른 기능 안내와 같은
  모달(왼쪽 시연 · 오른쪽 설명)로 그 나이스 화면의 사용법을 보여 준다. 시연은 이 지식에서 **생성**된다.
- **AI 에이전트(Claude Code 등)** — 나중에 나이스 업무를 대신 처리할 때 이 폴더가 «화면 지도»다.
  이 문서만 읽고 수집본·안내를 해석할 수 있게 쓴다.

> 이 폴더에는 **자료(학생·교원 이름, 성적, 아이디)가 없다.** 화면의 **구조**만 있다. 그것이 규칙이다.

## 1. 세 층 — 섞지 말 것

| 층 | 무엇 | 누가 쓰나 | 파일 |
|---|---|---|---|
| 메뉴목록 | 화면이 **어디에** 있나(1,384개, 단위업무›세부업무›메뉴그룹›화면) | 업무포털 엑셀 → `scripts/neis-catalog/build.mts` | `src/data/neisScreens.generated.ts` |
| 수집본 | 화면 **안에 무엇이** 있나(필드·버튼·표 머리글·안내문·안쪽 탭과 자리) | 기계 — `scripts/neis-kb/collect.py` 가 **덮어쓴다** | `captures/<단위업무>/<세부업무>/<메뉴그룹>__<화면>.json` |
| 안내 | **어떻게 쓰나**(용도·절차·주의) | 사람·AI — 재수집해도 **덮어쓰지 않는다** | `guides/<같은 경로>.json` |
| 설명서 | **업무로서** 누가·언제·무엇을 먼저 하나(절 머리글·단계·팁·묻고 답하기) | 기계 — `scripts/neis-kb/manual.py` 가 PDF 에서 **덮어쓴다** | `manual/p1.json`·`p2.json`·`screens.json`·`WORKFLOW.md` |

사실(수집본)은 다시 긁으면 되지만 의미(안내)는 사람이 쓴 것이라 날아가면 안 된다. 그래서 안내는 수집본을
**요소 ID** 로만 가리키고, 나이스가 바뀌면 검증기가 «안내가 가리키는 요소가 사라졌다»를 알려 준다(5절).

**설명서 층은 화면이 아니라 업무 단위다** — 한 절(학사일정 관리)이 화면 여럿을 거치고, 한 화면(교무자료권한승인관리)이
여러 절에 나온다. 그래서 안내(화면 단위)와 섞지 않고 따로 두며, 본문의 메뉴 경로 `[교육과정-학사일정관리-학사일정관리]`
를 메뉴목록 key 로 이어 `screens.json`(화면 → 절)을 만든다. 안내는 설명서를 **근거(`refs`)로 가리키고**, 설명서가 준
담당·선행·후행·묻고 답하기를 다듬어 담는다(3절). 원본 = 「2026년 상반기 나이스(NEIS) 교무업무 사용자 설명서(고등학교용)」
Part1·Part2(2026-01-23 기준, 67절 · 1,034쪽) — **PDF 는 저장소에 넣지 않는다.**

- ⚠️ **설명서는 «지필평가», 전북 나이스 메뉴는 «정기시험»** 이다(지필평가성적관리 = 정기시험성적관리,
  지필/수행선행작업 = 정기시험/수행평가선행작업, 성취평가기준관리 = 성취기준관리). 추출기의 `TERM_ALIASES` 가 잇는다 —
  빠지면 성적 화면 수십 개가 **오류 없이** «못 이은 경로»가 된다(실측 104 → 18).
- 못 이은 경로 18개는 대부분 업무분장 메뉴목록 **밖**의 화면이다(개인설정·기본메뉴·나이스플러스·엑셀 메뉴).
- 묻고 답하기는 PDF 에서 상자 그림이라 Q/A 경계가 섞일 수 있다 — 원자료로만 쓰고 안내에 옮길 때 다시 읽는다.
- `WORKFLOW.md` = 절 머리글만 모은 **업무 달력**(시기별 → 절별 담당·선행·후행·화면). «지금 시기에 무엇을» 볼 때 먼저 연다.

```bash
python scripts/neis-kb/manual.py "<Part1.pdf>" "<Part2.pdf>"   # 새 학기 설명서가 나오면
npx tsx scripts/neis-kb/check.mts                               # 안내의 refs 가 사라진 절을 가리키면 여기서 잡힌다
```

그 밖의 파일: `targets.json`(수집 대상 — 메뉴목록에서 유도) · `index.json`(앱용 작은 색인) ·
`COVERAGE.md`(어디까지 채웠나). 셋 다 생성물이다.
**`RULES.md`** = 화면을 넘나드는 규칙(«A 를 먼저 안 하면 B 가 비어 보인다» 36개 + 설명서↔화면 차이 + 다시 수집할 화면) — 사람이 쓴 문서다.

## 2. 수집본 읽는 법 (`neis-capture/1`)

```jsonc
{
  "key": "교무학사(고)›교육과정›학사일정관리›학사일정관리",   // 메뉴목록 key
  "status": "ok",          // ok | not_found(수집 계정 메뉴에 없음 — 대개 권한) | auth_required(2차 인증) | error
  "reachedVia": "부서장(나이스부) > 교육과정 > 학사일정관리 > 학사일정관리",  // 실제로 연 나이스 메뉴 경로
  "views": [               // 화면 안 탭이 있으면 탭마다 하나, 없으면 "main" 하나
    { "id": "tab:연간 학사일정관리", "tab": "연간 학사일정관리", "size": [1640, 828],
      "elements": [
        { "id": "field:학년도", "kind": "field", "label": "학년도", "control": "combobox",
          "required": true, "valueKind": "year", "region": "search", "aria": "학년도", "box": [175,137,100,30] },
        { "id": "button:공휴일정보생성", "kind": "button", "label": "공휴일정보생성", "variant": "primary", ... },
        { "id": "grid:연간학사일정", "kind": "grid", "columns": [
            { "id": "col:연간학사일정/학년별 수업일수>1학년", "label": "1학년", "depth": 1, ... } ] }
      ] }
  ]
}
```

| kind | 뜻 | 덧붙는 칸 |
|---|---|---|
| `field` | 라벨 + 입력 컨트롤 | `control`(combobox·input·date·number·textarea…), `required`, `valueKind` |
| `button` | 버튼 | `variant`(primary·secondary·plain·link) |
| `grid` | 표 — **머리글만** | `columns[]`(묶음 머리글은 `depth`·`span`, 칸 ID 는 `묶음>칸`), `selectable`(행 선택 체크), `declaredColumns` |
| `heading` | 구역 제목 | |
| `note` | 화면의 ※ 안내문 | |
| `check` / `radio` | 체크 상자 / 하나 고르기 | `checked` / `options` |
| `report` | 보고서 뷰어 — 본문이 출력용 문서(iframe). 조회하면 문서가 그려지고 쪽 넘김·확대·저장·인쇄·찾기 막대가 붙는다. 문서 내용은 담지 않는다 | |
| `tabs` | 화면 안 탭 줄 | `items`, `active`, `via`(`buttons` = 탭 폴더가 아니라 본문 윗줄의 큰 단계 버튼 — 전입·전출 같은 절차형 화면) |

view 에는 둘이 더 붙을 수 있다(`collect.py --query` 로 받은 화면):
- `query: { alerts, opened }` — [조회]를 눌러 봤을 때 뜬 **알림 = 선행 조건**(«현재 공시차수 3차는 조사가능일이 아닙니다» = 조사
  기간에만 열림, «… [담당자관리]에서 담당자 지정이 되어 있는지 확인» = 먼저 할 일)과, 본문 구조가 새로 생겼는지.
- `after: "query"` + id `…+조회` — 조회 후 본문 구조가 새로 생겼을 때의 모습(값은 여전히 없다 — 그리드는 머리글만).

공통 칸: `region`(`search` = 회색 조회 조건 띠 안), `disabled`(처음엔 꺼짐 — 행을 고르거나 조회해야 켜짐),
`aria`(나이스가 단 접근성 이름 — **자동화 때 셀렉터**), `box`(화면 루트 기준 CSS px, 1920×945 창).

- **`valueKind`** 는 값 대신 남긴 «값의 종류»다(year·semester·grade·class·date·number·text·empty).
  자동화할 때 매개변수의 타입이 된다. 원값은 수집기가 브라우저 안에서 버리므로 어디에도 없다.
- **요소 ID 규칙** = `${kind}:${label}`, 같은 것이 또 있으면 화면 읽는 순서(위→아래, 왼→오른)로 `#2`, `#3`.
  그리드 칸은 `col:<그리드 라벨>/<묶음>><칸>`. 규칙은 `src/lib/neisScreenModel.ts` 의 `assignElementIds` 가 정본이고
  수집기(파이썬)가 같은 규칙을 따른다 — 어긋나면 검증기가 잡는다.
- 라벨은 **화면에 보이는 글자**다(`기준학기`). aria 는 다를 수 있다(`학기`). 안내 문장은 보이는 글자로 쓴다.
  메뉴목록 엑셀의 안쪽 탭 이름과도 다를 수 있다(`학생생활기록부생성` ↔ 화면 `학교생활기록부생성`) — 화면 표기가 기준이다.
- 이름에 붙는 학년도(`(2026학년도)`)는 떼고 기록한다 — 해가 바뀌어도 ID 가 그대로여야 안내가 살아 있다.

## 3. 안내 쓰는 법 (`neis-guide/1`)

안내 한 흐름(flow) = 사용 방법 모달 한 편이고, 단계(step) 하나 = 모달의 한 장이다.
앞에 **[화면 찾기]**(메뉴검색 → 경로), 뒤에 **[주의]**(자료를 바꾸는 버튼 + `cautions`)가 자동으로 붙는다.

```jsonc
{
  "schema": "neis-guide/1",
  "key": "교무학사(고)›교육과정›학급담임편성관리›학급담임편성관리",
  "purpose": "학년별로 각 반의 담임교사(복수담임 포함)를 지정한다.",     // 한 줄
  "context": "이 화면이 학교 업무 흐름의 어디에 있는가",
  "flows": [ {
    "title": "반별 담임 지정", "view": "main", "when": "학년도 시작 전(2월)",
    "steps": [ {
      "label": "학년 조회",                                      // 단계 표시줄(2~5자)
      "text": "학년도와 학년을 고르고 [조회]를 누른다.",         // 오른쪽 제목
      "detail": "담임은 학년 단위로 편성한다. …",               // 오른쪽 문단 — 왜 그렇게 하는가
      "points": ["학년마다 따로 조회·저장한다."],                // 요점 3~4개
      "targets": ["field:학년도", "field:학년", "button:조회"]   // 포인터가 차례로 누른다
    } ] } ],
  "cautions": ["..."],                 // [주의] 단계의 요점
  "related": [ { "key": "...", "why": "..." } ],
  // ── 업무 맥락(선택) — 설명서에서. 화면 구조로는 알 수 없는 것 ──
  "who": "교육과정 업무담당자",                       // 업무담당(설명서 예시 — 학교마다 다르다)
  "before": ["「반영비율/만점관리」에서 반영비율을 정한다"],  // 먼저 끝나 있어야 할 일 → [화면 찾기]에 실린다
  "after": ["「학교일지관리」에서 학교일지를 생성한다"],       // 다음에 이어지는 일 → [알아 둘 것]
  "faq": [ { "q": "…", "a": "…" } ],                  // 현장 문의·나이스지원 답변(다듬은 것) → [알아 둘 것], 앞의 3개
  "refs": [ { "section": "2-06", "title": "학사일정 관리", "pages": "151-161" } ],  // 설명서 근거 — check 가 절 존재를 본다
  "source": "observed | manual | ai-draft",
  "writtenAt": "2026-10-05",
  "basedOn": "7c7f99f6"                // 쓸 때 본 수집본 지문 — check.mts --stamp 가 찍는다
}
```

- **단계는 목적으로 묶는다(흐름당 3~4단계)** — 칸 하나마다 한 단계로 쓰면 8단계가 되고 아무도 끝까지 안 본다
  (앱 기능 안내의 수칙, `.claude/skills/feature-guide-dialog`). 한 목적에 칸이 여럿이면 `targets` 에 함께 적는다 —
  시연의 카메라가 칸마다 따라가고 포인터가 차례로 누른다.
- **글은 시연을 되풀이하지 않는다** — "버튼을 누릅니다"는 왼쪽이 이미 말했다. `detail`·`points` 가 맡을 것은
  ①왜 그렇게 되어 있는지 ②오해하기 쉬운 것 ③모르면 손해 보는 것.
- `targets` 는 수집본의 요소 ID·칸 ID·`tab:<이름>`. 화면 안 탭에서 하는 흐름은 첫 단계에서 그 탭을 자동으로 누른다.
- **출처를 정직하게**: 화면을 실제로 써 보고 확인한 것만 `observed`. 수집본만 보고 쓴 것은 `ai-draft` —
  모달 머리글이 «AI 초안 — 검토 전»이라고 말한다. 모르는 것을 지어 쓰지 말 것 — 없는 절차로 데려가는 것보다 비워 두는 편이 낫다.
- 안내가 **없어도** 수집된 화면에는 사용 방법이 있다([화면 찾기] → [화면 구성] → [주의]).
- 안내를 새로 쓰거나 고친 뒤 `npx tsx scripts/neis-kb/check.mts --stamp`. 여럿이 동시에 쓸 때는 공용 색인을 다시 쓰지 않는
  `npx tsx scripts/neis-kb/validate-guides.mts <파일…>` 로 각자 검사하고, `check.mts` 는 마지막에 한 번.
- **설명서 기준 안내(`source: manual`)** 는 `refs` 가 필수다(없으면 경고). 설명서 문장을 옮기지 말고 다듬는다 —
  설명서는 «~함» 공문체이고 안내는 «~한다» 평서체다. 설명서의 ￭ 팁이 `detail`·`points` 의 재료다
  (예: «[공휴일정보생성]을 안 하면 토요휴업일에도 출결마감 칸이 생긴다»).
- 사용 방법 모달: [화면 찾기](+ 담당·선행) → 흐름 단계 → [주의] → **[알아 둘 것]**(묻고 답하기·후행, 있을 때만).

## 4. 자동화할 때 (AI 에이전트에게)

이 지식은 «화면을 클릭하는 스크립트»가 아니라 **계획의 재료**다. 지금은 사람이 처리하고, 나중에 AI 가 처리할 때:

0. **업무부터** — `manual/WORKFLOW.md` 에서 그 업무의 절을 찾고, 안내의 `before` 가 끝나 있는지 먼저 확인한다
   (선행이 안 된 화면은 오류 없이 **비어 있다** — 성적산출 전의 분석표, 공휴일 생성 전의 출결 마감 등).
   절차의 원문이 필요하면 절 ID 로 `manual/p1.json`·`p2.json` 의 `blocks` 를 읽는다(➊ 단계·￭ 팁·묻고 답하기).

1. **찾아 들어가기** — `reachedVia` 의 마지막 칸(화면 이름)을 나이스 메뉴 검색에 넣고, 경로가 `reachedVia` 와 같은
   결과를 누른다. 구현은 NEIS_helper `app/core/neis_nav.py` 의 `open_by_search(page, name, path)` — 인증서 로그인·
   공지 팝업·메가메뉴의 함정이 거기 다 모여 있으니 다시 만들지 말 것(NEIS_helper `.claude/skills/neis-navigate`).
2. **안쪽 탭** — view 의 `tab` 이름으로 탭을 누른다(합성 이벤트는 무시된다 — 실제 마우스 입력).
3. **조건 채우기** — `region: search` 인 field 를 `valueKind` 에 맞는 값으로 채우고 `button:조회`.
   셀렉터는 `aria`(Cleopatra 컨트롤은 `[aria-label]` 이 붙는다), 콤보박스는 `[role=combobox]`·`[role=option]`.
4. **버튼의 성격** — `neisButtonEffect(label)`: `read`·`export`·`navigate`·`write`. 모르면 `write` 로 본다.
   🚨 **`write`(저장·삭제·마감·반영…)는 사람의 확인 없이 누르지 않는다.** 생활기록부에 남는 자료다.
5. **표 읽기** — `grid` 의 칸 ID 로 열을 가리킨다. 가상 스크롤이라 행이 많으면 NEIS_helper `neis-record-download` 방식.

## 5. 나이스가 바뀌었을 때

```bash
# 1) 메뉴목록이 바뀌었으면(업무포털에서 새로 받은 엑셀)
npx tsx scripts/neis-catalog/build.mts "<메뉴목록.xlsx>"
npx tsx scripts/neis-kb/targets.mts

# 2) 화면 다시 수집 — 세션은 NEIS_helper 에서(9333 은 데스크가 쓰므로 다른 포트)
#    cd NEIS_helper && set NEIS_CDP_PORT=9334 && node .claude/skills/neis-navigate/neis-nav.js session
python scripts/neis-kb/collect.py --area 교무업무 --force     # 끊기면 --force 없이 다시 돌리면 이어 받는다

# 2') 영역 전체처럼 오래 걸리면 무인 수집기 — 세션이 끊기면 인증서로 다시 로그인하고 이어 받는다
python scripts/neis-kb/crawl.py 학교행정 일반행정 공통관리
#    수집기 규칙을 고친 뒤 영향받은 화면만: --keys-file <줄마다 key 하나>

# 3) 검증 — 고칠 안내가 여기 나온다
npx tsx scripts/neis-kb/check.mts
```

- `✗ … 이(가) … 에 없습니다` = 안내가 가리키는 요소가 사라졌다 → 안내의 target 을 고친다.
- `! 화면 구성이 바뀌었습니다` = 요소는 남았지만 구성이 달라졌다 → 안내를 다시 읽고 맞으면 `basedOn` 을 지우고 `--stamp`.
- `git diff neis-kb/captures` 가 **나이스가 무엇을 바꿨는지** 그대로 보여 준다(화면당 한 파일, 칸 하나가 한 줄).
- **2차 인증 화면**(`auth_required` — 세특 등)은 사람이 전화(ARS)로 인증해야 한다. 세션을 띄우고 화면을 열어 ARS 탭 →
  등록 번호 → [인증요청] → 화면에 뜬 두 자리 번호를 전화로 누른다 → «인증완료» [확인] 두 번. 같은 세션에서
  `collect.py --retry-missing` 으로 받는다. 완료는 «인증완료» 알림 글자로 판정한다(인증 창은 [확인] 전까지 남아 있다).

## 6. 하지 않는 것

- **스크린샷을 저장하지 않는다** — 화면을 여는 것만으로 교원 이름·아이디가 채워지는 화면이 있다(학급담임편성관리).
  그림은 구조에서 다시 그린다.
- **저장·마감을 누르지 않는다** — 수집기가 누르는 것은 메뉴 검색 결과·화면 안 탭, 그리고 `--query` 일 때 [조회]와 알림 [확인]뿐이다.
  [조회]는 2026-10-05 사용자 승인 범위에만 썼다 — 정보공시 21개, A(통계·집계·서식) 27개, B(교원 시간표·사용자) 10개.
  학생 개인 정보가 뜨는 화면(C 23개: 명렬·성적·건강·특수교육·졸업생 학생부)은 조회하지 않았다.
  다른 영역에 쓰려면 다시 묻는다 — 조회하면 학생·교원 자료가 화면에 뜨고 나이스에 조회 기록이 남는다.
- **수집 계정에 없는 메뉴는 `not_found`** 로 남긴다 — 화면이 없어서가 아니라 권한이 없어서다. 그 메뉴를 받은
  계정으로 `--retry-missing` 하면 채워진다.
